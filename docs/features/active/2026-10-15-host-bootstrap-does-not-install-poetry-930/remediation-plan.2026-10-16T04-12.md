## Conventions

- `<FEATURE>` means `docs/features/active/2026-10-15-host-bootstrap-does-not-install-poetry-930`. This plan's own artifacts are written to `<FEATURE>/evidence/other/<name>.<timestamp>.md` (Phase 0) and `<FEATURE>/evidence/qa-gates/<name>.<timestamp>.md` (Phase 2).
- `<timestamp>` in an artifact name, and every clock value written into a file, is read with `date -u +%Y-%m-%dT%H-%M` immediately before the write. It is never estimated. The same value is the artifact's `Timestamp:` line.
- All commands run from the worktree root with repository-relative paths. To observe an exit code, the executor appends `; echo "EXIT=$?"` for the run only; the recorded `Command:` field omits that suffix. `EXIT_CODE: SKIPPED` is invalid, and no exit code is invented: the recorded value is the observed value, including a non-zero value.
- Artifacts contain no absolute host path.
- Existing line endings and existing lines of the three files are preserved. Fields are added by appending lines after the last existing line.
- Added fields in FA: `Command:`, `EXIT_CODE:`, `Fields Added At:` (the clock value), `Verification Output:` (the observed output; the existing `Output Summary:` describes the original read and is kept as is), and `Note:`. Added fields in FB and FC: `Command:`, `EXIT_CODE:`, `Output Summary:`, `Fields Added At:`, and `Note:`. The existing `Timestamp:` line of each file stays the first `Timestamp:` record; the `Note:` line states that no command was run when the artifact was first written and that the `Command:` shown is the verifying command run when the fields were added.
- Anchor decision: the branch carries the feature's own commits ahead of origin/main, so a `git diff` anchored to origin/main lists those commits and cannot isolate this remediation. Scope and preservation checks anchor at REM0, the HEAD SHA recorded by P0-T3. Each name-listing diff is paired with `git status --porcelain` because the new artifacts of this plan are untracked.
