## Design Contract (from spec.md "Proposed Fix", with planner decisions)

Shared file W01 (pure, dot-sourced; byte-identical copy W09). Callers wrap calls that return arrays in `@(...)`.

- `Find-FeatureFolderCandidate -Text [string]` → distinct basenames in first-occurrence order (R1). Scan with the existing token pattern used at `.claude/hooks/enforce-epic-wave-barrier.ps1` line 122, anywhere in the text (any prefix). Normalize `\` to `/`, split on `/`, drop empty and `.` segments, require at least four segments, take segment four as the folder, trim trailing `.`, `,`, `;`, `:` from it, and drop an empty result. Deduplicate ordinally (case-sensitive). Null, empty, or no qualifying token → no output.
- `ConvertTo-FeatureFolderBasename -Value [string]` → basename or `$null` (R2). Normalize `\` to `/`, trim whitespace and trailing `/`, strip one leading `docs/features/<lifecycle>/`, `active/`, or `completed/` prefix, and return the last remaining segment. An empty or `.` result → `$null`.
- `Find-FeatureFolderRecord -Records [object[]] -Reference [object]` → one record or `$null`. A non-string reference, or a string matching `^\d+$`, matches records whose `issue_num` string form equals it. Any other string matches records whose `ConvertTo-FeatureFolderBasename` of `feature_folder` ordinally equals `ConvertTo-FeatureFolderBasename` of the reference. Zero or multiple matches → `$null`. A null reference or null records → `$null`.
- `Select-FeatureFolderTarget -Records [object[]] -Candidate [string[]] [-DeclaredIssueNumber [int]] [-FallbackIssueNumber [int]] [-DependencyAware]` → `[pscustomobject]@{ Status; Record; Basename; Remaining; Detail }`.
  1. Each candidate maps to at most one record through `Find-FeatureFolderRecord`. Unmatched candidates stay in the set.
  2. With `-DependencyAware`, a matched candidate c is removed when another matched candidate c' exists such that record(c) is in the transitive `depends_on` closure of record(c') and record(c') is not in the closure of record(c). A cycle therefore removes neither. Closure entries resolve through `Find-FeatureFolderRecord` with a visited set.
  3. One remaining → `Resolved` (`Record` may be `$null` for an unmatched candidate; `Basename` = the candidate).
  4. More than one remaining and `-DeclaredIssueNumber` bound: if exactly one remaining record has that `issue_num` → `Resolved`. It cannot select a record outside the remaining set.
  5. Zero candidates and `-FallbackIssueNumber` bound: `Find-FeatureFolderRecord` by issue number; found → `Resolved` with `Basename` = basename of its `feature_folder`.
  6. Otherwise zero → `NoTarget`, more than one → `Ambiguous`.
  7. `Detail` literals: `resolved target feature folder '<b>'`; `no target feature folder is cited`; `ambiguous target feature folder; remaining candidates: <b1>, <b2>` (Remaining in first-occurrence order). Neither length nor position affects `Status` (R6).
- `Resolve-FeatureFolderWorkMode -IssueContent [string] [-UnresolvedMode [string] = 'full-feature']` → regex `(?im)^-\s*Work Mode:\s*(minor-audit|full-feature|full-bug|full)\s*$` (identical to `.claude/hooks/enforce-prd-feature-before-planner-helpers.ps1` line 52). `full` → `full-feature`. No match (missing, empty, malformed, or unrecognized) → `-UnresolvedMode`.
- `Get-FeatureFolderPlanPrerequisite -WorkMode [string]` → `minor-audit`: `issue.md`; `full-bug`: `issue.md`, `spec.md`; `full-feature` and any other value: `issue.md`, `spec.md`, `user-story.md`.
