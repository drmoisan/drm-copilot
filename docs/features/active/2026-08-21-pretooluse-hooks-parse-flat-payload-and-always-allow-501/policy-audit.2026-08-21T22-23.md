### Blocking finding: batch-budget hook coverage regression

Reviewer measurement, throwaway worktree at merge-base `fb30a9a5`, running only the two suites with coverage scoped to the two hooks:

| File | Baseline | Post-change | Delta |
|---|---|---|---|
| `enforce-powershell-batch-budget.ps1` | 96.30% (78/81, missed lines 169, 180, 223) | 81.93% (68/83, missed lines 158, 221-241 region) | **-14.37 pp** |
| `enforce-python-batch-budget.ps1` | 96.30% (78/81, missed lines 166, 177, 220) | 81.93% (68/83, missed lines 155, 218-238 region) | **-14.37 pp** |

Mechanism: the baseline suites executed the whole hook file in-process (`$result = & $script:ScriptPath | ConvertFrom-Json`, baseline suite line 212), which covered the script tail below the dot-source guard. The migrated suites removed that execution (necessarily — the new tail calls `Read-ClaudeHookRawPayload`, which would consult live stdin) and replaced it with a text-scan test, so the entire tail is now uncovered. Unlike eight other hooks, these two were not given the `Invoke-<Name>EntryPoint` seam that makes the tail thin and the acquisition path testable.

Changed-line regression: `git diff -U0` changed-line set intersected with the missed-line set yields exactly one regressed changed line per file — `enforce-powershell-batch-budget.ps1:235` and `enforce-python-batch-budget.ps1:232` (the tail `$decision = Invoke-...Hook -ToolInputRaw (Read-ClaudeHookRawPayload) ...` statement), covered at baseline, uncovered post-change. This violates "Code changes or refactors must not reduce coverage for the lines that were changed" (`.claude/rules/general-unit-test.md`) and the feature-review modified-file gate (>= 85% and no regression).

The executor's coverage-comparison evidence (`evidence/qa-gates/2026-08-22T00-50-coverage-comparison.md`) states "there is no regression on changed lines", derived only from the per-file table of the nine newly registered denominator entries; the two batch-budget hooks were already in the denominator and were not re-examined. The denominator-composition explanation for the aggregate -0.39 pp delta is substantially correct and was reproduced byte-exactly, but it is incomplete: roughly 24-30 lines of real coverage loss in these two tails also contribute to the delta.
