## COV-1 Outcome Derivation (fixed; applied by P5-T3)

Inputs: the P5-T2 call disposition; the D-COV-FRESH values before (P5-T1) and after (P5-T3); the D-COV-READ match count `K` and the values `covered`, `missed`, `total`, `pct` after; the P0-T5 roots-identity result.

**Step A — evaluate every condition.** Evaluate all seven conditions below, in this fixed order, independently of one another. A condition marked "requires K = 1" is evaluated only when `K` is 1 and is otherwise recorded as not held.

| Order | Condition token | Holds when |
|---|---|---|
| C1 | `RUN-RAISED` | the P5-T2 call raised |
| C2 | `FILE-NOT-REWRITTEN` | the last-write time after equals the value before, or the `report name` line after equals the line before |
| C3 | `COUNTER-NOT-FOUND` | `K` is not 1 |
| C4 | `ROOTS-DRIFT` | P0-T5 recorded `ROOTS-DRIFT` |
| C5 | `DENOMINATOR-MISMATCH` | `total` is not 18116 (requires K = 1) |
| C6 | `BELOW-85` | `pct` is below 85.00 (requires K = 1) |
| C7 | `BELOW-BASELINE` | `pct` is below 90.42 (requires K = 1) |

**Step B — record every held condition.** Write one line `COV-1-CONDITIONS: ` followed by the tokens of every held condition in the order C1 to C7, separated by `, `; when none holds, write `COV-1-CONDITIONS: NONE`. Every observed value is recorded, including `covered`, `missed`, `total` and `pct` whenever `K` is 1, whether or not the file was rewritten.

**Step C — select exactly one outcome by precedence.** The first rule below whose test matches selects the outcome; later rules are not applied. The outcome line is written exactly as shown.

1. **NOT-PRODUCED** (C1, C2 or C3 held): `COV-1-OUTCOME: MEASUREMENT-POPULATION-MISMATCH (NOT-PRODUCED/<primary>)`, where `<primary>` is the first held token in the order `RUN-RAISED`, `FILE-NOT-REWRITTEN`, `COUNTER-NOT-FOUND`. Example: a stale file with a mismatched denominator holds C2, C5, C6 and C7 and records `COV-1-CONDITIONS: FILE-NOT-REWRITTEN, DENOMINATOR-MISMATCH, BELOW-85, BELOW-BASELINE` and `COV-1-OUTCOME: MEASUREMENT-POPULATION-MISMATCH (NOT-PRODUCED/FILE-NOT-REWRITTEN)`.
2. **DENOMINATOR** (otherwise, C4 or C5 held): `COV-1-OUTCOME: MEASUREMENT-POPULATION-MISMATCH (DENOMINATOR)`, recording `total`, 18116 and their difference. A population mismatch takes precedence over a below-threshold percentage because a percentage over a different population is not comparable with the 90.42 baseline. Example: `total` 12280 with `pct` 66.04 holds C5, C6 and C7 and records `COV-1-CONDITIONS: DENOMINATOR-MISMATCH, BELOW-85, BELOW-BASELINE` and `COV-1-OUTCOME: MEASUREMENT-POPULATION-MISMATCH (DENOMINATOR)`.
3. **REGRESSION** (otherwise, C6 or C7 held): `COV-1-OUTCOME: COVERAGE-REGRESSION`.
4. **CLOSED-LOCAL** (otherwise; no condition held): `COV-1-OUTCOME: COV-1-CLOSED-LOCAL`. P7-T6 still confirms AC-24 on the PR head.

The status line follows the outcome mechanically: rules 1 and 2 write `COV-1-STATUS: awaiting_ci (P7-T6, AC-24)`; rule 3 writes `COV-1-STATUS: open-regression`; rule 4 writes `COV-1-STATUS: closed-local (P7-T6 confirms on the PR head)`.

`MEASUREMENT-POPULATION-MISMATCH` is a recorded outcome, not a pass: COV-1 is reclassified `awaiting_ci` for orchestrator task P7-T6 (AC-24) on the PR head. `COVERAGE-REGRESSION` is a failure: the executor commits the evidence, then stops and reports BLOCKED; it does not change coverage configuration, exclusions, production files or tests to move the figure. Known limitation to verify rather than assume: the MCP PoshQC runner can resolve settings from the installed extension instead of the repository copy, so its measured population can differ from CI's; rule 2 covers that case.
