## Design Decisions (binding on execution)

1. **Capture pattern.** Every fixed call site uses parent-shell capture guarded for `set -e`: `local rc=0 out; out=$(cleanup_wt_git ...) || rc=$?` followed by iteration over `<<<"$out"`. Do NOT combine declaration and capture (`local out=$(cmd)` masks the exit code), and do NOT use bare `out=$(cmd); rc=$?` (an unguarded failing command substitution aborts under the wrapper's `set -euo pipefail`).
2. **Stdout-only capture (intentional deviation from the remediation-inputs example).** The remediation-inputs example shows `out=$(cmd 2>&1)`. This plan captures stdout only and lets stderr flow through to the caller's stderr. Rationale: captured stderr text would be iterated as candidate report records, and both real git warnings and the checked-in stub's `stub-git:` argv log are emitted on stderr. The essential required property — `rc` observed in the parent shell immediately after capture — is preserved.
3. **Hard-error verdicts.**
   - `parse_worktree_list`: on non-zero git exit, print a diagnostic to stderr and return that non-zero code, emitting **no** records. An empty porcelain output with exit 0 remains valid (returns 0, no records); only a non-zero exit is a hard failure.
   - `classify_cherry_equivalent`: on non-zero `git cherry` exit (cherry has no expected non-zero in this ladder), print the single internal verdict token `CHERRY_ERROR` and return 0 (matching the function's echo-verdict contract, like `classify_ancestry`).
   - `classify_branch`: any hard failure (worktree-list, protected-set, cherry, or rev-list enumeration) emits the existing report state `BRANCH|<name>|ANCESTRY_ERROR` and returns 2, following the established `CONTENT_NEUTRAL_ERROR → ANCESTRY_ERROR` mapping precedent. No new report-line state is introduced; `CHERRY_ERROR` is internal-only.
   - `run_report`: a `parse_worktree_list` hard failure propagates as a non-zero return before any branch classification.
   - Invariant: a hard git failure must never resolve to `MERGED_CLEAN`, `MERGED_CONTENT_NEUTRAL`, `MERGED_EQUIVALENT`, or a weakened protected set.
4. **500-line cap forces a pure-move split first.** `scripts/bash/cleanup_worktrees_lib.sh` is at 499 lines; the fix adds lines. Phase 1 moves the enumeration/protection function group verbatim into a new `scripts/bash/cleanup_worktrees_enumerate_lib.sh` before any behavior change. This is compelled by the uniform 500-line policy applied to the CR-1 change; it does not claim CR-3 remediation.
5. **Fail-before ordering.** Tests and fixtures land before the production fix (Phase 2), and one CI dispatch captures the failing (fail-open) behavior as genuine fail-before evidence; the final QA dispatch (Phase 4) is the pass-after run.
