## Extraction Decision — the G1–G4 coverage cascade moves out (option b)

The remediation inputs offer two candidate groups: (a) the G5/G6 literal rules, or (b) the G1–G4 coverage cascade. This plan extracts **(b), the coverage cascade**, into the new sibling module `scripts/dev_tools/plan_gate_coverage.py`. Justification on the two grounds the inputs require:

1. **Both files comfortably under the 450-line target.** The moved block — the constants `PLACEHOLDER_MARKERS`, `PATH_SEPARATORS`, `PYTHON_SUFFIX`, `PYTEST_NODE_SEPARATOR`, and the five functions `_is_placeholder`, `_dotted_remedy`, `_cov_values`, `_evaluate_cov_value`, `_evaluate_tracked_cov_value` — spans approximately 130 lines of the current module including interleaved blanks and two now-relocatable import names (`COV_FLAG`, `COV_FLAG_PREFIX`). **Projected counts: `plan_gate_discrimination.py` ≈ 380 lines (upper bound 400); `plan_gate_coverage.py` ≈ 155 lines (upper bound 220 with the policy-mandated module docstring and intent comments).** Both projections sit at least 50 lines under the 450 target and at least 100 lines under the 500 ceiling, so the next ordinary edit cannot immediately recreate R6. Task [P3-T1] verifies the realized counts against the 450 target; the cycle fails if either exceeds it.
2. **Fewest cross-module imports.** The coverage cascade's only dependencies on the shared gate types (`PlanGateReport`, `PlanGateContext`) are annotation-level: `_evaluate_cov_value` and `_evaluate_tracked_cov_value` receive the report and context as parameters and never construct them. With `from __future__ import annotations` those names can be imported under `TYPE_CHECKING` only, so the runtime module graph stays acyclic with exactly one runtime import edge (`plan_gate_discrimination` → `plan_gate_coverage`, three names). Option (a) is worse on this ground: `_evaluate_literal_rules` constructs `PlanGateReport()` at runtime, and the G5 channel routing needs `G5_SEVERITY`, `BLOCKING_CHANNEL`, and `WARNING_CHANNEL`, forcing either a runtime circular import or relocation of the public report/context types and the severity constants out of the module every caller imports them from. A repo-wide search confirms no test or production caller imports any of the five moved helpers directly — every consumer uses `evaluate_plan_gates` or the public names (`PlanGateReport`, `PlanGateContext`, `PlanGateGitRepository`, `GitPlanGateRepository`, `build_plan_gate_context`, `G5_SEVERITY`, `PlanCommand`, `extract_plan_commands`), all of which stay in `plan_gate_discrimination.py`, so the split requires zero import changes outside the two files and one test file.

`G5_SEVERITY` and every message constant remain defined in and importable from `plan_gate_discrimination`; nothing new is re-exported publicly.
