## Required Record Contract

The canonical grammar belongs in `.claude/skills/atomic-plan-contract/SKILL.md`; `.claude/agents/atomic-planner.md` uses that grammar, and `.claude/hooks/validate-planner-output.ps1` enforces it. The parser scopes the record from the sole `PLANNER-INTERNAL-REVIEW: PASS` line through the required `PREFLIGHT:` line, so labels elsewhere in the output cannot satisfy the contract. A complete record contains exactly one occurrence of each required declaration and one or more citation and AC-mapping records:

```text
PLANNER-INTERNAL-REVIEW: PASS
CITATION-TO-TREE: PASS
CITATION: <repository-relative path> | <nonblank locator>
ACCEPTANCE-CRITERION-TO-IMPLEMENTATION: PASS
AC-INVENTORY: AC1, AC2, ...
AC-MAPPING: <AC id> | IMPLEMENTATION: <nonblank path or identifier> | TESTS: <nonblank path or identifier> | EVIDENCE: <nonblank path or identifier>
SCOPE-BOUNDARY: PASS
UNRESOLVED-GAPS: NONE
```

The parser must reject a missing, blank, duplicate, or malformed declaration; a label-only declaration; an omitted, blank, partial, failed, blocked, or non-`PASS` review dimension; no citation record or a citation without a repository-relative path and locator; an empty or duplicate `AC-INVENTORY`; no AC mapping or a mapping without every implementation, tests, and evidence field; duplicate mapping identifiers; an inventory identifier without a mapping; a mapping identifier absent from the inventory; unresolved, failed, blocked, or absent gap disposition; and any label that occurs outside the bounded record. The hook must require exact unique-set equality between `AC-INVENTORY` and `AC-MAPPING` IDs. The hook remains the enforcement point; the canonical skill and agent prose state the same machine-checked grammar and do not substitute for validation.
