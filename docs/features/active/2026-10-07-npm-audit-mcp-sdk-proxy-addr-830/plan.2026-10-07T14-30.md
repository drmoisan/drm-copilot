**Acceptance criteria (as inventoried by this plan; P0-T2 verifies issue.md carries them):**
- AC-1: In each of `package.json`, `extensions/drm-copilot/package.json`, and `packages/mcp-server/package.json`, the `@modelcontextprotocol/sdk` dependency is `"^1.31.0"` and `overrides` contains `"proxy-addr": "^2.0.8"` next to the existing `fast-uri` and `brace-expansion` overrides; `@types/vscode`, `@types/node`, and `typescript-eslint` are unchanged; each `package-lock.json` is regenerated with npm install to match.
- AC-2: `npm audit --audit-level=moderate` exits 0 in `.`, `extensions/drm-copilot`, and `packages/mcp-server`, and `npm ls @modelcontextprotocol/sdk proxy-addr --all` in each shows only @modelcontextprotocol/sdk >= 1.31.0 and proxy-addr >= 2.0.8.
- AC-3: The root and extension TypeScript toolchains pass after the change (format check, lint, typecheck, tests with coverage not below baseline), the `packages/mcp-server` build passes, and PR CI is green including Publish to Marketplace. The pre-existing root `format:check` failure on `tests/fixtures/**` JSON is excluded as in #802.

**Chosen approach (decision record):** raise the direct `@modelcontextprotocol/sdk` dependency to `"^1.31.0"` in all three manifests and add a flat top-level `"proxy-addr": "^2.0.8"` to each `overrides` block (proxy-addr is transitive through express 5.2.1, whose own range already admits 2.0.8). Basis: the three lockfiles at `f6ef5b2f` resolve sdk 1.30.1 and proxy-addr 2.0.7. P0-T8 re-verifies the consumer set with `npm ls` before any edit; if any proxy-addr consumer requires a major other than 2, P1 must not start and the plan returns to the planner. `@types/vscode`, `@types/node`, and `typescript-eslint` must not change, because an `@types/vscode` bump breaks `vsce package` (the failure seen in Dependabot PR #827).

**Scope boundary:** the only tracked files modified are the three `package.json` and three `package-lock.json` files named in P1.
