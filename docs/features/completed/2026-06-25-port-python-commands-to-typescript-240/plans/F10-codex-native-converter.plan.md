## Scope and Constraints

This feature ports the full Codex-native converter pipeline (`codex_native_converter/`) to in-process TypeScript and wires `RepoAutomationService.runCodexNativeConverter()` to call it directly instead of spawning `resources/templates/codex_native_converter.py` (which delegates to `scripts.dev_tools.codex_native_converter.cli.main`). The pipeline is pure logic plus filesystem I/O through an injected `FileSystem`; there is no git/gh/subprocess dependency in this cluster. The Typer CLI is replaced by either a thin TS argument parser or a direct engine function call from the service helper.

The authoritative Python source lives at `scripts/dev_tools/codex_native_converter/*.py`. The bundled extension copy at `extensions/drm-copilot/resources/scripts/dev_tools/codex_native_converter/` re-exports those modules; port from the authoritative `scripts/dev_tools/...` source. The Python tests live at `tests/scripts/dev_tools/codex_native_converter/` (16 files).

Hard constraints (enforced by every code task):
- No production, test, or reusable-script file may exceed 500 lines. `engine.py` (499), `rewrites.py` (485), and `classifier.py` (484) are near the limit and their TS ports are pre-split as instructed below; split any other TS file further if it would exceed 500 lines.
- New `src/lib/codex-native-converter/**` files: line coverage >= 85%, branch coverage >= 75%.
- Tests are hermetic: inject `FileSystem` (`src/lib/file-system.ts`); no real filesystem, no temp files, no real subprocess. Reading source content uses the injected `FileSystem.readTextFile`; writing report/destination artifacts uses the injected `FileSystem`.
- Reuse F1 `src/lib/file-system.ts` and `src/lib/subprocess-runner.ts`. Do not re-port them. (`subprocess-runner.ts` is not exercised by this cluster but is referenced by the service for other methods; do not remove or modify it.)
- ES modules, strong typing, no `any`; kebab-case filenames; AAA test structure; Jest (`@jest/globals`, `jest.fn()`, `jest.mock`). The `extensions/drm-copilot` package uses Jest (`ts-jest`, `run-jest.cjs`), NOT Vitest, per spec decision D1; ported tests follow the real Jest toolchain.
- Preserve all enum values, dataclass→type shapes, error message strings, report content, ordering, and exit-code-equivalent behavior verbatim. Paths recorded in models stay normalized to POSIX text.
- Do NOT modify `command-runtime.ts`, the `"python"` runtime branch, or any Python under `scripts/dev_tools/**` or `resources/**/*.py` (removal is F11).
- `extensions/drm-copilot/src/repo-automation-service.ts` must remain <= 500 lines (currently 481). The `runCodexNativeConverter()` body delegates to a new `codex-native-converter-service-call.ts` helper.

### FileSystem capability note (decision recorded for the executor)

The Python `ConverterFileSystem` Protocol (in `reporting.py`) exposes `mkdir(path)` and `write_text(path, content)`. The converter additionally reads source files (via `Path.read_text`) and inspects existence/directory predicates during inventory and classification (`Path.exists`, `Path.is_dir`, `Path.iterdir`, `Path.glob`, `Path.read_text`). The shared F1 `FileSystem` interface already exposes `glob`, `isFile`, `exists`, `isDirectory`, `listDirectory`, `readTextFile`, `writeTextFile`, and `ensureDir` (the F9 additive extension already landed `exists`/`isDirectory`/`listDirectory`). These cover all converter needs:
- `ConverterFileSystem.mkdir` → `FileSystem.ensureDir`
- `ConverterFileSystem.write_text` → `FileSystem.writeTextFile`
- source reads → `FileSystem.readTextFile`
- inventory discovery → `FileSystem.glob` / `listDirectory` / `isDirectory` / `exists` / `isFile`

No new `FileSystem` method is required and no change to `file-system.ts` is planned. If, during porting, the executor finds a converter behavior that the existing interface cannot express (for example a read that must distinguish missing-file from empty-file), the extension MUST be additive (new method on the interface plus `RealFileSystem` implementation, no existing signature changed) and recorded in `docs/features/active/2026-06-25-port-python-commands-to-typescript-240/evidence/other/filesystem-extension-note.md`.

### CLI replacement decision (typer)

`cli.py` uses Typer with two commands (`review`, `apply`). Per inventory Section 6.4, the TS port exposes the engine directly and the service helper calls it; a thin TS argument parser is also provided to preserve the `review`/`apply` command behavior and the input-validation error strings (`source_root must point to an existing directory.`, `apply mode requires --destination-root.`, `source_ecosystem must be 'github-copilot' or 'claude'.`) and the apply-mode non-zero exit behavior (blocking findings + no destination write). The service helper bypasses argv parsing and calls the engine functions with a typed options object built from `RunCodexNativeConverterInput`.
