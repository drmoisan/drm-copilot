## Normative Content Contract (fixed by spec Test Strategy, lines 220-256)

Required substrings (AC10), asserted per affected `csharp-legacy` variant file:
`dotnet tool run csharpier format .` | `dotnet tool run csharpier check .` | `dotnet tool restore` | `/t:Rebuild /m` | `"/p:Platform=Any CPU"` | `/p:TreatWarningsAsErrors=true` | `#nullable enable`

File-scoped forbidden substrings (AC11), asserted per affected `csharp-legacy` variant file — exactly three members:
`csharpier .` | `sln /t:Build` | `/p:Platform="Any CPU"`

`/p:Nullable=enable` is deliberately NOT in the file-scoped forbidden set; its absence assertion is span-scoped per rule 6 below (spec `### Nullable-Literal Scoping`, lines 238-256; issue scope note, lines 94-104). Research section 6.7's file-scoped listing of `/p:Nullable=enable` is superseded by the spec's Nullable-Literal Scoping section, exactly as 6.7's bare `/t:Build` listing is superseded by the spec's `sln /t:Build` precision.

Scoping and collision rules (normative; encode exactly):
1. Absence scans run ONLY against the four `csharp-legacy` variant files. Bundle-wide or repository-wide absence scans are prohibited (the Codex default-slot files `.agents/skills/csharp/SKILL.md` and `.agents/skills/csharp-qa-gate/SKILL.md` legitimately carry stale forms; that pre-existing defect is out of scope and recorded at `docs/features/potential/2026-08-13-codex-default-csharp-slot-carries-legacy-content.md`).
2. The build forbidden literal is `sln /t:Build`, never bare `/t:Build` — the corrected files intentionally mention `/t:Build` inside explanation sentences ("CI may retain `/t:Build` on a cold checkout"), so a bare `/t:Build` scan fails by design.
3. The CSharpier forbidden literal is `csharpier .` — it matches both stale forms (`dotnet tool run csharpier .` and the global `` `csharpier .` `` fallback) and matches nothing in the corrected text (`csharpier check .` does not contain `csharpier .` as a contiguous substring).
4. Solution placeholders are preserved per file, never normalized: Claude-surface files use `<solution>.sln`; Codex-surface files use the literal `TaskMaster.sln`.
5. The platform property is normalized to the whole-argument form `"/p:Platform=Any CPU"` in all four variant files.
6. Span-scoped nullable predicate (normative, replaces any file-wide or line-scoped `/p:Nullable=enable` scan): in any of the four `csharp-legacy` variant files, no backtick-delimited inline code span may contain both `msbuild` and `/p:Nullable=enable`. Implementation: extract spans with the regex `` `([^`\n]+)` `` and assert the conjunction holds for no extracted span. Matching is case-sensitive: the lowercase `msbuild` token appears only in command spans, while prose refers to the product as `MSBuild` (capitalized), which the predicate does not select. Verified fact (spec lines 240-248): all four variant files contain zero fenced code blocks, so inline spans are the complete command surface and no fenced-block handling is required. The research replacement blocks are therefore applied verbatim on their original line structure, including the prohibition prose naming `/p:Nullable=enable` — post-fix, the only spans containing `/p:Nullable=enable` are the standalone `` `/p:Nullable=enable` `` spans inside the prohibition sentences, which contain no `msbuild`, so the predicate is satisfied with no source-line split. No task in this plan asserts file-wide absence of `/p:Nullable=enable`, and no task asserts a line-scoped predicate.
