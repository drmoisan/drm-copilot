## 0. Rules binding on every task

1. **Evidence location and schema.** Every artifact is written under `docs/features/active/enforcement-gates-lack-epic-level-checkpoint-seam-663/evidence/<kind>/` with `<kind>` one of `baseline`, `regression-testing`, `qa-gates`, `other`. Every command-step artifact carries `Timestamp:` (format `yyyy-MM-ddTHH-mm`), `Command:`, `EXIT_CODE:`, and `Output Summary:`. An artifact whose gate is expected to exit non-zero also carries `ExpectedExitCode: 1`. `EXIT_CODE: SKIPPED` is never a passing outcome, and no task in this plan authorizes a skip.
2. **No host data.** No artifact, test, fixture, or document written by this plan contains an absolute filesystem path, a drive letter, a user-profile path, or the executing account name. Where a command prints such a value, the artifact records it with the worktree root replaced by `<WORKSPACE_ROOT>` and the session scratchpad by `<SCRATCHPAD>`. Tests use only the synthetic roots `/synthetic-worktrees/epic-coordinator` and `/synthetic-worktrees/epic-integration`, which name no host. No test uses `C:/workspace` or any other drive-rooted literal.
3. **Fresh process.** Every PowerShell toolchain or Pester run executes in a fresh PowerShell 7 process launched through the route [P0-T6] selects. Scripts live in the session scratchpad, contain only repository-relative paths, obtain the root with `$root = (Get-Location).Path`, and are launched with the worktree root as the working directory. A reused interactive session is not a valid route. Cmdlet observations named in acceptance conditions (`Select-String`, `Get-Content`, `Get-FileHash`, `Test-Path`, `ConvertFrom-Json`) run through the same route.
4. **No count is read from a PoshQC MCP result.** The MCP tools `run_poshqc_format`, `run_poshqc_analyze`, and `run_poshqc_test` return a summary composed before the child runs and carry no test output. The executor may run them as a supplementary check, but every count, percentage, or finding an acceptance condition reads comes from the module functions `Invoke-PoshQCFormat`, `Invoke-PoshQCAnalyze`, and `Invoke-PoshQCTest` in `scripts/powershell/PoshQC/PoshQC.psd1` (the same functions CI runs at `.github/workflows/_poshqc.yml:26`, `:36`, `:42`), or from the scoped runner R-SCOPED of section 5.
5. **Batch budget.** `.claude/hooks/enforce-powershell-batch-budget.ps1` caps Write/Edit of PowerShell files at three production and three test files per batch and counts `.psd1` as production. Each batch phase begins with a reset task that deletes every `.claude/state/powershell-batch-budget.*.json` in the worktree and appends an entry to `docs/features/active/enforcement-gates-lack-epic-level-checkpoint-seam-663/evidence/other/batch-budget-resets.md` listing the deleted file names or `none present`. Section 6 fixes the file set of each batch.
6. **Mirrors are byte copies.** Every mirror is written with `Copy-Item -LiteralPath <source> -Destination <mirror> -Force` inside a scratchpad script launched through the [P0-T6] route (or with `cp` through the Bash tool), never with Write or Edit, so it consumes no budget slot and is byte-identical by construction. Each mirror task appends the copy commands (repository-relative) and a SHA-256 pair per file to `docs/features/active/enforcement-gates-lack-epic-level-checkpoint-seam-663/evidence/other/mirror-log.md`.
7. **Porcelain scope.** After Phase 0, a clean-tree condition is always stated as "lists no path outside `docs/features/active/enforcement-gates-lack-epic-level-checkpoint-seam-663/`", never as "is empty", because each task's own artifact is uncommitted when the observation is taken. Inside a commit task the porcelain observation is taken immediately after the commit and before the append to `evidence/other/commits.md`, and is labelled `Porcelain (post-commit, pre-append):`.
8. **Commit form.** Commit tasks stage the named paths explicitly (no `-A`, no `.`), write the message to a scratchpad file, and commit with `git commit -F <SCRATCHPAD>/<name>.txt`. The message follows the session's attribution instructions. No task pushes.
9. **Diff anchor.** Every `git diff` is anchored to `origin/main`. [P0-T3] records the `origin/main` SHA; [P7-T1] confirms it is unchanged before Phase 7 and [P8-T1] before the final QC loop runs.
10. **Test names are scoped to their owning testsuite.** Every name check against a JUnit report is scoped to the testsuite matched by the owning file's repository-relative path per section 5. R-SCOPED lines carry no container; every name asserted from R-SCOPED output in this plan is unique across that run's files, except the deliberate two-file duplicates in [P1-T4] and [P1-T7], whose counts are stated.

### 2.1 Resolver module `.claude/lib/worktree-resolution/EpicScopeResolution.psm1` (new)

Module conventions (enforced by `tests/scripts/claude-lib/ClaudeLibModuleConvention.Tests.ps1`): comment-based help containing the line `CONVENTION: this module fails fast at module scope and imports its siblings with -ErrorAction Stop.` and the line `AUTHORITY: PowerShell-authoritative. The epic readiness predicates have no Python reference implementation, and no enforcement hook invokes Python (issue #663, D5).`; `Set-StrictMode -Version Latest` immediately followed by `$ErrorActionPreference = 'Stop'`; column-0 `Import-Module (Join-Path $PSScriptRoot 'WorktreeResolution.psm1') -ErrorAction Stop` and the same for `WorktreeTargetResolution.psm1`; one `Export-ModuleMember -Function` statement; an intent comment above every loop and a decision comment above every multi-branch conditional; property reads guarded with `PSObject.Properties` checks because StrictMode is on. The module performs no direct filesystem call: every read goes through the exported seams `Get-WorktreeResolutionGitEntryKind` and `Get-WorktreeResolutionGitFileText` of `WorktreeResolution.psm1` (defined at its lines 61 and 84), so tests model any topology with `Mock -ModuleName EpicScopeResolution` and create no file. The module text contains neither `Get-Content` nor `Test-Path`, including in comments. At most 400 lines.

Exported functions:

| Function | Contract |
| --- | --- |
| `Get-EpicScopeCheckpointRelativePath` | Returns the literal `artifacts/orchestration/epic-orchestrator-state.json`. |
| `Get-EpicScopeCheckpointText -Path` | Seam. Returns `Get-WorktreeResolutionGitFileText -Path $Path` when `Get-WorktreeResolutionGitEntryKind -Path $Path` is `File`, otherwise `$null`. |
| `ConvertFrom-EpicScopeCheckpointText -Text` | Pure. Parses JSON inside `try`; returns the object, or `$null` for null, empty, unparseable, or non-object text. Never throws. |
| `Get-EpicScopeWorktreeGitDirectory -WorktreeRoot` | Returns `<root>/.git` when that entry is a `Directory`; when it is a `File` whose first line is `gitdir: <target>`, returns the target (joined to the root when relative); otherwise `$null`. |
| `Get-EpicScopeWorktreeHeadBranch -WorktreeRoot` | Seam. Reads `<gitdir>/HEAD`; returns the text after `ref: refs/heads/` (trimmed), or `$null` for a detached or unreadable HEAD. |
| `Test-EpicScopeMergeInProgress -WorktreeRoot` | Seam. `$true` when `Get-WorktreeResolutionGitEntryKind -Path <gitdir>/MERGE_HEAD` is `File`. |
| `Resolve-EpicScopeCheckpoint -Text [-SessionRoot] [-WorktreeSelector] [-MatchWorktreeHead]` | Returns `[pscustomobject]` with `IsEpicScope`, `CheckpointPath`, `Checkpoint`, `WorktreeRoot`, `Branch`, `MergeInProgress`, `Reason`. `SessionRoot` defaults to `(Get-Location).ProviderPath`. Never throws for any input. |

`Resolve-EpicScopeCheckpoint` algorithm, in order (the first matching row decides):

1. `$branch = Find-WorktreeResolutionBranchSignal -Text $Text` (`WorktreeTargetResolution.psm1:164`).
2. `$branch` null and `-MatchWorktreeHead` absent: not epic scope, reason `no-branch-signal`, and **no checkpoint read**.
3. `$root = Find-WorktreeResolutionRoot -Path $SessionRoot` (`WorktreeResolution.psm1:258`); null: not epic scope, reason `session-root-unresolved`.
4. `$path = Join-WorktreeResolutionPath -WorktreeRoot $root -RepoRelativePath (Get-EpicScopeCheckpointRelativePath)` (`WorktreeTargetResolution.psm1:311`). The path is always composed from the resolved root and never read from `$Text`.
5. `$checkpoint = ConvertFrom-EpicScopeCheckpointText -Text (Get-EpicScopeCheckpointText -Path $path)`; exactly one seam read per call. Null: not epic scope, reason `epic-checkpoint-absent-or-unparseable`.
6. `route_id` not exactly `epic`: not epic scope, reason `route_id`.
7. `integration_branch` empty: not epic scope, reason `integration_branch`.
8. When `$branch` is present it decides (case-sensitive `-ceq` against `integration_branch`); `WorktreeRoot` is `$root`. Otherwise (head matching): the effective worktree is `Find-WorktreeResolutionRoot -Path $WorktreeSelector` when a selector is supplied, else `$root`; a null effective worktree is not epic scope (reason `selector-unresolved`); the match compares `Get-EpicScopeWorktreeHeadBranch -WorktreeRoot <effective>` with `integration_branch`, and `WorktreeRoot` is the effective worktree.
9. No match: not epic scope, reason `branch-mismatch`. Match: `IsEpicScope $true`, `CheckpointPath $path`, `Checkpoint` the parsed object, `Branch` the matched value; when `-MatchWorktreeHead` was supplied, `MergeInProgress = Test-EpicScopeMergeInProgress -WorktreeRoot <effective>`, otherwise `$false`.
