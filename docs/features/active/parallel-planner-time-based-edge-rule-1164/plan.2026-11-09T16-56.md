Implementation tasks run no tests; they name the cases that the final gates prove. A gate is re-run only after a fix. Test order dependence is a defect fixed on both sides.
- Failure on the branch: a failing test whose file or subject is in the merge-base diff of `origin/main` and `HEAD`; fix it and restart the QA loop from formatting.
- Failure outside the branch: a failing test whose file and subject are both absent from that diff; name it, attach the diff file list as proof, keep `EXIT_CODE:` non-zero, leave the task unchecked, and stop for the caller.
- Out of scope: the in-flight run `harness-learnings-2026-11-09` (#1156-#1163), its run folder, worktrees, and manifests (DEC-1164-3); the execution-environment brief (D8); the PR body call-outs of US-AC13, which belong to PR authoring.
