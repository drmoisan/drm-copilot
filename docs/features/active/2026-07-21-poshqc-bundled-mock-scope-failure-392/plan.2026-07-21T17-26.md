## Coverage Decision (research Testing Implications item 5)

Decision: **add `scripts/powershell/PoshQC/PoshQC.Testing.psm1` to the `CodeCoverage.Path` list** in `pester.runsettings.psd1` and its bundled mirror (Phase 2). Reasoning:

1. `.claude/rules/powershell.md` makes coverage regression on changed lines a blocking finding, and the coverage evidence contract requires numeric changed-code coverage; without the changed file in the measured set, no changed-line coverage evidence can exist for this fix.
2. This is the established repository convention: the same settings file already documents per-issue additions for issues #214, #272, #298, #305, #312, #328, #334, #344 (sibling module `PoshQC.ScanConfig.psm1`), #357, and #366.
3. The Phase 3 unit tests execute the changed default seams in-process, so the changed lines produce real, deterministic coverage rather than a 0%-covered denominator entry.
4. `CoveragePercentTarget = 0` means the addition cannot hard-fail the run; the threshold and delta evaluation is performed explicitly by P6-T4, which fails closed if the changed lines are uncovered or aggregate coverage regresses.
