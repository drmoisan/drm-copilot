## Parity Notes (binding design decisions)

- **Git executable resolution.** The Python source validates `git` via `shutil.which("git")` and invokes the resolved absolute path. F1's `CommandRunner.run(args)` treats `args[0]` as the executable and uses `spawnSync` with `shell: false`. The TS port MUST invoke git through the injected `CommandRunner` with `args[0] = "git"` (Node resolves the executable from PATH). The `shutil.which` existence pre-check is replaced by the runner's spawn-failure handling: a failed spawn yields `status === null`, which F1's `SubprocessRunner` maps to exit code 1 and (when `allowError` is false) throws. The mandatory git calls (`remote -v`, `rev-parse --abbrev-ref HEAD`, `status -sb`) use `allowError: false` (parity with Python `check=True`); all diff/log/ls-files calls use `allowError: true` (parity with Python `allow_error=True`).
- **`run_git` return semantics.** Python returns `stdout.strip()` on success and, when `allow_error=True` and the command fails, returns `e.stdout.strip()` (often empty). F1's `SubprocessRunner.run` already strips trailing newlines and returns `{ stdout, stderr, code }`; the port's `runGit` helper MUST apply a full `String.prototype.trim()` equivalent of Python `.strip()` to the returned `stdout` (leading and trailing whitespace), then return that string. When `allowError: true` and a non-zero code is returned, the port returns the (trimmed) captured stdout, matching Python's `allow_error` branch.
- **Service return contract preserved.** `collectCommitContext` MUST continue to return a `RepoAutomationExecutionResult` with `tool: "collect_commit_context"`, `workspaceRoot: input.workspaceRoot`, `summary: "Collected commit context into artifacts/commit_context.txt."`, and `artifacts: [normalizeGeneratedPath(path.join(input.workspaceRoot, "artifacts/commit_context.txt"))]`. The output path written by the TS function is `path.join(input.workspaceRoot, "artifacts/commit_context.txt")` (replacing the Python `--output` argument and the spawn `cwd`). The git commands run with `cwd: input.workspaceRoot`.
- **Filesystem writes.** Directory creation (Python `output_path.parent.mkdir(parents=True, exist_ok=True)`) and the file write use the injected `FileSystem`. The F1 `FileSystem` interface exposes `writeTextFile` but no `mkdir`/`ensureDir`. The port MUST add a parent-directory-ensuring write path. Preferred approach (in priority order, choose the first that satisfies hermeticity and the 500-line limit): (a) extend the `FileSystem` interface in `src/lib/file-system.ts` with a `ensureDir(path: string): void` method, implement it on `RealFileSystem` via `fs.mkdirSync(path, { recursive: true })`, and have the in-memory test fake record created directories; or (b) if extending the shared interface is undesirable for F4 scope, have `RealFileSystem.writeTextFile` callers ensure the directory by adding `ensureDir` only. Decision: take approach (a) — extend `FileSystem` with `ensureDir` and implement on `RealFileSystem` — because the Python contract creates parent directories and an injected fake must observe that call for the `creates_parent_directories` parity test. Adding one method to the shared F1 interface is the minimal seam; this is the only permitted edit to `file-system.ts` in F4.
- **Printed line.** Python prints `Commit context written to: <output_path>` to stdout. The TS function MUST emit the same line through the injected output sink. Use the existing `CommandOutput` channel available to the service (`this.output.appendLine` or equivalent), OR return the message and let the service emit it. Decision: the pure `collectCommitContext` library function accepts an optional `log?: (message: string) => void` callback and calls it with `Commit context written to: <absolutePosixOutputPath>`; the service passes `this.output.appendLine` bound appropriately. The library function does not call `console.log` directly (no ad-hoc stdout per `.claude/rules/python.md`/general-code-change logging policy).
