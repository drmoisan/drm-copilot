## Design Summary

A new pure file `hook-epic-fan-in.ps1`, byte-identical at `.claude/hooks/`, `.codex/hooks/`, `extensions/drm-copilot/resources/claude-customizations/.claude/hooks/`, and `extensions/drm-copilot/resources/codex-and-agents-customizations/.codex/hooks/`, defines `Test-EpicFanInComplete`, `Get-EpicFanInStatusDocRelativePath`, `Test-EpicFanInWriteRelativePath`, `Test-EpicFanInCommitShape`, and `Get-EpicFanInAllowance` with the contracts in `spec.md` `### Technical specifications (interfaces/contracts):`. Each surface's `enforce-orchestration-preimplementation-gate-epic-scope.ps1` dot-sources it in a guarded single-statement `try`/`catch` calling `Add-HookDependencyFailure`, and the readiness scriptblock inside `Get-OrchestrationEpicScopeDecision` returns `''` only when `Get-EpicCommandLegReadinessFailure` returns exactly `merge-in-progress`, `Test-EpicFanInComplete -Checkpoint $Scope.Checkpoint -Branch $Scope.Branch` holds, and `(Get-EpicFanInAllowance -Scope $Scope -FilePath <paths> -Command <text> -StagedIndexReader <reader>).Allowed` is true; otherwise it returns the original failure unchanged. `-FilePath` is `[string[]]`: blank entries are ignored, and when any non-blank entry remains the call is a path leg in which every entry must convert and be allowlisted. The Claude scriptblock passes `-FilePath @($FilePath) -Command $epicScopeText`. The Codex scriptblock passes `-FilePath $legPaths -Command $legCommand`, so an `apply_patch` leg (patch body moved out of `$legCommand`, one or more marker paths in `$legPaths`) is judged on every marker path, and a command leg (`$legPaths` holding only the blank `$FilePath`) is judged on `$legCommand`. The reader wraps the existing `Get-OrchestrationGateStagedIndex -WorktreeRoot` seam (cleanup file, both surfaces), whose `ExitCode`/`Output` shape the allowance consumes. `Get-EpicFanInAllowance` takes an already-resolved scope object (the `Resolve-EpicScopeCheckpoint` result shape) plus the reader, which is the extension seam for follow-up findings 3 and 9; neither follow-up is implemented here.
