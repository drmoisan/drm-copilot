## 2. Design decisions and interpretations

1. **Manifest grammar and matcher** follow spec "Manifest grammar" exactly. A wildcard-free entry `E` matches candidate `C` when `C == E.rstrip("/")` or `C` starts with `E.rstrip("/") + "/"`, so `foo/bar` and `foo/bar/` match the same set; the normalized form keeps the trailing `/` the author wrote and `kind` is `directory` when it is present, `exact` otherwise. A wildcard entry (`*` or `?` present) is compiled with the `_blast_radius_glob.py` rule (`scripts/dev_tools/_blast_radius_glob.py:74-118`, `:121-137`): `**` to `.*`, `*` to `[^/]*`, `?` to `[^/]`, every other character escaped, full match. Python imports `matches_glob` from `scripts.dev_tools._blast_radius_glob`; TypeScript ports the same translation into `claude-exclusion-manifest.ts` and does not reuse `lib/file-system.ts` `compileGlob`.
2. **Normalization** of an entry: strip a leading U+FEFF from the manifest text once, then per entry trim surrounding whitespace, convert `\` to `/`, strip one leading `./`, collapse repeated `/`. Normalization is idempotent (property P4).
3. **Unmatched entries** are the manifest entries that are the first match of no skipped path (including the `.gitignore` skip in TypeScript). Consequence: the set of `entry` values in `skipped` and the `unmatched_entries` list are disjoint and their union is `entries`, so the report is self-consistent, and a shadowed entry (one that would match a path that an earlier entry already claimed) is reported as unmatched. Plan-corpus case `shadowed-entry-is-unmatched` pins this.
4. **Line numbers** are 1-based over the manifest text after BOM removal, counting comment and blank lines, split on `\r\n` or `\n`.
5. **Malformed conditions** and their detection point: directory at the manifest path (`isDir` true and `isFile` false; TypeScript `readExclusionManifest`, Python `read_exclusion_manifest`); undecodable text (Python wraps `UnicodeDecodeError` from `read_text`, `scripts/dev_tools/push_down_copilot_customizations_filesystem.py:171` reads with `encoding="utf-8"`; TypeScript rejects an entry containing U+FFFD); empty after normalization; absolute (`/` prefix or a drive prefix matching `^[A-Za-z]:`); a `..` segment; `!` prefix; `[` or `]`; wildcard plus trailing `/`. Each raises `ExclusionManifestError` whose `path` is the manifest relative path `.push-down-exclusions`, whose `line` is the offending line (`None` / `undefined` for the directory and undecodable cases), and whose message contains the path and, when a line applies, the text `line <n>`.
6. **Composition.** TypeScript: `readExclusionManifest(fs, destinationRoot)` runs in `pushDownCustomizations` (`extensions/drm-copilot/src/lib/push-down/claude-customizations.ts:239-322`) immediately after `effectiveBundle` is computed (`:260-261`) and before `resolvePublishedPaths` (`:265`); when it returns a manifest, `new ExclusionFilterFileSystem(excludingFs, effectiveSource, destinationRoot, manifest)` wraps the `ExcludingFileSystem` built at `:294-306` and is the `fs` passed to the engine at `:311`; when it returns `undefined`, `excludingFs` is passed unchanged. Python: `read_exclusion_manifest(fs, destination_root)` runs in `push_down_customizations` after `effective_bundle` is computed and before `_resolve_published_paths`; when it returns a manifest, `ExclusionFilterFileSystem(<the object currently passed as fs= to push_down_scoped_customizations>, effective_source, destination_root, manifest)` becomes that argument. The filter is therefore outermost regardless of which merge or derive decorators #507 and #508 add beneath `ExcludingFileSystem`.
7. **Destination-relative path of an enumerated source file** is the source-relative POSIX path, computed as `ExcludingFileSystem` computes it (`extensions/drm-copilot/src/lib/push-down/claude-filesystem-adapter.ts:169-171`; Python `path.relative_to(source_root).as_posix()`), because the engines derive the destination path from exactly that value (`extensions/drm-copilot/src/lib/push-down/copilot-customizations-engine.ts:381-386`). The destination-presence probe is `inner.isFile(<destinationRoot>/<relative>)` / `inner.is_file(destination_root / relative)` at enumeration time.
8. **Write guard.** `ExclusionFilterFileSystem.writeTextFile` / `write_text` computes the destination-relative target (`relativeToPosix(path, destinationRoot)`; Python `path.relative_to(destination_root).as_posix()`, with a target outside the destination root passed through) and raises `ExclusionViolationError` when it equals `EXCLUSION_MANIFEST_RELATIVE_PATH` or matches any manifest entry; otherwise it delegates to the inner adapter. A target whose destination-relative path begins with `ARTIFACT_DIRECTORY + "/"` (`artifacts/claude-customizations/`; `extensions/drm-copilot/src/lib/push-down/claude-customizations.ts:43`, `scripts/dev_tools/push_down_claude_customizations.py:99`) is passed through unconditionally; the artifact is not subject to the manifest (spec "Summary artifact"), and an entry matching it is reported as unmatched by item 3. This exemption is required because the engine writes the artifact through the enumerating adapter (`extensions/drm-copilot/src/lib/push-down/copilot-customizations-engine.ts:441`, `scripts/dev_tools/push_down_copilot_customizations.py:420`) and the service call sets `artifactRoot` to `destinationRoot` (`extensions/drm-copilot/src/lib/push-down/push-down-service-call.ts:185`), so without it an entry such as `artifacts/**` would make the guard raise on the artifact write.
9. **Report assembly and artifact.** `buildExclusionReport(manifest, skipped)` / `build_exclusion_report(manifest, skipped)` produce `ExclusionReport { manifestPath, entries, skipped, unmatchedEntries }` (Python frozen dataclass with `skipped_count` and `conflict_count` properties). `appendExclusionsToArtifact(fs, artifactPath, report)` / `append_exclusions_to_artifact(fs, artifact_path, report)` read the artifact the engine wrote, parse it, add the `exclusions` object with keys `conflict_count`, `entries`, `manifest_path`, `skipped`, `skipped_count`, `unmatched_entries` (each `skipped` element with keys `destination_status`, `entry`, `line`, `relative_path`), and rewrite it with `stringifySorted(payload, 2)` (exported from `copilot-customizations-engine.ts:283` by adding `export`) / `json.dumps(payload, indent=2, sort_keys=True)`. This runs only when a manifest was read, so the absent-manifest run performs exactly one artifact write.
10. **Returned summary.** TypeScript `export interface ClaudePushDownSummary extends PushDownSummary { readonly exclusions?: ExclusionReport }` in `claude-customizations.ts`; `pushDownCustomizations` returns the engine summary unchanged when no manifest was read and `{ ...summary, exclusions: report }` otherwise. Python `@dataclass(frozen=True, slots=True) class ClaudePushDownSummary(PushDownSummary)` with `exclusions: ExclusionReport | None = None` in `push_down_claude_exclusion_filter.py`, re-exported from `push_down_claude_customizations.py`; `push_down_customizations` returns `ClaudePushDownSummary` built from the engine summary's fields (`dataclasses.fields`) plus `exclusions`, which is `None` when no manifest was read.
11. **Line rendering.** `renderExclusionLines(report)` / `render_exclusion_lines(report)` return, in order, one line per `skipped` element in enumeration order (`push-down exclusion: skipped <path> (entry <normalized>, line <n>)` for `absent`, `push-down exclusion conflict: destination file present, not overwritten: <path> (entry <normalized>, line <n>)` for `present`), then one line per unmatched entry in manifest order (`push-down exclusion: entry matched no payload path: <normalized> (line <n>)`). `EXCLUSION_CONFLICT_LINE_PREFIX = "push-down exclusion conflict:"` is exported from `claude-exclusion-filter.ts` and is the only mechanism by which the VS Code command counts conflicts.
