## Pinned Composition Semantics (both languages, identical)

These pin the spec rules 1 to 13 (spec `## Proposed Fix`) to one algorithm so the TypeScript and Python outputs are byte-identical. Let `B` be the base document text and `O` the overlay text.

1. `O` absent (`null` / `None`): return the base text unchanged, byte for byte (no parse, no re-serialization).
2. Parse `O`. Unparseable text, or a root that is not a JSON object, raises `BlastRadiusOverlayError(overlayPath, detail)`. Python parsing rejects `NaN`, `Infinity`, and `-Infinity` as unparseable (via `parse_constant`), matching `JSON.parse`. Parse `B`; an unparseable base or non-object base raises `BlastRadiusOverlayError` with path `config/blast-radius.json`.
3. `version`: if `O` has `version` and it is not equal to `B.version`, raise `BlastRadiusOverlayError` naming key `version`. Equality is type-strict: in Python a `bool` never equals an `int` (matching TypeScript `!==`). The composed `version` is always `B.version`.
4. String-list keys `shared_surfaces`, `shared_surface_globs`, `mandate_reads`, `mergeable_paths`, `path_roots`: an `O` value that is not a list, or that has a non-string member, raises `BlastRadiusOverlayError` naming the key. Composed value: `B` entries in `B` order, then `O` entries not already present, in `O` order, with duplicates inside `O` removed. When `B` lacks the key, the value is the deduplicated `O` list, emitted per rule 7.
5. `modules`: an `O` value that is not a JSON object, or a module value that is not a list of strings, raises `BlastRadiusOverlayError` naming key `modules`. Each `O` module absent from `B` is added; each `O` module present in `B` replaces that module's glob list. Module names are emitted in ordinal (code-unit) order. The forbidden-glob guard then scans the composed map in emitted order and raises `BlastRadiusGuardError(moduleName, glob)` for the first glob in `FORBIDDEN_GLOBS` (`**`, `docs/**`, `tests/**`).
6. Any other key present in both: `merge(b, o)` where both JSON objects: members in `b` order merged recursively, then `o`-only members appended in `o` order; both lists: string ordered union as in rule 4 (a non-string member raises `BlastRadiusOverlayError` naming the dotted key, for example `conflict_tolerance.append_only_paths`); otherwise the `o` value wins. This covers `conflict_tolerance` (rule 6 of the spec) and the scalars `over_breadth_fraction` and `write_intent_extraction` (spec rule 7).
7. Keys only in `O`: appended after all `B` keys, in `O` order (validated by rules 4 and 5 when they are string-list keys or `modules`).
8. Serialization when `O` is present: TypeScript `JSON.stringify(value, null, 2) + "\n"`; Python `json.dumps(value, indent=2, ensure_ascii=False) + "\n"`.
9. Every error is raised before any write, so the destination main file keeps its prior bytes.
10. Error message shape (both languages): `Blast-radius overlay <overlayPath> was not applied; config/blast-radius.json was not written: <detail>`, where `<detail>` names the offending key when one applies.
