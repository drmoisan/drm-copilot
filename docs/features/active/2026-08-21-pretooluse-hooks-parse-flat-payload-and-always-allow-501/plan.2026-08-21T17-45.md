## Plan Overview

Requirements source of record: `docs/features/active/2026-08-21-pretooluse-hooks-parse-flat-payload-and-always-allow-501/spec.md` (`## Acceptance Criteria`, AC-1 through AC-14). Where the issue and the research disagree, the research is authoritative.

The fix has three mandatory legs, and no phase may drop any of them:

1. **Transport** — a shared payload reader at `.claude/lib/hook-payload/HookPayload.psm1`, stdin-first (`[Console]::In.ReadToEnd()` behind an injectable scriptblock seam per the `persist-session-id.ps1` precedent), falling back to `$env:CLAUDE_HOOK_INPUT` then `$env:CLAUDE_TOOL_INPUT`; first non-whitespace source wins.
2. **Shape** — tool arguments extracted strictly from the envelope's nested `tool_input` object; no flat-root fallback.
3. **Fail-closed anomalies** — an empty payload, unparseable JSON, or a parsed payload with no `tool_input` key produces an emitted deny JSON with process exit code 0 (or exit code 2), never exit 1. Exit 1 is non-blocking, so the current `throw` path is itself a fail-open.

Deliberate exceptions preserved, not "fixed": `validate-bash.ps1` keeps allow-on-empty and keeps treating unparseable raw text as command text (AC-5); property-level absence inside a well-formed `tool_input` keeps its allow early-return, because those are per-hook scope filters (AC-6).

Notational shorthand used throughout: `FEATURE/` denotes `docs/features/active/2026-08-21-pretooluse-hooks-parse-flat-payload-and-always-allow-501/`, and `MIRROR/` denotes `extensions/drm-copilot/resources/claude-customizations/.claude/`. All evidence artifacts go under `FEATURE/evidence/<kind>/` (canonical scheme; `artifacts/` evidence paths are invalid). Every command-step evidence artifact must carry `Timestamp:`, `Command:`, `EXIT_CODE:`, and `Output Summary:`; test-step artifacts must carry numeric coverage headline values in `Output Summary:`. Evidence artifact filenames use the ISO-8601 `yyyy-MM-ddTHH-mm` prefix per repository conventions.

**Fail-closed evidence rule:** if any required baseline artifact, QA artifact, or coverage-comparison artifact is missing, the audit verdict must be BLOCKED or INCOMPLETE, never PASS.

**Mirror rule (mechanically enforced):** every changed file under `.claude/hooks/` or `.claude/lib/` must be copied byte-identically to its `MIRROR/` counterpart in the same commit as the original; `test_bundled_claude_payload_contains_all_repo_runtime_contracts` in `tests/scripts/dev_tools/test_push_down_claude_resource_contracts.py` fails otherwise. Perform mirror copies with a file-copy command (for example `Copy-Item`), not editor writes, so migration batches stay inside the PowerShell batch budget (at most 3 production files and 3 test files edited per batch). If the format stage later reformats any hook or the module, re-copy the reformatted file to `MIRROR/` before re-running the mirror-parity pytest.

**Hard scope boundaries (AC-13):** no change to any path under `.codex/hooks/`, and no change to the eight SubagentStop validators (`validate-discovery-artifact-gate.ps1`, `validate-executor-output.ps1`, `validate-feature-review-coverage.ps1`, `validate-orchestrator-output.ps1`, `validate-planner-output.ps1`, `validate-pr-author-output.ps1`, `validate-required-artifact-output.ps1`, `validate-task-researcher-output.ps1`) or their test suites. No Python in any enforcement hook or in the shared module (Pester/pytest test code may parse `.claude/settings.json`). Research concluded no `.claude/settings.json` change is needed; if implementation discovers one is required, it is permitted — record the deviation in `spec.md` and mirror the file per the mirror rule.

Languages in scope: PowerShell (production + tests; coverage policy applies: line coverage >= 85%, no branch gate, no production file excluded from the denominator). Python production code is not modified; the single pytest guard runs as a named-test gate without a Python coverage obligation.
