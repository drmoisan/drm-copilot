2. **The Python side is the reference.** The TypeScript port reproduces `validate_cohort_barrier_ordering` behavior exactly, including: the module constants `ITEM_START_TIMESTAMP_FIELD = "worktree_created_at"` and `MERGE_CONFIRMATION_TIMESTAMP_FIELD = "merged_at"`; the barrier-satisfying set `{merged, worktree_removed}` (`ci_green` does NOT satisfy the barrier); the current-generation cohort projection (rows whose `generation` equals the top-level `recolor_generation`); the structural reading (both endpoints share a current-generation cohort index); the temporal reading; the degrade-to-structural-plus-status rule whenever either timestamp is absent or is not a string; and the byte-exact message form `PARALLEL_COHORT_BARRIER_VIOLATION: <a> ran concurrently with conflicting <b>` with `<a>` the earlier or first endpoint, NO context prefix, and NO trailing period.
3. **No checkpoint schema field is added.** Layer 2 validates existing F3-defined fields only. The nine parallel-surface enums are F3-owned: consume, never extend.
4. **Mandatory parity binding.** This epic has shipped the producer/consumer divergence defect twice at 100% per-side coverage, and B-1 is a third instance. Per-side coverage is blind to divergence. The two runtimes must therefore be bound against a SHARED set of constructed documents that carries the expected error strings once, and both suites must assert against that single artifact. Two independent per-side suites are not acceptable, because they can drift. The mechanism is the repository's established cross-language parity pattern: a committed JSON corpus asserted by both runtimes, exactly as `tests/scripts/dev_tools/test_blast_radius_parity.py` and `tests/scripts/claude-lib/blast-radius/BlastRadius.Parity.Tests.ps1` pin the Python and PowerShell blast-radius implementations to `tests/fixtures/blast_radius/*.json`. Neither suite can relax an expectation without the other observing the change.
5. **Seam must be parsed at run time.** Every new TypeScript test exercises the invariant THROUGH the dispatched public entry point `validateArtifact({ artifactType: "parallel-orchestrator-state", text })` from `extensions/drm-copilot/src/lib/validate/orchestration-artifacts.ts`. No new TypeScript test imports `parallel-orchestrator-state-cohort-barrier` directly. This mirrors the binding discipline the Python suite already demonstrates (it imports only `validate_parallel_orchestrator_state_text`), and it is what makes the seam edit itself load-bearing on every test run.
6. **Parity claim scope.** The parity claim covers barrier messages only: both runtimes filter validator output to the strings beginning with the literal token `PARALLEL_COHORT_BARRIER_VIOLATION` before comparison, and the corpus records only that filtered list. Corpus documents are restricted to JSON-representable values that round-trip through both runtimes' native types, exactly as F3's verified scope was (96 of 96 error strings across 43 constructed documents). The three divergence classes recorded in `.claude/rules/parallel-orchestration.md` — `pythonRepr` quote selection, integral floats erased by `JSON.parse`, and boolean/integer equality (`===` versus Python's `True == 1`) — are accommodated by staying outside them, NOT fixed: no corpus document may use an integral float where an integer is meaningful, a boolean where an integer is meaningful, or a string containing a single quote. All corpus timestamps are ASCII ISO-8601 strings, so ordinal string comparison agrees between the two runtimes.
7. **Evidence schema.** Every command-bearing task records `Timestamp:`, `Command:`, `EXIT_CODE:`, and `Output Summary:`. Test evidence records numeric line coverage and numeric branch coverage. Pester evidence records passed, failed, and skipped counts separately (the reported total must reconcile) and names the single pre-existing failure. Evidence paths resolve only to `docs/features/active/2026-08-07-parallel-enforcement-hooks-440/evidence/<kind>/` with `<kind>` in `remediation-baseline`, `regression-testing`, `qa-gates`. `artifacts/`-rooted evidence paths are forbidden. Timestamps use `yyyy-MM-ddTHH-mm`.
8. **No SKIPPED.** Every command-bearing task must execute its stated command and record the result. `EXIT_CODE: SKIPPED` is not a passing outcome. No task in this plan authorizes a skip branch.
9. **Toolchain restart rule.** If any formatting, lint, type-check, or test step fails or changes a file, restart the applicable language loop from its formatting step and repeat until a clean single pass completes.
10. **File size limit.** No new or modified production, test, or reusable script file may exceed 500 lines.
11. **No suppressions.** No `// eslint-disable*`, `// @ts-expect-error`, `// @ts-ignore`, `# noqa`, or `# type: ignore` may be added. Any need for one halts the task for re-planning.
