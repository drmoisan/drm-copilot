- PS-STEP (how every PowerShell step runs): the worktree isolation guard refuses `pwsh` typed directly into the Bash tool, but permits `sh <file>.sh`. For a task that names `PS-STEP <task-id>`, the executor (a) writes the PowerShell body verbatim to `SCRATCH/930/<task-id>.ps1` with the Write tool, (b) writes a two-line wrapper `SCRATCH/930/<task-id>.sh` with the Write tool, whose first line is `cd "$(git rev-parse --show-toplevel)"` and whose second line is `pwsh -NoProfile -NonInteractive -File SCRATCH/930/<task-id>.ps1`, so relative paths resolve from the worktree root regardless of the caller's directory, and (c) runs `sh SCRATCH/930/<task-id>.sh` from the worktree root. Because the wrapper changes to the worktree root, in-body helper calls use the single spelling `& ./SCRATCH/930/<helper>.ps1`. Heredocs are blocked, so these files are created with the Write tool only. A body that calls a helper ends with `exit $LASTEXITCODE` so the wrapper propagates the helper exit code. The evidence `Command:` field records the PowerShell body (or the `.ps1` path plus a summary of its content).
- `SCRATCH/` is NOT gitignored in this repository. Files under `SCRATCH/930/` are never staged or committed: no `git add` of any SCRATCH path is run. Every `git status --porcelain` scope check in this plan either excludes `SCRATCH/` or explicitly expects the line `?? SCRATCH/` once the first scratch file exists (after P0-T4).
