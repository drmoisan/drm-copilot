## Planner Decisions

- RP-1 (design). No existing seam names the repository-root entries: `TestFile` returns a boolean that is case-insensitive on Windows and default macOS, and `ListFile` rejects the empty path (`Test-DocsRelativePath`) and lists recursively. `Read-DocsFamilyEvidence` therefore keeps its signature and its `TestFile` probes, and confirms each positive probe against one `ListFile` call with the empty path, keeping a name only when the root listing contains it under `[System.StringComparer]::Ordinal`. No root listing is made when both probes are negative.
- RP-2 (required change outside the module). `Get-DocsContextFileList` in `.claude/lib/docs/Invoke-DocsCommand.ps1` gains one branch: an empty `RelativeRoot` returns the file names of the repository root only (top directory, ordinal-sorted); every other value is unchanged. A recursive listing of the root is rejected because it enumerates `.git`, dependency trees, and nested worktrees on every docs-complete run. No context member is added, so `New-DocsCommandContext` keeps its member set. The spec `## File Inventory` "Not edited" sentence is amended in place to record this edit.
- RP-3 (spec). D7 gains the ordinal-comparison sentence; the `### Family evidence` root-file bullet and the "Not edited" sentence are amended in place so the spec matches the code. No acceptance-criterion line changes.
- RP-4 (generator). No generated surface is touched (`.claude/lib/docs` is not a harness-generation target), so the harness generator `-Check` is not run; P1-T9 records this as N/A with the reason.

Mitigation: P1-T5 amends all three spec statements in place; P1-T1 and P1-T2 test both empty-path branches; P1-T1, P1-T3, and P1-T4 name every affected test; P1-T9 walks the three templates.

- Test isolation: a seam helper defined at script scope or a module left loaded could leak. Mitigation: helpers live in `BeforeAll`, each case builds its own seam, no temporary file is created, and the real-context case reads committed files only. Runs are one launcher `pester` run with `-TestPath` per check (`Invoke-PoshQCParallelTest`) and one launcher `pytest` run (`pytest -n auto`) over the four files, each re-run only after a fix; Jest is not in scope.
- CI-only behavior: the defect itself is host-dependent (Windows `windows-latest` shards versus the case-sensitive Linux hook job), so a test that relied on the real file system would pass or fail by host. Mitigation: the root-file cases use the in-memory seam, whose case behavior is fixed by the test, so they give the same result on every runner; the real-context case asserts only committed root files (`README.md`, `AGENTS.md`), present in every CI checkout, and exact-case names with forward-slash-free entries.
- Evidence: shared artifact names could select an evidence file of the original plan. Mitigation: every file carries `Plan:` and the write-time stamp, so the newest file is this cycle's; counts come from launcher-run JUnit and coverage files, never MCP summaries; evidence is append-only.
