## Executive Summary

The branch adds a planner allow branch to the three worktree-removal gates (`.claude/hooks/enforce-epic-worktree-removal-gate.ps1`, `.claude/hooks/enforce-parallel-worktree-removal-gate.ps1`, `.codex/hooks/enforce-epic-worktree-removal-gate.ps1`). The branch is a byte-identical pure helper `hook-planner-worktree-removal.ps1` behind a Claude adapter and a Codex adapter. It also adds key-gated validation of `planner_worktrees` to the Python and TypeScript epic-planner validators, a 21-file shared corpus, the recording protocol in both epic-plan skills and both epic-planner agents, and a planner sentence in the parallel-orchestrate skill and rule.

Remediation cycle 1 addressed PA-1. Both validators now apply one explicit blank set to `recorded_at`: Python `_RECORDED_AT_BLANK_CHARS = " \t\n\r\x0b\x0c"` with `str.strip(chars)`, and TypeScript `RECORDED_AT_BLANK = /^[ \t\n\r\v\f]*$/`. Four corpus files pin the set, and the spec `### Field shape` row names the six code points. The cycle changed no PowerShell file, mirror, manifest, or Jest configuration.

The reviewer verified the following directly at head:
- Cross-runtime probe: an esbuild bundle of the head TypeScript module and the head Python function were each called on 65596 single-entry checkpoints. The values were every UTF-16 code unit U+0000 to U+FFFF as a one-character `recorded_at`, four astral code points, 47 multi-character strings (all 36 ordered pairs of blank-set characters among them), and 9 non-string values. The two runtimes returned identical error lists for all 65596 values. Exactly 54 values are rejected: the six blank-set characters, the empty string, the multi-character blank strings, and the non-string values.
- Mutant discrimination: replacing the blank set with the native `str.strip()` makes the `recorded-at-unit-separator` and `recorded-at-next-line` rows fail in Python. Replacing it with native `trim()` makes `recorded-at-byte-order-mark` fail in TypeScript. Dropping any one of the six characters from either runtime makes `blank-recorded-at-ascii-controls` fail, because that value holds each blank character and stripping stops at the first non-member. The first two results agree with the executor's fail-before record `evidence/regression-testing/recorded-at-fail-before.2026-11-14T01-01.md` (ExpectedExitCode 1).
- `validate_evidence_locations --root <item worktree>` exits 0.
- `origin/main` after a fetch equals the merge base, so there is no base drift.

No blocking finding remains. CI on PR head `b7913c32c` was in progress at review time (Python quality checks, PowerShell QC, shell coverage, extension and root TypeScript tests); the completed checks are green. CI is a pending-CI item owned by the S9 gate, not a finding.
