## Design decisions fixed by this plan

- **One pattern, one statement, one rule token.** All cycle 1 spellings are added as alternatives to the existing `OrchestrationTargetNonLocalPattern`, which the existing first statement of the R1 loop (`if ($rawPath -match $script:OrchestrationTargetNonLocalPattern)`, canonical line 228 at HEAD) already tests against the raw input. No new statement, branch, function, or reason code is added. The result stays `New-OrchestrationTargetResult -Rule 'path-not-local' -Value $rawPath`. `ConvertTo-OrchestrationTargetPath`, `OrchestrationTargetAbsolutePattern` (canonical line 36), R0, R2 to R7, and the R6 `-C` leg are not edited (spec Non-Goals).
- **New pattern (replaces canonical lines 38 to 40 at HEAD; split with `+` because one line would exceed 120 characters, following the shape of `OrchestrationTargetRelocationPattern` at canonical lines 32 and 33):** `'^(?:\s|[\\/]{2}|[\\/]\?\?[\\/]|\\(?![\\/])|[A-Za-z]:(?![\\/])|file:|~)|\s$'`. Alternatives added in this cycle: `\s` after `^` and the top-level `\s$` (RI-2), `\\(?![\\/])` (RI-5), `file:` and `~` (RI-4). PowerShell `-match` is case-insensitive, so `FILE:` also matches.
- **RI-2 guard choice and justification.** Deny any path-leg input whose raw value begins or ends with whitespace (`^\s` and `\s$`), not only leading space before a non-local prefix. Reasons: (1) a leading space before any spelling, local or not, defeats both anchored patterns and sends the input to the relative fallback (canonical line 232), which is the session-root misresolution class #937 fixes (for example `' /wt/a.ps1'` currently resolves to the session root); (2) neither in-repo caller produces surrounding whitespace, because the Claude and Codex gates read `file_path` through `Get-StringProperty`, which returns `([string]$Value.$Name).Trim()` (`.claude/hooks/enforce-orchestration-preimplementation-gate.ps1` line 73; `.codex/hooks/enforce-orchestration-preimplementation-gate.ps1` line 80), and `Get-OrchestrationPatchMarkerPath` trims every marker path (canonical line 89), so the guard costs no legitimate input and makes the function's contract independent of caller trimming; (3) a regex alternative keeps the R1 loop at one guard statement, whereas a separate `$rawPath -cne $rawPath.Trim()` statement would add a second branch and three lines for the same outcome; (4) the orchestrator disposition names "surrounding whitespace". Because both gates trim, the RI-2 defect is reachable only at the function contract, so RI-2 is proven by unit rows on both surfaces and needs no gate row (a gate row would pass before and after).
- **RI-4.** `file:` covers `file:///C:/...` and `file://server/...`; `~` covers `~/...`, `~\...`, and `~user/...`. A narrower `file:` literal is used instead of a general URI-scheme alternative so that no relative path containing a colon outside position 1 changes behavior beyond the orchestrator's stated scope. A Windows 8.3 short name (`C:\PROGRA~1\...`) is unaffected because the `~` alternative is anchored at position 0.
- **RI-5.** `\\(?![\\/])` matches a raw value that begins with exactly one backslash (`\wt\a.ps1`, and bare `\`), which on Windows is rooted at the current drive and cannot be resolved to a local absolute path deterministically. A value beginning with one forward slash (`/wt/a.ps1`) matches no alternative and keeps resolving to itself (U01 and the cycle 0 gate row `denies a Write into a not-ready epic worktree` stay unchanged and passing). `OrchestrationTargetAbsolutePattern` is not edited.
- **RI-3.** U30 gains `@($result.Targets).Count` 0, `ReasonCode` `target-unresolvable`, and an exact `Detail` assertion; its existing `-Because` text is kept.
- **RI-6 wrap method.** Values, row names, and `-Because` text are unchanged. A `Should` line over 120 characters moves its unchanged `-Because` string into a local (`$resolvedBecause` or `$detailBecause`) assigned on the line above. A gate data row over 120 characters becomes a multi-line hashtable with one key per line, `=` aligned as `scripts/powershell/PoshQC/settings/pssa.settings.psd1` requires (`PSAlignAssignmentStatement` with `CheckHashtable = $true`, lines 37 to 40); a Codex patch-text value is split with `+` into two string literals whose concatenation is byte-identical to the original value.
- **Existing-row safety (RI-5 requirement, also RI-2 and RI-4).** P0-T6 statically classifies every path-leg literal of the three edited test files and the C1bCoverage and Parity suites against the old and new patterns and must find no existing literal that only the new pattern denies; the CI runs of P1-T18 and P3-T11 then confirm behavior across every hook suite.
