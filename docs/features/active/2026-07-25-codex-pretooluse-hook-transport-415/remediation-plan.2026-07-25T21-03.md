## Recorded Interpretations

- **RI-1 — Residual documentation is an already-passing case, never a substitute threshold (preflight RC-3, RC-10).** For a guarded hook whose raw per-file line percentage is below 85%, the evidence documents the transparent residual computation `covered / (instrumented − justified-guarded-entrypoint instrumented)` with the contributing line ranges. The residual denominator may exclude ONLY post-guard lines that carry the C6 per-line justification (an attempted in-process entrypoint case per C6 plus a named per-line reason); any post-guard line without that justification stays in the denominator. The residual number itself MUST be >= 85%. The computation exists to document, for the re-audit, a case that already passes once justifiably unreachable entrypoint lines are identified — it is never a mechanism to adjudicate a failing number, and no ~54%-class residual may be recorded as adjudicated. If any hook's residual is below 85% after all three gap-closure batches (Phases 2–4), the verification task (P4-T3) is FAILED and the plan outcome is remediation-required per RI-4. Removing files from measurement, lowering thresholds, and denominator adjustments are prohibited in all cases.
- **RI-2 — Batch accounting.** The runsettings edit is a mirrored pair (root + bundle) counted as 2 production PowerShell files against the Phase 1 per-batch cap (preflight RC-1); both are `.psd1` configuration data files. `.gitignore` is a non-PowerShell, non-Python file outside both language budgets.
