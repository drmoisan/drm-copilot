## Fixed Design (CR-1 and CR-2)

`Get-CodexReviewPolicyAuditPath -Message` keeps its name, parameters, and return shape (`Paths`, `ReasonCode`, `Reason`). Its extraction changes as follows.

- **Candidate sources**, all evaluated, merged in first-seen order and de-duplicated by ordinal comparison:
  1. Label remainder: for each message line containing `policy-audit-path:`, the text after the label to the end of that line (never across a line break), trimmed, with one pair of surrounding backticks or quotes removed. Spaces inside the remainder are kept.
  2. Span content: the content of each single-line backtick, single-quote, or double-quote span that contains `docs/features/active/`. Spaces inside are kept.
  3. The existing whitespace-delimited token scan, with its trailing guard relaxed so that `.`, `,`, `:`, and `;` may follow `.md` (the punctuation is not part of the token).
- **Normalization** of every candidate: backslashes become `/`, runs of `/` collapse to one, and trailing `.`, `,`, `:`, `;` after `.md` are stripped before the shape test (resolution item 3).
- **Eligibility:** a candidate is examined only when it contains `docs/features/active/` exactly once. A label remainder or span holding two audit paths is therefore not taken as one path; the token scan (source 3) still extracts both.
- **CR-2 order:** for every eligible candidate, a `..` segment in the candidate yields `AUDIT_PATH_TRAVERSAL` with the existing reason text (it names the `'..' segment`) before the shape test runs, so `docs/features/active/<folder>/../other/policy-audit.<ts>.md` reports the traversal code.
- **Unchanged:** the shape pattern, the prefix rule (empty, `./`, or an absolute prefix is kept; any other prefix is dropped, which discards the fragment `root/repo/docs/...` that source 3 yields from a root containing a space), the `Paths` output form, and `Select-CodexReviewPolicyAudit` and `Resolve-CodexReviewCoverageTarget`.
