## Execution conventions

- **Shells.** Commands shown as `pwsh -NoProfile -Command '...'` run from the PowerShell tool with the process working directory at the worktree root. Commands shown as `grep`, `wc`, or `git` run from either tool. Plain `grep` is used for every search, never `git grep`, because the new test file is untracked until commit.
- **Merge-base anchor.** `[P0-T3]` records the merge-base commit SHA as `MergeBase:` in `baseline.md`. Every later `git diff` uses that recorded SHA, written below as `BASE_SHA`. `origin/main` is never used as a diff operand after `[P0-T3]`.
- **Region location.** Edits are located by function name and by literal text, not by line number. `[P0-T4]` records whether the spec's cited line numbers still hold; the edit tasks proceed identically in either case.
- **Merge-order independence.** No task assumes that sibling items #707, #709, #710, or #713 have or have not merged. The plan writes no `.codex` path (spec D7) and no path under `docs/features/parallel/`.
- **PoshQC MCP route steps.** The tools `mcp__drm-copilot__run_poshqc_format`, `mcp__drm-copilot__run_poshqc_analyze`, and `mcp__drm-copilot__run_poshqc_test` return a pre-composed summary with no counts, percentages, or findings. Each is called as the policy route step, and only its call disposition (`returned` or `error`, plus the summary sentence) is recorded. Every asserted count, per-test result, finding count, and coverage percentage is derived from a readable source: the direct commands below, `artifacts/pester/pester-junit.xml`, or `artifacts/pester/powershell-coverage.xml`.
- **Observed output shapes.** Every asserted value below is a line that the stated command prints on a successful run, because the command itself composes that line (for example `PASSED=`, `FAILED=`, `PSSA_FINDINGS`, `FORMAT_UNCHANGED`, `LINE_PCT`). Two tool outputs are relied on only for exit status: `Invoke-PoshQCTest` (pester.runsettings.psd1 sets `Run.Exit = $true`, so a failing run exits the child process before the module's replayed summary at `scripts/powershell/PoshQC/PoshQC.Testing.psm1:420-462` is printed), and pytest (success-case summary line `<N> passed in <T>s`).
- **Batch budget.** At most 3 production and 3 test PowerShell files per session (`.claude/hooks/enforce-powershell-batch-budget.ps1`). This plan writes 2 production files (one via `Copy-Item`) and 1 test file. `.claude/state/*-batch-budget.*.json` files are deleted only in `[P4-T7]`, after the last planned PowerShell write.
