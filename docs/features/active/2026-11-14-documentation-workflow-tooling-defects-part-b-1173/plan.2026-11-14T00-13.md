- `SCRATCH` is `<session scratchpad>/issue-1173/`; scratch files are named `issue-1173-*`. Artifacts record the token `SCRATCH`, never a host path, host name or absolute path.

## Design Decisions and Premise Corrections

- PC-1 (B6): the spec fallback source root `.` is not a valid `relative-path` (common schema pattern and `Test-DocsRelativePath` reject a `.` segment), and `Get-DocsContextFileList` throws `DOCS_CONTEXT_PATH_INVALID` for it. Decision: detection order is `src`, then the `pyproject.toml` package directory, then `src` retained; `init` and `validate-profile` then report `DOCS_PROFILE_SOURCE_ROOT_MISSING`. `[P1-T1]` records the correction in `spec.md` and `user-story.md`.
- PC-2 (B2.1): batch item fields map through the existing `update_docs_ledger` field table, so the page of `pin`, `unpin` and `set-dimension` is `pages`, not `target` (`target` is the `set-disposition` target text). `[P1-T1]` corrects the spec example.
- D-1 (B2 module seam): `DocsLedgerBatch.psm1` does not import `DocsLedgerCommands.psm1`; the dispatch branch passes `Invoke-DocsLedgerOperation`, the document loader and the rule comparison as `[scriptblock]` parameters, so no circular import exists.
- D-2 (B2.4 in a batch): a `bind-page-refs` item expands into per-element internal bind items placed in input order in each element's partition, so the equivalence invariant holds.
- D-3 (B9): `call_sites.py` (existing) carries the provisional-receiver fields; the cross-module bind lives in `analyze_cli` of `cli.py`; the scanner bind lives in `DocsAnalyzerPythonCli.psm1`.
- D-4 (B11 capture): `New-DocsCapturedInput` returns `sha256` over LF-normalized bytes and a new `raw_sha256` over the raw bytes; `size` stays the raw byte count. `Test-DocsExtensionCapturedDigest` in `DocsAnalyzerExtensionImport.psm1` compares `raw_sha256` and `size` with the manifest entry, because discovery extension manifests declare raw-byte digests (`EXTENSION_INPUT_DIGEST_MISMATCH`, `EXTENSION_RESULT_DIGEST_MISMATCH`). The finding source check in `Get-DocsExtensionFindingProblem` compares two manifest values and is unaffected. Snapshot `inputs[].size` stays raw (B11 changes hashes only).
- D-5 (B5 boundary): `tests/scripts/claude-lib/docs/DocsReferenceBoundary.Tests.ps1` forbids `$Context` outside `DocsReferenceWriter.psm1` and pins the `DocsReference*.psm1` set and the seeded-property inventory. So `Context.ListFile` is called in `Invoke-DocsGenerateReferenceCommand` and the listed paths are passed to the pure `Get-DocsReferenceCandidatePagePath`; the split runs in `Get-DocsReferenceGeneration`; new codes use the `REFERENCE_` prefix, never `DOCS_PAGE_`.
- D-6 (B2 write boundary): `tests/scripts/claude-lib/docs/DocsWriteBoundary.Tests.ps1` pins the `WriteText` member access and the `Invoke-DocsArtifactWrite` reference to `Invoke-DocsUpdateLedgerCommand`. The batch write therefore stays in that function; `DocsLedgerBatch.psm1` and `DocsLedgerBindRefs.psm1` neither reference `Invoke-DocsArtifactWrite` nor touch `WriteText`, and that suite is unchanged.
