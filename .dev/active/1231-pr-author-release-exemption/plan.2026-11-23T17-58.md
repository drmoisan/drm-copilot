- Coverage: each new file needs at least 85% line coverage, with explicit rows for catch paths, seam throws, and absent files (P1-T1 to P2-T4). Figures are read from `artifacts/pester/powershell-coverage.xml` in P0-T2 and P4-T2 and compared in P4-T3. PowerShell has no branch gate.
- Mirror parity: each hook task writes its bundle copy and `core.json` entry. P3-T2 regenerates the docs, copies the four brief copies and the bundle copies of generated targets, and runs `-Check`. P3-T1 is the brief-update task (new `## Hook Execution Context` bullet and new contract-test name). P3-T3 pins byte identity, and P4-T5 confirms that no `.codex/` file changed.
- File size: P0-T1 and P4-T5 measure sizes. `enforce-orchestration-preimplementation-gate.ps1` grows by two lines (dot-source and call line) and stays far below 800. New files stay below 500. `enforce-pr-author-skill-helpers.ps1` and `hook-release-allowance-context.ps1` are not edited.
- Test isolation: there is one `Invoke-PoshQCParallelTest` run (P0-T2, P4-T2) and one `pytest -n auto` run (P0-T3, P4-T4), each re-run only after a fix. Jest is not applicable because no TypeScript file changes. Phase gates use parallel targeted Pester selections. P4-T1 runs `Invoke-PoshQCLeakScan`. Suites use no temporary files, synthetic roots, and mocked seams.
- CI-only behavior: the new suites run in `poshqc / PowerShell hook suites (Linux)` on a case-sensitive file system, so paths use forward slashes and no drive letters. No test reads `origin/main` or gitignored `artifacts/` state, and git is reached only through mocked seams.
- Evidence: every artifact goes to `FEATURE/evidence/<kind>/` with a UTC write-time stamp, is append-only, records `SCRATCH` and no host path, and reads counts from launcher-run files rather than MCP results.
