## Design

One rule for the whole function: the parser reads the feature-summary table completely or raises a terminating error. All changes are in `ConvertFrom-EpicProgressKickoffRow` in `scripts/dev-tools/Get-EpicProgressReport.Logic.ps1`.

NB-2 (one anchoring rule). Each line is trimmed once (`$trimmed = $line.Trim()`), and the header match, the end-of-table test, the row match, and the cell split all operate on `$trimmed`: header `^\|\s*(issue_num|issue)\s*\|`, end of table when `$trimmed -notmatch '^\|'`, row `^\|\s*(\d+)\s*\|`, and `$cells = @($trimmed -split '\|' | ForEach-Object { $_.Trim() })`. Leading whitespace before the first `|` is therefore accepted on every table line, and the cell indices (1 issue, 3 wave, 4 band, 5 plan path) are unchanged because the split input always starts with `|`. A blank line still trims to empty and ends the table.

NB-3 (short row, blank plan). After the row match and before the wave parse, the cell count is the split element count minus one, minus one more when `$trimmed` ends with `|`. When the count is below 5 the function throws `The kickoff row for issue #<issue> has <n> cells; a feature row needs 5 (issue, title, wave, band, plan path).`; when cell 5 is null or whitespace it throws `The kickoff row for issue #<issue> has a blank plan cell.`; then the existing `TryParse` wave check and its message run unchanged. The count check precedes the plan check, so a four-cell row with a trailing `|` reports its cell count, not a blank plan cell.

NB-1 (no recognized header). After the loop, when `$inFeatureTable` is still `$false` and `$KickoffText -match '\S'`, the function throws `The kickoff has no feature-summary table: no table header row whose first cell is 'issue_num' or 'Issue' was found.` Empty and whitespace-only text still return zero rows. A recognized header followed by no feature row returns zero rows (not in scope of NB-1). No row is emitted before the header, so the throw never follows partial output.

Help. The function `.DESCRIPTION` states the trim rule (leading whitespace allowed before the first `|` on every table line), the three terminating errors, and that empty or whitespace-only text returns no rows. P2-T9 extends `.PARAMETER KickoffPath` in `scripts/dev-tools/Get-EpicProgressReport.ps1` with the sentence that kickoff text without that header, a feature row with fewer than five cells, and a feature row with a blank plan cell each raise a terminating error. `Invoke-GitExe` discards git's error stream, so a kickoff path absent from the integration branch still yields empty text and zero rows; that behavior is unchanged and outside NB-1.

Size. The logic file is 670 physical lines and grows by about 11; the Logic test file is 651 and grows by about 45 (seven compact tests in the existing one-line-fixture style). If P2-T5 records 700 or more for either file, the self-review records the advisory-tier disposition: a non-blocking Warning, no split in this cycle because the file stays below 800 and the change is confined to one function and its one `Describe` block. The plan does not fail on it.

New tests, all in `Describe 'ConvertFrom-EpicProgressKickoffRow'` of `tests/scripts/dev-tools/Get-EpicProgressReport.Logic.Tests.ps1`, each with an `| Issue | Title | Wave | Band | Plan |` header and `|---|---|---|---|---|` separator unless stated:

- `It 'throws a clear error for a kickoff whose feature-table header is not recognized'` (NB-1): header `| Issue # | Title | Wave | Band | Plan |`, separator, row `| 12 | Alpha | 1 | small | docs/a/plan.md |`; asserts a throw matching `*no feature-summary table*'issue_num' or 'Issue'*`.
- `It 'throws a clear error for a feature table with no header row'` (NB-1): the single row `| 12 | Alpha | 1 | small | docs/a/plan.md |`; same expected message.
- `It 'returns no rows for a whitespace-only kickoff'` (NB-1 boundary): text of spaces, a tab, and LF; asserts zero rows and no throw.
- `It 'reads a feature table whose header row is indented'` (NB-2): header indented by two spaces, unindented row `| 12 | Alpha | 1 | small | docs/a/plan.md |`; asserts one row, issue `12`, plan path `docs/a/plan.md`.
- `It 'reads an indented row inside the feature table'` (NB-2): unindented header, separator, row `   | 5 | Alpha | 1 | small | docs/a/plan.md |` indented by three spaces, then `| 6 | Beta | 2 | large | docs/b/plan.md |`; asserts issues `5,6`, row 0 wave `1` and plan path `docs/a/plan.md`.
- `It 'throws a clear error for a feature row with fewer than five cells'` (NB-3): row `| 5 | Alpha | 1 | small |`; asserts a throw matching `*#5 has 4 cells*`.
- `It 'throws a clear error for a feature row with a blank plan cell'` (NB-3): row `| 5 | Alpha | 1 | small |  |`; asserts a throw matching `*#5 has a blank plan cell*`.

Mutant targets (P1-T4): mutant A deletes the post-loop NB-1 `if`/`throw` (kills the two NB-1 throw tests); mutant B changes the row-match operand from `$trimmed` back to `$line` (column-0 anchoring; kills only `reads an indented row inside the feature table`, because the indented-header test has unindented rows); mutant C deletes the cell-count check (the four-cell row then raises the blank-plan message, so only `throws a clear error for a feature row with fewer than five cells` fails).
