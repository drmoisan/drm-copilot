## Parity Notes (binding design decisions)

- **Short-name validation.** Port `SHORT_NAME_PATTERN = /^[a-z0-9]+(-[a-z0-9]+)*$/` and `validate_short_name`. A blank string or a value that does not fully match the pattern MUST throw an error whose message is byte-identical to the Python `ValueError`: `` `Aborted: '${shortName}' is invalid. Use kebab-case letters/numbers only (e.g., api-timeout).` ``. Use `RegExp.prototype.test` against the full string (the Python `fullmatch` with an anchored `^...$` pattern is equivalent to `.test` on this anchored regex). NOTE: the existing `mcp-tool-inputs.ts` `resolveNewPotentialBugEntryToolInput` already validates `short_name` at the input boundary; the port MUST still re-validate inside `createBugEntry` to match the Python contract (validation occurs before any filesystem work) and to keep the library independently correct. Do NOT modify `mcp-tool-inputs.ts`.
- **Author resolution.** Port `get_author`: call `gitLookup("user.name")` first; if blank/undefined, call `envLookup("USERNAME")`; if still blank/undefined, return the literal `"Unknown"`. Provide injectable seams `gitLookup: (key: string) => string | undefined` and `envLookup: (name: string) => string | undefined` with production defaults. The default git lookup MUST resolve `git` via the injected `CommandRunner` (run `["git", "config", key]` with `allowError: true`) and return the trimmed stdout when non-empty, else `undefined` — replacing Python `shutil.which("git")` + `subprocess.run`. The default env lookup reads `process.env[name]` and returns it only when present and non-blank (after trim), else `undefined`, matching Python `default_env_lookup`.
- **Date / slug / target path.** The date string defaults to today's `YYYY-MM-DD` (Python `date.today().strftime("%Y-%m-%d")`) and MUST be overridable via an `entryDate?: string` option for deterministic tests. The target directory is `<workspace>/docs/features/potential`; the target file is `<targetDir>/<date>-<shortName>.md`. The service path always passes `templateRoot`, so the template is `<templateRoot>/bug/potential_bug.md`; when `templateRoot` is undefined the template is `<workspace>/docs/features/templates/bug/potential_bug.md` (Python `create_bug_entry` branch). Use POSIX-style joins consistent with the rest of `src/lib` (use `node:path` and normalize with `toPosixPath` only where a returned path string must be forward-slash; the returned created path string MUST match the Python-equivalent path for the platform-neutral tests — assert via the same join the port uses).
- **Template copy + render.** Python copies the template to the target, reads it back, renders placeholders, and writes the result. The F1 `FileSystem` interface has NO `copyFile` method (it exposes `glob`, `isFile`, `readTextFile`, `writeTextFile`, `ensureDir`). The port MUST therefore: `ensureDir(targetDir)`; `readTextFile(templatePath)`; apply `renderContent`; `writeTextFile(targetPath, rendered)`. This collapses copy+read into a single template read and is behaviorally identical to the Python copy-then-read-then-write for the observable outcome (target file content). A missing template MUST surface as a file-not-found error; the in-memory test fake MUST throw when `readTextFile` is called for an absent path (mirroring Python `copy_file` raising `FileNotFoundError`). Do NOT add `copyFile` to the shared `FileSystem` interface (avoid widening the F1 surface; the single-read approach is sufficient and minimal).
- **`renderContent`.** Port `render_content` exactly: replace ALL occurrences of `<bug-name>` with `shortName`, ALL occurrences of `YYYY-MM-DD` with the date string, and the literal `- Author: name` with `- Author: ${author}`. Match Python `str.replace` semantics (replace-all) — use `split`/`join` or a global regex with escaped literals; `String.prototype.replace` with a string argument replaces only the first occurrence in JS, so the port MUST replace all occurrences to match Python. Preserve the exact placeholder strings.
- **VS Code launch (guarded no-op in MCP/non-interactive path).** Python `default_code_launcher` resolves `code`/`code-insiders` via `shutil.which`, picks the Insiders CLI first when the session signals Insiders (env vars `TERM_PROGRAM_VERSION`, `VSCODE_GIT_ASKPASS_MAIN`, `TERM_PROGRAM`, `VSCODE_IPC_HOOK_CLI` containing `insider`), and runs `code --reuse-window <files>`; on failure (`code` not found) it returns `false` and `create_bug_entry` prints a `WARNING: VS Code 'code' command not found...` message. The library port MUST expose an injectable `codeLauncher: (files: readonly string[]) => boolean` seam with a production default that ports `_is_insiders_session`, `_resolve_code_cli`, and `default_code_launcher` (using the injected `which`/`env`/`CommandRunner` seams). **The service/MCP call path MUST pass a no-op launcher that returns `false` (no subprocess), so `code`/`code-insiders` never launches in the non-interactive/MCP path.** When the launcher returns `false`, the library emits the two warning lines through an injected `log` callback (NOT `console.log`), preserving the message text: `WARNING: VS Code 'code' command not found. Open file manually:` and `  ${targetPath}`.
- **Return value.** The library `createBugEntry` returns the created absolute target path (Python returns `Path`). The service helper converts this to the service result contract.
- **Service return contract preserved.** `newPotentialBugEntry` MUST continue to return a `RepoAutomationExecutionResult` with `tool: "new_potential_bug_entry"`, `workspaceRoot: input.workspaceRoot`, `summary: ` `` `Created a new potential bug entry for '${input.shortName}'.` `` (byte-identical to the current summary), and `artifacts: [normalizeGeneratedPath(<createdTargetPath>)]`. The current method emits no `artifacts` field; adding the created path as a single artifact is the only intentional enrichment and MUST be reflected in the updated service/extension tests. If preserving exact prior output (no `artifacts`) is required by an existing test, the helper MUST instead omit `artifacts`; resolve this by inspecting the existing tests in P0-T2 and choosing whichever preserves all existing assertions — default to including the created artifact path unless an existing assertion forbids it. Record the decision in the parity artifact.
- **Inputs preserved.** The MCP input contract is unchanged: `short_name` (string) and `workspace_root`. `mcp-tool-inputs.ts` `resolveNewPotentialBugEntryToolInput`, the handler `handleNewPotentialBugEntry`, and the tool name `new_potential_bug_entry` are NOT modified and their tests MUST continue to pass unmodified.
- **Template root source.** The service already computes `this.templateRoot = buildTemplateRoot(this.extensionRoot)` = `<extensionRoot>/resources/feature-templates`. The helper MUST use this same value as `templateRoot`, so the template resolves to `<extensionRoot>/resources/feature-templates/bug/potential_bug.md` (parity with the Python `--template-root` argument currently passed).
