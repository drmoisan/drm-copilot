## Scope and Toolchain Applicability

This plan edits four Markdown production files, named in the `## Constraints & Risks` section of `issue.md`. Two are the canonical skill contracts, referred to throughout this plan as the **target files**:

- `.claude/skills/atomic-plan-contract/SKILL.md` (213 lines at baseline)
- `.claude/skills/remediation-handoff-atomic-planner/SKILL.md` (117 lines at baseline)

Two are their bundled copies under the extension resource tree, referred to throughout this plan as the **bundled mirrors**:

- `extensions/drm-copilot/resources/claude-customizations/.claude/skills/atomic-plan-contract/SKILL.md` (213 lines at baseline, byte-identical to its target file)
- `extensions/drm-copilot/resources/claude-customizations/.claude/skills/remediation-handoff-atomic-planner/SKILL.md` (117 lines at baseline, byte-identical to its target file)

These labels are used with fixed meanings for the remainder of this plan: "the two target files" never includes a bundled mirror, "the two bundled mirrors" never includes a target file, and "the four production files" means all four together. The bundled mirrors are in scope because every prior commit touching either skill contract updated both copies in the same commit (`88e7d5fc`, `04488789`, `45aad955`, `24353b0b`, `dbe87827`); leaving a mirror stale would ship an extension payload that disagrees with the repository contract.

No application source, build input, or test file is touched. No formatter, linter, type checker, or test runner in this repository takes these files as input, so no format/lint/type-check/test baseline command exists for this change and none is invented. Phase 0 therefore captures the mandatory policy-read evidence, a structural baseline of the two target files (HEAD commit and heading inventory), and the baseline blob-hash pair for each target/mirror pair, which is what the Phase 2 additive-only, end-state, and mirror-parity gates are measured against. Phase 2 verification is manual review recorded in named artifacts, per the `## Test Conditions to Consider` section of `issue.md`. P2-T8 additionally rewrites acceptance-criteria checkbox markers in `docs/features/active/2026-08-28-atomic-preflight-convergence-586/issue.md`, and Phase 0 and Phase 2 create the 15 Markdown evidence artifacts listed below. Neither is a toolchain input either, and neither is in scope of the additive-only constraint: "the four production files" in the additive-only bullet of `## Design Constraints Binding Every Phase 1 Task` refers to the four files named above and to nothing else, so `issue.md` and the evidence artifacts are outside it.

Review effort is not duplicated across a target file and its mirror. P2-T1 through P2-T7 read the two target files only; P2-T10 establishes that each bundled mirror is byte-identical to its target file after Phase 1. Byte-identity at baseline plus byte-identity after Phase 1 carries every content verdict recorded against a target file over to its mirror, including the additive-only verdict, so no separate diff, consistency, tonality, or heading gate is run against a mirror and none is needed.

Because no coverage-bearing language is in scope, the Coverage Evidence Contract in `atomic-plan-contract` produces no obligations for this plan; there is no coverage command to run and no coverage number to record.

## Design Constraints Binding Every Phase 1 Task

- Additive only. No existing line in any of the four production files may be deleted or reworded. P2-T1 and P2-T2 measure this as a removal-line count of zero in a ref-anchored diff over the two target files; the same verdict reaches the two bundled mirrors through the byte-identity established by P0-T5 and P2-T10, as stated in `## Scope and Toolchain Applicability`.
- Mirror sync. Every edit made to a target file by P1-T1 through P1-T13 is applied identically to that file's bundled mirror by P1-T14 or P1-T15, so that each pair remains byte-identical. A pair that diverges fails P1-T14, P1-T15, or P2-T10.
- New signal lines follow the existing directive-line convention already used in both target files (`DIRECTIVE: ...`, `PREFLIGHT: ALL CLEAR`, `PREFLIGHT: REVISIONS REQUIRED`). No unrelated format is introduced.
- New prose complies with `.claude/rules/tonality.md`: no humor, no hyperbole, no decorative metaphor, evidence-first wording.
- New prose in `.claude/skills/atomic-plan-contract/SKILL.md` matches the rigor of the existing `## Wrap-Tolerant Assertion Authoring (Mandatory)` section: each rule names its concrete failure mechanism, not only its abstract goal.
- `.claude/agents/atomic-executor.md` and `.claude/agents/orchestrator.md`, and the bundled mirror of each, are out of scope and must not be edited. The tensions with those files are recorded in `## Open Questions / Notes` for escalation.
