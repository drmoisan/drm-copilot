## Summary

**Overall Feature Readiness:** NEEDS REVISION

**Criteria summary:**
- **PASS:** 9 criteria (1, 2, 3, 4, 7, 8, 9, 10, 11)
- **PARTIAL:** 0 criteria
- **UNVERIFIED:** 1 criterion (6)
- **FAIL:** 1 criterion (5)

**Top gaps preventing PASS:**

1. **AC5 fails on proven behavior.** The `CHILD_OF` short-circuit changes classification outcome, not only cost. A branch that resolves `MERGED_CLEAN` and is a git ancestor of a `NOT_MERGED` branch — the normal relationship between any merged branch and any unmerged branch descending from `main` — now resolves `NOT_MERGED`, and apply mode stops emitting its deletion `ACTION`. Both stated properties of the invariant are violated. Because spec.md states the same inference rule, remediation must amend the spec and the criterion alongside the code, and must re-examine the gap 9c performance premise: the sound (descendant-direction) form of the inference would not fire on the epic child branches the issue actually cites, since those were ancestors of the integration branch.
2. **The tests that exist to prove AC5 cannot fail when it is violated.** No fixture pairs a delete-eligible branch with a `NOT_MERGED` branch; property (a)'s test compares a different branch under a different fixture, and property (b)'s test asserts a condition (`NOT_MERGED` is not deleted) that held before the change. A fixture and test for the failing case must be added, and the pre/post `NO_DIFF` sweep re-run with it included, or the same class of defect can recur.
3. **AC6 has no evidence.** The ordered, standalone regression gate required immediately after the shared stub edit and before any new fixture was authored was not performed and not recorded; plan task P2-T3 is unchecked and its artifact is absent. The end-state suite is green and the fallback logic reads correctly, but the specific risk spec.md identifies — a shared fixture silently replaying the wrong canned data for one of two distinct `for-each-ref` calls — is exactly what the ordered gate exists to exclude.

**Recommended follow-up verification steps:**

1. Add a scenario fixture with `main`, a branch resolving `MERGED_CLEAN` (or `MERGED_EQUIVALENT`) against `main`, and a `NOT_MERGED` branch that the merged branch is an ancestor of; assert both the report verdict and the presence of the apply-mode deletion `ACTION`. Confirm the new test is red before the AC5 fix and green after.
2. Re-run the pre/post outcome-preservation sweep recorded in `evidence/other/scan-seam-call-site-verification.2026-09-06T23-03.md` with the new scenario included, and record the result under `evidence/regression-testing/`.
3. Perform and record the AC6 ordered regression gate: apply the two stub key edits alone onto the base tree, run the pre-existing bats suite, and record the count and exit code under `evidence/regression-testing/stub-git-backward-compat.<timestamp>.md`. If re-deriving the intermediate state is not practical, record that explicitly instead of leaving the criterion silent.
4. Execute plan Phases 10 and 11 and record their evidence artifacts, including the post-change `Bash coverage (lines): NN.N%` figure and a single-pass loop confirmation. The underlying facts are already established in this audit, but the durable record the plan requires does not exist.
5. Add tests for the untested error paths named in spec.md's Test Strategy (`ORPHAN_DIR|<path>|unknown`, scan hard failure, unreadable pointer file) and for the `CLEANUP_WT_ORPHAN_ROOTS` override branch.
6. Record a before/after report-mode runtime measurement so the gap 9c objective becomes falsifiable, given the three new costs identified in the code review (O(n^2) ancestry probes, a doubled filesystem scan, and unconditional `du -sh` on every candidate directory).
