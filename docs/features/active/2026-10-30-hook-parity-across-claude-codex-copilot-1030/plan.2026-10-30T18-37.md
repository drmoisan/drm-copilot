## Design Decisions and Spec Reconciliation

- **Codex PreToolUse deny shape.** The Codex feature-folder entry follows the repository's Codex precedent `.codex/hooks/enforce-evidence-locations.ps1`: deny is a `hookSpecificOutput.permissionDecision` `deny` JSON object on stdout at exit 0, allow is exit 0 with empty stdout, and malformed stdin is exit 2 with stderr. This is the envelope `legacy-codex-hook-contracts.Tests.ps1` asserts (It `emits the current PreToolUse deny envelope for shell and patch violations`) and supersedes the spec's `## API / CLI Surface` wording of deny by exit 2.
- **SubagentStop adapter dispatch.** The planner and executor validators define functions with the same names (`Get-PlanFileContent`, `Get-PlanPathFromOutput`, `Test-HasPreflightSignal`), as do the researcher and prd-feature validators (`Test-NumericDerivationEvidence`) and the prd-feature and required-artifact validators (`Get-ArtifactPathFromOutput`). `hook-dependency-guard-completeness.Tests.ps1` (S2, S5) forbids dot-sourcing inside a function. The adapter therefore runs the selected byte-identical twin as a child PowerShell process with the Codex payload on stdin, through a `[scriptblock]` parameter seam, and translates the twin's exit 2 and stderr reason into a Codex continuation. The twin's own entry code is unchanged, so Claude and Codex execute the same validator code.
- **Feature-folder rule helper.** Pure rule functions move to `feature-folder-order-rules.ps1` together with one new shared function `Get-FeatureFolderOrderFileDecision`; the Claude entry keeps its H1-exempt guarded load of `feature-folder-resolution.ps1` (`HookImportFailureExemptions.Helpers.ps1` is not edited). The Codex entry loads `feature-folder-resolution.ps1` with the standard guard, so a load failure there denies every write.
- **Python-invocation guard residuals.** Extending the scan roots to `.codex/scripts` exposes two `&`-invocations of a non-`[scriptblock]` variable (`$resolver` in `Invoke-CodexTopologyCli` and `Invoke-CodexDeploymentCli`). They are replaced by module-qualified direct calls so the allowlist stays empty.
- **New matrix entries.** The two new Codex registrations need matrix entries for child 1's completeness test; they are added with child 1's field set and `id` encoding. The schema, encoding and completeness test are not changed.
- **Loop guard.** The adapter allows without re-validation when `stop_hook_active` is true (spec). The Claude validators re-block repairable failures on re-entry, so the equivalence fixtures use `stop_hook_active` false; the difference is recorded in the matrix `reason` of each ported SubagentStop group.
- **O2.** The preimplementation delegation-leg registration is not added. The matrix records the pending-runbook reason; [P4-T5] authors an owner-run runbook and no task depends on its result. O4, O5, O6 and O7 use the spec defaults; no `.codex/lib` publication and no TypeScript change.
