## Key Discoveries

### Project Structure

Bug #81 is not in the core PR-context collector implementation. It is in extension-side exposure wiring behavior: the extension command runs a lightweight bundled placeholder script rather than the canonical `scripts/dev_tools/pr_context/collector.py` pipeline.

### Implementation Patterns

Observed deterministic flow:

1. Extension command discovers/selects base branch (`symbolic-ref` + `for-each-ref` + `showQuickPick`).
2. Extension executes bundled script in destination workspace `cwd`.
3. Bundled PR script writes minimal placeholder content.

This means branch selection/wiring is functioning, but payload generation is intentionally shallow in the current bundled script.

### Technical Requirements

- Preserve extension execution boundary (bundled resource execution; no workspace script copy).
- Keep deterministic branch-selection UX and cancellation behavior.
- Replace placeholder PR payload generation with canonical collector-equivalent behavior.
- Strengthen tests so PR-context content quality is validated, not just file existence.

## Recommended Approach

Use a **minimal-scope parity fix**:

1. Keep `drmCopilotExtension.collectPrContext` branch discovery + `showQuickPick` flow unchanged.
2. Replace the bundled placeholder `extensions/scaffold-extension/resources/templates/collect_pr_context.py` implementation with a bundled implementation that calls canonical PR-context collection logic (or a faithful subset that produces meaningful summary/appendix content).
3. Preserve existing output paths and args (`--base`, `--out`, `--appendix-out`).
4. Add regression assertions in extension tests that fail when summary/appendix contain only placeholder headings/base line.

Rejected alternatives (brief, non-exhaustive):

- Rewriting extension branch-discovery flow: rejected; evidence shows branch selection already works and is not root cause.
- Accepting placeholder output as “non-empty”: rejected; it does not satisfy issue intent and downstream usefulness requirements.
- Copying workspace scripts and executing from destination repo root: rejected; violates current extension boundary model and existing tests.

## Implementation Guidance

- **Objectives**: Make extension-side PR-context artifacts materially equivalent to canonical collector output and prevent regressions.
- **Key Tasks**:
  - Update bundled PR collector implementation under `extensions/scaffold-extension/resources/templates/collect_pr_context.py`.
  - Keep extension command wiring in `extensions/scaffold-extension/src/extension.ts` stable unless needed for argument parity.
  - Add regression tests in `extensions/scaffold-extension/test/extension.integration.test.ts` and/or `extension.collect-pr-context.test.ts` that validate meaningful sectioned output.
- **Dependencies**:
  - Git CLI availability in destination workspace.
  - Existing extension Python runtime detection (`python` on PATH).
  - Canonical PR-context data model/sectioning from `scripts/dev_tools/pr_context`.
- **Success Criteria**:
  - Repro path from issue now generates non-placeholder PR summary/appendix.
  - Output contains branch/base/range + changed-context sections beyond heading/base-line only.
  - Existing command/cancel/error tests remain deterministic and passing.
  - New regression test fails on placeholder content and passes with the fix.
