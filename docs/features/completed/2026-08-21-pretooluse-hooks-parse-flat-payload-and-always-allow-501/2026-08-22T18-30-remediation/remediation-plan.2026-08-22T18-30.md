No Python code, PowerShell hook logic, or `.claude/hooks/**` file content changes in this cycle. The only production-tree edit is the JSON manifest addition.

### Decision — full-suite final QA for `.claude/**`-touching changes (required by this cycle)

**Decision: yes.** Any change touching `.claude/**` must run the full `poetry run pytest` suite and the full TypeScript suites (both the root suite and the extension's own suite) in final QA, not only a targeted selector, and this cycle's Phase 3 makes both unconditional.

Reasoning:

1. The cycle-1 defect was not a targeted selector picking the wrong test — it was a targeted selector correctly passing a *different* test (byte-parity) than the one that actually failed (manifest registration), because the two assertions live as **sibling test functions in the same file** (`test_push_down_claude_pack_manifest_completeness.py` sits next to `test_push_down_claude_resource_contracts.py` in the same directory, and neither is a subset of the other). No amount of care in selecting a *more specific* targeted selector generalizes to this failure mode, because the correct selector cannot be known in advance without already knowing which contract a given change might violate. Only running every test in the directory (in practice, the full suite) closes that gap.
2. `.claude/rules/general-code-change.md`'s Mandatory Toolchain Loop names "Unit tests" as stage 5 with no scoping qualifier; a targeted selector is a legitimate speed optimization for iterative development, but it is not a substitute for the unqualified full-suite obligation that gates a change before it is reported complete.
3. The TypeScript suite was not run by the plan's local final QA at all in cycle 1. `.claude/**` changes are asserted by TypeScript tests (`extensions/drm-copilot/test/lib/push-down/**`) as well as by Python tests, and CI enforces both; a final QA loop that never invokes one of the two runtimes cannot detect a defect that only that runtime's test exercises.
4. The marginal cost of running the full suites is bounded (both suites already run in CI on every PR) and is paid once at the end of the loop, not on every edit — it is added to Phase 3 (final QA) only, not to Phase 0 or Phase 1's iterative baseline/fix cycle.

This decision is scoped to this remediation plan's Phase 3 tasks below. Recording it as a standing rule for every future `.claude/**`-touching plan would require editing `.claude/rules/general-unit-test.md` or `.claude/skills/atomic-plan-contract/SKILL.md`, both of which are out of scope for this cycle (this remediation does not edit any policy file).
