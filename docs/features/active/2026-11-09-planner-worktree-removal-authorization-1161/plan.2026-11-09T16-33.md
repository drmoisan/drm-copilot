### Revision decisions (preflight round 1)

- R1 (Claude seams): the Claude adapter has exactly two I/O entry points, `Get-PlannerWorktreeCheckpointText -SessionRoot -RelativePath` (the only caller of `Get-WorktreeItemLiveRoot` and `Get-WorktreeRunCheckpointText`; it returns one `{Root, Text}` object per live root that holds the file) and `Invoke-PlannerWorktreeGitExe -GitArgs`. Reason: the adapter is dot-sourced into the gate's script scope, where the existing module-scoped baseline mocks do not intercept, so one script-scope seam is mocked instead. `Register-EpicStateBaselineMock` mocks it to return nothing, and each Claude gate suite that does not use the helper gains one direct mock line (P2-T6).
- R2 (git facts): one `git -C <root> worktree list --porcelain` call, parsed by the pure `ConvertFrom-PlannerWorktreePorcelain` in the byte-identical helper, supplies the branch-to-root match, the main checkout (first stanza; U2 and the `path` base root), and the `locked` line (U3) on both surfaces. It runs only after a candidate record exists. This replaces the spec's `Get-WorktreeItemLiveRoot -Branch` and `Get-WorktreeRunMainCheckoutRoot` calls on Claude and `ConvertFrom-HookTargetWorktreePorcelain` on Codex. Reason: those calls would be further unmocked script-scope reads, and `ConvertFrom-HookTargetWorktreePorcelain` does not emit the `locked` line that U3 needs (D20). The Codex adapter therefore does not dot-source `.codex/hooks/hook-target-worktree.ps1`, which supersedes preflight fix 6. The matching behavior of spec `### Record match` is unchanged.
- R3 (Codex option a): the Codex gate body reads `artifacts/orchestration/epic-planner-state.json` at the repository root once, next to the existing epic checkpoint read, and passes the text through a new optional `-PlannerCheckpointRaw` parameter (empty by default) of `Invoke-CodexWorktreeRemovalDecision` and `Get-CodexWorktreeRemovalTargetDenial`. With empty text the adapter returns `NoRecord` before any seam call. The U4 read of the target's `artifacts/orchestration/orchestrator-state.json` is also owned by the gate body: the body passes a reader script block through a second optional parameter, `-TargetCheckpointReader` (default `$null`, read as an absent file). The adapter's only seam is therefore `Invoke-CodexPlannerWorktreeGitExe -GitArgs`. Reason: a function in the adapter that held `Get-Content` would be a census seam (R4) in every Codex suite that loads the gate, and keeping every Codex file read in the body follows the existing epic read.
- R4 (isolation guard): `enforce-gate-suites.EpicStateIsolation.Discovery.Tests.ps1` requires a baseline mock only for census seams, which are functions whose body holds `Get-Content`, `ReadAllText`, or `ReadAllLines` (plus the four named module seams). The new Claude seam reads only through `Get-WorktreeRunCheckpointText` and is not a census seam, so the guard and `Invoke-EpicStateInterceptionProbe` need no registration. The interception is instead enforced by the P2-T2 AST rows, the P2-T6 sentinel rows, and the P2-T6 suite-coverage row.
- R5 (AC-31 reading): "passes unchanged" is applied to assertions. The suites listed as updated in `## Existing Test Dispositions` gain only a baseline-mock line and keep every assertion. Reason: spec D9 assumed the existing module-scoped mocks intercept the adapter's reads, and they do not.
- R6 (import): the adapter imports `.claude/lib/worktree-resolution/WorktreeItemResolution.psm1` in a guarded single-statement `try` with `-ErrorAction Stop` and without `-Force`. `Get-WorktreeItemLiveRoot` is not re-exported by `WorktreeRunResolution` or `WorktreeRunRecordPath`, and omitting `-Force` keeps the module instance that the suites have already imported and mocked.
- R7 (wording contract): `tests/scripts/claude-runtime/planner-worktree-removal-contract.Tests.ps1` holds per-file required tokens. It matches them after collapsing whitespace inside the extracted heading section, paragraph, or `.DESCRIPTION` help text (`GetHelpContent` of the parsed script). Test files are not pushed down, so it has no mirror or manifest entry.

## Size Justification

The spec fixes a file set of three gates, one byte-identical helper pair, two adapters, two validators with a shared corpus, four documentation surfaces, and thirteen mirrors, and its AC-8 requires a separate fail-before run. Phase 0 and Phase 4 hold eleven tasks that the contract mandates (static and test baselines per language, per-language final QC, scope check, self-review), leaving thirteen implementation tasks for 34 acceptance criteria. Splitting the item would separate the gate edits from the helper they call, which breaks the fail-before ordering and the twin pin. Revision 1 keeps the 24 tasks and adds test-file edits (the baseline helper, eleven Claude suites, one Codex suite, and the wording-contract suite) inside existing tasks, because each edit depends on the adapter or document that its task creates.
