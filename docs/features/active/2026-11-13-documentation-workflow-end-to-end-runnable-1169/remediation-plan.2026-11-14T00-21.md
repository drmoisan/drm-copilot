## Premise Corrections and Decisions

- **F3 seam choice.** Both cleanup suites null-mock `Get-WorktreeResolutionGitFileText` in their outermost `BeforeAll` at the merge base (Claude: the `Get-Command`-guarded script-scope `Mock`; Codex: the `-Surface 'Codex'` seam list). The function exists on both surfaces with one name and one contract (raw text, `$null` when absent): exported from `.claude/lib/worktree-resolution/WorktreeResolution.psm1` and defined in `.codex/hooks/enforce-orchestration-preimplementation-gate-epic-resolution.ps1`, both loaded by each main gate before the docs leg. The docs leg therefore reads the profile through it, deletes `Get-OrchestrationDocsEstateFileText`, and keeps the docs-leg file byte-identical in four copies. `Get-CheckpointContent` was rejected: path-agnostic non-null mocks of it are common, and unfiltered `Should -Invoke Get-CheckpointContent` counts in both TargetWorktree suites would gain calls.
- **F3 transparency check (done at planning, repeated in P2-T2).** The only script-scope non-null path-agnostic mocks of `Get-WorktreeResolutionGitFileText` are in `tests/scripts/codex-hooks/enforce-orchestration-preimplementation-gate-epic-resolution.Tests.ps1`, which dot-sources only the epic-scope file and never reaches the docs leg. No guard is added. With no profile the leg declines with an empty suffix, so the no-profile deny text stays byte-identical.
- **F3 discovery guard.** After the change the docs-leg file defines no function whose body holds `Get-Content`, `ReadAllText`, or `ReadAllLines`, so `Get-EpicStateSeamCensus` reports no seam for it and no suite needs the removed token. Removing the function makes every `Register-EpicStateBaselineMock -Seam 'Get-OrchestrationDocsEstateFileText'` throw, so the token leaves every suite (P2-T1, P2-T2).
- **F3 semantics.** An empty profile file now reads as absent (empty suffix) instead of `DOCS_LEG_PROFILE_INVALID`, and an unreadable file reads as absent instead of throwing into the never-throw catch; both decline, as before.
- **CR3 decision.** The docs path set becomes: the docs-init workflow constant, or a path under `docs/` that also lies under an `artifact_paths` directory or a `documentation_roots[].path`. A root or artifact directory outside `docs/` admits nothing, which matches E7 and M9. The spec holds no decision labelled D-A1-roots; the decision text is the `Docs path set` definition (item 3) and A1 criterion 4, revised in P3-T1, plus one new A2 criterion. `enforce-model-routing-receipt-docs.ps1` calls the shared `Test-DocsEstatePath` and is unchanged. The execution-environment brief and the pr-author skill say only "docs path set" and do not state the old rule, so they are unchanged; the `documentation-workflow/SKILL.md` rule sentence states it and is updated (P3-T3).
- **CR4 form.** `AfterAll` removes the functions defined at top level in each hook file the suite dot-sources directly and in the docs-leg files it loads, by the parse-and-remove form of `tests/scripts/claude-hooks/hook-docs-estate-context.Tests.ps1`.
