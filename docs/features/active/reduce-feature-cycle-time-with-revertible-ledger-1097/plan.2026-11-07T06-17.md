## Design

**Constants.** In `scripts/dev_tools/plan_gate_document.py` and `extensions/drm-copilot/src/lib/validate/plan-gate-document.ts`: `PLAN_TASK_GUIDELINE` becomes 20 and `PLAN_LINE_GUIDELINE` becomes 250; new `LEGACY_PLAN_TASK_GUIDELINE` (40), `LEGACY_PLAN_LINE_GUIDELINE` (400), and `PLAN_GUIDELINE_CUTOFF`, a string of the form `yyyy-MM-ddT00-00`. The names follow spec `## API / CLI Surface`, so no new production module and no new `coverageThreshold` entry is needed; the existing per-file entries for `plan-gate-document.ts`, `plan-gate-discrimination.ts`, and `orchestration-artifacts.ts` in `extensions/drm-copilot/jest.config.cjs` gate the changed files.

**Cutoff value (D2).** `<day>T00-00`, where `<day>` is the America/New_York calendar date of the G13 commit, because the feature-folder tooling stamps plan files in that zone. Derivation: read the host clock, convert it to America/New_York, take the date. [P1-T1] writes the value derived when it runs; [P2-T3] derives it again, rewrites the two modules and the rule file when the date moved, and [P2-T4] derives it once more immediately before the commit and repeats [P2-T3] when it moved. Tests never hard-code the value: they read the constant.

**Stamp reading (K4).** `plan_file_stamp` and `planFileStamp` split a path on both `/` and `\`, so relative, absolute, and Windows-joined MCP paths read alike. With `STAMP` the pattern `[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}-[0-9]{2}`, the file name fully matches `plan.STAMP.md`, `plan.remediation-cycle-N.STAMP.md` with `N` digits, or `remediation-plan.STAMP.md`; or the name is `remediation-plan.md`, its parent segment fully matches `STAMP`, and the segment above it is `remediation`. Any other name, an empty path, and no path yield no stamp. Matching is case-sensitive.

**Guideline selection.** `plan_size_guideline` and `planSizeGuideline` return the legacy pair when a stamp exists and sorts before `PLAN_GUIDELINE_CUTOFF` as a string, and the new pair otherwise, so a stamp equal to the cutoff, any unrecognized name, and no path use the new pair. A stamp is compared as written, whatever zone produced it.

**Path parameter (K5).** The path reaches G13 by its own parameter, never through the repository seam: Python `evaluate_document_gates(report, text, *, plan_path=None)`, `evaluate_plan_gates(text, *, context=None, plan_path=None)`, `validate_plan_text_with_warnings(text, *, context=None, plan_path=None)`, and `_plan_channels` passing `args.path`; TypeScript `evaluateDocumentGates(report, text, planPath?)`, `evaluatePlanGates(text, context?, planPath?)`, and `validateArtifactWithWarnings` passing `input.artifactPath` beside `buildPlanGateContext(input)`, which still returns `undefined` when any wiring field is absent. `validate_plan_text` keeps its signature and uses the new pair.

**Message.** `plan_size_message(tasks, lines, *, guideline=(PLAN_TASK_GUIDELINE, PLAN_LINE_GUIDELINE))` and `planSizeMessage(tasks, lines, guideline = [PLAN_TASK_GUIDELINE, PLAN_LINE_GUIDELINE])` render the pair that applied, in the existing format, so the legacy message is byte-identical to today's and the new one reads `exceeds the guideline of 20 tasks or 250 lines`.

**D9 for G13.** The installed MCP validator (1.1.22) applies 40 and 400 to every plan until a release carrying this change is installed. The planner's MCP self-check therefore does not report a plan between the two pairs; the contract tells the planner to hold a new plan to 20 and 250 itself, and preflight applies the new pair through the Python CLI route that `## Validator Gate` names, in a worktree whose tree carries this change.

**Result check.** In scope: every plan file of `FEATURE` (each K4 shape, and every other `plan*.md` or `remediation-plan*.md` name), and every plan path listed by the Epic #1019 kickoff: the folder under `docs/features/epics/` whose `epic.md` names `#1019`, read at the `refs/remotes/origin/epic/*` ref that holds it, each plan read at that ref or else at the remote branch that holds the path. The G13 outcome of a file is whether the Python CLI output for it carries a `plan size` finding. A file keeps its result when its outcome at its own path, after the change, equals its outcome under the legacy pair, which is the outcome of an identical copy under `SCRATCH` named `plan.2000-01-01T00-00.md`, and, for files recorded at [P0-T3], also equals the recorded outcome. Copies of #1019 plans keep their repository-relative path under `SCRATCH`, so the name and parent segments are unchanged.
