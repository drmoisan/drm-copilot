## Design Decisions

- **Shared scanner unchanged (owner question).** The shared option table `$script:CommandLineGlobalOptions` in `.claude/hooks/hook-command-invocation.ps1` (and its `.codex/hooks/` twin and bundle copies) is not edited. The helper reuses only the segmenter `Read-CommandLineInvocationSegment` (records with `Tokens`, `Depth`, `Origin`) and walks each record's tokens itself with a local Poetry option table. Reason: `Test-CommandLineInvocation` would classify `poetry -C <dir> install` as Indeterminate without a table entry, and `Skip-CommandLineTransparentWrapper` stops at the `VIRTUAL_ENV` operand of `env -u VIRTUAL_ENV`, so neutralization needs its own token pass in any case. Keeping the walk local leaves `git`, `gh`, and `npx` parsing untouched, so no existing assertion of the table changes: `tests/scripts/claude-hooks/hook-command-parser.AcceptanceCases.Tests.ps1`, `hook-command-invocation.Issue824Regression.Tests.ps1`, and the per-gate `*.TriggerScoping.Tests.ps1` suites keep disposition "unchanged, unaffected" and run in the P4-T5 gate (AC19).
- **Helper** `.claude/hooks/worktree-poetry-venv-policy.ps1`, byte-identical at `.codex/hooks/worktree-poetry-venv-policy.ps1`. Pure string logic, no environment, disk, or `$IsWindows` reads. Functions: `ConvertTo-WorktreePoetryComparablePath` (backslash to `/`, Git Bash `/c/` to `c:/`, trailing separators trimmed, lower-cased), `Test-WorktreePoetryPathWithin` (equal, or prefix plus `/` boundary, so `.venv-old` is not within `.venv`), `Join-WorktreePoetryTargetPath` (relative value joined to `cwd`), `Get-WorktreePoetryMutatingInvocation` (per record: skip `VAR=value`, `command`, `nohup`, `time`, `timeout`, and `env` with `-u NAME` arity, marking Neutralized when NAME is `VIRTUAL_ENV`; leaf word `poetry`; absorb `-C`/`--directory`/`-P`/`--project` with a value, inline `=` form included, and treat other dash tokens as standalone; subcommand in `install`, `sync`, `add`, `remove`, `update`; an earlier same-depth `unset VIRTUAL_ENV` record also neutralizes; the nearest earlier same-depth `cd <dir>` record supplies the cd value; Unbalanced or Opaque records are skipped), and `Get-WorktreePoetryVenvDenyReason -CommandText -Cwd -VirtualEnv` (returns the reason string or `$null`). Target precedence: Poetry directory option, then `cd` value, then `cwd`; a target that cannot be derived (missing `cwd` with a relative or absent override) allows.
- **Deny reason literal:** `WORKTREE_VENV_BLOCKED: a mutating Poetry command would write into the virtual environment named by VIRTUAL_ENV, which lies outside the target project. From the worktree root run env -u VIRTUAL_ENV poetry install to create the worktree's own in-project .venv; never repoint the main checkout's environment.`
- **Hooks.** `.claude/hooks/enforce-worktree-poetry-venv.ps1` copies the guard shape of `enforce-parallel-worktree-removal-gate.ps1` (bootstrap, guarded `Import-Module` of `HookPayload.psm1`, guarded dot-sources of `hook-command-scanner.ps1`, `hook-command-invocation.ps1`, and the helper; `Get-HookDependencyFailureDecision -ReasonPrefix 'WORKTREE_VENV_BLOCKED:'` first in the decision function; dot-source guard; tail). Seam `Get-WorktreePoetryVenvProcessValue` reads `VIRTUAL_ENV`; `Invoke-WorktreePoetryVenvDecision -ToolInputRaw [-VirtualEnv]` returns a deny dictionary or `$null` and reads `cwd` with `Get-ClaudeHookEnvelopeValue`; an invalid payload returns `$null` (fail-open). The entry point writes JSON only for a deny and returns 0; an allow writes nothing, because an emitted `allow` would bypass the permission prompt for every Bash call. The header comment states the hook is a guard against a known foot-gun, not a security control (AC9). The Codex twin `.codex/hooks/enforce-worktree-poetry-venv.ps1` is function-equivalent: same helper, payload read from stdin as `enforce-promotion-mcp-only.ps1` does, `cwd` from `payload.cwd` (existing Codex hooks read that field), no `HookPayload.psm1` import.
