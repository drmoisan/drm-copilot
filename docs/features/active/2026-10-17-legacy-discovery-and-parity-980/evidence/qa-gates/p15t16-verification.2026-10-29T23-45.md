## Execution decisions

- Same-process re-authorization. The service authorizes each request twice (once before capture, once after), so `HostServiceIO` remembers the references it latched and treats a re-authorization of the same grant within one gateway process as the same dispatch; only a different process (a new `HostServiceIO`) meets the latch as a replay. A gateway process serves exactly one request, so this admits no replay across processes.
- Spent grants. The latch is created immediately after the authorization is accepted, as the task specifies, so a request refused later for baseline drift, read scope or an unreadable baseline result has spent its one-use grant. The refusal suites state this per case (`spent=`); every refusal of the grant itself leaves the store unwritten.
- Fixed refusal vocabulary. The row-specific messages the task asks of `gateway.main` are six fixed strings that echo no argument, so the gateway still discloses no caller text; the default failure message is unchanged for every other failure.
- `InstalledHostStore.create_exclusive` is thin filesystem wiring and has no unit test, because a test would need a real file; the memory seam carries the behaviour and the P16-T4 comparison reads the module's coverage from the P16-T1 report.
- The `Clock` seam is the existing `service_contracts.Clock` alias; `gateway.utc_now` is public so the composition test can pin the clock the gateway passes.
