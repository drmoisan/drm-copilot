## Findings Under Remediation

### CI-614-001 — Pester byte-identity cases read the gitignored live checkpoint

`tests/scripts/codex-hooks/epic-execution-gates.Tests.ps1` line 274 builds the checkpoint path as `Join-Path $script:RepoRoot 'artifacts/orchestration/orchestrator-state.json'` and line 275 reads its bytes; line 291 re-reads them after the hook decision. `/artifacts` is gitignored (`.gitignore` line 6), so the file is absent in a fresh checkout and the six parametrized cases of the `It 'denies <Label> exactly without changing checkpoint bytes'` block at lines 266 through 293 raise `DirectoryNotFoundException` on the `poshqc / PowerShell QC` runner.

**Design determination (design (1) of the inputs is adopted; design (2) is inapplicable).** The hook resolves its repository root from its own script location, not from the process working directory: `.codex/hooks/enforce-epic-planning-only.ps1` line 85 sets `$script:EpicPlanningRepositoryRoot = Split-Path (Split-Path $PSScriptRoot -Parent) -Parent`, and line 321 assigns that value to `$repositoryRoot` before line 322 joins `artifacts/orchestration/orchestrator-state.json` onto it. Setting `WorkingDirectory` to a fixture repository root therefore cannot redirect that lookup. Furthermore the dot-source guard at lines 315 through 317 (`if ($MyInvocation.InvocationName -eq '.') { return }`) returns before the top-level block at lines 319 through 355, and the test helper `Invoke-EpicPlanningDecisionProcess` dot-sources the hook (`. $env:EPIC_PLANNING_HOOK_PATH`, line 26) and calls `Invoke-EpicPlanningOnlyDecision` with an explicit `-CheckpointRaw` argument, so the hook process reads no checkpoint file at all. The remediation therefore supplies the checkpoint text to the hook process from a committed fixture and takes the before and after byte reading from that same fixture, which is the file the assertion is about.
