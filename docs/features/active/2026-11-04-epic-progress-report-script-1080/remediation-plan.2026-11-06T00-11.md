## Design

CR-1 (feature-summary table only). `ConvertFrom-EpicProgressKickoffRow` in `scripts/dev-tools/Get-EpicProgressReport.Logic.ps1` gains a table gate. It initializes `$inFeatureTable = $false`; while the flag is false, each line only sets the flag to the result of `-match '^\|\s*(issue_num|issue)\s*\|'` (PowerShell `-match` is case-insensitive, so `issue_num`, `Issue`, and `ISSUE` all open the table) and continues. Once inside, a line that does not match `^\s*\|` ends the table with `break`, so every later table is ignored; the separator row and any other row whose first cell is not numeric are skipped by the existing `^\|\s*(\d+)\s*\|` match, which keeps the cycle-1 whitespace tolerance. Rows before the header are never read. The `.SYNOPSIS` and `.DESCRIPTION` help state that only the feature-summary table is read, name both header spellings, and state the end-of-table rule.

Nit (wave-cell overflow). The `^\d+$` check and `[int]::Parse` are replaced by one `[int]::TryParse($cells[3], [System.Globalization.NumberStyles]::None, [cultureinfo]::InvariantCulture, [ref] $wave)` call; on `$false` the existing terminating error `The kickoff row for issue #<issue> has a non-numeric wave cell '<cell>'.` is raised unchanged. `NumberStyles::None` admits ASCII digits only, so signs, separators, and values above `Int32` all take the error path.

Size. The change adds about five lines to the logic file (baseline 661 physical lines), so it stays below the 700 advisory tier; if P2-T5 records 700 or more, the self-review records the advisory-tier disposition (a non-blocking Warning; no split in this cycle because the file is below 800 and the change is confined to one function), and the plan does not fail on it.

Tests, all in `Describe 'ConvertFrom-EpicProgressKickoffRow'` of `tests/scripts/dev-tools/Get-EpicProgressReport.Logic.Tests.ps1`:

- `It 'returns only rows of the feature-summary table'`: kickoff text with an `| issue_num | feature_folder | wave | complexity | plan-path |` header (the repository spelling), a separator, rows `| 630 | f/a | 0 | C3 | docs/a/plan.md |` and `| 631 | f/b | 1 | C2 | docs/b/plan.md |`, a blank line, and then a `| wave | features | width |` table with separator and rows `| 0 | 630 | 2 |`, `| 1 | 631 | 1 |`, `| 2 | 632 | 1 |`. Asserts exactly two rows, issues `630,631`, waves `0,1`, and no blank `PlanPath`.
- `It 'ignores a numeric-first row with a non-digit wave position outside the feature table'`: kickoff text whose first table is `| id | note | detail | extra |` with row `| 7 | notes | n/a | more |` (the cell the parser reads as the wave is `n/a`), a blank line, then the `Issue` header fixture table with row `| 12 | Alpha | 1 | small | docs/a/plan.md |`. Asserts the call does not throw and returns one row with issue `12`.
- `It 'throws a clear error for a wave cell beyond the Int32 range'`: the `Issue` header, separator, and row `| 12 | Alpha | 99999999999 | small | docs/a/plan.md |`; asserts a throw matching `*#12 has a non-numeric wave cell '99999999999'*`. Before the change this throws the generic `OverflowException` text and fails.

Both header spellings are covered: `issue_num` by the first new test, `Issue` by the existing `$script:kickoffText` fixture and the second new test.
