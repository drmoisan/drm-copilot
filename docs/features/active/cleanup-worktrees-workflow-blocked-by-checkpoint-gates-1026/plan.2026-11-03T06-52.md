## Design Decisions Fixed by This Plan

These resolve the mechanism choices the spec leaves to the planner. Each is binding on the tasks below.

- DP1 Temporary-root seam: `Get-OrchestrationGateTemporaryRoot` returns the distinct non-empty values of `[System.IO.Path]::GetTempPath()`, `$env:TEMP`, `$env:TMP`, and `$env:TMPDIR`. `GetTempPath()` supplies the long-name spelling (measured in `reproduction-pr-leg.2026-11-03T12-12.md`); the session scratchpad spelling handed to the Write tool comes from the runtime's TEMP environment value, which carries the 8.3 short-name form. P0-T3 confirms this precondition before any code is written.
- DP2 Command leg: every chained segment must be `git -C <absolute value> add` or `git -C <absolute value> commit`. A segment without `-C` denies even when the session root is the consolidation worktree. This is stricter than the spec's optional session-root exception and keeps the prefilter process-free for every existing `git commit` test input.
- DP3 Patch leg: `Test-OrchestrationCleanupContextAllowed` admits an `apply_patch` manifest Add only when called with `-AllowPatchManifest`; only the Codex gate passes it.
- DP4 Dependencies: the preimplementation sibling dot-sources `hook-cleanup-context.ps1` and `hook-docs-only-diff.ps1`, and the PR-author sibling dot-sources `hook-cleanup-context.ps1` and imports `CleanupWorktreeManifest.psm1`, each in its own single-statement `try` recorded through `Add-HookDependencyFailure`. Each gate file gains exactly one guarded dot-source of its sibling.
- DP5 Literal names in `hook-cleanup-context.ps1` avoid the removal gates' `$script:CleanupWorktreeManifestPath`: `$script:CleanupContextBranch` (`documentationandmemories`), `$script:CleanupContextManifestRelativePath` (`artifacts/orchestration/cleanup-worktrees-manifest.json`), `$script:CleanupContextManifestTool` (`cleanup-merged-worktrees`), `$script:CleanupContextManifestSchemaVersion` (`1`), `$script:CleanupContextFreshnessHours` (`24`).
- DP6 PR-author cleanup context: the wrapper `Get-PrAuthorPreflightExemption` (same parameters and return shape as `Get-PrAuthorDocsOnlyExemption`) returns the docs-only result unchanged when it is exempt or when the matched `gh pr create`/`gh pr edit` segment carries no token that equals `documentationandmemories` or ends with `=documentationandmemories` or `:documentationandmemories` (ordinal). Inside the context it evaluates K1 to K6 and, on the first failure, returns the docs-only reason followed by `; cleanup exemption not applied: ` and the sub-code text. Sub-codes: `CLEANUP_EXEMPTION_NOT_CREATE` (K1), `CLEANUP_EXEMPTION_CHECKPOINT_PRESENT` (K2), `CLEANUP_EXEMPTION_HEAD_UNRESOLVED` (K3: exactly one `--head` token whose value is ordinal-equal to the branch), `CLEANUP_EXEMPTION_BASE_UNRESOLVED` (K4: `Get-PrAuthorDocsOnlyBaseName` returns exactly `main`), `CLEANUP_EXEMPTION_MANIFEST_INVALID` (K5), `CLEANUP_EXEMPTION_DIFF_FAILED`, `CLEANUP_EXEMPTION_EMPTY_DIFF`, and `CLEANUP_EXEMPTION_NON_ALLOWLISTED_PATH` (K6).
- DP7 Model-routing label rule (`Test-CleanupConsolidationBranchLabel`): exactly one `branch:` label line, its value ordinal-equal to the branch, and no `--head` or `--branch` token anywhere in the prompt.
- DP8 Codex entry tail: the mapped-record statement forwards `content` only when the tool name is `Write` (an `Edit` record forwards an empty string), as a line-neutral replacement.
- DP9 Codex pack manifest: `render_manifest` in `scripts/dev_tools/generate_codex_agent_variants.py` adds agent paths only, so the two new Codex hook paths are added to the Codex `core.json` by hand, after which the generator runs in write mode and then with `--check`. This corrects research Q7, which stated that new Codex files enter the manifest through the generator.
- DP10 Scratch rule extra fail-closed condition: `Test-CleanupScratchPath` returns `$false` when any registered worktree root lies under an accepted temporary-root spelling.
- DP11 Coverage of the Codex copy: `hook-cleanup-context.Tests.ps1` runs every case over both repository copies through `-ForEach`, so `.codex/hooks/hook-cleanup-context.ps1` is measured as its own production file.
