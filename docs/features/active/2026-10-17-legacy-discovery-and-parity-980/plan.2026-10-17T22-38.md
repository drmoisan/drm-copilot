## Size Justification

The feature changes versioned artifacts, an installable Python runtime, twelve analyzer adapters, protected native authority, three host integrations, four specialist roles, nine workflows, conversion, and publication. Independently verifiable transitions and complete baseline/final evidence require more than 40 tasks and 400 lines. Keeping these distinct avoids a single implementation or testing bucket. Each implementation task includes its own tests; final QA verifies integration and repository-wide invariants. The revision that adds Phases 12 and 13 closes the two escalated self-review rows (installed completion-receipt path, over-limit publisher files) with separately verifiable Python, TypeScript, packaging, installed-host, and final-QA transitions; folding them into fewer tasks would hide the security-sensitive refusal classes behind one bucket. The revision that adds Phase 14 corrects a schema-registry performance defect after Phase 13 evidence was partly written and after a rebase that changed the file-size policy; the existing task identifiers and checkboxes are preserved, so the re-run of every final gate on the changed, rebased tree is expressed as new tasks rather than as edits to recorded ones. The revision that adds Phases 15 and 16 answers a feature review with four blocking findings, one of which (the trusted-identity supplier) is a design change across three PowerShell hosts, the TypeScript gateway client and the Python runtime; each host adapter, schema, store partition, server consumer and probe control is a separately verifiable transition, and the final gates are re-run on the final tree as new tasks because the recorded Phase 14 gates describe a superseded tree. The revision that adds Phases 17 and 18 answers the cycle-1 re-review's Blocker with a cross-language contract fixture pinned on three sides, a fail-before run, the PowerShell probe correction, a real-filesystem cross-runtime smoke and a re-run of the mandatory gates for the touched languages; the Minor and the Nit of that review are deferred to follow-up issues by user decision, so the cycle stays small, and the recorded Phase 16 gates again describe a superseded tree.

Decision: canonical consumption representation. A one-use record the gate writes (`tool-authorization`, `root-grant`, the sentinel `host-observation`) is immutable once published; its `state` is `issued` as written, or `revoked`. Consumption by the MCP server is the exclusive sibling latch `<record>.json.consumed`, a JSON object naming the record's reference (`request_id`, `grant_ref` or `observation_ref`) and `consumed_at`. Dispatch by the Python runtime is the exclusive sibling latch `<record>.json.used` (`USED_LATCH_SUFFIX` in R/gateway_host.py, `create_exclusive` in R/gateway_host_store.py). Both are one convention, chosen because the Python side already uses it and the TypeScript consumers of root grants and sentinel grants already write it: the producer never rewrites the record and every reader decides from the latch. The consumer side therefore does not change; the probe is corrected to read the latch. Every reader treats a record as live only when its `state` is `issued` and no `.consumed` latch exists, and as consumed when the latch exists; the probe additionally requires the latch's `observation_ref` to equal the record's, so a latch beside the wrong record proves nothing. The tool-authorization `consume()` in ES/discovery-authorization.ts keeps its record rewrite, because `decode_authorization` in R/protected_records.py reads `consumed_at` from that record; the rewrite is a second consumer's input, not the consumption marker, and no task changes tool authorizations. The `state` enum of S2/host-observation.schema.json is unchanged; `consumed` stays admissible for a decoder but is never written by this repository. The probe does not parse `consumed_at` (the TypeScript consumer writes it with millisecond precision while the PowerShell timestamp parser reads the schema's second-precision spelling); the shared fixture pins the exact latch text instead.
