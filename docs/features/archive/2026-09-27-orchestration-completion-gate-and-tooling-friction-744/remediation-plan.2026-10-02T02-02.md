### Execution conventions

- Every command runs from the worktree root as one plain command. No command contains a pipe, heredoc, `cd` chain, or loop, and none contains the words the isolation guard refuses. File edits use the Edit tool.
- Every command-step rem1 artifact carries `Timestamp:`, `Command:`, `EXIT_CODE:`, and `Output Summary:`, with exactly one `Command:` and one `EXIT_CODE:` row (the task's primary command). Additional commands of the same task are recorded in the body under the heading `Companion commands`, each line indented by two spaces. An artifact whose primary command is expected to exit non-zero also carries `ExpectedExitCode:`. The four schema rows come first in the file. Companion exit codes are written as `exit=<n>` on the companion's line; no body line, indented or not, may begin (after leading whitespace) with `Timestamp:`, `Command:`, `EXIT_CODE:`, or `ExpectedExitCode:`, because both parsers strip leading whitespace from the key.
- No rem1 artifact contains a line that begins with `Timestamp: 2026-10-02T01-17` or with `Timestamp-Correction:`. Quoted command output is indented by two spaces. This keeps the evidence-folder searches in Phase 3 exact.
- Phase 0 rem1 artifacts are written to FEATURE/evidence/remediation-baseline/, which the PR-context collector does not read (`scripts/dev_tools/pr_context/verification_evidence.py` lines 24-28 glob only `qa-gates`, `regression-testing`, and `other`). Phase 3 and Phase 4 rem1 artifacts are written to FEATURE/evidence/qa-gates/ and are collected, so each must parse to `pass`.
- Phase 1 and Phase 2 write no artifact. P3-T1 therefore runs the collector over exactly the evidence set that existed at baseline.
- Collector outputs go under `artifacts/` (gitignored, `.gitignore` line 6), which is permitted for intermediate tool output and is not an evidence location.

### Why the correction does not change any PR-context result

Both parsers keep the first occurrence of `Timestamp`, `Command`, `EXIT_CODE`, and `ExpectedExitCode` and ignore any other key (`scripts/dev_tools/pr_context/verification_evidence.py` lines 121-133; `extensions/drm-copilot/src/lib/pr-context/verification-evidence.ts` lines 25 and 130-149). The corrected value stays on the existing first `Timestamp:` row (line 3 of every affected file). The key of CL, read up to its first colon, is `Timestamp-Correction`, which is not an accepted key. `Command:`, `EXIT_CODE:`, and `ExpectedExitCode:` rows are not touched, so every normalized result is unchanged. Of the 27 corrected files, 9 are collected (6 under `regression-testing/`, 3 under `other/`); the 18 under `baseline/` are not.
