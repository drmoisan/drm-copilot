## Source-of-Truth Divergence (binding — read carefully)

There are TWO Python source variants per command. The service invokes the **bundled** copies under `extensions/drm-copilot/resources/scripts/dev_tools/` (the template wrappers add `resources/scripts/` to `sys.path` and import `dev_tools.*`). The in-process TS port MUST reproduce the **bundled** copies' observable behavior, because that is what the current service path actually executes.

- Hard-lock: `extensions/drm-copilot/resources/scripts/dev_tools/resolve_hard_lock_prompt.py` is the authoritative behavior for `resolveExecuteHardLockPrompt`. It matches `scripts/dev_tools/resolve_hard_lock_prompt.py` closely (same `--target`/`--workspace`/`--template-kind`/`--template-root`/`--output`/`--quiet` contract; same `${plan-path}`/`${work-mode}`/`${fallback-reason}` substitution; same clipboard fallback; same `✓ Copied to clipboard` / `✗ Could not copy to clipboard` stderr lines; same `--quiet requires --output` hard error; exit 0 success, 1 on error). The executor MUST diff the two and replicate the bundled variant where they differ.
- File prompt (atomic-plan): `extensions/drm-copilot/resources/scripts/dev_tools/resolve_file_prompt.py` is the authoritative behavior for `resolveAtomicPlanPrompt`. It DIFFERS materially from `scripts/dev_tools/resolve_file_prompt.py`:
  - bundled `main()` accepts `--template` (required), `--target` (required), and `--workspace` (optional). It resolves the workspace root via `_resolve_workspace_root(--workspace)` (defaults to cwd) and the target via `_resolve_target_path(--target, workspace_root)` (absolute target used verbatim; relative target joined to workspace_root).
  - bundled `main()` checks template existence (error+return 1), target existence (error+return 1), reads template, calls `resolve_prompt(template_content, target_path, workspace_root)`, then: if `copy_to_clipboard` succeeds prints `Successfully resolved prompt and copied to clipboard.` then the resolved content (stdout) and returns 0; otherwise prints `Could not copy to clipboard; printing resolved prompt to stdout.` (stderr) then the resolved content (stdout) and returns 0. `main()` returns an int exit code.
  - the `scripts/dev_tools/resolve_file_prompt.py` variant's `main()` returns `None`, prints `Successfully resolved prompt and copied to clipboard.` (no content), and on clipboard failure prints `Clipboard copy not available; printing resolved prompt to stdout.` — this variant is NOT what the service runs and MUST NOT be the parity target for the service-method behavior. The executor MAY still mirror the pure `resolve_prompt` / `strip_front_matter` test scenarios from `tests/scripts/dev_tools/test_resolve_file_prompt.py` because the substitution logic (`resolve_prompt`, `strip_front_matter`, variable rules) is identical between the two variants; only the CLI `main()` shell differs.
- Both `resolve_prompt` implementations share the same supported variables and rules (enumerate from the source): `${file}`, `${folderpath}`, `${name}`, `${spec}`, `${user-story}` (annotated `(missing)` and clause-removal when absent), `${research}` (line removal when absent), `${work-mode}`, `${fallback-reason}`; front-matter stripping; minor-audit overrides (`_apply_minor_audit_overrides`: remove spec/user-story/research lines, insert the three-phase block after `## Core Requirements`); feature-foldername derivation (versioned `v*` leaf uses parent); `${name}` extraction from `yyyy-MM-dd-${name}-${issue}`; platform-agnostic path splitting; unresolved-placeholder safety check raising `ValueError`.

## Parity Notes (binding design decisions)

- **In-process wiring pattern.** Follow the F2/F4 precedent: keep `repo-automation-service.ts` thin by placing the in-process wiring in dedicated support modules. Create `extensions/drm-copilot/src/lib/resolve/resolve-prompts-service-call.ts` exposing two functions — `resolveExecuteHardLockPromptServiceCall(...)` and `resolveAtomicPlanPromptServiceCall(...)` — each returning the preserved `RepoAutomationExecutionResult`-shaped record. The service methods delegate to these, mirroring how `validateOrchestrationArtifacts` delegates to `validate-orchestration-service-call.ts`. This keeps `repo-automation-service.ts` under 500 lines.
- **Hard-lock template root and template selection.** The bundled wrapper injects `--template-root` = `<extensionRoot>/resources/customizations/.github/codex` when absent. The TS port MUST resolve this template root from the service's `extensionRoot` (the wrapper computed it as `Path(__file__).parent.parent / "customizations" / ".github" / "codex"`; in the in-process port the equivalent is `<extensionRoot>/resources/customizations/.github/codex`). Template selection: `--template-kind` defaults to `execute` → `execute-hard-lock.prompt.md`; `resume` → `resume-hard-lock.prompt.md`. The service currently passes only `--target`/`--workspace`/`--output`/`--quiet` (no `--template-kind`/`--template-root`), so the in-process port MUST default `templateKind` to `"execute"` and `templateRoot` to the bundled codex path, then probe `templateRoot/<name>` first and `<workspaceRoot>/.github/codex/<name>` as fallback (the `_resolve_template_path` deterministic order). On not-found, the port returns the error path (no output written) with the `Error: Template '<name>' not found. Checked locations:` message format and an error/exit-1 equivalent.
- **Atomic-plan template path.** The bundled atomic-plan wrapper injects `--template` = `<extensionRoot>/resources/customizations/.github/prompts/generate-atomic-plan.prompt.md` when absent. The in-process port MUST resolve this template path from `extensionRoot` and read it through the injected `FileSystem`. If the template file is missing, reproduce the `Error: Template file not found: <path>` + exit-1 behavior; if the target is missing, reproduce `Error: Target file not found: <path>` + exit-1.
- **MCP quiet path (no clipboard).** Per research Section 6.5, the MCP/extension service path for hard-lock passes `quiet: true` + `output`, so NO clipboard interaction runs. The atomic-plan service path is the bundled `resolve_file_prompt` behavior which DOES attempt clipboard, but in the in-process port clipboard MUST be implemented as an injectable, default-no-op-friendly seam (a `copyToClipboard?: (text: string) => boolean` callback) so that the service can pass a function that does not perform real OS clipboard I/O in the quiet/MCP path and tests remain hermetic. The clipboard fallback chain (pbcopy/wl-copy/xclip/xsel/clip/clip.exe via a resolved executable) MAY be implemented behind the same injectable seam using the F1 `CommandRunner`, but it MUST NOT execute on the quiet/MCP path and MUST NOT run in unit tests. Default the clipboard callback to a deterministic no-op-returning-false in the service quiet path so the bundled atomic-plan "Could not copy to clipboard; printing resolved prompt to stdout." branch is the deterministic outcome.
- **Hard-lock service return contract (preserved exactly).** `resolveExecuteHardLockPrompt` MUST continue to return `{ tool: "resolve_execute_hard_lock_prompt", workspaceRoot: input.workspaceRoot, summary: "Resolved the execute hard-lock prompt for '<target>'.", artifacts: [<normalized output path>] }` when `output` is provided. The output artifact path is computed exactly as the existing `buildResolveExecuteHardLockPromptArguments` does: `normalizeGeneratedPath(isAbsolutePathLike(output) ? output : path.join(workspaceRoot, output))`. When `output` is undefined, `artifacts` is omitted (undefined). The `quiet && output === undefined` combination MUST throw `resolve_execute_hard_lock_prompt: 'quiet' requires 'output' to be set.` BEFORE any file work (preserving the existing TS-layer guard message verbatim). When `output` is provided, write the resolved prompt to that path via the injected `FileSystem` (ensuring parent dir via `ensureDir`).
- **Atomic-plan service return contract (preserved exactly).** `resolveAtomicPlanPrompt` MUST continue to return `{ tool: "resolve_atomic_plan_prompt", workspaceRoot: input.workspaceRoot, summary: "Resolved the atomic-plan prompt for '<target>'." }` with no `artifacts` field (the current builder sets none). The atomic-plan service path does NOT write an output file (the bundled wrapper writes nothing; it prints to stdout). In the in-process port, the resolved prompt content is produced and surfaced via the injected `log` sink (the existing `this.output.appendLine`) rather than process stdout, preserving the observable "resolved" outcome without spawning Python. Do NOT add an output file for atomic-plan unless required to preserve an existing asserted artifact (none is asserted; confirm in P0).
- **`${plan-path}` value normalization (hard-lock).** `resolve_prompt` (hard-lock) resolves the target relative to the workspace root (`_try_relative_to_workspace`), converts to forward slashes via `_normalize_prompt_path_value` (replace `\\` with `/`), substitutes `${plan-path}`, then `${work-mode}` and `${fallback-reason}` resolved from the nearest `issue.md` (`_resolve_issue_file_for_target`: direct `<plan-dir>/issue.md`, else for `v*` plan dirs the parent `issue.md`, with fail-closed to `full-feature`). Reproduce this issue.md resolution exactly using the injected `FileSystem` and `prompt-mode-contract.ts` helpers.
- **File-prompt variable resolution (atomic-plan).** Reproduce `resolve_prompt` (file-prompt) exactly: `strip_front_matter`, `_try_relative_to_workspace`, `${file}` forward-slashed, `${folderpath}` = relative parent, `${name}` derived from feature foldername (versioned `v*` leaf → parent; `yyyy-MM-dd-name-issue` extraction), `${spec}` = `<folderpath>/spec.md`, `${user-story}` = `<folderpath>/user-story.md` or `<...> (missing)`, work-mode/fallback-reason from `<folderpath>/issue.md`, minor-audit overrides when mode is `minor-audit`, optional `${research}` line removal when missing, user-story clause removal when missing, then `_replace_all_variables` (sorted deterministic substitution + unresolved-placeholder safety check raising on leftover `${...}`). All path existence checks use the injected `FileSystem` (`isFile`), not real disk.
- **Line-removal and insertion helpers.** Port `_remove_lines_referencing_variable` (uses `splitlines(keepends=True)` semantics — preserve line endings; in TS split on `\n` keeping the trailing newline behavior so re-join is byte-identical), `_remove_user_story_clause_when_missing` (replace literal `" and the \`${user-story}\`"` with empty string), `_insert_after_heading` (insert block after first exact-trimmed heading match, ensuring a trailing newline on the inserted block), and `_apply_minor_audit_overrides` (remove `spec`/`user-story`/`research` lines then insert the exact `### Minor-Audit Mode Overrides (Mandatory)` block after `## Core Requirements`). The minor-audit block text MUST be byte-identical to the Python source (including the three phases `Phase 0 — Baseline Capture`, `Phase 1 — Handoff to small-path planning/development agent`, `Phase 2 — Final QC loop`).
