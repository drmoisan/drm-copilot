## Required Revisions

### FAIL #1 — Task `[P0-T11]` baseline inventory expects 10 matches but 11 exist on disk

**Discrepancy.** P0-T11 acceptance criterion states `Output Summary states "Occurrences: 10" and lists files \`feature-promotion-lifecycle/SKILL.md\`, \`pr-base-branch-merge-base/SKILL.md\`, \`execute-hard-lock/SKILL.md\``. Running the prescribed grep against the current tree returns 11 occurrences, not 10. The 11th occurrence is:

```
.claude/rules/powershell.md:57:- Organize tests to mirror code structure (e.g., `tests/scripts/dev-tools/ScriptName.Tests.ps1`).
```

This match is in `.claude/rules/powershell.md`, which is explicitly listed in the plan's Implementation Strategy Notes as a read-only file ("No-creation rule for source policy files. `.claude/rules/*.md` and `.github/instructions/*.md` are read-only in this plan."). It is also outside the spec.md Inputs/Outputs scope.

**Recommended remediation.** Modify P0-T11 to:

1. Update the acceptance criterion to expect `Occurrences: 11` (the current on-disk count), and require the Output Summary to enumerate the eleven occurrences across four files.
2. Add an explicit annotation in the Output Summary template that the `.claude/rules/powershell.md:57` occurrence is an out-of-scope reference (a documentation pattern in a read-only policy rule file, not an invocation reference) and is documented for awareness only.
3. Cross-link P0-T11 to the new exclusion required in P6-T1 (FAIL #2) so that the inventory baseline and the post-cleanup grep filter are consistent.

### FAIL #2 — Task `[P6-T1]` cleanup grep does not exclude `.claude/rules/powershell.md`

**Discrepancy.** P6-T1 runs the same regex set as P0-T11 against `.claude/**/*.md` and asserts `RESIDUAL_PRIMARY_SURFACE_MATCHES: 0`. The Python filter applied in the task only excludes line ranges inside the `### Fallback only — when MCP server is unreachable` subsections of `feature-promotion-lifecycle/SKILL.md`. The match at `.claude/rules/powershell.md:57` will not be excluded by that filter; it will appear in `filtered`, causing `RESIDUAL_PRIMARY_SURFACE_MATCHES: 1` and a non-zero exit code. The acceptance criterion will fail and AC #1 will not be marked PASS.

**Recommended remediation.** Modify P6-T1 to add a second documented exclusion for the policy-rule documentation reference. Two acceptable options:

1. **Path-scoped exclusion (preferred):** add a documented `EXCLUDED_POLICY_REFERENCE_PATHS` set containing `.claude/rules/powershell.md` and skip its matches in the `filtered` accumulation. The Output Summary must record this exclusion explicitly (path, reason: "policy rule file is read-only and the match is a documentation example of test layout, not an invocation reference"), per the spec.md Edge Cases requirement that exclusions be documented filters, not silent omissions.
2. **Pattern-scoped exclusion:** restrict the regex `scripts/dev[_-]tools` to require it be embedded in a backtick code span that begins with `poetry run python` or `${workspaceFolder}` (i.e., narrow the pattern to invocation-shaped occurrences). Document the narrowing decision as a filter rationale.

Either option must:
- update the Python script in P6-T1 to enumerate excluded paths in addition to excluded line ranges,
- update the artifact's required Output Summary to list both exclusion classes (subsection-range exclusion in `feature-promotion-lifecycle/SKILL.md` AND the path-or-pattern exclusion for `.claude/rules/powershell.md`),
- propagate the same exclusion model into the AC #1 evidence row in P14-T5 so the cross-reference holds.
