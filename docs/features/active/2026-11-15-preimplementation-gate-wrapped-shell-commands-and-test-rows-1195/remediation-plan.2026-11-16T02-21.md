## Design (F1)

`Get-OrchestrationGateWrapperPayloadText` in `CLASSIFY` strips `NAME=value` words and `env` with its value options only at the head of the segment, before its hop loop. When `env` follows another transparent prefix, `Get-CommandLineWrapperPayload` (shared module, unchanged) skips the prefix with `Skip-CommandLineTransparentWrapper`, which treats `-u` as a bare dash token and reads the option value as the command word, so no payload is found. The fix moves the prefix strip to the top of each hop of the existing loop and makes it repeat until the first word that is not a prefix:

1. a `NAME=value` word is skipped;
2. a word whose leaf is `env` is skipped together with its options by the existing env value-option rule (`-u NAME`, `--unset NAME`, `--unset=NAME`, `-C DIR`, `--chdir DIR`, `--chdir=DIR`, other dash tokens, and `NAME=value`), and the function returns nothing on `-S`, `--split-string`, or `--split-string=`;
3. any other transparent prefix (`timeout`, `time`, `command`, `nohup`) is skipped by calling `Skip-CommandLineTransparentWrapper -Token <rest> -Except 'env'` and advancing by its `Index` when `SkippedWrapper` is true, so the shared skip stops at the next `env` and step 2 handles it;
4. otherwise the strip ends and the remaining words go to `Get-CommandLineWrapperPayload` as now.

Because the strip runs at the top of every hop, `Kind` `Words` (xargs-injected words) receives the same treatment. The hop bound, the PowerShell flag scan, the encoded-command decline, and `Get-OrchestrationGateWrappedPatternIndex` are unchanged, and no function is added. Forms without an `env` after another prefix take the same path as before, because `Get-CommandLineWrapperPayload` skips the same prefix tokens that step 3 skips.
