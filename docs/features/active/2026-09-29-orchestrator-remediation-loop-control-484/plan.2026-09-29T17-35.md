## Resolved Spec Ambiguities

1. Batch-budget resets. Spec `## Assumptions, Constraints, Dependencies` (line 366, amended) permits deleting `.claude/state/<kind>-batch-budget.*.json` only at reset points this plan schedules, with evidence, under orchestrator decision OD-484-2 (recorded in the checkpoint). No hook file, hook test, or #769 file is edited.
2. TypeScript `{v}` rendering. Spec says TypeScript renders `{v}` with `pythonRepr` "as the existing human-interaction message does". The human-interaction module uses a file-local `pythonRepr` with `str()` semantics (`extensions/drm-copilot/src/lib/validate/orchestrator-state-human-interaction.ts`, the function at lines 55-66: `None`, `True`/`False`, otherwise `String(value)`), whereas the exported `pythonRepr` in `extensions/drm-copilot/src/lib/validate/parallel-state-shared.ts` quotes strings. Resolution: `orchestrator-state-remediation.ts` renders `{v}` and `{e}` with `str()` semantics identical to the human-interaction local helper, so `got: Pass` renders without quotes in all three runtimes (Python f-string, PowerShell `ConvertTo-PythonDisplayText`). The parity corpus enforces this.
3. "No reduction on changed lines" (spec AC-16). Resolution: for each edited pre-existing production file, whole-file line coverage is not below its baseline, and executable added lines are at least 85% covered; new files meet the 85% line / 75% branch thresholds as whole files.
4. Upstream-absent halt. Resolution: the executor writes a blocker artifact and stops; the orchestrator records the halt with `blocked_reason: "external_dependency"` when the tree's validator accepts that member, and otherwise records the halt reason in a free-form checkpoint key with a validator-accepted `blocked_reason`.
5. Pester naming. `tests/scripts/claude-runtime/test-name-uniqueness.Tests.ps1` fails when sibling `Describe`/`Context`/`It` names (including `-ForEach` expansions) differ only by letter case. Case-variant tests therefore name each case by a descriptive label or index, never by the raw literal alone.
6. R11 negative index. Python list indexing accepts negative integers; R11 treats any integer below 0 as out of range in all three runtimes.
