## 2. Candidate Approaches and Selection

### 2.1 Lock mechanism (question 3)

| Candidate | Assessment |
|---|---|
| A. OS file lock: `[System.IO.FileStream]` opened with `FileMode.OpenOrCreate`, `FileAccess.ReadWrite`, `FileShare.None` on a per-user machine-level file, held for the suite's lifetime by the launcher process | Works from PowerShell 7 on Windows and Linux with one code path. The OS releases the lock when the holder process exits for any reason, so a crashed holder never leaves a stale lock; only the holder metadata record can be stale. The FileShare documentation states: "Any request to open the file (by this process or another process) will fail until the file is closed." A non-blocking probe (open, catch `IOException`, close) gives the hook a read-only view of lock state. |
| B. Named `System.Threading.Mutex` with `Global\` prefix | Windows-native; on Linux .NET emulates named mutexes per user, and the `Global\` namespace semantics differ. Abandoned-mutex handling (`AbandonedMutexException`) is needed, the mutex must be released on the acquiring thread, and bash cannot observe it. |
| C. `flock(1)` from bash | Linux-only in practice; Git Bash on Windows does not interoperate with Windows file locks taken by .NET, so the hook and launcher would see different lock states on Windows. |

**Selected: A.** Rejected alternatives: B for cross-platform semantics and thread affinity; C for Windows. Unix behaviour of `FileShare.None` in .NET (advisory `flock`-style locking, which an opt-out environment variable can disable) is from recollection and not confirmed from documentation in this session; **CONFIRM** with one live two-process run on Linux (the devcontainer) recorded under `evidence/other/`.

Design details:

- Lock directory (outside every worktree): on Windows `[Environment]::GetFolderPath('LocalApplicationData')` joined with `drm-copilot/test-execution`; elsewhere `$XDG_STATE_HOME` or, when unset, `$HOME/.local/state`, joined with `drm-copilot/test-execution`. `XDG_RUNTIME_DIR` is not used because it is often unset in containers and CI. Files: `test-suite.lock` (held) and `test-suite.holder.json` (holder record, written by the holder after acquiring, opened with `FileShare.Read` so waiters can read it).
- Scope is per user per machine; a devcontainer and its host are separate machines for the lock. Agents run as one user, so per-user scope covers the observed incident.
- Holder record fields: `pid`, `processStartUtc`, `suite`, `commandLine` (the suite's command words), `worktreeRoot`, `acquiredAtUtc`, `policyVersion`.
- Stale-holder detection: when the lock probe reports busy, the waiter reads the holder record and asks the process seam for the start time of `pid`. A live process with a matching start time is the named holder; a missing process or a different start time means the record is stale and the holder is reported as "an unidentified process (stale record for pid N)". When the lock is acquirable and a record exists, the record is stale and is overwritten.
- Bounded wait: default `waitMilliseconds` 90000 and `pollMilliseconds` 2000, below the Bash tool default timeout of 120000 ms. The validator accepts `waitMilliseconds` from 0 to 540000 (below the 600000 ms maximum) and `pollMilliseconds` from 100 to 10000.
- Retry exit code: 75 (`EX_TEMPFAIL` in BSD `sysexits.h`, meaning a temporary failure the caller may retry). No existing script uses exit 75 (searched outside `docs/`). The code is a documented constant, not a configuration knob.
- Worker count: the launcher passes each suite's command words unchanged and adds no worker option; the pure command builder never emits `-n <k>`, `--maxWorkers`, `--runInBand`, `-p no:xdist`, or `-WorkerCount`, and the policy rejects those tokens in configured suite commands and in caller extra arguments (D9). The owner's parallel-only directive is consistent with this rejection.

## 3. Behavior Semantics

Launcher (`run-test-suite.sh <suite> [extra args]` / `Invoke-TestSuite.ps1 -Suite <suite> [-ExtraArgument ...]`):

1. Load policy: built-in defaults merged with the repository's `config/test-execution-policy.json` when present. An invalid file stops the launcher with exit 2 and a message that starts `TEST_EXECUTION_POLICY_BLOCKED:` and names the file and field.
2. Resolve the suite; an unknown suite name exits 2 with the known names listed.
3. Classify the extra arguments: an argument that selects an excluded lane (a path operand whose file name ends with a configured lane suffix, a pytest `-m` expression that selects a lane marker without `not`, a Pester `-Tag` of a lane tag, a `--filter` naming a lane category) exits 2 with `TEST_EXECUTION_POLICY_BLOCKED: local <lane> lane is CI-only evidence (test-execution policy)`. A worker-reduction token exits 2 likewise.
4. Build the command: suite command words, then the lane-exclusion arguments for that runner, then the extra arguments.
5. Acquire the lock: probe; if busy, read the holder, poll every `pollMilliseconds` until acquired or `waitMilliseconds` elapses. On timeout print `TEST_EXECUTION_QUEUE_TIMEOUT: test-execution policy allows one suite per machine; lock held by <holder description>; waited <ms> ms; retry later.` to stderr and exit 75. `machineLock.enabled: false` skips this step.
6. Write the holder record, start the suite with inherited standard streams, wait, release the lock (dispose the stream in `finally`), delete the holder record, and exit with the suite's exit code. For `pester`, the exit code is the `ExitCode` property of the `Invoke-PoshQCParallelTest` result.

Hook (`enforce-test-execution-policy.ps1`, PreToolUse):

- Bash: for every record from `Read-CommandLineInvocationSegment`:
  - A sanctioned launcher invocation (the script path ends with `skills/test-execution-policy/scripts/run-test-suite.sh` or `skills/test-execution-policy/scripts/Invoke-TestSuite.ps1`) is allowed unless its arguments select an excluded lane or reduce workers (same pure classifier as the launcher). The launcher, not the hook, queues on the lock, so a second launcher waits and then exits 75.
  - A direct runner invocation outside the launcher (`pytest`, `python -m pytest`, `poetry run pytest`, `npx jest`, `node run-jest.cjs`, `npm test`, `npm run test`, `npm --prefix <dir> run test`, `Invoke-Pester`, `Invoke-PoshQCTest`, `Invoke-PoshQCParallelTest`, `Invoke-PoshQCSuite`, `bats`, `shell-qc.sh test`, `dotnet test`, including inside `sh -c` and `pwsh -Command` payloads) is denied with `TEST_EXECUTION_POLICY_BLOCKED: test suites run only through the test-execution launcher ...`, naming the launcher command for that suite and, when the lock is held, the holder.
  - A script-file operand (`sh`, `bash`, `zsh`, `dash`, `ksh` with a file operand; `pwsh` or `powershell` with `-File`; `python`, `python3`, or `poetry run python` with a `.py` operand; `node` with a `.js`/`.cjs`/`.mjs` operand other than `run-jest.cjs`) that is not the sanctioned launcher is read through a seam (cap 262144 bytes, path resolved against the payload `cwd`). Shell and PowerShell text is parsed structurally (the shell lines through `Read-CommandLineInvocationSegment`, PowerShell text through the PowerShell parser's command AST); Python text matches `pytest.main(` or a quoted `pytest` command word; a runner invocation inside the file is denied as a hidden wrapper suite launch. An unreadable or oversized file is allowed (policy-level guard, same fail-open stance as `enforce-worktree-poetry-venv.ps1`).
  - Non-test PowerShell through `SCRATCH` `sh` launchers (analyzer, `Invoke-PoshQCLeakScan`, format) stays allowed.
- MCP: `mcp__drm-copilot__run_poshqc_test` and `mcp__drm-copilot__run_poshqc_suite` are denied while the lock probe reports busy, with the holder named. When the lock is free they are allowed; until the extension release that carries the template change (D7), such a run does not itself hold the lock.
- Invalid configuration: every test-runner or launcher command is denied with a message naming `config/test-execution-policy.json` and the field; non-test commands are unaffected.
- `requireLauncher: false` disables the direct-runner and hidden-wrapper denials; `localLanes.exclude: []` disables lane denials; `machineLock.enabled: false` disables the MCP busy denial and the launcher queue.

Edge cases: an empty or whitespace command allows; a malformed payload allows (fail open, documented); `Opaque` records with `DecodeFailure` on a PowerShell host are denied only when the visible text names a runner word (mention test), otherwise allowed; a launcher whose suite command itself is a runner is never re-scanned; the holder record of the current process is never reported as a foreign holder.

## 4. Decisions (adopted as recommendations)

- **D1. Lock mechanism.** OS file lock (`FileStream`, `FileShare.None`) on `test-suite.lock` in the per-user state directory described in 2.1, with a separate `test-suite.holder.json` record. Alternatives: named `Global\` mutex, `flock(1)`. Reason: one cross-platform implementation whose lock disappears with the holder process.
- **D2. Policy configuration.** Optional repository file `config/test-execution-policy.json`, `version: 1`, merged over built-in defaults; absent file means defaults. Schema:
  - `localLanes.exclude`: array of lane names; default `["integration", "golden"]`.
  - `lanes.<name>.pytestMarkers`, `lanes.<name>.pesterTags`, `lanes.<name>.mstestCategories`, `lanes.<name>.fileNameSuffixes` (case-insensitive ordinal suffix match on the file name). Defaults: integration = `integration`, `Integration`, `Integration`, suffixes `.integration.test.ts`, `.integration.test.js`, `_integration.py`, `.integration.tests.ps1`; golden = `golden`, `Golden`, `Golden`, suffixes `.golden.test.ts`, `.golden.test.js`, `_golden.py`, `.golden.tests.ps1`.
  - `machineLock.enabled` (default `true`), `machineLock.waitMilliseconds` (default 90000, range 0 to 540000), `machineLock.pollMilliseconds` (default 2000, range 100 to 10000).
  - `requireLauncher` (default `true`).
  - `suites.<name>`: `{ "workingDirectory": "<repo-relative>", "command": ["<word>", ...], "runner": "pytest|pester|jest|mstest|bats" }`. Built-in suites: `pytest` (`poetry run pytest -n auto`), `pester` (PoshQC module import plus `Invoke-PoshQCParallelTest`, exit with its `ExitCode`), `jest` (`node run-jest.cjs` in the repository root), `dotnet-test` (`dotnet test`).
  - This repository's file adds suffixes `-integration.test.ts` and `integration.tests.ps1` (to cover `collector-integration.test.ts`, `DocsCompleteIntegration.Tests.ps1`, `DocsReferenceIntegration.Tests.ps1`, `codex-pretooluse-integration.Tests.ps1`), and suites `jest-extension` (working directory `extensions/drm-copilot`, `node run-jest.cjs`) and `bats` (`bash scripts/bash/shell-qc.sh test`).
  - The file is repository-owned and not pushed down (it would overwrite a destination's file, because `config/` publication is a plain overwrite). Alternatives: pushed-down config file (overwrites destination settings); settings in `pyproject.toml`/`package.json` (language-specific). Reason: defaults travel with the code, overrides stay local.
  - Defaults change by design (lanes excluded, one suite per machine, launcher required); there is no other knob.
- **D3. Validator.** Pure function `Test-TestExecutionPolicyDocument` returning an error list (unknown top-level key, wrong `version`, non-array or blank entries, lane names in `localLanes.exclude` absent from `lanes`, out-of-range integers, absolute or `..` paths in `workingDirectory`, empty `command`, worker-reduction tokens in `command`), plus `Get-TestExecutionPolicy` that merges and throws a message naming the file and field. A Pester contract test validates the committed `config/test-execution-policy.json` (the `FileSizePolicy.RepoGate.Tests.ps1` precedent). Alternative: JSON Schema file (no schema validator dependency exists in the PowerShell path). Reason: same fail-fast style as `Get-PoshQCScanConfigFolder`.
- **D4. File layout.**
  - Pure logic, dot-sourced, byte-identical in both hook folders: `.claude/hooks/test-execution-policy.ps1` and `.codex/hooks/test-execution-policy.ps1` (config defaults, merge, validation, lane classification, worker-token check, suite command builder, runner recognition over parsed records, hidden-wrapper text classification), and `.claude/hooks/test-execution-lock-decision.ps1` / `.codex/hooks/test-execution-lock-decision.ps1` (pure lock decision). Precedent: `hook-epic-fan-in.ps1` and `enforce-epic-merge-gate-review.ps1` are byte-identical twins.
  - Thin I/O adapter, byte-identical twins: `.claude/hooks/test-execution-lock.ps1` and `.codex/hooks/test-execution-lock.ps1` (directory resolution from injected environment values, probe, open-and-hold, holder record read and write, process start-time query through `Get-Process`). ## 6. Testing Implications (question 7)

- Pure modules are tested by dot-sourcing the hook-folder helper; inputs are strings, hashtables, and scriptblock seams. No temporary files: config text, script-file text, and holder records are in-memory strings passed through `ReadText` seams; the lock adapter's file calls go through `OpenLockStream`, `ReadHolderText`, `WriteHolderText`, and `GetProcessStartUtc` seams that tests replace.
- Lock waiting: the driver loop takes `Clock` and `Sleep` scriptblock seams; tests supply a clock that advances by `pollMilliseconds` on each `Sleep` call and assert the decision sequence (for example 45 `Wait` decisions then `Timeout` at 90000 ms with the defaults). No real wait.
- Hook tests feed PreToolUse JSON strings to the decision function (the `Invoke-WorktreePoetryVenvDecision` pattern) with seams for lock probe, config text, and script-file text; cases: each runner word bare, inside `sh -c`, inside `pwsh -Command`, inside `-EncodedCommand`; launcher allowed; launcher with a lane path, a lane marker, a worker token; hidden `sh` script, `pwsh -File` script, `.py` script, unreadable script; MCP tool busy and free; invalid config; malformed payload; dependency-load failure. ## Pre-Mortem

- Review checklists: a reviewer can find a denial path that is not tested, such as an `-EncodedCommand` payload, a `.py` hidden wrapper, or a Codex MCP payload. Mitigation: the plan enumerates every Section 3 branch as a named Pester case in the hook and twin tests, and the self-review maps each deny code to a test name.
- Coverage: new PowerShell files can miss 85% line coverage because adapter code is I/O-bound, and local coverage of production files reached only through the integration-named tests drops once lanes are excluded. Mitigation: keep the adapter thin with every call behind a seam; confirm the coverage population includes the new files; cite the CI coverage step for files covered only by excluded lanes, as D13 requires.
- Mirror parity: the brief, atomic-plan-contract, qa-gate, invoke, agent, settings, config.toml, PoshQC, template, and skill copies span more than forty files across `.claude`, `.agents`, `.github`, `.codex`, and `extensions/drm-copilot/resources`. Mitigation: one task per surface family that writes all copies, followed by the contract tests in Section 7, the Codex generator `--check`, and `test_poshqc_bundled_parity.py`; the plan's brief-update task names all six copies.
- File size: `PoshQC.Testing.psm1` is already large, and the hook helper could grow past 500 lines with every runner shape. Mitigation: read the current sizes and the baseline entry first; use the four-file split in D4; put lane parameters in a small helper if the Testing module is near a tier.
- Test isolation: hook tests that read real config, real lock directories, or `$env:LOCALAPPDATA` leak machine state between files sharing a shard. Mitigation: all environment, file, and process reads go through seams; no test sets environment variables without a paired restore; `Invoke-PoshQCLeakScan` runs in the gate; bats uses checked-in stubs only.
- CI-only behavior: the Linux hook-suite job runs `tests/scripts/claude-hooks` and `tests/scripts/codex-hooks` on a case-sensitive file system, and directory resolution differs by OS (`LocalApplicationData` versus `XDG_STATE_HOME`). Mitigation: resolution is a pure function of injected values with both OS branches tested; forward-slash relative paths and exact file-name case in fixtures; no drive letters.
- Evidence: launcher and hook messages contain absolute worktree paths and pids, and a queue timeout (exit 75) during a gate can be mistaken for a failure. Mitigation: evidence artifacts record `SCRATCH` and repository-relative paths only and redact holder paths; a gate that exits 75 is re-run after the holder finishes and is recorded append-only with `ExpectedExitCode` used only where the plan intends a non-zero result.
