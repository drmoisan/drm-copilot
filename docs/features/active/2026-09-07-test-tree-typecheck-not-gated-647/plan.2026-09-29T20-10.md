## 0. Rules binding on every task

1. **Symbols.** `FEATURE` = `docs/features/active/2026-09-07-test-tree-typecheck-not-gated-647`. `<ts>` = the execution timestamp in `yyyy-MM-ddTHH-mm` format. `BASE_SHA` and `HEAD_SHA` = the values [P0-T14] records; the executor substitutes the recorded 40-character values into every command that names them.
2. **Evidence location and schema.** Every artifact is written under `FEATURE/evidence/<kind>/` with `<kind>` one of `baseline`, `regression-testing`, `qa-gates`, `other`. Every command-step `.md` artifact carries `Timestamp:`, `Command:`, `EXIT_CODE:`, and `Output Summary:`. An artifact whose command is expected to exit non-zero also carries `ExpectedExitCode: <n>`. `EXIT_CODE: SKIPPED` is never a passing outcome, and no task in this plan authorizes a skip.
3. **No host data.** No artifact, test, or document contains an absolute filesystem path, drive-letter host path, user-profile path, or account name. Where a command prints such a value, the artifact replaces the worktree root with `<WORKSPACE_ROOT>`. Raw Jest output is not persisted; the artifact copies only the `Test Suites:`, `Tests:`, and coverage summary lines. Raw `tsc` output is persisted as `.log` files because `tsc` run from the worktree root prints repository-relative paths only (verified in the 2026-09-29T20-15 baseline log).
4. **Command route.** Every command runs in the Bash tool (Git Bash) from the worktree root. No command uses `cd`. No command text contains `pwsh`, `bash`, `wsl`, a heredoc, `${PIPESTATUS}`, or any shell variable other than `$?`; the agent-worktree guard refuses these (verified at preflight). Placeholders are replaced with literal text before running. Exit codes are captured by appending `; echo "EXIT=$?"` (for tsc, `; echo "TSC_EXIT=$?"`). Commands use `node`, `npm`, `git`, `grep`, `sed`, `sort`, and `actionlint`. `node` and `npm` are outside the atomic-executor frontmatter patterns but are required, because the worktree root has no `node_modules`; the execution session must allow them, as the 2026-09-29 preflight session did. The exit-code suffix applies to every command in this plan whether or not the task text shows it; "exit code N" in an acceptance condition means the printed `EXIT=N` (or `TSC_EXIT=N`) value. An acceptance condition stating that a command or pipeline "prints no line" excludes the appended `EXIT=` line.
5. **Prohibited constructs (spec constraints).** No added `any` (`: any`, `as any`, `<any>`, `any[]`), no `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, or `eslint-disable` of any form, no `require` in new code, no temporary files in tests, no `.skip`/`.only`/`xit`/`xdescribe`/`xtest`, no removed or changed assertion. No `tsconfig*.json`, `jest.config.cjs`, `run-jest.cjs`, or ESLint configuration file is written. If a diagnostic appears to require a suppression, the executor stops as BLOCKED and follows `.claude/rules/typescript-suppressions.md` lines 17 to 21; it does not add the suppression.

The executor never works around a hook. The alternate artifact-writing route in rule 14 is authorized by this plan and is not a workaround.
11. **Procedure R-DIAG (per-phase type-check evaluation).** Every phase-check task runs the `tsc` command it names in the form `<tsc command> > <log> 2>&1; echo "TSC_EXIT=$?"`, and then evaluates the log with these Bash commands, substituting `<log>`, `<prev>`, and `<list>` with the paths the task names. `<paths>` is `<log>` with `.log` replaced by `.paths.txt`; `<prev-paths>` is `<prev>` with `.log` replaced by `.paths.txt` (created by the previous phase's R-DIAG run, or by [P0-T15]).
    - Log: `<tsc command> > <log> 2>&1; echo "TSC_EXIT=$?"`
    - Distinct paths: `grep -oE '^extensions/drm-copilot/[^(]+\([0-9]+,[0-9]+\): error TS' <log> | sed -E 's/\(.*//' | sort -u > <paths>`
    - PHASE_HITS: `grep -cF -f <list> <log>`. PREV_PHASE_HITS: `grep -cF -f <list> <prev>` (positive control; must be > 0).
    - NEW_PATHS: `grep -vxF -f <prev-paths> <paths>`; no output means none.
    - TOTAL: `grep -c 'error TS' <log>`; PREV_TOTAL: `grep -c 'error TS' <prev>`.
    - `grep -c` prints 0 and exits 1 on no match; the printed number is the recorded value, and that exit status is not a failure.
    - Gate: `PHASE_HITS` 0, `PREV_PHASE_HITS` > 0, `NEW_PATHS` none, `TOTAL` < `PREV_TOTAL`.

    The artifact records `TSC_EXIT`, `PHASE_HITS`, `PREV_PHASE_HITS`, `NEW_PATHS` (the list, or `none`), `TOTAL`, and `PREV_TOTAL`. A `PREV_PHASE_HITS` of 0 means the phase list does not match the previous log (for example a malformed list line), so the gate cannot discriminate; it stops execution as BLOCKED. Because each phase's `<prev>` is the previous phase's log, the set of files carrying diagnostics shrinks monotonically from the Phase 0 log, and no file outside the baseline set can gain a diagnostic unnoticed.
12. **Phase file lists.** Each `FEATURE/evidence/other/phase-N-files.txt` holds one line per phase file in the form `extensions/drm-copilot/<path>(`, with LF line endings and no blank line. The trailing `(` makes each line match only that file's `tsc` diagnostic prefix.
13. **Jest counts.** A Jest artifact records the `Tests:` summary line verbatim, and the values `PASSED` and `FAILED` read from it (`FAILED` is 0 when the line has no `failed` term). `FULL_BASE_PASSED` is the `PASSED` value [P0-T23] records.
14. **Artifact writing route.** Every `.md` artifact and every phase file list (rule 12) is written with the Write tool: the executor runs the command in the Bash tool, captures the printed output, and writes the artifact from it (applying rule 3). A `.log` or `.paths.txt` artifact is written by the Bash `>` redirection its task names. Whether the repository hooks accept a Bash `>` redirection into `FEATURE/` was not verified at preflight. If a hook denies that redirection, the executor re-runs the same command without the `> <path>` or `> <path> 2>&1` redirection (keeping the exit-code suffix), captures the printed output, and writes it to the same path with the Write tool. If the Bash tool reports that captured output was truncated, the executor stops as BLOCKED (rule 10), because a truncated log would understate `TOTAL`. A denial of the Write route stops execution as BLOCKED.
