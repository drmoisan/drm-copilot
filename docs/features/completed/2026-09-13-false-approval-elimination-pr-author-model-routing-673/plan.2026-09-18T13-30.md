## 2. Design

### 2.1 Outcomes (both hook families)

| Resolution state (F1) | Action | Reason text begins with |
| --- | --- | --- |
| `SessionRoot` or `OtherWorktree` | proceed with the **absolute** path `Join-WorktreeResolutionPath -WorktreeRoot <target.WorktreeRoot> -RepoRelativePath (Get-OrchestratorStateCheckpointRelativePath)`; all existing decision logic runs unchanged | existing reasons only |
| resolved, checkpoint absent / not ready / empty / unparseable | existing deny, unchanged | `ORCHESTRATOR_STATE_PREFLIGHT_FAILED` (pr-author) or `MODEL_ROUTING_RECEIPT_BLOCKED` (model-routing) |
| `NoTarget` | deny | the value of `$target.ReasonCode`, which F1 sets from `Get-WorktreeResolutionNoTargetReasonCode` (`TARGET_WORKTREE_NOT_DERIVABLE`) |
| `Ambiguous` | deny | the value of `$target.ReasonCode`, which F1 sets from `Get-WorktreeResolutionAmbiguityReasonCode` (`TARGET_WORKTREE_AMBIGUOUS`) |

There is no cwd fallback on any branch. A target-resolution deny reason never contains `ORCHESTRATOR_STATE_PREFLIGHT_FAILED` or `MODEL_ROUTING_RECEIPT_BLOCKED`, and an existing-reason deny never contains either `TARGET_WORKTREE_` code (AC-15).

### 2.2 Design decisions

- **DD-1 — one accessor for the repo-relative checkpoint location.** AC-4 forbids any relative checkpoint-path assignment in `enforce-pr-author-skill.ps1`, and AC-7 forbids the token `artifacts/orchestration/orchestrator-state.json` in executable code of the four in-scope hook files. The absolute path still needs its repo-relative operand, and no existing module exposes it: the only other definition is the parameter default at `.claude/lib/orchestrator-state/OrchestratorState.psm1:427`, which must not be modified (499 lines). This plan therefore adds `.claude/lib/orchestrator-state/OrchestratorStateCheckpointLocation.psm1`, exporting one function, `Get-OrchestratorStateCheckpointRelativePath`, consumed by both hook families. A unit test pins it equal to the `OrchestratorState.psm1:427` default so the two definitions cannot drift. Cost, planned explicitly: a bundled mirror copy, a `core.json` `paths[]` entry, an `OrchestratorState.Manifest.Tests.ps1` `ExpectedPaths` entry, and a `CodeCoverage.Path` entry in both runsettings copies. Rejected alternative: a named script-scope constant in a hook file, which would require restating both AC-4 and AC-7.
- **DD-2 — resolve once, pass explicitly.** In `Get-PrAuthorBypassReason`, after the resolution step returns a path, `$script:OrchestratorStateCheckpointPath` is assigned that absolute path (AC-4's specified form: `$null` at `enforce-pr-author-skill.ps1:49`, absolute after resolution). Making the reader's parameter mandatory forces every direct caller to supply it, which is why the direct-call test rows change under AC-19 form (a) (§3.3).
- **DD-3 — model-routing seam mirrors the #687 seam.** New `Resolve-ModelRoutingWorktreeTarget -PromptText` calls `Resolve-WorktreeCallTarget -Text $PromptText -SessionRoot (Get-Location).Path`, the same call shape as `helpers:61`. New `Get-ModelRoutingTargetCheckpointResolution -PromptText` maps the four states exactly as §2.1. - **DD-5 — test construction.** See §4.

### 2.3 The relative feature-folder consequence and the caller contract (model-routing)

A repository-relative feature-folder token is looked up in every worktree reachable from the session root (`WorktreeTargetResolution.psm1:229-230`); with more or fewer than exactly one candidate it resolves `Ambiguous` (`:290-292`). The superseded plan observed 12 candidates for this feature's own folder (`payload-derivability-results.md:92`). Under the 2026-09-18 ruling this deny is intended: the gate cannot tell which of the matching worktrees the delegation concerns, and answering from any one of them is the defect this feature removes. A relative token still resolves when it matches exactly one worktree.

A gated delegation is allowed to reach the receipt check only when its `prompt` carries at least one signal that places in exactly one worktree and no signal that places elsewhere. Callers must supply one of:

1. the item's feature folder as an **absolute** path inside the item's own worktree (preferred);
2. an absolute path to a file inside the item's worktree — only the **first** absolute file path in the prompt is read (`WorktreeTargetResolution.psm1:57`, `:203-207`), so an earlier absolute path outside any worktree (for example a scratchpad file) makes the call `Ambiguous`;
3. a `branch: <name>` label naming a branch checked out in exactly one worktree (`:61`).

The contract is stated in the hook's comment-based help by [P7-T2] and in the deny reason text. Callers of the pr-author gate supply `--head <branch>` (#687).

## 4. Test construction

- **Why committed fixtures cannot be real worktrees.** Git refuses to track any path containing a `.git` component, so a committed fixture root cannot carry the worktree marker F1's upward walk looks for (`WorktreeResolution.psm1:228-256`). Real derivation of an absolute path inside a committed fixture places it in the executing checkout instead. Rows whose verdict depends on checkpoint content therefore inject the derivation **result** through the hook's resolution seam, built with F1's own constructor `New-WorktreeResolutionTargetResult` (`WorktreeTargetResolution.psm1:66`), while the checkpoint reader and the rest of the decision path run unmocked. Rows whose verdict does not depend on content (R2, R5, R8, the relative-token row) use real, unmocked derivation, which is deterministic for those payloads: no signal returns `NoTarget` before any filesystem read (`:282-284`); a relative token against a fixture session root returns zero candidates because the fixture has no administrative directory (`WorktreeResolution.psm1:360-364`); an absolute path under a drive-root folder that does not exist has no marker on its ascent.
- **AC-9 and AC-10.** The two R2 rows run the hook out of process with the working directory set to a committed fixture session root that holds a ready sibling checkpoint, with no mock of any kind. They mock neither the checkpoint reader nor the derivation.
- **No temporary files.** All fixture content is committed under `tests/fixtures/worktree-resolution/`. Committed repository content is not a temporary file, so the prohibition in `.claude/rules/general-unit-test.md` is not engaged. No test creates a file or directory; no test uses `TestDrive`, `New-TemporaryFile`, or a temp path.
- **Out-of-process spawn.** Follows `enforce-pr-author-skill.OrchestratorStatePreflight.Tests.ps1:91-114`: the parent sets `CLAUDE_TOOL_INPUT` and restores it in `finally`; the child is `& <pwsh> -NoProfile -Command <script>`. The child script sets **both** `Set-Location -LiteralPath <fixture>` and `[System.Environment]::CurrentDirectory = <fixture>` before dot-sourcing the hook by absolute path (spec trap 1: `Get-PrBodyFileBytes` uses `[System.IO.File]::ReadAllBytes`). When a seam result is injected, the child redefines the seam function after the dot-source.
- **Coverage.** Out-of-process execution is not instrumented, so every new production line is also exercised by an in-process row (R5, R8, R9, R10, the reason-code separation rows, the AC-17 rows, and the path-capture rows).
- **Fixture schema coupling.** The pr-author fixture checkpoints are the checkpoint recorded verbatim at `evidence/baseline/repro-fixture-manifest.md:53-100`, which was observed to pass `Invoke-OrchestratorStatePreflight` with no errors. `tests/fixtures/worktree-resolution/README.md` and the head comment of the pr-author test file name the two sources a fixture must satisfy: `REQUIRED_STATE_KEYS` and `OrchestratorStateUnconditional.psm1`.
- **Determinism of receipts.** The fixture receipt `created_at` is `2099-01-01T00:00:00Z`, strictly newer than any checkout time of the context file. `.gitattributes:1` (`* text=auto eol=lf`) keeps the body bytes LF on every checkout, so the recorded SHA-256 holds.
- **Pre-fix isolation.** In-process rows that mock `Resolve-ModelRoutingWorktreeTarget` register the mock inside their own `It` (or inside a `Context` holding only in-process rows), because that function does not exist before [P7-T2]; a Describe-level registration would fail the out-of-process rows in the [P4-T5] pre-fix run for an unrelated reason.
