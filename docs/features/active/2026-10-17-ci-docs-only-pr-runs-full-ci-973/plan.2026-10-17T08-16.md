## Conventions for This Plan

- `FEATURE` abbreviates `docs/features/active/2026-10-17-ci-docs-only-pr-runs-full-ci-973`. Evidence is written under `FEATURE/evidence/<kind>/` as `<name>.<timestamp>.md`, the stamp read from the UTC clock immediately before the write; a consuming task selects the lexicographically greatest `<name>.*.md`. No artifact records an absolute path, a drive letter, or a host name.
- `SCRATCH` resolves to `<session scratchpad>/issue-973/`. Every scratch file this plan uses lives under it and its file name starts with `issue-973-`. Artifacts record the token `SCRATCH`, never a host path. No `.ps1`, `.psm1`, or `.psd1` scratch file is created or changed with Write or Edit.
- Tool routes, launchers, command-text restrictions, the batch budget, hook context, and CI shape are those of `.claude/skills/execution-environment/SKILL.md` (the brief); this plan does not restate them. PowerShell commands run through the brief's `## PowerShell Route and PoshQC MCP Limits` route; Pester counts come from `artifacts/pester/pester-junit.xml`, per-file line coverage from `artifacts/pester/powershell-coverage.xml`, analyzer findings from a direct analyzer run with `scripts/powershell/PoshQC/settings/pssa.settings.psd1`. No count, percentage, or finding is read from a PoshQC MCP result.
- Pester runner and CI job: every Pester acceptance condition is observed in a local run on the executor's Windows host; the CI job that runs the same suites with coverage is `poshqc / PowerShell QC` (shards on `windows-latest`). No acceptance condition relies on `poshqc / PowerShell hook suites (Linux)`.
- Batch budget: two production PowerShell files are written (`scripts/ci/CiChangeScope.psm1`, `scripts/ci/Invoke-CiChangeScope.ps1`), under the direct-mode cap. The brief copies are Markdown and do not count.
- Scope comparisons anchor on the merge base of `origin/main` and `HEAD` (written `MB` below), never on `origin/main` itself. `scripts/dev-tools/run-actionlint.ps1` may create an untracked `tools/` directory (not gitignored); it is never staged and is excluded from every porcelain assertion.
- Test purity: files under `tests/` written by this plan create no temporary files, start no process, change no environment variable, and use test-local fake invokers passed through `-GhInvoker`, `-GitInvoker`, `-OutputWriter`, and `-ReadVariable`; no blanket mocks. Helpers live in `BeforeAll`.
- AC numbering: `AC-n` denotes the n-th checkbox of `FEATURE/spec.md` `## Acceptance Criteria` in document order (AC-1 to AC-26); `spec.md` carries no IDs and its criterion text is never changed. AC check-off follows `.claude/skills/acceptance-criteria-tracking/SKILL.md`. AC-24 and AC-25 are CI-dependent and AC-26 is post-merge; executors never check them off.
