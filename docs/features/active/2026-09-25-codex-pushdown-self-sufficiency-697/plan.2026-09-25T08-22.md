## 1. Binding execution rules

1. **Evidence location.** Every artifact is written under `docs/features/active/2026-09-25-codex-pushdown-self-sufficiency-697/evidence/<kind>/` with `<kind>` one of `baseline`, `regression-testing`, `qa-gates`, `coverage`, `other`. `coverage` is required by AC-6.3 and has the canonical `<FEATURE>/evidence/<kind>/` form. File names use `<name>.<yyyy-MM-ddTHH-mm>.md`; `<ts>` in a task stands for that timestamp. No artifact is written under `artifacts/baselines/`, `artifacts/qa/`, `artifacts/coverage/`, or `artifacts/evidence/`. Tool output files that tools write on their own (`artifacts/python/coverage.json`, `artifacts/pester/powershell-coverage.xml`, `extensions/drm-copilot/coverage/lcov.info`) are inputs that evidence artifacts quote; they are not evidence locations.
2. **Artifact schema.** Every command-step artifact carries `Timestamp:`, `Command:`, `EXIT_CODE:`, and `Output Summary:`. An `[expect-fail]` artifact additionally carries `ExpectedExitCode: <int>` in its own file. `EXIT_CODE: SKIPPED` is never a passing outcome.
3. **No host data.** No artifact, test, fixture, or document may contain an absolute path, a drive letter, a user-profile path, or an account name. Where a command prints one, the artifact replaces the worktree root with `<WORKSPACE_ROOT>` and the session scratchpad with `<SCRATCHPAD>`.
4. **No commits inside this plan.** Files created by a task are untracked for the rest of the plan. Therefore `git grep` is never used against a file this plan creates; plain `grep` (or `Select-String`) is used instead, and every name-listing `git diff` is paired with a `git status --porcelain` span in the same task.
5. **Grep patterns beginning with `-`** are always supplied through `-e`.
6. **Mirror lockstep (AC-6.1).** A source file with a copy under `extensions/drm-copilot/resources/` is copied to that mirror in the same phase and before any test that reads the mirror runs. Mirror copies are made with `Copy-Item -LiteralPath <source> -Destination <mirror> -Force` in a PowerShell process, never with Write or Edit, so they consume no batch-budget slot.
7. **Batch-budget resets.** `.claude/hooks/enforce-powershell-batch-budget.ps1` and `.claude/hooks/enforce-python-batch-budget.ps1` deny the fourth distinct production or test file of a kind per session (`.ps1`, `.psm1`, and `.psd1` count for PowerShell; `tests/**` decides test versus production). A reset deletes `.claude/state/<kind>-batch-budget.<session_id>.json`. The hook resolves `<session_id>` in this order (`.claude/hooks/enforce-powershell-batch-budget.ps1:139-173`): the `CLAUDE_SESSION_ID` environment variable; else the trimmed contents of `.claude/state/current-session-id`; else a worktree-derived identifier `worktree-<leaf>-<8 hex>` built from the root's leaf name and a SHA-256 of its normalized path. The executor may additionally locate the state file by searching `.claude/state/<kind>-batch-budget.*.json` for the one whose `prodFiles` or `testFiles` array contains the last file this plan wrote; that search is a locator only and does not replace the hook's resolution order. Scheduled resets are [P6-T1], [P6-T11], and [P7-T1]. **Standing rule:** whenever a remediation edit would be the fourth distinct file of a kind in the current session, perform an unscheduled reset first and record it the same way (`evidence/other/batch-budget-reset-<n>.<ts>.md`, with the repository-relative path deleted and a `Test-Path` result of `False`).
8. **Write-mode commands** state the literal their clean run prints, or a before-and-after tree observation, in the task text.
9. **Coverage commands** name importable dotted modules with `--cov=<dotted>` and pass `--cov-report=term-missing`.
10. **Temporary files in tests are prohibited.** Seams are the in-memory filesystem doubles, non-existent path strings, committed fixtures, and the bundle-location hook probe whose derived root has no `config/` directory. No task creates a temporary directory. The only non-committed file this plan creates is the corpus generator script of [P6-T2], which lives in the session scratchpad, is not a test, and is not committed.
11. **Red before green.** For AC-1.1/AC-1.5, AC-2.4, AC-3.1, AC-4.11, AC-4.13, AC-4.16, and AC-5.2 the failing run is recorded as `[expect-fail]` evidence before the fix. No whole-suite run occurs before Phase 12, so no whole-suite gate can observe a deliberately red test.
12. **PoshQC MCP tools** return a fixed summary composed before the child runs. They are called only as the policy route-compliance step and their disposition is recorded. Every asserted count, percentage, finding, or per-test result comes from a readable on-disk artifact or from captured console output of a self-hosted `Import-Module ./scripts/powershell/PoshQC/PoshQC.psd1 -Force` invocation.
13. **Pester runs** use `pwsh -NoProfile -Command '$r = Invoke-Pester -Path <file> -Output Detailed -PassThru; exit $r.FailedCount'` (single-quoted so the calling shell does not expand `$r`). The success-case summary line, observed in the recorded full-suite run of issue #554, has the form `Tests Passed: 3818, Failed: 0, Skipped: 9, Inconclusive: 0, NotRun: 0`; acceptance conditions read the `Failed:` value from that line.

## 2. Design decisions and interpretations

1. **AC-2.4 hook set.** AC-2.4 requires synthetic PreToolUse payloads. Codex delivers PreToolUse payloads only to registrations under `[[hooks.PreToolUse]]`. The bundle `.codex/config.toml` registers 21 unique hooks (research §12 N1): 17 under PreToolUse (`:119-234`) and 4 under other events (`authorize-root-epic-invocation.ps1` UserPromptSubmit `:100-107`, `record-subagent-routing-attestation.ps1` SubagentStart `:109-117`, `validate-codex-subagent-routing.ps1` and `validate-feature-review-coverage.ps1` SubagentStop `:236-252`). The probe invokes the 17 PreToolUse hooks with every candidate tool name (`Bash`, `apply_patch`, `Edit`, `mcp__drm_copilot__run_poshqc_format`) that each hook's own matcher admits, which is 41 invocations (5 x 1 + 5 x 4 + 8 x 2 registrations). A derivation test asserts 17 probed plus exactly those 4 excluded equals 21, so no registration escapes classification.
2. **Hook fix (item 3).** Remove `.codex/hooks/enforce-epic-planning-only.ps1:86-88`. Add `[string] $RegistryPath = (Join-Path $script:EpicPlanningRepositoryRoot 'config/orchestration-handoff-registry.json')` to `Invoke-EpicPlanningOnlyDecision`. Replace `:272-273` so that the lifecycle check runs first; only when it is false and `$toolName -like 'mcp__*'`, a missing registry returns `Get-EpicPlanningDenyDecision` with the reason `semantic MCP registry '<RegistryPath>' does not exist; registry-dependent MCP tool '<toolName>' is denied in preparation mode.`, and a present registry is read with `Get-EpicPlanningRegisteredMcpTool` (which still throws for an invalid registry into the existing `catch`, exit 2). The reason therefore contains the literal `does not exist`. The bundle copy is replaced by `Copy-Item`.
3. **Malformed-registry fixture (AC-3.8).** `tests/fixtures/codex-hooks/invalid-orchestration-handoff-registry.json` holds valid JSON `{"version": 1, "semantic_tools": {}}` plus a trailing LF. `Get-EpicPlanningRegisteredMcpTool` throws `semantic MCP id '...' is not registered.` for it (`enforce-epic-planning-only.ps1:65-68`). Valid JSON is chosen so no JSON formatter or parser in the repository fails on a committed fixture.
4. **Shared module source (item 4).** New byte mirror `extensions/drm-copilot/resources/lib/codex-routing/{CodexTopology,CodexDeployment}.psm1`, read through the bundle parent like `resources/config` (research §2.4).
5. **Publisher generalization.** Both publishers replace the single-path virtual class with `VIRTUAL_RESOURCE_PAIRS` (destination-relative, resource-relative) and `VIRTUAL_ROOT_FOLDERS = (config, .codex/lib/codex-routing)`; `PUBLISHED_ROOT_FOLDERS` becomes `(.codex, .agents, config, .codex/lib/codex-routing)`. Pairs: the three `config/*.json` files map to themselves; `.codex/lib/codex-routing/CodexTopology.psm1` maps to `lib/codex-routing/CodexTopology.psm1`; `.codex/lib/codex-routing/CodexDeployment.psm1` maps to `lib/codex-routing/CodexDeployment.psm1`. A virtual root answers `list_files`/`listFiles` from the pair map only and never from the physical tree. `ROOT_FOLDERS` keeps its value `(.codex, .agents)` (asserted by `codex-agents-customizations.test.ts:118`).
6. **Wrapper structure.** A shared helper `.codex/scripts/codex-routing-cli-common.ps1` holds the module-candidate list, the candidate resolver, the GNU token parser, and a Python-compatible JSON serializer, so the two wrappers do not duplicate that logic. Each wrapper (`.codex/scripts/Resolve-CodexTopology.ps1`, `.codex/scripts/Resolve-CodexDeployment.ps1`) dot-sources the helper with `. (Join-Path $PSScriptRoot 'codex-routing-cli-common.ps1')`, defines `Invoke-CodexTopologyCli` / `Invoke-CodexDeploymentCli -Arguments <string[]> [-ModuleCandidates <string[]>]` returning `[pscustomobject]@{ ExitCode; Stdout; Stderr }`, and ends with a dot-source guard `if ($MyInvocation.InvocationName -eq '.') { return }` followed by a five-line entry that calls the function with `$args`, writes `Stdout` with `[Console]::Out.Write`, writes `Stderr` with `[Console]::Error.Write`, and `exit`s with `ExitCode`. The entry block is covered in process by [P6-T6] (`& <wrapper> @argv` with `[Console]::SetOut` and `[Console]::SetError` string writers, reading `$LASTEXITCODE`), so no wrapper line is left to child-process-only execution. The helper adds a fifth item-4 path to `core.json`; AC-5.1's list of four is a subset of the published set, and "every other transitive dot-source dependency" in AC-5.1 covers the helper.
7. **Wrapper contract.** Module candidates, in order: `Join-Path $PSScriptRoot '../lib/codex-routing/<Module>.psm1'`, then `Join-Path $PSScriptRoot '../../.claude/lib/codex-routing/<Module>.psm1'`. No existing candidate: exit 1 with stderr `CODEX_ROUTING_MODULE_NOT_FOUND: none of the candidate module paths exist: <c1>; <c2>`. Parsing: `--flag value` and `--flag=value`; `--language` appends; `--cross-cutting` takes no value; the last occurrence of a single-value flag wins; an unknown flag, a positional token, a missing value, a missing required flag, an invalid choice, or a non-integer count exits 2 with an stderr line containing `error:` and empty stdout. Counts parse with `[int]::TryParse(<token>, [System.Globalization.NumberStyles]::Integer, [System.Globalization.CultureInfo]::InvariantCulture, [ref] $n)`. When no `--language` is given the wrapper passes `[string[]]@()`, never `$null` (`CodexTopology.psm1:159-164` rejects a `$null` member). A module `System.ArgumentException` exits 1 with its message on stderr and empty stdout. `-AvailableModel` is not exposed.
8. **JSON serializer.** Output equals Python `json.dumps(receipt, indent=2, sort_keys=True)` with `ensure_ascii=True`: keys sorted with `[System.StringComparer]::Ordinal`, two-space indent, `": "` between key and value, `,` plus newline between members, arrays one element per line and `[]` when empty, `null`/`true`/`false`, integers with `ToString([System.Globalization.CultureInfo]::InvariantCulture)`, strings with `\"`, `\\`, `\b`, `\f`, `\n`, `\r`, `\t`, `\u00XX` for other characters below 0x20, and `\uXXXX` (lowercase hex, one escape per UTF-16 code unit) for every character above 0x7E. A `[string]` value is tested before `[System.Collections.IEnumerable]`. The built-in `ConvertTo-Json` is not used, because its non-ASCII escaping is unverified (research §16).
9. **Argument delivery contingency.** Whether `pwsh -File <script> --flag value` delivers `--flag` to `$args` unchanged is unverified (research §16). [P6-T15] settles it by process invocation. If the process-level parity run shows token loss or alteration while the in-process run passes, the entry block is changed to take its tokens from `[Environment]::GetCommandLineArgs()` after the element equal to the script path, the root and bundle copies are re-copied, and the observation is recorded in `evidence/other/wrapper-argument-delivery.<ts>.md`. Under that contingency the token extraction lives in a helper function `Get-CodexRoutingCommandLineArgument -CommandLine <string[]> -ScriptPath <string>` in `.codex/scripts/codex-routing-cli-common.ps1`, unit-tested with injected arrays, and the in-process entry cases of [P6-T6] assert that the entry writes exactly the streams and exit code that `Invoke-Codex*Cli` returns for the token list the helper derives from the host command line. The same applies if the in-process `& <wrapper> @argv` splat of [P6-T6] is observed to alter `--` tokens. No other design change is authorized by that contingency. **Observation recorded at preflight round 2:** the reviewer tested both paths directly. The in-process `& <wrapper> @argv` and `pwsh -NoProfile -File` through `ProcessStartInfo.ArgumentList` each delivered every token unchanged, including `''`, `--`, `--flag=value`, and `é` (code point 233). The contingency is therefore not expected to trigger. The one quirk outside the contract is that `-File` splits `--flag:value` into two tokens. No corpus record in [P6-T2] or [P6-T3] uses the colon form, so no gate depends on it.
10. **Prepack anchoring (scope addition B).** `shouldCopy` keeps the `.py` exclusion and replaces the segment regex with an anchored check: `path.relative(SOURCE_DIR, source)` normalized to `/` equals `scripts` or starts with `scripts/`. `module.exports = { SOURCE_DIR, shouldCopy }`, and `cpSync` runs only inside `if (require.main === module)`. `packages/mcp-server/package.json` runs it as `node prepack.cjs` (`:38`), so the guard is true in packaging. `packages/mcp-server/package.json` is not modified (AC-6.6).
11. **Prepack test runner (AC-4.14 versus AC-6.6).** `packages/mcp-server` has no test runner, and AC-6.6 forbids adding one. The test is placed in the extension Jest suite at `extensions/drm-copilot/test/packaging/mcp-server-prepack.test.ts` and loads the module with `require("../../../../packages/mcp-server/prepack.cjs")`. The configuration admits it: `extensions/drm-copilot/jest.config.cjs:4` `testMatch: ["**/test/**/*.test.ts"]` matches the file, `:8` transforms only `.tsx?` so the `.cjs` is loaded by Node's CommonJS loader untransformed, and no `roots` key restricts resolution. The same mechanism is already in use: `extensions/drm-copilot/test/jest-config-resolution.test.ts:36-37` requires `../jest.config.cjs` behind a pre-authorized `// eslint-disable-next-line @typescript-eslint/no-require-imports -- <reason>` line. CI executes this suite: `.github/workflows/_drm-copilot-extension-tests.yml:30` runs `npm --prefix extensions/drm-copilot run test`. The test directory deviates from the mirror rule of `.claude/rules/general-unit-test.md` because the mirrored location has no CI runner; this is recorded here as the reason. `prepack.cjs` sits outside `collectCoverageFrom` (`jest.config.cjs:17`, `src/**/*.ts`); AC-6.3 names Python, TypeScript, and PowerShell production files, so the CommonJS script's coverage is reported as a branch-by-branch case list in [P13-T7] rather than as a percentage.
12. **AC-4.13 red run without side effects.** The prepack test installs `jest.spyOn(nodeFs, "cpSync").mockImplementation(() => undefined)` on the object returned by `require("node:fs")` before requiring `prepack.cjs`, then asserts zero calls. Against the unfixed module the spy is called once and does nothing, so the red run copies no file.
13. **Non-ASCII corpus value.** The corpus stores the non-ASCII `--language` value as the JSON escape `\u00e9`, so both corpus files are pure ASCII with LF endings. `* text=auto eol=lf` (`.gitattributes:1`) alters neither, and no `.gitattributes` exemption is needed. The test for [P6-T2] asserts this byte property.
14. **Empty `--language` token.** The corpus passes `--language` followed by an empty string token. `ProcessStartInfo.ArgumentList` quotes an empty element; delivery through `pwsh -File` is covered by the contingency of item 9.
15. **Role-file key allowlist (AC-1.2).** The observed top-level keys across the three role-file sets are `name`, `description`, `developer_instructions`, `model`, `model_reasoning_effort`, `default_permissions`, and the `skills` table (`.codex/agents/orchestrator.toml:5`, `:198`); research §5 adds the documented optional keys `sandbox_mode` and `nickname_candidates`. The allowlist is exactly these nine. `variant` and `mcp_servers` are excluded.
16. **Routed role files (AC-1.4).** A file is routed when its stem is a family of `GENERATED_AGENT_FAMILIES` (`scripts/dev_tools/resolve_codex_deployment.py:32-47`, 12 families) optionally followed by `-c1`, `-c2`, `-c3`, `-c3-elevated`, or `-c4`, or is `epic-planner` or `epic-orchestrator`.
