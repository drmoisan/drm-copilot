- Adopted defaults from `spec.md` `## Open Decisions for Confirmation` (not overridden by the user):
  1. Strict ratchet: a baselined file that shrinks must have its entry tightened; the gate fails otherwise.
  2. Per-file `<= 500` Pester assertions are kept; `It` names, `-Because` strings, and comments that call 500 the repository cap are reworded. General (directory-discovered) size gates switch to the shared 800 hard limit: `ClaudeLibModuleConvention` (named by the decision) and, by the same rule, `codex-epic-runtime-contracts`, whose row discovers every `.codex/hooks`, `.codex/scripts`, and `.codex/agents` file and would otherwise be a competing gate that fails AC2. The test tree is searched for each `It` name before it is renamed.
  3. The over-800 population is re-derived by the generator at the merge base; the generator output is the authoritative baseline content. This plan states no baseline count.
  4. `.psd1` is not covered.
- Design corrections to `spec.md`, confirmed against the tree: `.codex/agents/feature-review.toml` is hand-edited (it is not in `GENERATED_AGENT_FAMILIES` in `scripts/dev_tools/resolve_codex_deployment.py`); the generator `scripts/dev_tools/generate_codex_agent_variants.py` reads the hand-edited base `.codex/agents/<family>.toml` (not `.claude/agents/*.md`) and writes the bundle base, the five variants per family, and the agent entries of the Codex `core.json` (`render_manifest` appends agent paths only, so hook entries are added by hand and `--check` confirms no drift). Codex hooks cannot reach `.claude/lib` in a consumer repository, so the Codex twin of the policy module is the dot-sourced `.codex/hooks/file-size-policy.ps1` (the Codex shared-module convention named by `SharedModuleNames` in `legacy-codex-hook-contracts.Tests.ps1`), held to function-level identity with the Claude module by a parity test. Repository-level ratchet evaluation and baseline JSON handling are repository-internal and live in `scripts/ci/FileSizeBaseline.psm1` (not shipped); the single-entry ratchet comparison stays in the shared module as the spec states. `.claude/lib/file-size-policy` is a new project under rule R4 of `discover_projects` in `scripts/dev_tools/quality_tiers_contract.py` and needs a `quality-tiers.yml` entry.
- Shared module API (names fixed here): `Get-FileSizePolicyLimit` (Guidance 500, Advisory 700, HardLimit 800), `Get-FileSizeLogicalLineCount` (split on `\r?\n`; a trailing terminator adds no line; empty content is 0), `Get-FileSizeTier`, `ConvertTo-FileSizeRelativePath` (returns `$null` for a path outside the repository root), `Test-FileSizeCoveredPath` (allowlist `.py .ps1 .psm1 .ts .tsx .js .cjs .mjs .cs .sh .bats`; excluded segments `.git node_modules artifacts coverage dist out virtual docs build .venv venv env __pycache__ .pytest_cache .mypy_cache .ruff_cache .tox .nox htmlcov .vscode-test` and the prefix `.claude/worktrees/`), `Compare-FileSizeBaselineEntry`, `Resolve-FileSizeEditContent` (replacement approach of `Resolve-EditedCheckpointContent` in `.claude/hooks/enforce-completion-consistency.ps1`, including `replace_all`), `Get-FileSizeHookDecision`. Hook reason prefix: `FILE_SIZE_LIMIT_BLOCKED:`.
- A path outside the repository root (for example a `SCRATCH` throwaway script) is not covered; this realizes the throwaway-script exemption mechanically.
