## Design

- New sibling `.claude/hooks/validate-orchestrator-output-target.ps1` (dot-sources and imports nothing) holds:
  - `Resolve-OrchestratorOutputItemTarget`: returns `$null` when the artifact type is not `orchestrator-state`, the assistant text is blank, or `Test-OrchestratorOutputCheckpointLeafShape` rejects `-CheckpointPath` (so the empty-output and leaf-shape blocks read nothing, as today). Otherwise calls `Resolve-SubagentStopTargetWorktree` with the parsed envelope, no advertised path, the session root, and only the bound seams, and returns `{ Status, WorktreeRoot, ReasonCode, Detail, FallbackNote, FallbackApplied = $false }`. Status: `Resolved` for source `DelegationPrompt` with a root; `NoTarget` for `TARGET_WORKTREE_NOT_DERIVABLE`; `Ambiguous` for `TARGET_WORKTREE_AMBIGUOUS`; `Fallback` for source `SessionRoot` (no transcript, no prompt identity, or a resolver exception).
  - `Resolve-OrchestratorOutputItemOperandTarget`: maps that object to the operand-target shape that `Resolve-OrchestratorOutputCheckpointPath` consumes. `Resolved` gives the item root; `NoTarget`/`Ambiguous` give an unresolved target with the reason code and detail, and nothing is read; `Fallback` calls `Resolve-WorktreeOperandTarget -Path ''` with the session root (today's call, so a subdirectory cwd still ascends) and sets `FallbackApplied`.
  - `Get-OrchestratorOutputFallbackNote`: returns `''` unless `FallbackApplied`; otherwise text starting with the token `ORCHESTRATOR_CHECKPOINT_FALLBACK:` and stating that no target worktree is identifiable from the delegation prompt (no `branch:` label or canonical issue line) and the session worktree checkpoint is validated, including the resolver-failure detail when present.
  - `Write-OrchestratorOutputAllowNote`: writes a non-empty `Note` of an allow result through an injectable writer (default `[Console]::Error`).
- `Resolve-OrchestratorOutputCheckpointPath` (resolution sibling) gains optional `-ItemTarget`; the item branch uses `Resolve-OrchestratorOutputItemOperandTarget` when it is non-null, else the unchanged call. Epic and parallel branches are untouched.
- Main hook (minimal, separated edit for PR #1146, issue #1139, which merged into `main` during planning): guarded loads of `subagentstop-target-worktree.ps1` and the new sibling placed directly after the resolution-sibling load and before the module imports (so the final module instances are unchanged); `Invoke-OrchestratorOutputValidation` gains optional `-ReadTranscriptHead` and `-WorktreeListInvoker`, computes the item target, passes `ItemTarget` to `Get-OrchestratorOutputBlockDecision` (one new optional parameter, forwarded to the resolver), appends the fallback note to a block message before the halt line, and returns `Note` on allow (`Message` stays `$null`); the entry tail calls `Write-OrchestratorOutputAllowNote` before `exit 0`.
- Unresolved item targets keep today's block: `ORCHESTRATOR_CHECKPOINT_UNRESOLVED: orchestrator-state: <Status> (<ReasonCode>): <detail>`, non-repairable, so the #903 re-entry policy blocks once.
- Premise correction (research row 5): a prompt with a `branch:` label is placed without the checkpoint issue reader, so branch-versus-issue disagreement is not an Ambiguous source; Ambiguous arises from two distinct canonical issue lines, a branch checked out in two worktrees, or an issue recorded by two worktrees.
- `.agents/skills/orchestrate/SKILL.md` and its bundle copy are not edited: Codex registers no orchestrator checkpoint stop hook (research section 4). AC-7 "all copies" is read as both copies of the Claude skill.
