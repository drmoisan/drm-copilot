## Pre-Mortem

- Review checklists: reviewers look for case-insensitive comparisons on Python names, a configuration value in a property or message, an `&` call through a variable, a broad `catch`, and a production file excluded from coverage. Prevented by the module rules in `## Execution Context`, the marker-value and case properties in [P4-T6], the guard suite in [P5-T3], and the template walk in [P6-T14].
- Coverage: recognizers and diagnostic rows multiply branches; a module below 85% fails `poshqc / PowerShell QC`. Each classified form has a positive test and each diagnostic row its own test; per-file figures come from `artifacts/pester/powershell-coverage.xml` in [P6-T4]; `config/poshqc-coverage.json` already measures `.claude/lib` and no file is excluded.
- Mirror parity: a stale bundle copy or missing `CORE` entry fails `Docs.Manifest.Tests.ps1` and the push-down contract tests; [P5-T1] copies after the last edit, [P6-T1] repeats the copy after any formatter rewrite, and [P6-T7] re-runs the tests. The plan alters no fact the execution-environment brief states (no CI job, required context, tool route or batch-budget rule changes), so no brief-update task is needed.
- File size: the lexer, syntax and CLI modules could pass 500 lines. The spec module split is kept, [P6-T9] records each count, and a module reaching 500 lines is split into a new module with its own suite, mirror copy, `CORE` entry and classification row.
- Test isolation: `-Force` imports and dot-sourced entry scripts leave modules and culture state behind. Every suite removes its modules and restores `CurrentCulture` in `AfterAll`; [P6-T5] performs three seeded shuffled file-order runs of the touched Pester suites with each seed recorded, and [P6-T6] a fresh single-process run over `tests/scripts`. No Jest or Python test is added, so the seeded Jest shuffle and the reversed-order Python run are not applicable.
- CI-only behavior: CI runs Pester on `windows-latest` with its own PowerShell and `Test-Json` version and checks out with `eol=lf`. CRLF cases exist only as escapes or in-code strings ([P6-T10]), envelope tests assert validity rather than messages, sorting is ordinal, and no test reads gitignored `artifacts/` state.
- Evidence: golden values computed by the code under test prove nothing; [P2-T3] computes them with a helper that loads no `LIB` module and records it. Every evidence path is `FEATURE/evidence/<kind>/<name>.<timestamp>.md` with the UTC write time and records `SCRATCH`, never a host path.
