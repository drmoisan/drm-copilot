When the guard refuses it, the executor writes that exact one-line pwsh command into a script file in the session scratchpad directory (outside the repository, never inside the worktree) and runs it with `sh <that script file>`. The artifact `Command:` field records the pwsh command line and the `sh` wrapper, and `EXIT_CODE:` is the wrapper's exit code, which is pwsh's exit code. `Invoke-Pester` without `-EnableExit` or `-CI` can exit 0 while tests fail, so the acceptance for these tasks relies on the printed `Tests Passed: N, Failed: 0` summary line; do not add `-CI`, because it writes a test results file into the working directory. The same fallback (scratchpad script run via `sh`) applies to any other command the guard refuses. A guard refusal is never a SKIPPED outcome. The scratchpad script is not a repository file and is not a deliverable.

**Exit-code expectation rule:** one artifact carries one `ExpectedExitCode`. The baseline format check is expected to fail with exit code 2 and is recorded in its own artifact with `ExpectedExitCode: 2`.
