## Design Summary

- F1: `Write-DocsFileText` and `Write-DocsContextText` in `.claude/lib/docs/Invoke-DocsCommand.ps1` declare `[CmdletBinding(SupportsShouldProcess = $true)]`. `Write-DocsFileText` wraps directory creation and the stream write in a `$PSCmdlet.ShouldProcess` gate; `Write-DocsContextText` forwards, so `-WhatIf` and `$WhatIfPreference` reach the primitive. The inert `PSUseShouldProcessForStateChangingFunctions` suppression on `Write-DocsContextText` is removed because the declared capability satisfies the rule. The suppression on `New-DocsCommandContext` is a different function and stays. The `init` dry run, `-Write`, and `-Force` behavior is unchanged: `Invoke-DocsContextMember` in `DocsProfileCommands.psm1` calls the `WriteText` member with no `-WhatIf`, so the gate returns true.
- N2: the `Test-Json` mock in `DocsSchema.Tests.ps1` (test `maps each Test-Json ErrorRecord to DOCS_SCHEMA_INVALID when the walk finds nothing`) must put its error record in the caller's `-ErrorVariable` without printing to the console. `Test-DocsArtifactText` calls `Test-Json` with `-ErrorAction SilentlyContinue -ErrorVariable schemaErrors`, so the mock raises the record through the error stream of the mock invocation rather than `Write-Error` text on the host. The assertions on code and pointer are unchanged.
