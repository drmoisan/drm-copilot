## Detailed Notes

### Remediation cycle 1 verification

- RS08-RS10 failed on the pre-fix tree (3 of 10 failed) and pass after (10 of 10) (`evidence/regression-testing/r1-cr-regression-*.md`).
- `PoshQC.TestingSeamDefaults.Tests.ps1` now mocks `Get-Module` so the seam-default test does not depend on the modules installed on the host.
- The two shell scripts keep their own predicates; this was stated as out of scope for CR-3.

### Sharding design

- The shard job runs with `-DisableKoverageCopy`; the merge job writes the single Koverage copy from the merged report.
- Each shard measures the full coverage population: the merged artifact has 206 sourcefiles, equal to the local unsharded run, and per-file totals match the unsharded PR-head artifact for all unchanged files.
- The completeness guard compares the shard manifests with each other (identical `all` lists, disjoint selections whose union equals `all`) and compares the sum of shard JUnit `tests` with an independent `Invoke-Pester` discovery pass over the same file list. CI reported `3 shards, 382 test files, shard tests 3203 + 4092 + 3306 = discovery 10601`.
- No coverage threshold is enforced in the merge job (D3); the job logs `Merged PowerShell line coverage: 16830 of 18302 lines (91.96%), 1472 missed.`

### API compatibility

- New `Invoke-PoshQCTest` parameters default to an unsharded run (`ShardCount = 0`). The `EnsureModule` seam now receives four positional arguments; caller-supplied scriptblocks that declare fewer parameters receive the rest in `$args`.
