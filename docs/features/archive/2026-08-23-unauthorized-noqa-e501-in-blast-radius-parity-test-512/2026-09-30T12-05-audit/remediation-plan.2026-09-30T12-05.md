- `pyproject.toml` sets the pytest `addopts` value to `-ra` plus an LCOV reporter that writes `artifacts/python/lcov.info`, with no terminal coverage reporter, and sets `testpaths = ["tests"]`. `[tool.coverage.run]` sets `source = ["src", "scripts/dev_tools"]`, `data_file = "artifacts/.coverage"`, and an `omit` list that includes `tests/*`. - Because the `addopts` value carries no terminal reporter, a coverage command must pass `--cov-report=term-missing` to print a table. With `--cov-branch` the table has the columns `Name`, `Stmts`, `Miss`, `Branch`, `BrPart`, `Cover`, `Missing` and a `TOTAL` row. `Cover` is one combined figure equal to `(Stmts - Miss + branch hits) / (Stmts + Branch)`. **Separate line and branch percentages are not printed.** This was observed in recorded full-suite runs, for example `docs/features/completed/2026-08-07-parallel-planner-surface-443/evidence/remediation-baseline/pytest-coverage-baseline.2026-08-08T15-25.md`, whose `TOTAL` row reads `13539 1107 5000 555 90%` while its separated rates came from coverage totals. This plan therefore derives the separated rates from the LCOV record sums `LF`, `LH`, `BRF`, and `BRH`, which coverage.py writes for every measured file and which `pytest-cov` writes on every coverage run through the `addopts` reporter.
- For the single module `scripts\dev_tools\compute_blast_radius.py` the earlier evidence records `Stmts 80`, `Miss 24`, `Branch 14`, `BrPart 3`, `Cover 63%`, and the audit read `LF 80`, `LH 56`, `BRF 14`, `BRH 3` from the LCOV file.
