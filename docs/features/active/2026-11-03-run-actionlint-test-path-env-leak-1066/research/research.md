# Research: run-actionlint test PATH environment leak (issue 1066)

Environment facts (tool routes, `sh` launcher, batch budget, CI shape, isolation checks) are in `.claude/skills/execution-environment/SKILL.md` and are referenced, not restated.

## 1. Current State: process-global mutations in `tests/scripts/dev-tools/run-actionlint.Tests.ps1`

The script under test is `scripts/dev-tools/run-actionlint.ps1`. The test file does not dot-source the script. In `BeforeAll` it calls `Import-ScriptFunction` (defined as `function global:Import-ScriptFunction` in `tests/scripts/powershell/Support/TestHelpers.ps1`) for six functions: `Resolve-ActionlintPath`, `Find-ActionlintOnPath`, `Install-Actionlint`, `Add-DirectoryToPath`, `Invoke-ActionlintExe`, `Invoke-ActionlintCommand`. `Import-ScriptFunction` parses the script with the AST, extracts one function definition, and returns a scriptblock. The script's main body (the `Resolve-ActionlintPath` call, `Find-ActionlintOnPath`, `Install-Actionlint`, `Add-DirectoryToPath`, `Invoke-ActionlintCommand`) is therefore never executed at load time. No dot-source-time mutation or unmocked `Install-Actionlint` call exists in this suite.

Inventory (Context, test, mutation, restored, cross-suite effect):

| Context / test | Mutation | Restored | Can affect another suite |
|---|---|---|---|
| `BeforeAll` (Describe `run-actionlint.ps1`) | Six functions defined by dot-sourcing the returned scriptblocks | Pester removes `BeforeAll` definitions with the Describe scope | No |

Not present in the file: `Set-Location`, `Push-Location`, `Set-Alias`, `[Environment]::SetEnvironmentVariable`, `Import-Module`, or any global function definition. The `Edge cases` test "Install-Actionlint handles special characters in path" mocks `New-Item`, `Join-Path`, `Write-Information`, `Invoke-WebRequest`, `Expand-Archive`, `Remove-Item`, and `Test-Path`, so it touches no disk.

Repo-wide scope of the pattern: a count of `$env:PATH =` assignments under `tests/scripts` finds 7, all in `run-actionlint.Tests.ps1`. Other `$env:<name> =` assignments exist in 30 test files (98 occurrences, for example `tests/scripts/claude-hooks/enforce-python-batch-budget.Tests.ps1`, `tests/scripts/claude-hooks/enforce-powershell-batch-budget.Tests.ps1`, `tests/scripts/dev-tools/activate.Tests.ps1`). Whether each restores was not audited; that is outside this issue and the guard must not depend on it.

## 3. Regression guard

Existing structure (verified): `Invoke-PoshQCTest` in `scripts/powershell/PoshQC/PoshQC.Testing.psm1` enumerates `*.Tests.ps1` under the scan folders in `config/poshqc-scan.json` (`scripts`, `tests/powershell`, `tests/scripts`) and runs them through a single `Invoke-Pester -Configuration` call on the global session state (the `InvokePester` trampoline). CI runs it in three shards (`_poshqc.yml`, job `poshqc-shard`) on `windows-latest`; the Linux job runs only the two hook folders. No existing per-file environment snapshot, shuffle guard, or order-dependence guard exists: grep for shuffle, leak, and `GetEnvironmentVariables` in `scripts/`, `tests/`, and `config/` finds only a trampoline-leak comment in `PoshQC.Testing.psm1`, a trampoline cleanup in `tests/scripts/powershell/PoshQC/PoshQC.TestingSeamDefaults.Tests.ps1`, and an ordinal-sort test in `PoshQC.Coverage.Tests.ps1`. Because a shard runs a subset in one process, order dependence appears only when the leaker and victim land in the same shard (the reason it surfaces intermittently).

Candidates:

- (a) Per-file environment snapshot and compare inside `Invoke-PoshQCTest`. File set: `PoshQC.Testing.psm1` (production, T4 tooling, plus its mirror/bundle copy under `extensions/drm-copilot/resources/` and its tests). Blast radius: every suite in every shard and the installed-extension bundle; Pester 5 gives no per-file hook outside a plugin or `Run` container hooks, so the implementation needs a Pester plugin or a loop that splits one `Invoke-Pester` into per-file runs, changing JUnit and coverage merging and the shard-completeness count in `_poshqc.yml`. It would also fail the roughly 98 other `$env:` assignment sites if any leak. Highest risk and highest production-file cost. Rejected.
- (b) Dedicated guard test that runs `run-actionlint.Tests.ps1` via a nested `Invoke-Pester -PassThru` and asserts `[Environment]::GetEnvironmentVariables()` before and after are equal (compares the full environment, not only PATH). File set: one new test file, for example `tests/scripts/dev-tools/run-actionlint.EnvironmentIsolation.Tests.ps1`; no production file; no temp files (nested run uses `Run.PassThru` and `Output.Verbosity = 'None'`, `TestResult.Enabled = $false`, `CodeCoverage.Enabled = $false`). Blast radius: none on other suites beyond its own runtime (the run-actionlint suite takes milliseconds per test). CI: runs on `windows-latest` shards and is a `tests/scripts/dev-tools` file, so the Linux hook-suite job does not run it; on Windows `$env:PATH` and `Path` share one variable case-insensitively, so snapshot comparison must use a case-insensitive dictionary comparison. Can fail: with the current code the nested run leaves PATH as `/new/:/existing`, so the before/after comparison fails. Open risk: nested `Invoke-Pester` inside a running Pester 5 run is supported but shares the process-wide Mock/Pester state; the executor must verify it passes in single-process runs over `tests/scripts/dev-tools` and under `Invoke-PoshQCParallelTest`.
- (c) Static AST test that scans `tests/scripts/**/*.Tests.ps1` and fails when an `$env:PATH` assignment exists in a file or Context that lacks a `BeforeEach`/`AfterEach` (or `BeforeAll`/`AfterAll`) save and restore of `PATH`. File set: one new test file under `tests/scripts/ci/` or `tests/scripts/dev-tools/`; no production file. Blast radius: scans 7 PATH assignments, all in the file being fixed, so the rest of the repo passes. Narrow by design: it cannot see leaks from other variables, from helper functions, or from the restore pattern being present but not covering a Context (the pattern in this bug: the restore exists in a sibling Context). To catch this exact bug it must evaluate restore scope per `Context`, which makes the heuristic complex. Can fail: yes, on the pre-fix file, since `Edge cases` has the assignment and no restore.

Recommendation: (b), the dynamic environment-equality test, because it checks behavior (any variable, any mechanism) instead of source shape, adds no production file, and leaves other suites untouched. If the executor shows the nested `Invoke-Pester` is unstable in single-process or parallel runs, fall back to (c) limited to PATH. Also fix the root cause by adding `BeforeEach`/`AfterEach` PATH save and restore to the `Edge cases` Context, or move the existing save and restore to the `Describe` level so it covers every Context, and restore `$global:LASTEXITCODE` in `AfterEach` for the `Invoke-ActionlintExe` and `Invoke-ActionlintCommand` Contexts (optional hygiene).

Rejected alternatives (brief): (a) per-file snapshot inside `Invoke-PoshQCTest` (production change, mirror parity, shard accounting risk).

## 4. Verification approach

Per the execution-environment brief, PowerShell runs from an `sh` launcher script under `SCRATCH` (for example `issue-1066-run.sh`) that calls PowerShell 7 inside the file. Inside it:

1. Import `scripts/powershell/PoshQC/PoshQC.psd1` (or `Import-Module Pester -MinimumVersion 5.9.0 -MaximumVersion 5.99.99`) and build `New-PesterConfiguration` with `Run.Path` set to an explicit ordered file list from `tests/scripts/dev-tools`, `Run.PassThru = $true`, `Run.Exit = $true`, `TestResult.Enabled = $true`, `TestResult.OutputPath` under the feature evidence folder (`evidence/regression-testing/`), `CodeCoverage.Enabled = $false`. `Invoke-Pester` without `Run.Exit` exits 0 on test failures, so read the JUnit file.
2. Orders: forward (`Sort-Object FullName`), reversed (`[array]::Reverse`), and at least three seeded shuffles (`Get-Random -SetSeed <n>` over the file list; record each seed and file order).
3. Run each order on the pre-fix tree (fail-before) and post-fix tree. Evidence artifacts carry `Timestamp`, `Command`, `EXIT_CODE`, `Output Summary`.
4. Separate PATH failures from host failures by test-name set difference: parse each JUnit file (`[xml]`), collect fully qualified `testcase` names that contain a `failure` child, and compute `Failed(order with run-actionlint before victims, pre-fix) minus Failed(order with run-actionlint after victims or post-fix)`. The expected victim set is the 8 suites' failing testcases; the remainder, including the roughly 89 Linux host failures in 17 suites addressed by sibling issue #1067, appears in both runs and cancels. The post-fix runs in all orders must show an empty difference against the run-actionlint-excluded baseline. Do not edit those 17 suites.
5. Final check: a fresh single-process run over `tests/scripts` (CI shape) and a concurrent run through `Invoke-PoshQCParallelTest`, per the brief's Test Isolation Checks.

## Pre-Mortem

- Review checklists: a reviewer may find the new guard lacking Arrange/Act/Assert comments or descriptive names, or find the fix only repaired one Context. Mitigation: plan carries an AAA-structured guard test and a Describe-level restore, and self-reviews against `.claude/rules/general-unit-test.md` and `.claude/rules/powershell.md`.
- Coverage: the guard and the one-test edit add no production code, so PowerShell line coverage (85% threshold, no branch gate) is unchanged. Mitigation: no production file is edited; do not add the guard to any coverage `exclude`.
- Mirror parity: not applicable for the recommended approach, since only test files change. If the plan edits `PoshQC.Testing.psm1` or any file under `.claude/`, `.agents/`, `.github/skills/`, or `extensions/drm-copilot/resources/`, the plan must update every mirror and bundle copy; the execution-environment brief is not altered because no fact it states changes.
- File size: `run-actionlint.Tests.ps1` is about 520 lines (guidance tier at 500, no gate). The fix adds under 15 lines. The new guard goes in a separate file, not appended. Mitigation: confirm both files stay under 700.
- Test isolation: the guard itself must not leak (it must restore anything the nested run touched and use no temp files), must pass in forward, reversed, and at least three seeded shuffled orders in one process, and under `Invoke-PoshQCParallelTest`. Nested `Invoke-Pester` state sharing is the main risk; the fallback is guard (c).
- CI-only behavior: Windows shards treat environment names case-insensitively and use `;` as the PATH separator, and `run-actionlint.Tests.ps1` uses `[IO.Path]::PathSeparator`; Linux hook-suite job does not scan `dev-tools`. The guard must compare environment dictionaries without assuming path format or drive letters. A shard split can place the leaker with different victims than the local run, so a local pass in one file order is not proof.
- Evidence: fail-before and pass-after runs in each order must be recorded under `<FEATURE>/evidence/regression-testing/` with seeds and file orders, JUnit-derived name sets, and the #1067 host failures shown cancelling out. If fail-before cannot be shown, write `fail-before-exception.<timestamp>.md`.

## Automation Feasibility

All steps are automatable. Evidence: (1) the fix and guard are test-file edits made with Edit/Write; (2) the single-process runs use `Invoke-Pester` configured with an explicit `Run.Path` list, with orders and seeds produced by `Sort-Object`, `[array]::Reverse`, and `Get-Random -SetSeed`, launched from an `sh` script as described in the execution-environment brief; (3) JUnit output (`TestResult.OutputPath`) is XML parsed by `[xml]` for set difference, so no manual inspection is needed; (4) the CI-shape and concurrent runs use `Invoke-PoshQCTest` and `Invoke-PoshQCParallelTest` from `scripts/powershell/PoshQC`. No GUI, credential, or manual step is required.

## Summary of recommendation

- Fix: add a PATH save in `BeforeEach` and restore in `AfterEach` that covers the `Edge cases` Context (preferably at `Describe` level); optionally restore `$global:LASTEXITCODE`.
- Guard: guard (b), a new test file that runs the suite nested via `Invoke-Pester -PassThru` and asserts the process environment is identical before and after; fallback (c).
