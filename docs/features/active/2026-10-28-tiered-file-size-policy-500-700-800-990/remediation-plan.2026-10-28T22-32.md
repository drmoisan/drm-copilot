## Scope

- In scope: finding PA-B1 only. `scripts/ci/New-FileSizeBaseline.ps1` (function `New-FileSizeBaseline`) derives each blob's line count by joining the git output elements with LF and passing the text to `Get-FileSizeLogicalLineCount`. A blob whose final element is empty yields text ending in LF, which the module subtracts as a terminator, so the count is one short. The fix counts the native element array so the generator matches the on-disk logical line count.
- File inventory: `scripts/ci/New-FileSizeBaseline.ps1`, `tests/scripts/ci/New-FileSizeBaseline.Tests.ps1`, and evidence files under `<FEATURE>/evidence/`.
- Out of scope: FA-B1 (AC7, awaiting_ci) is carried forward unchanged and no task touches it or checks AC7. The code-review Minor about the duplicated excluded-directory list lives in `tests/scripts/ci/FileSizePolicy.RepoGate.Tests.ps1` and `FileSizePolicy.psm1`, outside the inventory; it is not planned here. `config/file-size-baseline.json` is never hand-edited.
- Existing tests asserting the changed behavior: the only test file referencing `New-FileSizeBaseline` is `tests/scripts/ci/New-FileSizeBaseline.Tests.ps1`. Its existing counts (800, 801, 1200 lines with no empty final element, and the default-seam test over 801 generated lines) are unaffected by the change: native element count equals the joined count when no final element is empty. Disposition: unchanged; new rows are added.
