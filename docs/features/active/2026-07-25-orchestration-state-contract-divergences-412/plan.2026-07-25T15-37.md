## Plan Conventions

- Evidence root (canonical, non-overridable): `docs/features/active/2026-07-25-orchestration-state-contract-divergences-412/evidence/`. Canonical kinds used: `baseline/`, `regression-testing/`, `qa-gates/`, `other/`. No `artifacts/`-rooted evidence path is valid anywhere in this plan.
- Every command-bearing task records one evidence artifact containing at minimum: `Timestamp:` (ISO-8601 `yyyy-MM-ddTHH-mm`), `Command:`, `EXIT_CODE:`, `Output Summary:`. Python and TypeScript test-command artifacts must record numeric line and branch coverage headline values in `Output Summary:`; TypeScript coverage is produced by Jest (`npm run test:coverage` = `node run-jest.cjs --coverage --coverageReporters=lcov --coverageReporters=text-summary`) — the extension has no Vitest dependency. PowerShell test-command artifacts record the Pester-obtainable coverage values specified in each task text (Pester 5 with `CoverageGutters` output measures commands, not branches).
- **Fail-closed evidence rule:** if any required baseline artifact, QA artifact, or coverage-comparison artifact is missing or field-incomplete, the outcome is BLOCKED or INCOMPLETE, never PASS. `EXIT_CODE: SKIPPED` is never a passing outcome for any planned command task. The PowerShell branch-coverage tooling limitation recorded per task text is not a missing field and does not trigger this rule.
- Toolchain loop rule (applies to every per-phase and final QA sequence): run format → lint → type-check (Python/TypeScript only) → test in order; if any step fails or changes files, restart the sequence from the format step and re-record evidence for each rerun step.
- Push-down guard: `tests/scripts/dev_tools/test_push_down_claude_resource_contracts.py` asserts byte parity for every root `.claude/**` file except `settings.local.json` and `agent-memory/**`. Hook-written state under `.claude/state/**` has no bundle counterpart and fails that assertion. Before every full-suite pytest run and every mirror-parity task, run `pwsh -NoProfile -Command "Remove-Item -Path .claude/state -Recurse -Force -ErrorAction SilentlyContinue"` and record the removal in the same evidence artifact under `Output Summary:`. Do not add `.claude/state` to the bundle and do not modify the parity test.
- Jest discovery override (environmental): this worktree is located under the dot-directory `.claude`, so `jest.config.cjs`'s `testMatch: ["<rootDir>/test/**/*.test.ts"]` expands to a glob that matches nothing and every Jest invocation reports `No tests found` and exits 1. This is environmental, is not caused by this branch, and does not affect CI (a normal checkout is not under a dot-directory). `jest.config.cjs` MUST NOT be modified. For every Jest task, run the planned command FIRST and record its real exit code and output, then re-run the same command with the rootDir-relative override `--testMatch "**/test/**/*.test.ts"` and record that result as the authoritative gate outcome. Both invocations, both exit codes, and this environmental explanation MUST appear in the same evidence artifact. The override is not a skip: the acceptance clause is judged on the override run, which exercises all 168 suites.
- No temporary files in tests; all test fixtures are in-memory. No runtime temp files. No production, test, or reusable script file may exceed 500 lines.
- Python toolchain commands run from the repo root under Poetry. TypeScript toolchain commands run from `extensions/drm-copilot/`. PowerShell QC runs via the PoshQC MCP tools; direct Pester invocations run from the repo root.
