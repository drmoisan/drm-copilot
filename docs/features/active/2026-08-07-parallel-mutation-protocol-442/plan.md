- **Item-key type (reconciled against landed F2/F3): every item key is an `int`, never a `str`.** F3's schema prose in `.claude/rules/parallel-orchestration.md` makes `items[].issue_num` a positive integer and the primary key for every item reference, and `mutations[].item_key` resolves to `items[].issue_num`. F2's landed coloring entry point takes and returns `int` keys. Every engine signature, every value-object key type, and every conflict-edge tuple in this plan uses `int`. A `str` key would fail Pyright at the delegation boundary.
- **Conflict relation call shape (reconciled against landed F1): `conflicts(a: BlastRadius, b: BlastRadius, config: Mapping[str, object]) -> ConflictResult`**, defined in `scripts/dev_tools/_blast_radius_conflicts.py` and re-exported by `scripts/dev_tools/compute_blast_radius.py`. Operands are `BlastRadius` value objects, not strings. The `config` argument is the parsed `config/blast-radius.json` mapping and is required (the relation reads no key from it today, but the parameter is part of the frozen contract and a non-mapping raises `TypeError`). Callers in this plan map the resulting `ConflictResult` verdicts onto `(int, int)` conflict-edge tuples.
