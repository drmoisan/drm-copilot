## Design

Logic file `scripts/dev-tools/Get-EpicProgressReport.Logic.ps1` (pure functions only: data in, data out; no file, process, network, or clock access; no entry point, no `param` block). Every function is an advanced function with comment-based help and singular nouns. Syntax stays compatible with the analyzer's `PSUseCompatibleSyntax` targets (no ternary, null-coalescing, or pipeline-chain operators). Numeric text uses the invariant culture.

- `ConvertFrom-EpicProgressKickoffRow -KickoffText` returns one record per table row beginning with `| <digits> |` (any numeric issue), with `Issue`, `Wave` (int), `Band`, `PlanPath` from cells 1, 3, 4, 5 as in the recovered reference script.
- `Get-EpicProgressIssueFromKickoff -KickoffText` returns the digits of the first `Epic issue: #<n>` occurrence (mid-line allowed), or `$null`.
- `ConvertFrom-EpicProgressWorktreeList -PorcelainLine` returns a branch-to-worktree-path map from `git worktree list --porcelain` lines.
- `ConvertFrom-EpicProgressPrList -Json` returns `#<number> <state>` for the first entry of a `gh pr list --json number,state` array, and an empty string for an empty array, blank input, or unparseable input.
- `Get-EpicProgressWeeklyQuota -Json` returns the first active account's `usage.sevenDay.pct` from `cswap list --json` output as a double, and NaN when no account is active or the input is blank or unparseable.
- `Get-EpicProgressTaskCount -PlanText` returns `Total` and `Done` from `- [ ] [P#-T#]` and `- [x] [P#-T#]` checkboxes (the recovered regex).
- `Get-EpicProgressCurrentPhase -PlanText` returns the heading text of the phase that holds the first unchecked task, `Phase <n>` when no heading matches, and an empty string when no task is unchecked.
- `Get-EpicProgressFeatureState -MergeStatus -PrState -Done` returns `Completed`, `Running`, or `Pending` by the recovered rule.
- `Get-EpicProgressAverageVelocity -Done -BaselineDone -ElapsedHours` returns `(Done - BaselineDone) / ElapsedHours`, and 0 when ElapsedHours is not above 0.
- `Get-EpicProgressRecentVelocityInterval -Sample` returns per-interval rates for consecutive samples at least 2 minutes apart, each clamped to at least 0.
- `Get-EpicProgressStandardDeviation -Interval` returns the sample SD (n - 1 denominator) with at least 3 intervals, else NaN.
- `Get-EpicProgressCriticalPath -Feature -Velocity -WaveOverheadHours` returns `Tasks` (sum over waves with a non-Completed feature of the largest remaining count), `OpenWaves`, and `Hours` (`Tasks / Velocity + OpenWaves * WaveOverheadHours`, NaN when Velocity is not above 0).
- `Get-EpicProgressRangeText -AverageVelocity -StandardDeviation -IntervalCount -CriticalPath -WaveOverheadHours` returns the recovered range wording: the needs-3-intervals text below 3 intervals, the bounded `to` text when average minus 2.05 SD is above 0.5, and the no-upper-bound text otherwise.
- `Select-EpicProgressSample -Sample -NowUnixSeconds -Done -SampleCap` returns `Sample` and `Changed`: a sample is added only when there is no previous sample, the previous one lacks `ts`, or it is at least 90 seconds older; samples without `ts` are dropped on add; only the last `SampleCap` are kept.
- `Format-EpicProgressHours -Hours` returns `H h MM min` and `Format-EpicProgressClock -Hours` returns `HH:MM`; both derive from the rounded total minutes so the minute field stays within 0 to 59, and both return `n/a` for a non-finite value. `Format-EpicProgressNumber -Value -Digits` returns the rounded value as text, or `n/a` for a non-finite value.
- `Get-EpicProgressSummary` takes the feature records, baseline, start and now instants, samples, wave overhead, weekly and baseline weekly percentages, epic issue, and epic name, and returns one record with every value the report prints.
- `Get-EpicProgressTldrLine -Summary` returns the four TL;DR lines; `Get-EpicProgressFullLine -Summary` returns the lines that follow them in Full mode (blank line, status heading, Elapsed and Progress line, State table, Wave table with Total row, Velocity and Remaining line, straight-line and wave-parallel lines, weekly-quota line). The text `Epic #1019` becomes `Epic #<EpicIssue>` and the heading name becomes `<EpicName>`, which is the `-EpicFolder` value (AC3 defines no separate epic-name parameter); dates and times use the invariant culture.
- Non-finite values print `n/a` (AC5). Asserted literals: `about n/a hours left on the wave-parallel estimate`, `**Weekly** quota is at n/a.`, `Straight line, no parallelism: about n/a (upper bound).`, `about **n/a**.`, `n/a used, n/a points since the epic started.`, and `n/a hrs (range needs 3 or more check-in intervals)`.

Main script `scripts/dev-tools/Get-EpicProgressReport.ps1`:

- Comment-based help (`.SYNOPSIS`, `.DESCRIPTION`, one `.PARAMETER` per parameter stating its default, and at least one `.EXAMPLE` that uses the placeholder epic folder `example-epic`, never a real epic name, issue, or start time).
- `[CmdletBinding()]` `param` block with the AC3 parameters: `-EpicFolder` and `-StartUtc` (`[datetime]`, converted with `ToUniversalTime`) mandatory; `-EpicIssue`, `-IntegrationBranch`, `-KickoffPath`, `-RepositoryRoot`, `-CheckpointPath`, `-StatePath` blank by default and resolved by `Resolve-EpicProgressSetting`; `-BaselineDone` 0, `-BaselineWeeklyPct` 0, `-WaveOverheadHours` 1.25, `-SampleCap` 14; `-Mode` `[ValidateSet('TLDR', 'Full')]` default `Full`.
- `Resolve-EpicProgressSetting` (pure, takes `-TempRoot` and `-CurrentLocation`) applies the AC3 defaults: `origin/epic/<EpicFolder>-integration`, `docs/features/epics/<EpicFolder>/epic-kickoff.md`, the current location, `artifacts/orchestration/epic-orchestrator-state.json` under the repository root via `Join-Path`, and `epic-progress-<EpicFolder>.json` under `[System.IO.Path]::GetTempPath()` via `Join-Path`. Git object specs (`<branch>:<path>`) use the repository-relative path with `/` separators; filesystem paths use `Join-Path`.
- Seams, each a one-statement wrapper: `Invoke-GitExe -GitArgs [string[]]`, `Invoke-GhExe -GhArgs [string[]]`, `Invoke-CswapExe -CswapArgs [string[]]` (each splats into its executable and returns stdout lines; stderr is not merged into the returned text, which is parsed), `Test-EpicProgressCommand -Name` (Get-Command for an application), `Test-EpicProgressPath -Path`, `Read-EpicProgressFile -Path` (raw text), `Write-EpicProgressState -Path -Content` (`SupportsShouldProcess`, UTF-8 write guarded by ShouldProcess), and `Get-EpicProgressUtcNow`.
- `Invoke-EpicProgressReport` (wiring only) calls git with exactly `fetch -q origin`, `worktree list --porcelain`, and `show <IntegrationBranch>:<path>`; calls `gh` with `pr list --head <branch> --state all --json number,state` only when `Test-EpicProgressCommand -Name gh` is true; calls `cswap list --json` only when `Test-EpicProgressCommand -Name cswap` is true; reads the checkpoint, the live plan in the feature worktree, and the state file through the read seams (an unparseable checkpoint or state file is treated as empty); writes the state only when `Select-EpicProgressSample` reports `Changed`; throws a terminating error naming `-EpicIssue` when neither the parameter nor the kickoff yields an epic issue; and returns the TL;DR lines, followed by the Full lines unless `-Mode TLDR`.
- Entry point: the dot-source guard `if ($MyInvocation.InvocationName -ne '.')` (the guard convention of `Invoke-ReleaseReconciliation.ps1`, which has no location handling) pushes to the repository root, writes the lines of `Invoke-EpicProgressReport`, and pops the location in `finally`. Tests dot-source the script with `-EpicFolder` and `-StartUtc` bound, as `tests/scripts/dev-tools/Invoke-ReleaseTagPush.Tests.ps1` does for its mandatory parameter.

Tests use Pester 5, mock the seams with matching `param` signatures (for example `param([string[]]$GitArgs)`), and use only in-memory fixture text: no TestDrive, no temporary file, no network, no wall clock, and no real git, gh, or cswap. The fixture kickoff uses issue numbers of two and five digits.
