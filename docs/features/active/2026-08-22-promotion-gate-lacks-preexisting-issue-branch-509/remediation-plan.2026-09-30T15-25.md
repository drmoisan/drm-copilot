## Rules that apply to every task

**Fail-closed evidence rule.** Every artifact named below is mandatory. If an artifact is missing, if any of its `Timestamp:`, `Command:`, `EXIT_CODE:`, or `Output Summary:` fields is absent, or if a numeric coverage value is replaced by a placeholder, the verdict is BLOCKED or INCOMPLETE, never PASS. `EXIT_CODE: SKIPPED` is not a valid outcome for any command task.

**Evidence location rule.** All evidence is written under `docs/features/active/2026-08-22-promotion-gate-lacks-preexisting-issue-branch-509/evidence/` in the `remediation-baseline/`, `regression-testing/`, `qa-gates/`, and `other/` subtrees. Nothing is written under `artifacts/` as evidence; `artifacts/python/lcov.info` is tool output only. Historical evidence files from the first execution are not edited; this cycle adds new files.

**Timestamp convention.** `TIMESTAMP` in an artifact filename is the ISO-8601 `yyyy-MM-ddTHH-mm` value of the run that produced it.

**Working directory.** Every `poetry`, `git`, `grep`, `wc`, `diff`, `sort`, `find`, `rm`, `cp`, and `sha256sum` command runs at the worktree root (the directory printed by `git rev-parse --show-toplevel`). Artifacts record that location as the words "worktree root", never as an absolute path.

**Executor command constraints.** No command text contains the PowerShell host executable name, the POSIX shell names, or the Windows Linux subsystem launcher name; no heredoc is used; no command chains a directory change with a read. Files are created with the Write tool and edited with the Edit tool. Commit messages are written to a file with the Write tool and passed with `git commit -F`. PowerShell work uses only the MCP tools `mcp__drm-copilot__run_poshqc_format` and `mcp__drm-copilot__run_poshqc_analyze`; no PowerShell host command and no Pester run is part of this plan.

**Search rule.** Content assertions use plain `grep` (never `git grep`), with every pattern passed through `-e`.

**Negative-search artifacts.** A search whose passing outcome is "no match" exits 1. Each such search is recorded in its own artifact file carrying `ExpectedExitCode: 1`, and the task passes only on `EXIT_CODE: 1` exactly (exit 2, which grep returns for an unreadable path, fails the task).

**Issue #510 state step.** Any task that runs `tests/scripts/dev_tools/test_push_down_claude_resource_contracts.py` (directly or through a directory or full-suite run) first runs `rm -f .claude/state/python-batch-budget.*.json .claude/state/powershell-batch-budget.*.json`, then `find .claude -maxdepth 2 -name "*-batch-budget.*.json"`, and records both outputs; `find` must print nothing. **Test-file token rule.** No Python file created or edited by this plan contains any of the tokens `tmp_path`, `tmpdir`, `tempfile`, `mkdtemp`, `NamedTemporaryFile`, `TestDrive`, `New-TemporaryFile`, `GetTempPath`, `GetTempFileName`, `mkdtempSync`, `globals()`, or `noqa`, including in comments and docstrings.

**Python loop restart rule.** In Phases 1, 2, and 4, if a formatter rewrites a file, a linter or type checker reports a diagnostic, or a test fails, fix the cause in the file that owns it and restart that phase's Python loop at its Black task. Only the final uninterrupted pass is recorded as the passing artifact; earlier runs are summarised in the same artifact under a "Prior runs" heading.

**Commit-and-push rule.** Each phase ends with a commit-and-push task. The commit message file carries a conventional subject, a short body, and the trailer line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. If a hook refuses `git add`, `git commit`, or `git push`, the artifact records the refusal verbatim, the executor returns `BLOCKED: COMMIT REFUSED (Pn)` with the phase number, the orchestrator performs the same `git add` path list, commit with the same message file, and push, and the executor resumes at the first task of the next phase.
