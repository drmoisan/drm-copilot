## Binding Constraints (non-negotiable during execution)

- The surface is named `parallel` throughout; the module name `parallel_cohort_computation.py` is fixed by the epic.
- Optimality is not the objective; determinism and explainability are (design §13.3). Substituting an optimal or randomized coloring algorithm (DSatur with randomized ties, ILP, or similar) violates the accepted design and is prohibited. A cohort count at or above the graph's chromatic number is the expected and correct outcome of this algorithm and must never be treated as a defect or "optimized away"; no task may add a post-pass that merges or reduces cohorts.
- Determinism is an epic NFR: identical inputs — including permuted `item_keys` and permuted or direction-flipped `conflict_edges` — must produce identical cohort assignments. The implementation must guard against the five enumerated hazards from the spec: (1) vertex order derived from input iteration order — sort by the total-order key `(-degree, item_key)` ascending, never by insertion order, never relying on sort stability for ties; (2) set iteration — any set or dict feeding an ordered output must pass through `sorted(...)` first, including the final per-cohort key lists; (3) dict insertion order — never build ordered results by iterating insertion-ordered structures; (4) mixed-type or duplicate item keys — keys are `int` only and duplicates are rejected as malformed input; (5) tie-break direction — ascending item-key tie-breaking, verified by a dedicated test.
- Additive only: no task may modify or refactor `scripts/dev_tools/epic_wave_computation.py` or any other existing epic implementation. Reuse is by near-verbatim adaptation into the two new files. No file outside the two named new files is created or modified.
- The module accepts an already-computed conflict graph (item-key set plus undirected edge list). It must not compute blast radii and must never evaluate `conflicts(a, b)` — that is F1 (`parallel-blast-radius`) scope.
- Out of scope (no tasks exist for these, and none may be added): pinned-set / recolor-generation mechanics (F6), checkpoint serialization (F3), creating or modifying `quality-tiers.yml` (F1), a PowerShell counterpart module, and any change to `.claude/skills/atomic-plan-contract/SKILL.md`.
- No new Python dependencies (`hypothesis` must not be added). Standard library only.
- 500-line limit per production and test file. The only permitted test-file split is the spec's pre-approved fallback encoded in task [P1-T17].
- Coverage gates: line coverage >= 85% and branch coverage >= 75% for `scripts/dev_tools/parallel_cohort_computation.py`.
- All evidence artifacts resolve under `docs/features/active/2026-08-07-parallel-cohort-scheduler-445/evidence/<kind>/` (canonical kinds: `baseline/`, `regression-testing/`, `qa-gates/`, `issue-updates/`, `other/`). `artifacts/`-rooted evidence paths are forbidden.
- Each command-step evidence artifact must include `Timestamp:`, `Command:`, `EXIT_CODE:`, and `Output Summary:`. `EXIT_CODE: SKIPPED` is not a passing outcome for any command task in this plan; no task text authorizes a skip branch.
