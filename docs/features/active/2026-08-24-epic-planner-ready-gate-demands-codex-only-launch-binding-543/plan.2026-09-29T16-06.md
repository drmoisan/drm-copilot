## The change, already decided

Under `require_ready_for_execution=True`, the epic-planner ready gate calls two Codex-only launch-evidence validators unconditionally: the launch-binding validator (`scripts/dev_tools/validate_epic_planner_state.py:331`) and, through the readiness-integrity validator, the launch-evidence validator (`scripts/dev_tools/epic_planner_readiness.py:354`). The TypeScript twins carry the same shape. The correction, which this plan encodes and does not re-litigate:

1. The ready gate computes one activation value per runtime. Python: `key_gated = not (require_codex_model_routing or require_codex_topology)`. TypeScript: `requireLaunchPaths = options.requireCodexModelRouting !== true && options.requireCodexTopology !== true`.
2. That value is passed to both launch validators as `require_launch_paths` / `requireLaunchPaths`. When it is true, a feature that carries neither `launch_receipt_path` nor `launch_status_path` (judged by key membership) is skipped inside the existing per-feature loop, so error indices are preserved.
3. `require_generated_orchestrator=True` / `requireGeneratedOrchestrator: true` stays unchanged for every validated feature.
4. No error string is added, removed, or reworded in either runtime.
5. The MCP `epic-planner-state` dispatch forwards both Codex flags. The Python CLI is not changed (`scripts/dev_tools/validate_orchestration_artifacts.py` is 495 lines; recorded deviation in spec Non-goals).
6. The three Codex guidance callers and their bundle mirrors pass both Codex flags, so Codex enforcement stays unconditional.

## Execution notes

- **Shell.** `poetry`, `npx`, `node`, `npm` and plain `git` commands run directly in the Bash tool; a command marked 'in `extensions/drm-copilot/`' runs as `cd extensions/drm-copilot && <command>`. Every PowerShell command, and every `git diff` containing `(git merge-base origin/main HEAD)`, runs through the scratchpad route: write the PowerShell verbatim into `<scratchpad>/<step>.ps1`, then run `sh <scratchpad>/<step>.sh`, whose body is `cd` to the worktree root followed by `exec pwsh -NoProfile -File <scratchpad>/<step>.ps1`. Direct `pwsh` and `$(...)` substitution around `git` are refused by the worktree isolation guard. Each artifact records the PowerShell command verbatim in `Command:` and adds `Route: sh-pwsh`.
- **sh-pwsh route scope.** Because the `.sh` wrapper changes to the worktree root before starting `pwsh`, every path inside a `.ps1` file is worktree-root-relative, including paths under `extensions/drm-copilot/`. The route applies to every `Select-String`, `Get-Content`, `Get-FileHash`, `Copy-Item`, `Get-ChildItem`, `Remove-Item`, `Test-Path`, `Get-Module`, and `Invoke-Pester` command in this plan (P0-T4, P0-T6, P0-T15, P0-T17, P0-T18, P2-T1, P2-T4, P3-T2, P3-T4, P4-T10, P4-T11, P6-T1, P6-T3 through P6-T9, P7-T3, P9-T7, P10-T5, P10-T6) and to the anchored `git diff` commands in P7-T1, P7-T2, P8-T7, P9-T6, P10-T1, P10-T3, and P10-T4. The `poetry`, `node`, `npm`, `npx`, `git fetch`, `git merge-base`, and `git status --porcelain` commands in those same tasks run directly in the Bash tool.
- **Pester exit semantics.** `Invoke-Pester` returns process exit 0 on a failing suite unless `-EnableExit` is passed. This plan therefore runs it through the sh-pwsh route inside a `.ps1` file that assigns `$r = Invoke-Pester ... -PassThru` and prints `$r.PassedCount` and `$r.FailedCount`, and records `EXIT_CODE:` as the printed `FailedCount`, together with `PassedCount`. Do not assert a Pester exit code from a bare invocation, and do not use the PoshQC MCP test tool for any numeric claim (its results carry no output detail).
- **Line counts.** Use `@(Get-Content -LiteralPath <path>).Count` through the sh-pwsh route, which counts physical lines. Do not use `Measure-Object -Line`, which skips blank lines.
- **Acceptance-criteria tick rule.** When a task named in P10-T6's criterion-to-task list passes, the executor immediately changes that criterion's line in the `## Acceptance Criteria` section of `docs/features/active/2026-08-24-epic-planner-ready-gate-demands-codex-only-launch-binding-543/spec.md` from `- [ ]` to `- [x]`, changing no criterion text and no other section. If a later loop iteration re-runs P8-T6 or P9-T5 and that task fails, its criterion's checkbox is returned to `- [ ]` until the task passes again. Citations are not written into `spec.md`; they go in the P10-T6 artifact.
- **Python branch coverage.** The `term-missing` `Cover` column is a combined statement-plus-branch figure. Per-file line and branch percentages are read from `coverage json` output (`files[<key>].summary.covered_lines / num_statements` and `covered_branches / num_branches`), never derived from the terminal row.
- **Known local-only failure (#510).** `tests/scripts/dev_tools/test_push_down_claude_resource_contracts.py::test_bundled_claude_payload_contains_all_repo_runtime_contracts` enumerates the on-disk `.claude` tree, and the Python batch-budget hook writes gitignored `.claude/state/python-batch-budget.<session_id>.json`, so the node fails locally regardless of this change. Every full-suite Python run in this plan (baseline and final) passes the identical `--deselect` for that node, so baseline and final use the same selection. This diff does not touch the `.claude` tree the node protects; CI runs the node on a fresh checkout.
- **Python batch budget.** The plan writes four Python production files and three Python test files; the hook caps a session at three of each. Phase 2 contains one scheduled reset before the fourth production file. If any other Python Write or Edit is denied by the hook, delete every `.claude/state/python-batch-budget.*.json` file in this worktree, append a reset record to the batch-budget artifact, and retry the same write.
- **Guidance mirrors.** Bundle copies are produced with `Copy-Item -LiteralPath <root> -Destination <bundle> -Force` through the sh-pwsh route, never by editing the bundle file, so the pair is byte-identical by construction.
- **Scope anchor.** Every `git diff` in this plan is anchored to `(git merge-base origin/main HEAD)`, the merge base with `origin/main`, which stays a fixed ancestor if `origin/main` advances during execution. That parenthesised form is PowerShell syntax, so every such `git diff` runs through the sh-pwsh route. Run `git fetch origin main` once in Phase 0 before the first use.
