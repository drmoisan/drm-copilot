## Design Decisions Fixed by This Plan

- DR1 (R1-1) Published-head seam: `Get-PrAuthorCleanupPublishedHead -WorktreeRoot` is added to `.claude/hooks/enforce-pr-author-skill.cleanup.ps1`. It returns a `[pscustomobject]` with `Remote` and `Head`, each the commit printed by `rev-parse --verify --quiet <ref>^{commit}` through `Invoke-PrAuthorDocsOnlyGitExe` for the refs `refs/remotes/origin/` plus `$script:CleanupContextBranch` and `HEAD`, or an empty string when that call throws, exits non-zero, or prints a value that is not a 40- or 64-digit lowercase hex commit. It never throws. `Get-PrAuthorCleanupExemptionFailure` begins K6 with this check, before the `origin/main` resolution: an empty `Remote`, an empty `Head`, or `Remote -cne Head` returns the new sub-code `CLEANUP_EXEMPTION_REMOTE_HEAD_MISMATCH`, whose text states either that the remote branch does not resolve or that it differs from the consolidation worktree `HEAD`, and that the push precedes `gh pr create`. The file header K list gains the sub-code.
- DR2 (R1-2) Gate result function: `Get-OrchestrationCleanupContextResult` (same parameters as `Test-OrchestrationCleanupContextAllowed`) is added to `.claude/hooks/enforce-orchestration-preimplementation-gate-cleanup.ps1`. It returns a `[pscustomobject]` with `Allowed` (bool) and `DenySuffix` (string). `DenySuffix` is empty unless a leg has identified the consolidation worktree as the target (the Write leg: enclosing root equal to the `Find-CleanupConsolidationRecord` root; the command leg: every resolved target equal to that root) and then fails; it is then the literal `" Cleanup leg not applied: "` followed by one sub-code and a short detail. Sub-codes: `CLEANUP_LEG_PATH_NOT_ALLOWLISTED` (Write leg, relative remainder not allowlisted, detail names the relative path); `CLEANUP_LEG_STAGED_INDEX_UNREADABLE` (commit: staged-index result `$null` or exit code non-zero, checked first; or non-empty output not NUL-terminated, checked after the empty check); `CLEANUP_LEG_STAGED_INDEX_EMPTY` (commit: empty output, or output that lists no path); `CLEANUP_LEG_STAGED_PATH_NOT_ALLOWLISTED` (commit: a staged path outside the allowlist, detail names it). A rejection by a pure prefilter, the manifest or scratch leg, an empty or throwing listing, a missing consolidation record, an unresolved or mismatched target, or any exception leaves `DenySuffix` empty, so the deny text for every non-consolidation target and every prefilter rejection stays byte-identical (spec `Deny wording`, AC13) and prefilters stay process-free. `Test-OrchestrationCleanupContextAllowed` keeps its signature and Boolean return as a wrapper that returns `.Allowed`. The legs `Test-OrchestrationCleanupConsolidationWrite` and `Test-OrchestrationCleanupConsolidationCommand` become `Get-OrchestrationCleanupConsolidationWriteResult` and `Get-OrchestrationCleanupConsolidationCommandResult` with the same return shape (a search of `tests/` finds no test that calls either old name).
- DR3 Line-neutral call sites: in both `enforce-orchestration-preimplementation-gate.ps1` copies the cleanup `if` statement of `Invoke-OrchestrationPreimplementationGateDecision` becomes one statement that assigns `$cleanup` from `Get-OrchestrationCleanupContextResult` (Codex keeps `-AllowPatchManifest` and the mapped `content`) and returns the allow decision when `$cleanup.Allowed`; the final `PREIMPLEMENTATION_GATE_BLOCKED` reason becomes the unchanged literal concatenated with `$cleanup.DenySuffix`. Neither gate gains a line.
- DR4 Baseline registration and Discovery: `Register-EpicStateBaselineMock` in `tests/scripts/claude-hooks/EpicStateIsolation.Baseline.Helpers.ps1` gains one guarded block: when the seam list contains `Get-CleanupWorktreeManifestContent` and `Get-PrAuthorCleanupPublishedHead` is loaded, it mocks that seam at script scope with empty `Remote` and `Head` (fail closed). The Discovery census (`Get-EpicStateFileSeamCensus` in `EpicStateIsolation.Discovery.Helpers.ps1`) counts only functions whose body holds a read primitive (`Get-Content`, `ReadAllText`, `ReadAllLines`) or one of the four named seams; neither `Get-PrAuthorCleanupPublishedHead` nor `Get-OrchestrationCleanupContextResult` holds one, so no suite's Discovery guard requires a baseline mock for either, and no guard file is edited. The suites that register the manifest seam and reach K6 (`enforce-pr-author-skill.Cleanup.Tests.ps1`, `cleanup-merged-worktrees-workflow.EndToEnd.Tests.ps1`) override the default in their fixtures; every other registering suite names no consolidation branch, so `Get-PrAuthorPreflightExemption` returns before K6.
