## Design Decisions (fixed by this plan)

1. **Sibling file.** `.claude/hooks/validate-orchestrator-output-rejection.ps1` holds four pure-or-seam-only helpers and a script-scope array `$script:ParallelMutationRejectionCodes` with the four codes in rule order, preceded by a comment that cites `## Mutation Rejection Signal (issue #1012)` in `.claude/rules/parallel-orchestration.md`. It imports no module, invokes no Python, and starts no process; it relies on `Find-WorktreeRunIdentitySignal`, `Get-WorktreeItemLiveRoot`, `Get-WorktreeRunCheckpointText`, and `Get-WorktreeRunCheckpointPath`, which the hook already imports.
2. **Helpers.** `Get-ParallelMutationRejectionCode -AgentOutput` returns the code or `$null` per the spec's signal grammar (last non-blank line after trimming trailing whitespace including `\r`, case-sensitive pattern `^PARALLEL_MUTATION_REJECTED: (?<code>[a-z_]+)$`, ordinal membership). `Test-ParallelRunStateAbsent -AgentOutput -SessionRoot` implements research section 4.2. `Get-OrchestratorOutputRejectionDecision -ArtifactType -Resolution -AgentOutput -SessionRoot` returns `@{ Ok = $true; Message = $null }` only when the four allow gates hold, otherwise `$null`. `Get-ParallelMutationRejectionHint -ArtifactType -Status -AgentOutput` returns the text appended to the block message: an empty string unless the artifact type is `parallel-orchestrator-state` and `Status` is `NoTarget`; otherwise one hint line naming `PARALLEL_MUTATION_REJECTED: <code>` and `## Mutation Rejection Signal (issue #1012)`, plus, when the last non-blank line begins with `PARALLEL_MUTATION_REJECTED:` and `Get-ParallelMutationRejectionCode` returns `$null`, one line listing the allowed codes joined from `$script:ParallelMutationRejectionCodes`. The fourth helper is an addition to the three named in the spec; it keeps the code array referenced only inside the sibling and keeps the main-hook edit to one load statement, one decision call, and one message append. [P5-T13] records it in `spec.md`.
3. **Main-hook edit.** `.claude/hooks/validate-orchestrator-output.ps1` gains one guarded dot-source, `try { . (Join-Path $PSScriptRoot 'validate-orchestrator-output-rejection.ps1') } catch { Add-HookDependencyFailure -Name 'validate-orchestrator-output-rejection.ps1' -ErrorRecord $_ }`, placed beside the existing `validate-orchestrator-output-routing.ps1` guarded dot-source. Inside the `if (-not $resolution.Resolved)` branch of `Get-OrchestratorOutputBlockDecision`, before that branch's `return`, it calls `Get-OrchestratorOutputRejectionDecision` and returns its result when non-null; otherwise it returns the existing block with `Get-ParallelMutationRejectionHint` output appended after the existing `ORCHESTRATOR_CHECKPOINT_UNRESOLVED: {type}: {Status} ({ReasonCode}): {Detail}` text. The `Repairable` computation is unchanged.
4. **Rule section form.** `## Mutation Rejection Signal (issue #1012)` holds a table with header `| Code | Meaning |` and exactly four rows, each first cell a single backticked code. The Pester parity row and the Python contract test both read the code set from that table.
5. **Skill emission.** At each mapped STOP path in the spec's emission table, the skill instructs: emit `parallel_slug: <slug>` before the signal where the slug is known; end the final output with the literal line `PARALLEL_MUTATION_REJECTED: <that path's code>` as the last line with no formatting; cite `## Mutation Rejection Signal (issue #1012)` by heading. No skill names all four codes. `parallel-add`, `parallel-close`, and `parallel-remove` each state in `## Prerequisites` that the run-existence check is evaluated first (the sentence contains `run-existence check is evaluated first`), and each states for its unmapped STOP paths that the path `emits no rejection signal`.
6. **Batch budget.** The change writes four non-test PowerShell files: two source files through `Write` or `Edit` (two slots) and two bundle copies through the copy script of [P4-T1], which runs under `sh` and is not seen by the batch-budget hook. The plan therefore runs in direct mode without a large, preparation, or remediation route checkpoint.
