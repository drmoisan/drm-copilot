## Verdict Rules

- Percent = `round(hit*100/found, 2)`, the same arithmetic as the hook. A file whose `BRF` total is 0, or whose `SF:` record has no `BRF:` line (coverage.py omits `BRF:`/`BRH:` when a file has no branches, `coverage/lcovreport.py` lines 149-151), has branch 100.00% and is recorded as `0/0` by the convention recorded in `extensions/drm-copilot/jest.config.cjs` lines 23-24. A Python file whose `SF:` record has no `LF:` line (coverage.py omits `LF:`/`LH:` when a file has no statements, `coverage/lcovreport.py` lines 50-52) has line 100.00% and is recorded as `0/0`, matching coverage.py's own zero-denominator rule (`coverage/results.py` lines 336-340).
- Repo-wide PASS: line >= 85.00 and (where measured) branch >= 75.00. There is no no-regression path for repo-wide figures.
- Per changed production file: `PASS` when line >= 85.00 and branch >= 75.00; otherwise `NO-REGRESSION` when the identity check for that language in [P0-T6] exited 0 (source, tests, and configuration byte-identical to main tip `daa6436cd`, so the deterministic suite measures the same figure on main); otherwise `FAIL`.
- A failing test in a coverage run makes that RT `FAIL`.
- On any `FAIL` the executor continues the remaining measurement phases (they edit no source), records `OUTCOME: REMEDIATION-REQUIRED` in [P4-T1], commits the evidence, and reports FAIL. No source file is edited in this cycle.
- SF path matching ([P1-T3] and [P2-T3]): a set path matches an `SF:` path by exact equality after normalizing `\` to `/`; no prefix is stripped or added.
- Per-file figures come from each file's own `SF:` record counters (`LF`/`LH`/`BRF`/`BRH` written once per record); no per-file figure requires summation. Repo-wide figures come from the tool's own totals ([P1-T2], [P2-T2]).
