## Context

- Summary: the docs-only exemption added by #901 lets `gh pr create` skip the failed orchestrator-state checkpoint preflight when the branch diff against `origin/<base>` lists only paths under `docs/`. The exemption weakens an enforcement gate, so every input it does not inspect is a bypass route. Review of #901 recorded three findings that were classified as related follow-ups but were not remediated because PR #924 merged first:
  - CR-1 (Medium): the base-branch reader inspects only tokens that begin with `-B`. A clustered shorthand such as `-dB other`, or a repository override (`-R`, `--repo`, inline `GH_REPO=`), makes gh target a different base or repository than the one the exemption diffed against, while the exemption still allows the call.
  - CR-2 (Low): path separation depends on PowerShell preserving NUL bytes in captured native `git` stdout. No guard checks that property and no test executes the capture statements of the git seam.
  - PA-N3 / PA-N2: the #901 evidence record contains timestamps that are contradicted by recorded file-modification epochs and commit times, one `EXIT_CODE` value that was never observed, and an unchecked `## Evidence Checklist`.
- Merge-side gap (added in version 1.1): the exemption covers `gh pr create` only. The epic merge gate (`.claude/hooks/enforce-epic-merge-gate.ps1`; Codex `.codex/hooks/enforce-epic-merge-gate.ps1`) denies `gh pr merge <N> --merge` for a PR that no checkpoint records, with `TARGET_WORKTREE_NOT_DERIVABLE` and `STANDALONE_MERGE_AUTHORIZATION_ABSENT` (Claude) or the standalone deny (Codex). A docs-only PR created under the exemption therefore cannot be merged without an exception or a standalone-authorization record (addendum sections 0, 1.4, 2).
- Observed environment(s): any host running the Claude Code PreToolUse hooks `.claude/hooks/enforce-pr-author-skill.ps1` and `.claude/hooks/enforce-epic-merge-gate.ps1`, or the Codex hook `.codex/hooks/enforce-epic-merge-gate.ps1`; main at `f6915d42` (original research), origin/main `adb9aa5f` (addendum).
- Customer impact and severity: Medium. A `gh pr create` call without a passing checkpoint can be allowed for a branch whose diff against the actual gh target base contains non-docs paths. The sanctioned pr-author command shape does not use the affected flags, so the exposure is to non-sanctioned or adversarial command shapes. Separately, docs-only PRs require a manual exception to merge.
- First observed: #901 review cycle 2 (`docs/features/active/2026-10-11-pr-author-hook-docs-only-exemption-901/policy-audit.2026-10-13T11-40.md`, `code-review.2026-10-13T11-40.md`); merge-side gap on PR #939 (cited from the addendum; not verified in this revision).

## Root Cause Analysis

- CR-1 (confirmed by code read): `Get-PrAuthorDocsOnlyBaseName` loops over `$match.Segment.Tokens` and returns `$null` only when a token satisfies `StartsWith('-B', Ordinal)`. gh uses spf13/pflag, which parses a single-dash cluster left to right: boolean letters consume themselves and a value-taking letter consumes the remainder, the `=` text, or the next argument. Therefore `-dB other` sets base `other`. `-R`/`--repo` (inherited gh option) and the `GH_REPO` environment variable retarget the repository; none is inspected. `Get-CommandLineFlagValue` reads only the long `--base` flag.
- CR-2 (confirmed by code read): `ConvertFrom-PrAuthorDocsOnlyNameList` splits on `[char]0`. `git diff --name-only -z` terminates every entry with NUL. If the native-command capture dropped or replaced NUL, entries would concatenate into one string that may begin with `docs/` (for example `docs/a.md.claude/x.ps1`) and pass E7. No guard detects this. The seam invokes the literal `git` executable, and the repository purity hook (`.claude/hooks/check-powershell-test-purity.ps1`) correctly forbids `Mock git` and `Start-Process` in tests, so its body has no test route.
- PA-N3 / PA-N2 (cited from research section 7): three evidence files record `Timestamp: 2026-10-13T00-00` although their content derives from a run whose coverage XML mtime is 2026-10-13T10:51:17Z; several rows added by commits `ff1b7cbd4` and `70e58ca84` are stamped later than those commits (commit times are cited, not observed); `p1-poshqc-direct-run.2026-10-12T19-50.md` records `EXIT_CODE: 0` for a run whose exit code its rerun file states was not observed; `local-powershell-coverage.2026-10-12T19-50.md` records a value matching America/New_York local time rather than UTC.
- Merge side (addendum 1.3-1.4, 2; code read): the Claude gate trusts on-disk checkpoints and never calls gh or git (header design decision at `enforce-epic-merge-gate.ps1:36-39`). When no checkpoint records the PR, the only allow route is a standalone-authorization record. The Codex gate reads checkpoints only at the repository root and has the same single allow route. Neither gate has a docs-only route, and the create-side exemption cannot be reused directly: it is unavailable to the Codex runtime, and its `...HEAD` range does not apply because the session root's `HEAD` is not the PR head.
- Affected components: `.claude/hooks/enforce-pr-author-skill.docs-only.ps1`, `.claude/hooks/enforce-pr-author-skill.ps1` (header only), `.claude/hooks/enforce-epic-merge-gate.ps1`, `.claude/hooks/enforce-epic-merge-gate-resolution.ps1`, `.codex/hooks/enforce-epic-merge-gate.ps1`, the new `hook-docs-only-diff.ps1`, their bundled mirrors, both pack manifests, and the #901 feature folder.

## Proposed Fix

### Design summary

1. **CR-1 base and repository override detection** (`Get-PrAuthorDocsOnlyBaseName`, token loop). Replace the `StartsWith('-B')` test. Return `$null` when any token in `$match.Segment.Tokens`:
   - is a single-dash token: `Length -ge 2`, first character `-`, second character not `-`, and `Substring(1)` contains `B` or `R` under ordinal, case-sensitive comparison. This covers `-B x`, `-Bx`, `-B=x`, `-dB x`, `-R x`, `-Rx`, `-dR x`. Lowercase `-b` (body) and `-r` (reviewer) are not matched.
   - equals `--repo` or begins with `--repo=` (ordinal-ignore-case, consistent with the existing `--base=` comparison; case-insensitive matching only widens denial).
   - begins with `GH_REPO=` (ordinal-ignore-case). The token list includes `VAR=value` prefixes of the gh segment, so an inline prefix such as `GH_REPO=o/r gh pr create ...` is visible.
   The checks run before the `--base` count check and before any git call; the decider maps `$null` to E3 `DOCS_ONLY_EXEMPTION_BASE_UNRESOLVED`. The E3 message is extended to state that the exemption requires exactly one explicit `--base <branch>` and does not accept `-B`, `-R`, `--repo`, a single-dash shorthand cluster containing `B` or `R`, or an inline `GH_REPO=` prefix. The reason code is unchanged.
2. **CR-2 NUL-termination guard** (`Get-PrAuthorDocsOnlyExemption`). Immediately after the existing `if ($null -eq $diff -or $diff.ExitCode -ne 0)` block, the decider calls the shared pure function `Get-DocsOnlyDiffTextViolation -DiffText ([string]$diff.Output) -BaseName $base` (Design item 8). That function returns `DOCS_ONLY_EXEMPTION_DIFF_FAILED: git diff against origin/<base> did not return NUL-terminated output.` when the text is non-empty and does not end with `[char]0`; otherwise it splits on NUL and returns the `DOCS_ONLY_EXEMPTION_EMPTY_DIFF` or `DOCS_ONLY_EXEMPTION_NON_DOCS_PATH` text, or `$null` when every path is under `docs/`. A non-null result is returned as `Exempt = $false`. Empty output passes the NUL guard and reaches `DOCS_ONLY_EXEMPTION_EMPTY_DIFF` unchanged.
3. **CR-2 seam injection** (`Invoke-PrAuthorDocsOnlyGitExe`). Add `[ValidateNotNull()][scriptblock] $GitInvoker = { git @args 2>$null }` and change the capture statement to `& $GitInvoker -C $WorktreeRoot @GitArgs 2>$null`. Production callers in `Get-PrAuthorDocsOnlyExemption` do not pass `-GitInvoker`, so production behavior is unchanged. Tests pass the scriptblock of a test-local PowerShell function (for example `${function:Invoke-DocsOnlyFakeGitEcho}`). A `[scriptblock]`-typed parameter is the only `&`-invoked variable form the repository guard `tests/scripts/claude-runtime/enforcement-hooks-no-python-invocation.Tests.ps1` accepts in hook files. This seam remains in the docs-only file and is not replaced by the shared seam.
4. **Documentation.** Update the E3 and E5 rows of the comment-based help and the `.DESCRIPTION` of `Get-PrAuthorDocsOnlyBaseName` in the docs-only file, and the `Docs-only` block of the `enforce-pr-author-skill.ps1` header (the `--base` condition sentence and the `BASE_UNRESOLVED` / `DIFF_FAILED` sub-code descriptions). Record the ambient `GH_REPO` residual limit in the docs-only file header.
5. **Mirrors.** Copy every edited or new hook file byte-identically to its bundled mirror: Claude files to `extensions/drm-copilot/resources/claude-customizations/.claude/hooks/`, Codex files to `extensions/drm-copilot/resources/codex-and-agents-customizations/.codex/hooks/`.

9. **Merge-side conditions M1-M9** (evaluated in order by `Get-DocsOnlyMergeExemption`; the first failure returns `Exempt = $false` with the stated code; all pass returns `Exempt = $true`):
   - **M1 shape, before any process, `DOCS_ONLY_EXEMPTION_PR_UNRESOLVED`.** `PrNumber -gt 0`; `Read-CommandLineSegment` returns exactly one segment and that segment is not raw-scan (not wrapper-led, no live substitution, balanced); `Get-CommandLineStructuralMatch` for `gh pr merge` is non-null; no token matches `^[A-Za-z_][A-Za-z0-9_]*=` (covers `GH_REPO=` and `GH_HOST=`); no single-dash token (second character not `-`) contains `R` (ordinal, case-sensitive); no token equals `--repo` or begins with `--repo=`; no `--auto` token. The single-segment rule excludes a `cd <dir> &&` prefix and a second `gh pr merge` in the same command.
   - **M2 root, no process, `DOCS_ONLY_EXEMPTION_PR_UNRESOLVED`.** `WorktreeRoot` is non-blank and an existing directory.

### Residual limits (documented in hook headers)

- An ambient `GH_REPO` or `GH_HOST` exported earlier or inherited from the session is not visible in the command text (create side and merge side).
- On the merge side, a push between the `gh pr view` lookup and the merge can change the PR head. This window is closed only when the operator passes `--match-head-commit`.
- On the merge side, gh and git run in the root the gate passes (the Claude session worktree root or the Codex repository root); a working directory set by an earlier shell call is not visible (revision 1.3).
- The control is policy-level, not cryptographic, consistent with the existing merge-gate header.
- A stale local `origin/<base>` cannot produce a false allow under three-dot semantics (an older base yields an older or equal merge base, so the listing is a superset). This is reasoned, not tested.

### Technical specifications

- `Invoke-PrAuthorDocsOnlyGitExe -WorktreeRoot <string> -GitArgs <string[]> [-GitInvoker <scriptblock> = { git @args 2>$null }]` returns `[pscustomobject]@{ ExitCode = <int>; Output = <string> }`; output lines are joined with `` `n ``.
- `Invoke-DocsOnlyGitExe` has the same return shape; its default invoker is `{ Invoke-DocsOnlyBoundedNative -FileName 'git' -ArgumentList $args -TimeoutMilliseconds 3000 }`. `Invoke-DocsOnlyGhExe -WorkingRoot <string> -GhArgs <string[]> [-GhInvoker <scriptblock> = { Invoke-DocsOnlyBoundedNative -FileName 'gh' -ArgumentList $args -TimeoutMilliseconds 7000 }]` returns the same shape. `Invoke-DocsOnlyBoundedNative -FileName <string> -ArgumentList <string[]> [-TimeoutMilliseconds <int> = 3000] [-ProcessStarter <scriptblock>]` emits the output lines and sets `$LASTEXITCODE`; an expired wait stops the process tree, emits nothing, and sets `$LASTEXITCODE` to 124 (revision 1.3).
- `Get-DocsOnlyMergeExemption -CommandText <string> -PrNumber <int?> -WorktreeRoot <string>` returns `[ordered]@{ Exempt = <bool>; Reason = <string> }`.
- `Get-PrAuthorDocsOnlyBaseName` keeps its string-or-`$null` contract.
- Backward compatibility: callers that omit `-GitInvoker` observe identical behavior. Commands of the sanctioned pr-author shape (`gh pr create --title ... --body-file ... --head ... --base main`) resolve the same base as before. Callers of `Invoke-CodexEpicMergeDecision` that omit `-RepositoryRoot` observe the previous allow/deny outcome; only the explicit-number deny text gains the appended suffix.
- Performance: create side adds one string scan per token and one `EndsWith` check. Merge side adds, only on the docs-only branch, one `gh pr view` call and up to three git calls.

## Risks & Mitigations

- False denials from the create-side letter rule: a value-taking shorthand followed by inline text containing `B` or `R` (for example `-tBump`) or a dash-leading value token (for example `--title "-Rework"`) denies the exemption. Mitigation: the sanctioned pr-author shape uses long flags only (AC-4); denial falls back to the normal checkpoint requirement, which is the fail-closed direction.
- False denials from the merge-side rules: any inline `VAR=` prefix, any single-dash token containing `R`, `--auto`, a `cd` prefix, or a wrapper denies the docs-only branch. Mitigation: the denial falls back to the existing standalone-authorization route.
- Ambient `GH_REPO` / `GH_HOST` remains undetectable from command text. Mitigation: documented as a residual limit in the hook headers (AC-11, AC-M21); the merge exemption also requires that no checkpoint records the PR and that the diff is computed against the local repository's `origin`.
- Head change between lookup and merge. Mitigation: `--match-head-commit` equality is enforced when present (AC-M8); the residual window is documented (AC-M21).
- Existing Claude merge-gate suites could reach real gh or git through the new branch. Mitigation: baseline seam mocks in every suite that dot-sources the gate (AC-M16); new suites include an interception probe.
- The merge gate's PreToolUse latency increases on the docs-only branch by one gh call and up to three git calls. Mitigation: the branch runs only when no checkpoint records the PR; Codex registration keeps its 30 s timeout. Revision 1.3: each gh and git call on that branch is time-bounded inside the helper (worst case 20 s), and an expired call denies.
- Seam rows do not prove real NUL preservation. Mitigation: the CR-2 guard denies when NUL is absent on both sides (AC-6, AC-M11).
- The PR-context evidence collector (`scripts/dev_tools/pr_context/verification_evidence.py`) will classify `p1-poshqc-direct-run.2026-10-12T19-50.md` as unparseable after `EXIT_CODE: NOT_OBSERVED`. This is the accurate state of that record and is accepted.
- Cited commit times may differ from the confirmed values. Mitigation: AC-13 requires confirmation before edits and AC-14 derives bounds from confirmed values.
- The #901 folder may be moved to `docs/features/archive/` on main. Mitigation: the AC-M25 locator; edits never target an archive copy.
- Coverage figures cannot be read from PoshQC MCP results. Mitigation: AC-9, AC-21, and AC-M24 use the Windows CI artifact.
