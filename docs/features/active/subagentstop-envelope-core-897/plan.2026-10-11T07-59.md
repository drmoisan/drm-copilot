## Execution Conventions

- Run every command from the worktree root unless a task names another directory.
- PowerShell tasks are written for `atomic-executor`, which delegates PowerShell authoring to `powershell-typed-engineer`. Either agent executes each task as written.
- PoshQC route. The self-hosted module is used for every PowerShell toolchain step: `Import-Module ./scripts/powershell/PoshQC/PoshQC.psd1 -Force`. The `mcp__drm-copilot__run_poshqc_*` tools return a summary with no output body, so no acceptance condition in this plan reads a count, percentage, or finding from an MCP PoshQC result. The MCP formatter is not used because it cannot be restricted to the in-scope files.
- Type checking is not applicable to PowerShell (`.claude/rules/powershell.md`); the loop is format, analyze, test.
- Artifact schema. Every command artifact carries `Timestamp:` (`yyyy-MM-ddTHH-mm`), `Command:` (exact text), `EXIT_CODE:`, and `Output Summary:`. For a process-level run (`poetry run pytest`, `npx jest`, the full Pester run) `EXIT_CODE` is the process exit code. For an in-session PowerShell block, `EXIT_CODE` is 0 when the block completes with no terminating error and 1 otherwise. For an in-session targeted Pester run, `EXIT_CODE` is 0 when `FailedCount` is 0 and 1 otherwise. Expect-fail artifacts add `ExpectedExitCode: 1`.
- Targeted Pester run (referred to below as R-TARGETED with a list of files). In-session block:
  `Import-Module Pester -MinimumVersion 5.0 -Force; $cfg = New-PesterConfiguration; $cfg.Run.Path = @(<files>); $cfg.Run.PassThru = $true; $cfg.Run.Exit = $false; $cfg.Output.Verbosity = 'Detailed'; $r = Invoke-Pester -Configuration $cfg`
  then print one `CONTAINER: <path> | result=<Result> | passed=<PassedCount> | failed=<FailedCount>` line per `$r.Containers` entry (committed evidence must not contain absolute host paths, so `<path>` is the container's test file printed relative to the repository root with forward slashes: the block sets `$repoRoot = (git rev-parse --show-toplevel)` and prints `[System.IO.Path]::GetRelativePath($repoRoot, $c.Item.FullName).Replace('\','/')` for each container `$c`, where `$c.Item` is the `System.IO.FileInfo` of a file container on Pester 5.x; for example `tests/scripts/claude-hooks/subagentstop-envelope.Tests.ps1`), one `FAILED: <ExpandedPath> | <first line of ErrorRecord[0].Exception.Message>` line per `$r.Failed` entry, and `TOTAL: passed=<n> failed=<n> skipped=<n>`.
- Full Pester run (R-FULL). Run in a fresh PowerShell 7 process, because the runsettings set `Run.Exit = $true` and the process exit code equals Pester's failed count:
  `Import-Module ./scripts/powershell/PoshQC/PoshQC.psd1 -Force; Invoke-PoshQCTest -Root (Get-Location).Path -SettingsPath scripts/powershell/PoshQC/settings/pester.runsettings.psd1`
  On success Pester prints a `Tests Passed: <n>, Failed: <n>, Skipped: <n>, Inconclusive: <n>, NotRun: <n>` line and a `Covered <pct>% / <pct>%. <n> analyzed Commands in <n> Files.` line; both lines are copied verbatim into the artifact. The run writes `artifacts/pester/powershell-coverage.xml` and `artifacts/pester/pester-junit.xml` (both gitignored).
- Coverage reader (R-COV). In-session block that reads `artifacts/pester/powershell-coverage.xml` as `[xml]`, selects `//package` nodes whose separator-normalized `name` ends with `/.claude/hooks` and does not contain `extensions/`, selects their `sourcefile` children whose `name` is `subagentstop-envelope.ps1` or ends with `/subagentstop-envelope.ps1`, reads `counter[@type='LINE']`, and prints `COVERAGE: .claude/hooks/subagentstop-envelope.ps1 | <pct, 2 decimals> | covered=<n> | missed=<n> | SOURCEFILE_MATCHES: <count>` with `pct = 100 * covered / (covered + missed)`, followed by one `UNCOVERED: <line nr>` line per `line` child whose `ci` is 0. It also prints `PACKAGE: .claude/hooks | covered=<n> | missed=<n>` from the package-level `counter[@type='LINE']`.
- JUnit failure reader (R-JUNIT). In-session block that reads `artifacts/pester/pester-junit.xml` as `[xml]` and prints `JUNIT_ROOT: tests=<n> failures=<n> errors=<n>` from the root element, then one `FAILING: <testsuite name> :: <testcase name> | <first line of the failure or error child's message attribute>` line per `testcase` element that has a `failure` or `error` child, or `FAILING_TESTCASES: none`. Committed evidence must not contain absolute host paths, so `<testsuite name>` is printed relative to the repository root with forward slashes: the reader sets `$repoRoot = (git rev-parse --show-toplevel)` and prints `[System.IO.Path]::GetRelativePath($repoRoot, $name).Replace('\','/')` for each testsuite `name` attribute.
- Root redaction (R-REDACT). Before any captured output line or message is written to an artifact, every occurrence of the repository root is replaced with the literal `.` using case-insensitive literal replacement (`-ireplace [regex]::Escape(<form>), '.'`), applied once for the `/` form from `$repoRoot = (git rev-parse --show-toplevel)` and once for the `\` form `$repoRoot.Replace('/','\')`. It applies to the PSScriptAnalyzer passed line, the message field of every `FAILED:` and `FAILING:` line, and every recorded pytest or Jest failure message. [P0-T13] register rows and every later register comparison ([P5-T3], [P5-T4], [P5-T7], [P5-T8], [P3-T7]) use the redacted form.
- Commit protocol (every phase boundary). `git add` with explicit paths only (named files, or a named `evidence/<kind>/` directory inside the feature folder); never `git add -A` or `git add .`. Commit with `git commit -m "<subject from the task>" -m "Refs #897" -m "Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>"`; the `Co-Authored-By:` trailer is the final paragraph, after the `Refs #897` paragraph. Push with `git push -u origin bug/subagentstop-envelope-core-exec-897`; never force-push. `artifacts/` is gitignored and is never staged or claimed in a commit message. After each commit `git status --porcelain` prints nothing.
- AC check-off follows `.claude/skills/acceptance-criteria-tracking/SKILL.md`: change only `- [ ]` to `- [x]` on the named AC line in `spec.md`, one AC at a time, only after its named verification passed, and record each flip in `docs/features/active/subagentstop-envelope-core-897/evidence/other/ac-status.md` as `AC-<n>: CHECKED | <task id> | <evidence path>`.
