## Size Justification

This plan holds 41 canonical tasks against the guideline of 20. The issue requires six separable deliverables that cannot be merged into one task without becoming bucket tasks: a measurement tool with a before run that must precede every registration edit; two runtime dispatchers (module, runner, Codex helper, two entry scripts) with a policy-oracle carve-out; generated registries and a D6 audit; an in-item production fix to the discovery capability probe that the registration change would otherwise break; dispositions for every existing test that pins the registration shape (Phase 4); and a mirror set spanning settings, config, registries, dispatchers, edited hooks, two manifests and six brief copies. Phase 0 carries eleven tasks because the execution-start merge, the derived inventory, four gate baselines, the measurement tool and the D13 record are each evidence-bearing steps the spec orders before any edit. The 41st task is the pre-merge integration pass that the owner directive OD-2026-11-09-max-parallel (spec D15) requires so the item is merge-order independent; it must precede the QA gates that prove it, and each remaining fold candidate (the two leak scans, the two Python steps, the two D13 tasks) would combine two evidence-bearing gates with separate artifacts into one bucket task, so the count stays at 41 rather than reducing scope. Splitting the item would place the before-cost run and the registration change in different branches, which the spec forbids.
