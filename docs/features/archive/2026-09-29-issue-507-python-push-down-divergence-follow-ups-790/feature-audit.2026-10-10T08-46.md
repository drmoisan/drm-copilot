The coverage policy in `.claude/rules/general-unit-test.md` and `.claude/rules/quality-tiers.md` is met (repository-suite measurement 95.58% / 89.29%), so this is not a policy violation.
  - Remediability: `autonomous`.
  - Remediation: add tests to a file that the Test Strategy command already runs, so the named command reaches at least 21 of 28 branches (currently 18). Recommended: in `tests/scripts/dev_tools/test_push_down_claude_customizations.py` (458 lines; about 40 lines of headroom), add direct `ExcludingFileSystem.list_files` tests that cover (a) `memory_mode="skip"` dropping a general-scoped `.claude/agent-memory/**` file, (b) `memory_mode="merge"` with a `destination_root` where the destination memory exists (dropped) and where it does not (kept), and (c) `memory_mode="merge"` with `destination_root=None` (kept). This covers the branches at lines 406, 408, and 409 (four branch targets), which brings the targeted figure to about 78.6%. If the file would exceed 500 lines, place the tests in `tests/scripts/dev_tools/test_push_down_claude_pack_end_to_end.py` (390 lines), which the command also runs. Then re-run the full Python toolchain loop (AC-24 commands), record post-change coverage under `evidence/qa-gates/`, and check off AC-22. Changing the AC-22 verification command to include `test_push_down_claude_memory_scope.py` and `test_push_down_claude_pack_memory_modes.py` would also close the gap, but that changes AC text, which is the planning agent's responsibility, not the executor's or the reviewer's.
