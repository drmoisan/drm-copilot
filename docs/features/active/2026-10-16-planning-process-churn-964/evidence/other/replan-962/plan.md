## Design Decisions Derived From the Current Tree

1. **D5 shape.** At authoring, `.github/workflows/ci.yml` carries the `merge_group` trigger (#952) and `.github/workflows/_poshqc.yml` carries the sharded job set `poshqc-static`, `poshqc-shard`, `poshqc`, `poshqc-linux-hooks` (#953). The plan implements the sharded branch of D5. [P0-T2] re-records the state before any workflow edit.
2. **Existing assertions that the spec design breaks (D6).** Three committed assertions contradict the spec and are narrowed, each limited to that one assertion and recorded under `<FEATURE>/evidence/other/`:
   - `tests/scripts/workflows/CiWorkflow.Tests.ps1`, test `reads no pull-request event field and declares no path filter anywhere in the ci.yml call graph`: the D2 `changes` job reads `github.event.pull_request.head.sha`, `github.event_name` and `github.head_ref`. Narrowing: the event-field check skips the lines of the `changes` job block in `ci.yml` only; every other `ci.yml` job, every called workflow, and the path-filter half are unchanged.
   - `tests/scripts/workflows/PoshQcWorkflow.Tests.ps1`, scriptblock `$script:GetResultGateViolation`: it reports any step-level `if:` on the gate step, and AC-21 requires that step to carry `inputs.run-heavy`. Narrowing: a step-level condition is accepted only when it is exactly `if: ${{ inputs.run-heavy }}`; any other condition is still reported.
   - `tests/scripts/dev_tools/test_quality_checks_workflow_contracts.py`, test `test_threshold_step_runs_on_every_matrix_leg`: it asserts the threshold step has no `if` key, and AC-20 requires every step to reference `inputs.run-heavy`. This file is outside the two files D6 names; the plan applies the D6 limit to it by analogy (one assertion, recorded) because AC-20 and AC-32 cannot both hold otherwise (AC-32 requires every heavy job, including the four `quality-checks7` Pytest legs that run this module, to conclude `success`). Narrowing: the `if` value equals `${{ inputs.run-heavy }}` and does not reference `matrix`.
3. **Config seam.** `Invoke-CiChangeScope.ps1` takes a `-ConfigText` string parameter whose default is the text of the committed `config/ci-docs-only-paths.json`, so the AC-14 invalid-config test injects text and creates no file.
4. **Output seam.** `-OutputWriter` is a scriptblock taking `-Target` (`output`, `summary`, or `log`) and `-Text`. The default writes `output` to `$GITHUB_OUTPUT`, `summary` to `$GITHUB_STEP_SUMMARY`, and `log` to the job log; the `::warning::` annotation and the `code=<v> reason=<R>` line go to `log`.
