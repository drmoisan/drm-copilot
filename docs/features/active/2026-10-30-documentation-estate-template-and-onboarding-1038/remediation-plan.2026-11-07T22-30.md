## Design Amendments Recorded by the Planner

- **D-3a (amends D-3 of `plan.2026-10-30T18-59.md`, scenario independence):** the end-to-end suite keeps `Invoke-EstateScenario -Through <step>`, which still builds a fresh fixture context per call. The `Describe 'documentation estate end to end'` block is split into four `Context` blocks, one per step (`Baseline`, `Defects`, `Fixed`, `Unpinned`). Each `Context` calls `Invoke-EstateScenario` exactly once in its own `BeforeAll` and stores the result in a block-local variable (no `$script:` assignment), so no state is shared across `Context` blocks. Because PSScriptAnalyzer judges each script block separately, a variable assigned in a `Context` `BeforeAll` and read only in its `It` blocks raises `PSUseDeclaredVarsMoreThanAssignments`; the file therefore carries one file-level `[Diagnostics.CodeAnalysis.SuppressMessageAttribute('PSUseDeclaredVarsMoreThanAssignments', '', Justification = 'Each Context BeforeAll assigns the scenario result that its It blocks read')]` on a `param()` block after the `#Requires` lines, following the precedent in `tests/scripts/claude-lib/orchestrator-state/OrchestratorState.Tests.ps1`. Every `It` only reads that result; no `It` mutates it, so no `It` needs its own copy. The scenario is replayed 4 times per file run instead of 10. Test names and assertions are unchanged; each test's full JUnit name gains its `Context` segment.
- **D-6a (amends D-6, manifest support codes):** a non-integer `issue_num` is reported under the distinct code `EPIC_MANIFEST_ISSUE_NUM_INVALID` instead of `EPIC_MANIFEST_KEY_MISSING`; `EPIC_MANIFEST_KEY_MISSING` keeps its missing-key meaning only. A positive control asserts the new code.
- **R-3 design:** `Invoke-EstateDocumentElement` replaces its `-DispositionOnly` and `-PinOnly` switches with one mandatory `-LedgerOperation` parameter (`[ValidateSet('Disposition', 'Pin', 'Dimension')] [string[]]`) that runs the named `update-ledger` operations in the order disposition, pin, dimension. Every helper path is then used, and the scenario's inline `pin` and `set-dimension` argument lists move into the helper. The `update-ledger` call sequence of the scenario is unchanged.
