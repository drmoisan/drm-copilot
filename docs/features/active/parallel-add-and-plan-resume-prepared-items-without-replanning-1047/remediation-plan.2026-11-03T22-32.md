## Design Summary

- **B1 (receipt base_commit format).** In `Invoke-ParallelAdmissionAssess`, the existing absent-field check on the receipt `base_commit` (the `IsNullOrWhiteSpace` test that triggers the `merge-base <main> <branch>` fallback) is replaced by a case-sensitive full-string match against `\A(?:[0-9a-fA-F]{40}|[0-9a-fA-F]{64})\z` on the value cast to `[string]`. A value that does not match (null, empty, option-shaped, short, or non-hex) takes the existing fallback path exactly as an absent field does, so the value never reaches `Get-ParallelAdmissionAssessStaleness` and no `merge-base --is-ancestor`, `diff`, or `cat-file` call receives it; the emitted `base_commit` is then the merge base. A matching value is used unchanged. `Get-ParallelAdmissionAssessStaleness` and every other function are unchanged.
- **B1 tests.** In Describe `assess` of `Invoke-ParallelAdmission.Tests.ps1`, the two Its `falls back to the merge base when no receipt records a base commit` and `takes the base commit from the newest preparation receipt` are replaced by one table-driven It `takes the receipt base commit only when it is a full object name: <Case>` with six `-ForEach` rows. The `receipt999` placeholder (not a valid object name) is replaced by valid hex values in `Get-AssessGitResponse` and in It `resumes at preflight when the receipt plan hash differs from the current blob hash`. Net change to the test file is at most +2 logical lines (695 to at most 697).
