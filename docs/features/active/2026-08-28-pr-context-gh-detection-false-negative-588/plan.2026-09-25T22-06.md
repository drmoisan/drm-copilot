## Merge-order handling (spec D8, D10, D11, D13)

Sibling #622 is expected to merge into `origin/main` before this plan executes; the plan does not depend on that order. Per D13, no test added by this plan asserts the presence or the absence of #622's annotation line in either merge order; tests for that line belong to #622.

Recorded states used below:

- `TS_BUILDER_STATE` / `PY_BUILDER_STATE`, derived from `*_PARAM` (the availability parameter inside the builder range) and `*_BODY` (the exact unavailable body literal `None (GitHub CLI unavailable; closing issues not verified)` in the builder file or its `models` file):
  - `PRESENT`: parameter present and body literal present.
  - `PARAM-ONLY`: parameter present and body literal absent. This is the expected state after #622.
  - `ABSENT`: neither present.
  - `PARTIAL`: body literal present and parameter absent. `PARTIAL` stops execution at [P0-T2] with a report to the orchestrator, because a body without a parameter cannot be completed without judging #622's intent.
- `TS_CALLSITE` / `PY_CALLSITE`: `PRESENT` when the builder call in `collector-core.ts` / `collector.py` already passes availability; otherwise `ABSENT`.
- Consistency: `TS_CALLSITE: PRESENT` with `TS_BUILDER_STATE: ABSENT` stops at [P0-T2] (Python likewise), because a call passing a parameter the builder lacks indicates an inconsistent tree. `PARAM-ONLY` and `PRESENT` are consistent with either call-site state.

Builder action per state (both runtimes): `ABSENT` adds the parameter, its default, and the unavailable-body branch; `PARAM-ONLY` adds only the unavailable-body branch; `PRESENT` makes no builder edit. Call-site action: `ABSENT` adds one argument line; `PRESENT` makes no edit.
