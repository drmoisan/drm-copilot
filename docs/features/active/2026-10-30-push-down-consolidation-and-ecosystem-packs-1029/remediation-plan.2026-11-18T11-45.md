## Decisions

- **D1 — target set (recorded per the remediation brief).** The section is added to the Claude target only. Reason: the Codex target of `SRC` already omits every Claude-runtime scope section that neighbours it (`owner-directive-scope-and-backward-compatibility`, `regeneration-path-scope-and-backward-compatibility`, `concurrent-review-scope-and-backward-compatibility`, and the model-routing and merge-authorization sections), and keeps, beside its own head and enforcement sections and the shared foreign-schema warning and scope sections, only the portable-handoff projection, remediation-cycle, review-outcome, concurrent-review key, and human-interaction invariants; the Release-Commit Allowance leg is a preimplementation-gate hook rule of the same kind. `SRC` has no Copilot target: `config/harness-parity-matrix.json` entry `claude:path-scoped-rule:orchestrator-state` lists `copilot-vscode` as a consumer of `GEN` itself, so Copilot reads the regenerated Claude file. `CDX` is therefore expected unchanged.
- **D2 — single fix-and-QA phase.** The fix and the final QA loop share Phase 1, so the final QA loop is that phase's gate. Reason (OD-4 cost-benefit): a separate fix phase would need its own `[phase-gate]` full Pester run (about 12 minutes) immediately followed by an identical final Pester run with no tracked change between them.
- **D3 — Phase 0 reuses the recorded Pester baseline.** `evidence/baseline/baseline-pester.2026-11-18T08-22.md` and `evidence/qa-gates/final-pester.2026-11-18T11-34.md` are one parallel run each over the same tree state for this finding (29032 tests, 1 failure, the F-1 case). Recapturing would reproduce them. Phase 0 adds targeted fail-before evidence instead.
- **D4 — pytest and Jest.** Not run unless `[P1-T6]` finds a remediation path that is an input to them; the change touches one Markdown and one JSON generator source that no Python or TypeScript test reads, and the generated files are expected byte-identical.
