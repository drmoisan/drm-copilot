## Design Decisions (binding on execution)

1. **Capture pattern (unchanged from cycle 2).** Every fixed call site uses parent-shell capture guarded for `set -e`: `local rc=0 out; out=$(cmd) || rc=$?`, then iteration over `<<<"$out"` (or `printf '%s' "$out" | ...` where a herestring would fabricate an empty line). Never `local out=$(cmd)` (masks the exit code); never a bare unguarded failing substitution; never `|| true` on a git command whose output is treated as authoritative.
2. **Stdout-only capture.** Capture stdout only; let stderr flow to the caller (cycle-2 Decision 2 rationale: stub argv log and real git diagnostics live on stderr).
3. **Internal hard-error tokens (echo-verdict contract, return 0; report mapping in `classify_branch`).**
   - `DIFF_TREE_ERROR` — emitted by `classify_cherry_equivalent` on a non-zero `git diff-tree` exit during the empty-residual check (NEW-1 site 1). `classify_branch` maps `CHERRY_ERROR | DIFF_TREE_ERROR` to `BRANCH|<name>|ANCESTRY_ERROR` with return 2; `select_cherry_pick_candidates`' defensive re-check treats both as return 2.
   - `RESIDUAL_ERROR` — emitted by `classify_residual_commit` on a non-zero exit of the name-status `git diff-tree` (NEW-1 site 2) or of the D-rung `git ls-tree` probe. Both consumers (`classify_branch` residual loop, `select_cherry_pick_candidates`) map it to `ANCESTRY_ERROR`/return 2. A hard git failure never resolves to `CONTENT_ON_MAIN`, `UNIQUE`, or any `MERGED_*` verdict.
   - `MINUS_PRESENT` — emitted by `classify_cherry_equivalent` (before the `RESIDUAL` lines, only when residuals remain) when any `- <sha>` cherry line was seen. `classify_branch` reads this token from the already-captured cherry verdict instead of re-invoking `git cherry` at lib line 364. This removes the second cherry invocation whose exit code was discarded in a pipeline — the fail-open instance becomes structurally impossible rather than guarded.
4. **NEW-2 semantics.** In `compute_protected`, a non-zero exit from `git rev-parse --abbrev-ref HEAD` or `git rev-parse --show-toplevel` is a hard failure: print a stderr diagnostic and return the git exit code. The detached-HEAD case is unaffected (rev-parse succeeds and prints `HEAD`). `classify_branch` already maps a `compute_protected` failure to `ANCESTRY_ERROR`/return 2 (cycle-2 fix).
5. **D-rung disambiguation via `ls-tree`.** The exit code of `git rev-parse main:<path>` cannot distinguish "path absent on main" (expected, droppable) from a repository hard failure (currently also droppable — fail-open toward `MERGED_EQUIVALENT`). Replace the probe with a guarded capture of `git ls-tree main -- <path>`: non-zero exit → `RESIDUAL_ERROR` (hard failure); exit 0 with non-empty output → path present on main → the deletion is unique work; exit 0 with empty output → path absent → droppable. The stub gains an `ls-tree` key (`ls-tree.<sanitized-ref>_<sanitized-path>`); no existing scenario fixture contains a D-status diff-tree line (verified by grep), so no existing fixture changes.
6. **Driver up-front captures.** `run_report` and `run_apply` capture `parse_worktree_list` AND `enumerate_branches` output/rc before emitting any line; a non-zero rc returns immediately, so a git failure never yields a partial or "clean" report/apply run. `run_apply` additionally captures `classify_branch` output with rc and propagates a non-zero rc into its own non-zero return (the state allowlist already prevents deletion on error states).
7. **NEW-4 semantics.** `consolidation_worktree_path` fails (non-zero return, stderr diagnostic, empty stdout) on a `parse_worktree_list` hard failure OR an empty main-worktree path; the malformed `-wt/documentationandmemories` derivation becomes impossible. `create_consolidation_worktree` guards the capture and returns non-zero before any git mutation. `cleanup_consolidation_on_abort` guards the capture; on failure it emits `ACTION|worktree-remove||FAILED` (path unknown, removal skipped) and still attempts the branch deletion (best-effort cleanup contract preserved).
8. **Consistency conversions.** `reverify_delete_eligible` (fail-closed today via the state-token allowlist) and `remove_worktree_safe`'s status read (diagnostic-only) are converted to guarded captures so no instance of the `< <(...)` idiom over a git-backed producer remains anywhere in the three libraries. These are behavior-preserving on the failure direction; fail-before runs are structurally impossible and are covered by the exception dossier (Decision 10).
9. **Accepted-safe sites (audited, not changed).** Sites where the exit status is checked and every failure direction is fail-closed are recorded in the audit with rationale and left unchanged: `classify_ancestry`, `classify_content_neutral` (rc-mapped 0/1/>1); `_blob_equal` (failure → not-equal → UNIQUE, fail-closed); `check_main_freshness` (advisory; skip-on-failure can only produce a false NOT_MERGED); `cleanup_wt_git` (127 fallback); `create_consolidation_worktree`'s ref-exists probe (hard failure → proceed → guarded `worktree add` fails → FAILED); `cherry_pick_candidates`' `--skip`/`--abort` best-effort calls and `CHERRY_PICK_HEAD` probe (failure surfaces on the next pick → rc=1); `verify_consolidation_merged`'s `fetch || true` (a stale main can only block deletion — ancestry cannot be fabricated by a failed fetch) and guarded merge-base; `run_apply`'s consolidation-branch probe (failure → consolidation stays BLOCKED) and `vout` allowlist. See the Call-Site Audit table.
10. **Fail-before ordering and the exception dossier.** All new fixtures/tests land before the production fixes; one deliberate red CI dispatch captures the pre-fix fail-open verdicts (cycle-2 precedent: runs 29970355445/29970805348). Sites where a pre-fix failing observation is structurally impossible (P3-T6 minus-present refactor — the stub keys both `git cherry` invocations identically so the first invocation fails first; P3-T12 conversions — already fail-closed) are documented in `fail-before-exception.2026-07-22T21-16.md` per `evidence-and-timestamp-conventions`.
11. **New test suite file.** All cycle-3 tests live in a new suite `tests/shell/test_cleanup_worktrees_hard_failures.bats` (same harness pattern as the existing suites: source enumerate lib → classification lib → actions lib, checked-in stub via `CLEANUP_WT_GIT_BIN`, scenario via `CLEANUP_WT_STUB_SCENARIO`, stderr discarded). This keeps every existing suite stable and within the 500-line cap.
12. **500-line cap watch.** Pre-fix counts: classification lib 411, enumerate lib 209, actions lib 301. Estimated additions keep all files under 500; P4-T2 verifies and carries an explicitly authorized split branch if any file exceeds the cap.
