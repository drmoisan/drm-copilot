## Owner Standing Instructions

1. PowerShell only; no new Python. Tests use in-memory fixtures and injected seams; no test creates a temporary file, reads gitignored `artifacts/` state, or writes `$global:` state. Fixtures use `example-epic` and `/fixture-repo` roots.
2. Phase 0 runs the test baseline once before any change: one `Invoke-PoshQCParallelTest` run and one `pytest -n auto` run with coverage, plus format and PSScriptAnalyzer baselines for the skill scripts. Each baseline artifact records pass and fail counts and coverage (repo-wide and each in-scope file). The final gate runs each parallel gate once and compares with this baseline: no new failing test, no per-file coverage drop.
3. Tests run in parallel only: one run per gate, re-run only after a fix. A focused single-file run is debugging only, never a gate or evidence. Implementation tasks therefore name the `It` cases they add or change; the final gates prove them.
4. Proportionate plan; this plan exceeds 20 tasks, see `## Size Justification`.
5. The executor commits and pushes after each task with `git commit -F <file>`. Never push a git tag. Never run an unqualified `poetry install` from the item worktree.
6. Environment facts (otherwise owned by `execution-environment`): run Poetry with the session `VIRTUAL_ENV` unset (`env -u VIRTUAL_ENV poetry run ...`) so the worktree environment is used; for pytest coverage from the item worktree set `PYTHONPATH` to the worktree's `packages/discovery-runtime/src`; branch-current Pester runs import `scripts/powershell/PoshQC/PoshQC.psd1` and call `Invoke-PoshQCParallelTest` from a `sh`-launched PowerShell 7 script under `SCRATCH`; counts come from `artifacts/pester/pester-junit.xml` and coverage from `artifacts/pester/powershell-coverage.xml`, never from PoshQC MCP results.

## Execution Terms

- `SCRATCH` resolves to `<session scratchpad>/issue-1118/`; scratch file names start with `issue-1118-`. Evidence records the token, never a host path.
- `FEATURE` is `docs/features/active/2026-11-07-progress-report-orchestration-step-model-1118`. `SKILLDIR` is `.claude/skills/epic-progress-report/scripts`; `TESTDIR` is `tests/scripts/claude-skills/epic-progress-report`; `BUNDLE` is `extensions/drm-copilot/resources/claude-customizations`.
- `VERDICT(C)`: a step script ends with `exit ([int](-not (C)))`, so its `EXIT_CODE:` is non-zero whenever condition C fails. Every value-gated evidence step ends with a VERDICT.
- Pester gate reading path: `EXIT_CODE:` is the `ExitCode` property of the object `Invoke-PoshQCParallelTest` returns. Counts come from the merged JUnit file after a green run; after a non-green run, from `artifacts/pester/parallel/shard-<i>/pester-junit.xml`, compared as per-container counts (tests, failed), never as test-key sets.
- A failure outside the branch: a failing test whose test file and subject are both absent from `git diff --name-only` of the merge base of `origin/main` and `HEAD` (pair it with `git status --porcelain`) and that also fails in the `Phase 0 baseline`. The gate artifact names it with that diff as proof, keeps `EXIT_CODE:` non-zero, leaves the task unchecked, and stops for the caller. Any other failure is a failure on the branch: fix it and restart the final QA loop from formatting.
- Golden lines in tests are derived by hand from the fixture and the `spec.md` rules (a comment states the arithmetic); they are never captured from the implementation's own output.
- Decision record (spec D13 and `-WaveOverheadHours`): `Get-EpicProgressAverageVelocity`, `Get-EpicProgressRecentVelocityInterval`, `Get-EpicProgressStandardDeviation`, `Get-EpicProgressCriticalPath`, `Get-EpicProgressRangeText`, and `Format-EpicProgressClock` are deleted with their tests (no caller remains). `-WaveOverheadHours` stays accepted with its default and affects no figure; `Invoke-EpicProgressReport` names it in one `Write-Verbose` line.
- Interpretation of D3: `epic_row` samples are typed and approximate (`main-sync` from a sync row's `worktree_created_at` to `merge_confirmed_at`; `merge` from the item's last closed `ci` end to its row `merge_confirmed_at`). `cycle_entry` and `artifact_stamp` records (cycle entry differences, review artifact stamps from checkpoint paths) are composite remediation time: listed on the unmapped line, marked approximate, never in a median (D2).
