## The Settled Change

Two predicate bodies are replaced in place in each of four hook copies. No shared helper, no new parameter, no signature change, no workspace-root resolution. Case handling is zero-delta: case-insensitive matching for the checkpoint literal set (preserving `-contains` semantics), case-sensitive matching for the documentation prefix (preserving `StartsWith` semantics). The documentation predicate becomes a case-sensitive segment-anchored match on the prefix `docs/features/active/`; the checkpoint predicate becomes a loop over `$script:CheckpointPaths` applying a case-insensitive segment-anchored, end-anchored match built with `[regex]::Escape`. The segment anchor is the two-alternative group shown in the spec's `Proposed Fix` section. A source comment in each copy must record the case-sensitivity choice so a later reader does not normalize the case-sensitive operator into the case-insensitive one.

An absolute path to a production source file must still classify as an implementation path and must still be denied.
