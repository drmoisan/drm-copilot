- Review checklists: reviewers ask whether the full toolchain loop ran; task checks could read as a skipped loop. The canonical section states that the loop runs at every phase gate and in the final QA loop, and [P2-T6] cites the phase-gate artifact of [P1-T11] and the final-QA artifacts of [P2-T1] to [P2-T4].
- Coverage: no production file changes (Markdown, TOML, templates, one Pester test file). Repo-wide Pester line coverage and pytest line and branch coverage are compared with the `Phase 0 baseline` in [P2-T3] and [P2-T4]; no per-file production threshold is in scope, and [P2-T5] proves no production path changed.
- Mirror parity: every edit task copies each base to its bundle copy in the same task; Codex variants come only from the generator in [P1-T7]; the execution-environment brief, whose facts this plan changes (a task-check Pester route, a new contract test), is updated in all six byte-identical copies by [P1-T8]. - File size: the only new script file is the Pester test of [P1-T9], kept under 500 lines by generating rows from base lists; every other target is Markdown or TOML, which the size tiers exempt or the generator writes.
- Test isolation: the new suite reads tracked files from `$PSScriptRoot` with `Join-Path`, defines helpers in `BeforeAll`, writes no file, sets no global or environment state, and is checked by `Invoke-PoshQCLeakScan`. Gates are one `Invoke-PoshQCParallelTest` run, one `pytest -n auto` run, and Jest through its normal parallel workers, each re-run only after a fix.
- CI-only behavior: the new suite runs in the `poshqc / PowerShell QC` shards on `windows-latest`; it uses forward-slash relative paths and exact file-name case, so it is also Linux-safe. The ledger chain test runs in those shards and is run inside the [P1-T11] gate before push. AC14 (CI green on the PR head) stays pending until CI reports.
- Evidence: task checks write one new file per task under `<FEATURE>/evidence/other/`, labeled as task checks and never as gate or coverage evidence; gates write under `<FEATURE>/evidence/baseline/` and `<FEATURE>/evidence/qa-gates/`; every filename stamp is the UTC write time read from the clock.

## Size Justification

The plan has 21 tasks, one above the 20-task guideline. Spec D1 to D12 touch eleven mirror families (contract, policy texts, orchestrate, language rules and QA gates, executors and prompts, planners and templates, Codex generation, brief, new test, ledger) that cannot share a task without mixing unrelated acceptance, and the owner rule adds a phase-gate task while the policy adds one static artifact per language in the final phase. Merging families would make a task check select unrelated tests and blur the ledger blocks per source.
