## Design and Correctness Review

- Filter placement: both entry points read the manifest before `resolve_published_paths` / `resolvePublishedPaths` and before any decorator is constructed, and wrap `ExcludingFileSystem` as the outermost adapter. Enumeration order matches the engine (`joinPosix(sourceRoot, root)`), and `relativeToPosix` uses the same POSIX normalization, so the string-prefix comparison in TypeScript is consistent with the engine's listed paths.
- Write-guard semantics: the guard raises `ExclusionViolationError` for the manifest path and for any first-match target, passes targets outside the destination root, and exempts the summary-artifact directory. Direct unit tests in both languages assert each branch, including the pass-through order of permitted writes.
- Artifact-directory exemption: required so the engine's summary artifact is written even when an entry such as `artifacts/**` exists; the spec states such an entry is reported as unmatched. Both implementations and tests agree (`artifacts/**` in the write-guard tests).
- Artifact post-processing: `append_exclusions_to_artifact` / `appendExclusionsToArtifact` write through the raw adapter, not the filter, so the exemption is not load-bearing for this second write. Sorted-key rendering is asserted in both languages.
- Gitignore delivery (TypeScript only): the manifest is consulted separately and the skip is appended to the report; no read or write occurs for an excluded `.gitignore`. Tested for both `present` and `absent`.
- Absent manifest: one `isFile` probe (plus one `isDir` probe when the file is absent). The spec states "one `isFile` probe"; the added `isDir` probe is needed for the directory-at-path malformed condition and has no side effect.
- Python/TypeScript parity: constants, error classes, grammar, check order of malformed reasons, matcher, first-match rule, report shape, and line text are identical, with the exception recorded in CR-07.
