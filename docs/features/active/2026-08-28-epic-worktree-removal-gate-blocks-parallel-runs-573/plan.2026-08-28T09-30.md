## Risks recorded before execution

- **Accepted residual: a stale parallel checkpoint can authorize a path.** The orchestration artifact tree is gitignored, so the parallel checkpoint persists after a run ends. For a stale document to authorize a removal it should not, a worktree would have to exist at a path byte-identical after separator normalization and trailing-slash trim to one recorded with `merge_status` in the allowed set. Worktree paths here carry a session or timestamp component, so a collision is implausible, and where the recorded status is `worktree_removed` the path was already deleted. This is a documented accepted trade (research Q5), not an unexamined gap. No code mitigation is added; the route guard does not address this case.
- **Test non-determinism from the second read seam.** Mitigated by the mandatory `$null` mock (AC-10, P2-T4) and by the determinism statement added to the test file docstring.
- **Pre-existing red from issue #510.** A local push-down contract failure may predate this change. Phase 0 captures the baseline for both Python parity tests; Phase 3 and Phase 5 compare against that baseline BEFORE concluding the mirror is wrong.
- **MCP PoshQC runner caveat.** The MCP test runner reads the installed extension's settings and can ignore newly added coverage entries. This change adds NO new file, so the existing coverage registration already covers the hook. If a coverage entry nonetheless appears missing, invoke the self-hosted PoshQC module directly rather than trusting the MCP runner, and treat the MCP figure as a runner artifact.
- **Repo-wide formatter drift.** The format stage rewrites any unformatted PowerShell file it finds, which would put out-of-scope files in the diff and break AC-21. Phase 0 captures the pre-edit drift set so it can be distinguished and restored.

Tests added in this phase fail until Phase 2 lands, because mocking a command that does not yet exist is an error. That is the intended fail-before signal. No full-suite green gate appears in this phase.

Every Pester run in this phase uses the explicit-exit wrapper below. A bare `Invoke-Pester` returns process exit code 0 even when tests fail, so `ExpectedExitCode: 1` could never match; and `-CI`, which does return 1, writes `testResults.xml` — a tracked file at the repository root — which would put an eighth file in the diff and break AC-21. The wrapper also satisfies the explicit-exit requirement in `.claude/rules/ci-workflows.md`.

The suite-run command, referred to below as **the suite-run wrapper**, is exactly this single line, and is used unchanged in P1-T1 through P1-T6 and again in P2-T2, P2-T3, and P2-T5:

```
pwsh -NoProfile -Command "if ((Invoke-Pester -Path tests/scripts/claude-hooks/enforce-epic-worktree-removal-gate.Tests.ps1 -Output Detailed -PassThru).FailedCount -gt 0) { exit 1 } else { exit 0 }"
```

The wrapper deliberately contains no `$` sigil and no quote character inside the `-Command` payload. An outer double-quoted payload has `$r` expanded to the empty string by bash and by PowerShell alike, leaving a parser error that exits 1 without running any test — which would make every `ExpectedExitCode: 1` artifact in this phase pass unconditionally. Outer single quotes are not an alternative: bash cannot nest single quotes and PowerShell mangles embedded double quotes for a native command. The passed and failed counts required by each `Output Summary:` are read from the `Tests Passed: N, Failed: M` line that `-Output Detailed` already prints; do not add a `Write-Host` to produce them, because that reintroduces quotes.
