## Premise Corrections

- **F1 seam transparency.** The inputs state that `validate-orchestrator-output.OwnerDirectives.Tests.ps1` null-mocks `Get-CheckpointFileContent`. Its outermost `BeforeAll` does, but its rows replace that mock through `Set-OwnerDirectiveCheckpointRead` with a path-agnostic mock that returns the checkpoint text for every path. A plain switch of the sibling's reads to `Get-CheckpointFileContent` would hand that checkpoint text to the sibling as the ledger, parent, and child text, so rows such as `S8 allows a refused gate_bypass record for <Type>` and `U5 allows an honored extra_planner_revision record` would block with `OWNER_DIRECTIVE_LEDGER_INVALID`. The design therefore adds a self-read guard (P1-T7): a sibling source read whose content is ordinally equal to the checkpoint text under validation is treated as absent. In production the ledger, parent checkpoint, and child checkpoint are different files from the checkpoint under validation, so the guard changes no production decision except that a ledger file byte-identical to the checkpoint is treated as absent instead of reported invalid. Under every path-agnostic mock that returns the checkpoint text, the guard gives the same decision the former `Read-OrchestratorOutputOwnerPassDownText { $null }` mock gave.
- **F1 mock removal is required, not optional.** Removing `Read-OrchestratorOutputOwnerPassDownText` makes every unguarded `Mock` or `Register-EpicStateBaselineMock` of it throw (Pester cannot mock an absent command), so the 13 `validate-orchestrator-output*` suites other than the AC-29 suite and the sibling suite lose the line in this cycle (P1-T4). The four `Get-Command`-guarded lines become dead code and are removed (P1-T5).
- **Ordering.** The mock lines are removed (P1-T3 to P1-T5) while the function still exists, so each of those task checks runs passing suites; P1-T6 adjusts the read-list rows of the TargetWorktree suite; P1-T7 then removes the function. Between P1-T3 and P1-T7 the read seam is unmocked in those suites; the window closes before the P1-T8 gate, whose `enforce-gate-suites.EpicStateIsolation.Discovery.Tests.ps1` rows confirm compliance.
- **Recorded read lists (preflight defect, revision 1).** After P1-T7 the sibling's ledger read reaches every `Get-CheckpointFileContent` mock, because `Get-OrchestratorOutputBlockDecision` calls `Get-OrchestratorOutputOwnerPassDownDecision` after its own checkpoint read whenever the resolution has a worktree root, and that decision always reads `artifacts/orchestration/owner-directives.jsonl`. `validate-orchestrator-output.TargetWorktree.Tests.ps1` records every path in its `Invoke-Case` mock, and rows H1, H3, H7, H8, and H11 assert the exact list (preflight probe: 5 failed, each list longer by the ledger path). P1-T6 projects the checkpoint reads for those rows. The sweep of every other suite that records or counts calls of a seam P1 changes is in `## Changed Behavior and Asserting Tests`; no other suite asserts a call set the ledger read enters.
