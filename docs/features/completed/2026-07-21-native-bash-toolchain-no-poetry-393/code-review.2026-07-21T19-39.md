## Executive Summary

The change replaces the Python/Poetry-driven shell quality-control toolchain with a native bash wrapper (`scripts/bash/shell-qc.sh`) and function library (`scripts/bash/shell_qc_lib.sh`), removes `scripts/dev_tools/shell_qc.py` and its five Poetry console-script entries, repoints all consumers (CI workflows, VS Code tasks, `fix_all_branches.py`, README, policy-audit templates), and adds a path-scoped `.claude/rules/shell.md` with a byte-identical extension mirror.

Code quality is high. The bash implementation is a careful, well-commented parity port: discovery, tool-resolution, skip-marker, exit-code, and coverage-pipeline semantics match the removed module, including the seam design (`SHELL_QC_<TOOL>_BIN`, `SHELL_QC_KCOV_OUT_DIR`) that makes the library unit-testable with checked-in stubs. `set -euo pipefail` interaction with legitimately-non-zero tools is handled correctly and consistently (`|| rc=$?` with an explicit re-exit in the source-guard). Both bats suites are deterministic, stub-driven, and assert the byte-identical contracts consumed by `fix_all.py`.

One Blocking finding exists, inherited rather than introduced: the kcov coverage pipeline produces an empty merged Cobertura report (zero instrumented lines) on CI, and the summary-line parser reads a path (`$out_dir/cov.xml`) that kcov's merge never writes (it writes `$out_dir/kcov-merged/cov.xml`). The port preserves this defect faithfully — parity was an explicit spec requirement — but it leaves the new bash production files without a measurable line-coverage number, which fails the uniform coverage gate. This is routed to remediation rather than a silent fix, per review policy.

Recommendation: address the coverage-measurement finding (REM-1/REM-2 in `remediation-inputs.2026-07-21T19-39.md`); no other code changes required.

## Design and Implementation Notes (non-findings)

- **Exit-code integrity under `set -e`:** every external tool call that can legitimately return non-zero is captured with `|| rc=$?`, and the wrapper's source-guard re-exits the captured code explicitly (`main "$@" || rc=$?; exit "$rc"`). This is the correct pattern and is consistently applied.
- **Discovery robustness:** NUL-delimited `find` output with prune expressions matches the documented exclusion contract; `LC_ALL=C sort -u` gives deterministic codepoint ordering, asserted exactly in the discovery suite.
- **Shebang parsing parity:** lowercasing, `env`/`env -S` handling, unreadable-file tolerance, and empty-payload rejection all mirror the Python semantics; each branch has a dedicated bats test.
- **Byte-identical contracts:** the two skip markers consumed by `fix_all.py` and the five-line missing-tool block are asserted with exact string equality, protecting the hidden consumer identified in the spec.
- **Workflow changes:** `_shell-coverage.yml` cleanly drops five Python/Poetry setup steps; `_build-check.yml` adds a zero-dependency `--help` smoke as its own named step. No deliberately-failing nested commands, so the ci-workflows exit-code rule is not implicated.
- **Rule doc quality:** `.claude/rules/shell.md` covers toolchain order, discovery contract, coverage expectations (including the kcov line-only limitation), CI-vs-local drift with CI-canonical resolution, and coding standards; frontmatter `paths:` scoping matches the sibling rule files; the extension mirror is byte-identical (verified with `cmp`).
- **Typed-Python review:** the only Python production change is three command-list literals in `fix_all_branches.py`; type surface unchanged, pyright clean, and the pre-existing step-name-keyed fakes made test edits unnecessary exactly as the spec predicted.
