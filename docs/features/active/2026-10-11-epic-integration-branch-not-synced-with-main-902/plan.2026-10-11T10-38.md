## Design Decisions

- **Bound on repeated syncs (research "Risks").** At most one main-sync child runs per wave. After it merges, `epic-orchestrator` re-runs step 2 (fetch the integration tip) and launches the wave without repeating the count. Commits that reach `origin/main` afterwards are picked up by the next wave's check or by the final integration PR. This prevents an unbounded sync loop while `origin/main` keeps moving and accepts a bounded residual lag of one wave.
- **Wave-barrier hook (no hook change).** `.claude/hooks/enforce-epic-wave-barrier.ps1` line 331 denies an epic-mode delegation whose feature record is not found. The step text therefore requires writing the sync child's `features[]` row before delegation.
- **Issue-number collision.** `scripts/dev_tools/_epic_orchestrator_state_resolution.py` lines 99-108 index features by `issue_num`, and a later duplicate overwrites the earlier one. The step text therefore forbids reusing a manifest child's issue number.
- **Concurrent item #900 risk.** Edits are confined to the two named sections. If #900 or any other branch also edits `.claude/skills/epic-orchestrate/SKILL.md` or the digest line in `tests/scripts/dev_tools/parallel_orchestrator_surface_expectations.py`, the digest conflicts at merge and must be recomputed after the second merge. Task P2-T10 records whether `origin/main` changed either file during execution.
- **Digest computation and LF.** `tests/scripts/dev_tools/parallel_orchestrator_surface_test_support.py` line 111 computes `hashlib.sha256((REPO_ROOT / relative_path).read_bytes()).hexdigest()` over raw bytes. `.gitattributes` line 1 is `* text=auto eol=lf`. The new digest is taken from the `found <digest>` value printed by `test_frozen_epic_surface_matches_pinned_baseline_digest` (test file lines 482-485) and cross-checked with the first field of `sha256sum .claude/skills/epic-orchestrate/SKILL.md` run in the Bash tool. LF worktree bytes are verified with `git ls-files --eol` (`w/lf`). After the Phase 1 commit, the committed blob is hashed with `git cat-file blob HEAD:.claude/skills/epic-orchestrate/SKILL.md | sha256sum`, and that value must equal the pinned digest, so the digest computed locally is the digest CI computes over the checked-out LF file. `git diff --exit-code HEAD` alone does not prove byte equality, because the `text=auto` clean filter normalizes CRLF before comparison and a CRLF worktree file would still compare equal to an LF blob.
- **Mirror copies.** The bundles are hand-maintained byte copies; no generator exists (research Section 3). Each copy is made with one `cp <source> <destination>` command run directly in the Bash tool (not a wrapper script), which copies bytes unchanged and does not consume a Write/Edit batch-budget slot. `cp` is used because the executor's tool set has no PowerShell runner and the worktree isolation guard refuses any command text that names the PowerShell executable. Pair equality is verified with `git hash-object`.
- **Coverage scope.** No production Python file changes. `pyproject.toml` `[tool.coverage.run]` omits `tests/*`, so a coverage run with the project config measures no test-support file. Two coverage measurements are therefore planned: (a) `--cov=scripts.dev_tools` over the regression set, as a like-for-like no-regression comparison value; (b) the edited test-support module `tests.scripts.dev_tools.parallel_orchestrator_surface_expectations` (imported by that dotted name at `tests/scripts/dev_tools/test_parallel_orchestrator_surface_contracts.py` line 36) measured with a feature-local coverage config `FEATURE/evidence/other/coveragerc-902.ini` that has no `omit` entry.    own remediation loop, and opens a PR into the integration branch. The wave does not launch
   until that PR has merged into the integration branch and the sync entry's `merge_status` is
