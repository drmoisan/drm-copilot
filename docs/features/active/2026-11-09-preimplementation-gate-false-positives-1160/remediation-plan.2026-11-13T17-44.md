## Design: decision D16 (pipeline consumers)

Stage 2 judges each record of `Read-CommandLineInvocationSegment` alone and skips any record that does not carry the governed word, so in `Get-Command pytest | ForEach-Object { & $_ }` the carrying `Get-Command` record is a host and the executing `ForEach-Object` stage is never examined. D16 adds a fourth confirmation rule to `Test-OrchestrationGateInvocationConfirmed`:

- **Rule.** A stage-1 hit is confirmed when a record that does not carry the governed word is a pipeline consumer of a carrying record and is not an accepted consumer.
- **Pipeline consumer.** A record R that follows a carrying record C in record order at the same `Depth`, with no record of lower `Depth` between them (records of greater `Depth`, which are nested payloads, are skipped). For a `Posix` C, every same-depth record from C up to the record before R ended with the `|` delimiter, so `;`, `&&`, `||`, and `&` end the pipeline. For a `PowerShell` C, every later record of the same payload qualifies, because PowerShell payload records carry no pipeline delimiter (fail-closed).
- **Accepted consumer.** R is led (after transparent wrappers) by a mention host under the same lookup rule 3 uses, with no executing option, or R is a PowerShell non-command expression record whose text contains neither `::` nor `.Invoke`. Every other consumer confirms: `ForEach-Object`, `%`, `foreach`, an evaluator, a call-operator record (its command word is an expression, never a host name), `xargs`, `env`, any wrapper, and any unmodelled command word.
- **Why "not a mention host" rather than an enumerated list.** D2 is a negative model that fails closed for launchers it does not model; an enumerated consumer list would reopen F1 for any unlisted executor (`Invoke-Item`, `parallel`). Stage 1 is unchanged and D16 only adds confirmations, so the classified set after D16 lies between the head set and the merge-base set: no widening (AC-3), and every row on which head and merge base agree is unchanged.
- **FP rows.** In FP-01, FP-02, FP-15, FP-16, and FP-17 the carrying record is the last stage of its pipeline or is followed only by an accepted consumer (FP-16 is followed by an expression record without `::` or `.Invoke`); the other FP rows have no pipeline. All 17 stay unclassified.
- **Cost.** A PowerShell payload with a later unrelated statement (`Get-Command pytest; Get-Date`) is classified, as it is at the merge base.
- **Table (N1, N2).** `NotHost` becomes `ForEach-Object`, `%`, `foreach`, `find`, and is read: a command word in `NotHost` is never a host even when a host group lists it, in rule 3 and in the consumer check alike. `ExecutingOption` gains `sort` with `--compress-program`, ordered after `rg` and `git`.
- **AC reading.** AC-2's existing-denial table includes rows ED-43 to ED-50; AC-5's "D2 table" is the D2 table as amended by D16. No AC text changes.
