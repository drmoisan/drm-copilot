## Executive Summary

The design follows the #1026 cleanup-leg precedent closely: each new leg is evaluated only where its gate would otherwise deny, returns `Allowed` and `DenySuffix`, never throws, keeps the existing deny text byte-identical when no docs profile exists, and routes every git call through a bounded seam. The receipt revision rule is a pure function shared by `validate`, the integration docs-complete gate, and the delegation leg, with a seeded property test. Mirrors are byte-identical, coverage is high (new files 91.30% to 100.00%, changed lines 96.14%), and the gates are clean.

The reviewer probed the new predicates with direct calls (18 command shapes, 17 path cases, 6 label prompts). Seventeen shapes behave as specified: chained `pytest`, pipes, redirections, `$(...)`, backticks, process substitution, `-am`, `--no-verify`, `git -c`, and a commit pathspec all decline. One defect was found (CR1): a commit whose only option uses the `=` spelling throws inside the prefilter. Together with one stale message (CR2) and the spec's unchanged-suite criterion (FA1 in the feature audit), there are three blocking findings, all contained and autonomous.
