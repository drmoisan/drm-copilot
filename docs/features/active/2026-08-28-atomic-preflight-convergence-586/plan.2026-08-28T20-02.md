## Design Constraints Binding Every Phase 1 Task

- Additive only. No existing line in any of the four production files may be deleted or reworded. P2-T1 and P2-T2 measure this as a `git diff --numstat` deletion count of zero against `main` over the two target files; the same verdict reaches the two bundled mirrors through the byte-identity established by P0-T5 and P2-T10, as stated in `## Scope and Toolchain Applicability`.
- Mirror sync. Every edit made to a target file by P1-T1 through P1-T13 is applied identically to that file's bundled mirror by P1-T14 or P1-T15, so that each pair remains byte-identical. A pair that diverges fails P1-T14, P1-T15, or P2-T10.
- New signal lines follow the existing directive-line convention already used in both target files (`DIRECTIVE: ...`, `PREFLIGHT: ALL CLEAR`, `PREFLIGHT: REVISIONS REQUIRED`). No unrelated format is introduced.
- New prose complies with `.claude/rules/tonality.md`: no humor, no hyperbole, no decorative metaphor, evidence-first wording.
- New prose in `.claude/skills/atomic-plan-contract/SKILL.md` matches the rigor of the existing `## Wrap-Tolerant Assertion Authoring (Mandatory)` section: each rule names its concrete failure mechanism, not only its abstract goal.
- `.claude/agents/atomic-executor.md` and `.claude/agents/orchestrator.md`, and the bundled mirror of each, are out of scope and must not be edited. The tensions with those files are recorded in `## Open Questions / Notes` for escalation.
