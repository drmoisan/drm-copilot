## Binding Constraints (apply to every task)

1. **Both barrier layers are required; neither alone closes the gap.** A `PreToolUse` hook fires once per tool call with no cross-call or conversation-state visibility, so it cannot validate a batch of concurrent `Agent` calls; the retrospective validator sees the recorded batch but only after execution. Layer 1 (per-call deterrent) and Layer 2 (retrospective backstop) must both be delivered. No task may collapse them into one mechanism.
2. **Wave-4 contention constraint (mandatory, stated here as plan text).** F7 executes concurrently with F6 (`parallel-mutation-protocol`) and F8 (`parallel-drift-detection`). All three extend `.claude/skills/parallel-orchestrate/SKILL.md` and `scripts/dev_tools/validate_parallel_orchestrator_state.py`. Therefore:
   - F7's edit to `.claude/skills/parallel-orchestrate/SKILL.md` is confined to one distinct appended section titled `## Cohort Barrier Enforcement (F7)`; if the Phase 0 check (assumption U14) finds that F5 reserved a named placeholder section for F7, that reserved name is used verbatim instead.
   - F7's edit to `scripts/dev_tools/validate_parallel_orchestrator_state.py` is confined to exactly two added statements: one `from scripts.dev_tools._parallel_orchestrator_state_cohort_barrier import validate_cohort_barrier_ordering` import (which `black` at `line-length = 88` renders as a three-line parenthesized form, because the single-line form is 106 characters) and one `errors.extend(validate_cohort_barrier_ordering(state_map))` call appended at the end of the existing extend sequence. All invariant logic lives in the new helper module `scripts/dev_tools/_parallel_orchestrator_state_cohort_barrier.py`.
   - F7 must NOT reflow, reorder, reformat, or otherwise touch existing sections of either contended file, nor any section added by F6 or F8.
   - F3 owns the complete checkpoint schema. F7 adds NO checkpoint schema fields; Layer 2 adds validation logic over existing fields only (`cohorts[]`, `conflict_edges[]`, `items[].merge_status`, F3-defined lifecycle timestamps).
   - F7's Python test file is `tests/scripts/dev_tools/test_validate_parallel_orchestrator_state_cohort_barrier.py`, a file F3/F6/F8 do not own.
3. **Out of scope.** The drift gate (blocking a child's transition to review while an unresolved `drift_events[]` entry exists) belongs to F8. The abandon gate (denying `--disposition abandon` without an explicit confirmation marker) belongs to F6. No task in this plan implements either; any such logic is a scope violation.
4. **Additive only.** `.claude/hooks/enforce-epic-wave-barrier.ps1`, `.claude/hooks/enforce-epic-worktree-removal-gate.ps1`, and `.claude/hooks/enforce-epic-merge-gate.ps1` are not modified. Reuse is by near-verbatim adaptation into new `parallel`-named files. `.claude/hooks/enforce-epic-invocation-origin.ps1` is the one existing file extended, and its epic behavior — including the `EPIC_INVOCATION_ORIGIN_BLOCKED` deny reason string — remains byte-identical for epic targets.
5. **PowerShell batch budget.** `.claude/rules/powershell.md` caps a batch at 3 production PowerShell files and 3 test files, and `.claude/hooks/enforce-powershell-batch-budget.ps1` scopes a batch to the whole executor session, classifies `.psd1` files as production, and resets only when `.claude/state/powershell-batch-budget.<session_id>.json` is deleted. This feature's PowerShell production surface is five files: the two new hooks (Phase 1), the extended invocation-origin hook, and the two parity-locked `pester.runsettings.psd1` copies (Phase 2). Phase 1 writes 2 production + 2 test files; P2-T1/P2-T2 write 1 production + 1 test file, reaching the cap; P2-T3 resets the batch before P2-T4 writes the two `.psd1` files. No batch reaches the cap without an explicit recorded reset.
6. **Fail closed.** Once a hook call is in scope, every unresolvable condition — missing checkpoint, malformed checkpoint JSON, unresolvable target item, missing record, missing `merge_status` — denies. Out-of-scope calls (empty payload, non-`orchestrator` target, missing marker, non-matching command) allow.
7. **Evidence schema.** Every command-step evidence artifact below must record `Timestamp:`, `Command:`, `EXIT_CODE:`, and `Output Summary:`. Test evidence for Python (pytest) must record numeric line and branch coverage headline values. Test evidence for PowerShell (Pester) must record the numeric line/command coverage headline percentage and must explicitly record `BRANCH: not emitted by PoshQC/Pester coverage output`; the repository's PowerShell coverage tooling emits no BRANCH counter (precedent: `docs/features/active/2026-07-09-subagent-tree-mcp-and-dropdown-334/evidence/qa-gates/coverage-delta.2026-07-09T09-59.md`), so line/command coverage is the authoritative PowerShell numeric and this explicit absence note is the required substitute — it is not a placeholder for an available metric. Evidence paths resolve only to `docs/features/active/2026-08-07-parallel-enforcement-hooks-440/evidence/<kind>/`; `artifacts/`-rooted evidence paths are forbidden. Timestamps use `yyyy-MM-ddTHH-mm`.
8. **No SKIPPED.** Every command-bearing task must execute its stated command and record the result. `EXIT_CODE: SKIPPED` is not a passing outcome. The only skip branch in this plan is the one explicitly authorized inside P4-T3.
9. **Toolchain restart rule.** If any formatting, lint, type-check, or test step fails or changes files, restart the applicable language loop from its formatting step until a clean single pass completes.
10. **Phase 0 halt gate.** Any Upstream Contract Assumption row (U1–U16) that does not hold on the then-current integration branch halts execution for re-planning per P0-T11. Assumptions are not worked around.
11. **Acceptance-criteria tracking.** Per the `acceptance-criteria-tracking` skill, the AC sources for this `full-feature` plan are the identical 16-item `## Acceptance Criteria` sections in `spec.md` and `user-story.md`. Each Phase 6 check-off task flips the named checkbox from `[ ]` to `[x]` in BOTH files, without changing criterion text, and only after the cited evidence exists and passed.
