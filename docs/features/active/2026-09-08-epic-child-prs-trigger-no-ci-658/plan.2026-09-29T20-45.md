## Conventions for This Plan

- `FEATURE` denotes `docs/features/active/2026-09-08-epic-child-prs-trigger-no-ci-658`. Every evidence path below is written out in full and resolves under `docs/features/active/2026-09-08-epic-child-prs-trigger-no-ci-658/evidence/<kind>/` with `<kind>` one of `baseline`, `regression-testing`, `qa-gates`, `other`.
- `<ts>` in an evidence filename is the ISO-8601 timestamp `yyyy-MM-ddTHH-mm` captured when the task runs.
- Every command-step artifact carries `Timestamp:`, `Command:`, `EXIT_CODE:`, and `Output Summary:`. An artifact whose observed exit code is expected to be non-zero, or whose task says so, also carries `ExpectedExitCode: <int>`. `EXIT_CODE: SKIPPED` is never a passing outcome, and no task in this plan authorizes a skip.
- **No host data.** No artifact records an absolute filesystem path, drive letter, or account name. PoshQC log lines that print absolute paths are recorded with the worktree root replaced by `<WORKSPACE_ROOT>`.
- **PowerShell route.** The agent-worktree isolation guard refuses any Bash command whose text contains `pwsh` (observed at preflight). Every PowerShell command in this plan is therefore written verbatim, as the only line, to a script file in the session scratchpad (outside the repository) and executed with `sh <script-path>` from the worktree root, using a Bash timeout of 600000 ms. Because the pwsh command is the script's only line, the wrapper's exit code is the pwsh exit code. The artifact's `Command:` field records the inner pwsh command verbatim and adds a `Route: sh-wrapper` line; the scratchpad path is not recorded. No `-Command` string in this plan contains `$`, a backtick, or an embedded double quote, so each is copied without escaping. The self-hosted PoshQC module (`scripts/powershell/PoshQC/PoshQC.psd1`) is used, not the PoshQC MCP tools: MCP PoshQC results compose their summary before the child runs and carry no test output, so no count or percentage could be read from them. Every count and percentage an acceptance condition reads comes from observed console output of the module functions or of `Invoke-Pester`.
- **Observed success-case output (planner-verified by reading source and recorded runs):** `Invoke-PoshQCFormat` logs `Already formatted: <path>` per unchanged file and `Formatted: <path>` per rewritten file (`scripts/powershell/PoshQC/PoshQC.Analyzer.psm1:60-65`); `Invoke-PoshQCAnalyze -Root .` logs `PSScriptAnalyzer passed: no findings under .` and throws on findings (`PoshQC.Analyzer.psm1:181-185`); `Invoke-PoshQCTest` sets `Output.Verbosity = 'Normal'` (`scripts/powershell/PoshQC/PoshQC.Testing.psm1:321-322`) and, after Pester returns, replays `Pester summary (replayed for readability):` followed by the counts line and, with coverage enabled, the coverage headline of the form `Covered <pct>% / 0%. <n> analyzed Commands in <n> Files.` (`PoshQC.Testing.psm1:420-461`; `CoveragePercentTarget = 0` at `scripts/powershell/PoshQC/settings/pester.runsettings.psd1:329`). `scripts/powershell/PoshQC/settings/pester.runsettings.psd1:4` sets `Run.Exit = $true`, so when any test fails Pester exits the process with the failed-test count before `Invoke-PoshQCTest` reaches its replay; the replay is printed only on a zero-failure run.
