## Scope and conventions

- FEATURE means `docs/features/active/dependabot-bumps-types-vscode-past-engines-940`. All evidence is written under `FEATURE/evidence/<kind>/` with kinds `baseline`, `regression-testing`, and `qa-gates`. No other evidence location is used.
- Repository files created or edited outside FEATURE: `.github/dependabot.yml` (edit) and `tests/scripts/dev_tools/test_dependabot_config_contract.py` (create). Nothing is deleted. No other repository file changes.
- Language in scope: Python (the new pytest module). TypeScript, PowerShell, C#, and bash tooling are not touched, so no baseline or QC task exists for them.
- `SCRATCH/940/` resolves to the directory `SCRATCH/940/` under the session scratchpad; every scratch file name in this plan is unique under that directory. Scratch files here are limited to the full-suite output captures and coverage JSON reports. The plan records the literal token `SCRATCH/940/` and never a host path.
- Output capture for coverage commands: the redirect `> SCRATCH/940/<file>.txt 2>&1` is applied by the executor to the pytest command named in the task and is described in prose, not inside the command span. The command span shows `--cov-report=term-missing` directly after the `--cov=` arguments. Validator rule G9 reviewed: each coverage command in this plan passes `--cov-report=term-missing`, so any G9 "supplies no terminal reporter" warning on P0-T6 or P2-T8 is a false positive.
- Evidence file naming: every artifact is `<name>.<timestamp>.md`, with one exception: the Phase 0 policy-read record is the unstamped `phase0-instructions-read.md`. The stamp is the UTC time read from the host clock immediately before the file is written (`Get-Date -AsUTC -Format yyyy-MM-ddTHH-mm` in PowerShell 7), never composed in advance and never taken from this plan. A later pass writes a new file with a new stamp. A task that consumes an artifact selects the lexicographically greatest file matching `<name>.*.md`.
- Evidence artifact fields (rule E1): every command artifact contains `Timestamp:`, `Command:`, `EXIT_CODE:`, and `Output Summary:`. The Output Summary states the essential result signal, quoting the literal success line named in the task. An artifact for a gate expected to exit non-zero also contains `ExpectedExitCode: <int>`.
- Commit and push at each phase boundary. Pushes use `git push origin HEAD` and never force. No file is deleted.
- Restart-on-change rule: in Phase 2, if any QC command task exits non-zero or any file changes, fix the cause and restart at [P2-T1]. Each restarted pass writes new artifacts with new stamps. Only the lexicographically greatest artifact of each name is consumed by later tasks, and the last pass must be an unbroken clean pass.
- Observed success-case output used for every assertion below (read from recorded runs in other feature folders under `docs/features/`, for example `black-check-baseline`, `ruff-file-baseline`, `pyright-file-baseline`, `pytest-full-suite-coverage-baseline`, and `collected-count` artifacts): `poetry run black --check` prints `N file(s) would be left unchanged.`; `poetry run ruff check` prints `All checks passed!`; `poetry run pyright` prints `0 errors, 0 warnings, 0 informations`; pytest prints `N passed in Xs` (and `M failed, N passed` when tests fail); `--collect-only -q` prints `N tests collected in Xs`. The pytest-cov terminal table prints one combined `Cover` column on the `TOTAL` row (columns `Stmts Miss Branch BrPart Cover`), not separate line and branch percentages. `check_python_coverage_thresholds` prints nothing on success and exits 0; it prints to stderr and exits 1 only on a breach or an unreadable report.

### Phase 1 — Implementation (test first, then configuration edit)

Design of the new test module (constraints for [P1-T1]): the module is `tests/scripts/dev_tools/test_dependabot_config_contract.py`, under 500 lines, with a module docstring and a docstring on every function, `from __future__ import annotations`, imports of `pytest`, `yaml`, `Path`, and `cast`. It sets `REPO_ROOT = Path(__file__).resolve().parents[3]` and reads `.github/dependabot.yml` with `Path.read_text(encoding="utf-8")` then `yaml.safe_load`, immediately narrowed with `typing.cast` because pyright runs in strict mode and no `types-pyyaml` stub exists. It creates no temporary file. It defines constants for the two directories `("/", "/extensions/drm-copilot")`, the name `@types/vscode`, the name `typescript`, and the update type `version-update:semver-major`. It defines helpers that return the `updates` entries whose `package-ecosystem` is `npm` and whose `directory` is one of the two directories. It contains exactly these five tests, with the parametrized ones using `pytest.mark.parametrize("directory", ..., ids=["root", "extension"])`:

1. `test_npm_entry_ignores_types_vscode_for_all_update_types[root]` and `[extension]`: the entry for the directory has an `ignore` item whose `dependency-name` equals `@types/vscode`, and that item contains neither an `update-types` key nor a `versions` key. When no such item exists, the assertion message starts with the exact text `npm entry for directory` and contains the exact text `lacks an ignore item for @types/vscode`.
2. `test_npm_entry_retains_typescript_major_ignore[root]` and `[extension]`: the entry has a `typescript` ignore item whose `update-types` equals `["version-update:semver-major"]`.
3. `test_exactly_two_target_npm_entries_are_checked`: the selection of npm entries for the two directories has length 2 (non-vacuity).
