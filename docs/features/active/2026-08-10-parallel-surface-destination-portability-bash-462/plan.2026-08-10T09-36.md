## Binding Environment Constraints (executor must not deviate)

1. **Bash toolchain is CI-only.** shfmt, shellcheck, bats, and kcov cannot run on this win32 host (per `.claude/rules/shell.md`; verified precedent issues #393/#394). Every shell verification task in this plan is a `gh workflow run _shell-coverage.yml --ref <branch>` dispatch (or the PR-triggered `ci.yml` run) with the run URL, conclusion, and the `Bash coverage (lines): NN.N%` log line captured as evidence. No plan task assumes a local bats/shfmt/shellcheck/kcov run. From P1-T6 onward each dispatch must show two green steps: the `check` step (`bash scripts/bash/shell-qc.sh check` — shfmt `-d` + shellcheck) and the coverage step (`bash scripts/bash/shell-qc.sh test --coverage` — bats + kcov). The workflow has no coverage-threshold gate — a low-coverage run still concludes `success` — so every shell gate task must read the printed `Bash coverage (lines): NN.N%` log line and enforce the >= 85% threshold from that evidence, not from the run conclusion.
2. **`poetry run python -c` with a multi-line string silently produces no output and exits 0 in this environment** (verified 2026-08-10). Any inline Python invocation in this plan MUST be a single-line `poetry run python -c "..."`, or plain `python -c "import sys; sys.path.insert(0,'.'); ..."`, or a committed script file. Never a multi-line `poetry run python -c`.
3. **`scripts/dev_tools/validate_orchestrator_state.py` has no `__main__` guard**; the `python -m scripts.dev_tools.validate_orchestrator_state` CLI form exits 0 without validating. No task in this plan uses that CLI form. Fixing the defect is out of scope for #462.
4. **Dual-home rule.** Production push-down reads the bundled tree (`extensions/drm-copilot/src/lib/push-down/push-down-service-call.ts:169-172`), not the repo root. Every new or changed `.claude/**` file in this plan has an explicit bundled-mirror task; mirroring is never assumed.
5. **No temporary files in tests.** All test inputs are checked-in fixtures under `tests/fixtures/`.
6. **No schema change.** No parallel-surface schema field, enum member, or validator invariant may be added, removed, or altered. `scripts/dev_tools/parallel_*.py`, `scripts/dev_tools/_parallel_state_*.py`, and the TypeScript parity port under `extensions/drm-copilot/src/lib/validate/parallel-*.ts` are read-only for this feature.

## Fixed Design Decisions (from spec + research; binding on implementation)

- **CLI shapes (final flag spelling, fixed here):**
  - `bash .claude/lib/bash/compute-cohorts.sh --keys "<k1> <k2> ..." --edges "<a>:<b> <a>:<b> ..."` (`--edges` optional; empty means no edges). Output: compact JSON array of arrays on stdout identical to Python `json.dumps(..., separators=(",", ":"))`; exact Python error message on stderr with exit code 1 on invalid input.
  - `bash .claude/lib/bash/compute-concurrency-batches.sh --keys "<k1> <k2> ..." --max-concurrency <n>` with the same output/error convention.
  - `bash .claude/lib/bash/validate-parallel-manifest.sh <manifest-path>` (errors one per line on stdout; exit 0 valid / 1 invalid), plus `bash .claude/lib/bash/validate-parallel-manifest.sh --print-mode <manifest-path>` and `--print-max-concurrency <manifest-path>` accessor subcommands.
- **Integer lexical rule:** accepted key/edge tokens match `-?(0|[1-9][0-9]*)`; tokens with leading zeros (`-?0[0-9]+`) are rejected fail-closed with a bash-side lexical error (documented; excluded from the parity corpus).
- **Determinism countermeasures (R9):** `export LC_ALL=C` at every entry-point top; all numeric ordering via `sort -n` (composite Welsh-Powell key via `sort -k1,1nr -k2,2n`); bash associative-array iteration order never reaches output; validation ordering matches Python exactly (duplicate-key errors before edge errors; self-loop before unknown-endpoint for the same edge; M1 fence errors before identity, prohibited-key, and item errors).
- **Declared divergence classes (recorded in all four parity-suite headers):** (a) the M1 YAML-parse-failure message — parity scoped to the prefix `Parallel manifest frontmatter is not valid YAML: ` plus single-element error-list shape; (b) non-printable string-repr escapes. Everything else is byte parity, including Python `repr` quote selection.
- **YAML handling:** hand-written bash parser restricted to the machine-authored manifest subset, fail-closed on any construct outside it. No `yq`, no Node validation, no new MCP `artifact_type`.
- **Push-down routing-source pinning (three-copy rule):** three copies of `orchestration-routing.json` exist after this feature: the repo root `config/orchestration-routing.json` (canonical; carries `$schema`, `version`, `model_policy`, `model_budget`, `codex_topology_policy`, `codex_model_policy`, and the six routes `small, large, remediation, preparation, parallel, epic`), the extension-runtime mirror `extensions/drm-copilot/resources/config/orchestration-routing.json` (byte-identical to root, required by `.claude/rules/parallel-orchestration.md`), and the new push-down source `extensions/drm-copilot/resources/claude-customizations/config/orchestration-routing.json`. The push-down source is pinned as **byte-identical to the repo-root file**, enforced by a Jest byte-equality assertion (P4-T5). Rationale: the runtime mirror is already required to be byte-identical, so a single canonical content across all three copies is mechanically verifiable and needs no asymmetry note; a deliberately different generic document would forfeit that mechanical check. The merge rule below governs destination-side writes only, not the bundled source content.
- **Routing merge serialization rule (pinned for idempotency):** destination file absent → write source text unchanged. Destination present → start from the destination document; preserve destination key order for preserved keys; the source `parallel` route overwrites/inserts; source routes absent at destination (including `preparation`) and top-level non-`routes` blocks absent at destination are appended in source order; serialize with 2-space indentation and a trailing LF; pushing twice must be byte-stable; unparseable destination JSON fails that file with an explicit run-summary error and is never written.
- **Corpus floors:** `tests/fixtures/parallel_cohorts/` minimum 20 fixtures; `tests/fixtures/parallel_manifest_bash/` minimum 24 fixtures. All four parity suites enforce the floor.
- **Manifest-membership test language:** bats (`tests/shell/parallel_bash_manifest_membership.bats`), following the `tests/scripts/claude-lib/blast-radius/BlastRadius.Manifest.Tests.ps1` pattern (discovery + `core.json` membership + byte-identical bundled counterpart), so no new PowerShell surface is introduced.
