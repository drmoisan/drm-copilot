## Design and Correctness Notes

- Predicate parity: `SCRATCH_DEFINITION_PATTERN` and `SCRATCH_NAMESPACE_PATTERN` are the same strings in both runtimes (`plan_gate_scratch.py:61-68`; `plan-gate-scratch.ts:52,59`). Python compiles with `re.ASCII`, which aligns `\b` with the JavaScript non-`u` semantics.
- Step 2 is evaluated on the text after the first definition match only (`plan_gate_scratch.py:94`; `plan-gate-scratch.ts:129`), matching the spec. A namespace placed before the definition does not accept the line (probe: `issue-5: SCRATCH means the session scratchpad.` is flagged).
- The TypeScript walker uses a pending-line state machine while Python uses a nested loop; both produce the same logical lines for the spec fixtures, and the shared frozen strings assert it.
- `evaluate_scratch_gate` exposes a keyword `severity` parameter defaulting to `G10_SEVERITY`, which keeps the channel a single constant and allows a future Warning downgrade without code changes.
- The scratch contract test now imports the production detector (`test_scratch_location_contracts.py:26`), and its parametrized self-test demonstrates that the check can fail (`:315-341`), which resolves the #900 review gap.
- The corpus measurement (493 files, 17 findings, 0 false positives) was taken after the decision rule was committed (`3135d7ee2` precedes the measurement commit), as the spec requires.
