## Design: decision D17 (closed modelled-command rule)

Cause (F2): `Read-CommandLineSegment` drops whitespace-only segments, so the `|` after a group closer, and every brace, is never recorded; the D16 walk runs forward only and stops at the first same-depth delimiter other than `|`. Each round has found another construct stage 2 mis-models, so D17 inverts the default: stage 2 drops a hit only for commands built entirely from constructs it positively models. Stage 2 is a policy-level control, not a security control (as the header of the commands sibling states), and any construct whose meaning the model does not decode keeps the hit classified.

**Rule.** Where rules 1 to 5 (D2, D16) would drop a stage-1 hit, D17 drops it only when all three conditions hold; otherwise the hit is confirmed:
1. *Modelled.* The normalized command text, every modelled Posix payload, and every PowerShell payload consist only of the allowlisted constructs below.
2. *Operand.* Every record carrying a governed word is a mention-host record (rule 3 lookup), a modelled payload wrapper whose payload carries the word, or a PowerShell expression record inside the scriptblock argument of a mention-host command.
3. *Pipeline mates.* Every non-carrying record of the same pipeline as a carrying record, before or after it, is an accepted consumer (D16 definition). Posix: the maximal run of same-depth records joined by `|`, skipping deeper payload records and ended by a lower-depth record. PowerShell: every record of the same payload (fail-closed, as in D16).

**Posix allowlist** (quote-aware scan, as `Read-CommandLineSegment` scans, of text after `ConvertTo-CommandLineNormalizedText`): words that are unquoted, `'...'`, or `"..."` without `$(` or a backtick inside, backslash escapes, unquoted `$name` operands, and the standalone `{}` word that normalization quotes; the separators `|`, `;`, `&&`, `||`, and newline; the transparent wrappers `env`, `timeout`, `time`, `command`, `nohup` of `Skip-CommandLineTransparentWrapper` (for `env`, only without a split-string option); payload wrappers re-derived through `Get-CommandLineWrapperPayload` from the words `Add-CommandLineWrapperExpansion` received (`Split-CommandLinePosixWord` of the record text for Posix records, `Tokens` for PowerShell and `ArgumentInjector` records): `sh`, `bash`, `zsh`, `dash`, `ksh` with a `-c` flag whose payload is the last word, `pwsh` or `powershell` with `-c` or a `-Command` prefix, or with `-CommandWithArgs`, `-cwa`, or an `-EncodedCommand` form whose payload is the last word, and `xargs` with its injected command; the mention hosts of the unchanged table with their operands. **Unmodelled** (keeps the hit): any unquoted `(`, `)`, `{`, `}`, `<`, `>`, backtick, `#`, or `&` outside `&&`; an unquoted `$` immediately followed by `'` (ANSI-C quoting, which decodes escapes such as a newline or `|`); `$(` or a backtick inside double quotes; a backslash in the raw command text immediately followed by LF or CR LF (`ConvertTo-CommandLineNormalizedText` joins it with the newline even inside single quotes, so the normalized text no longer shows the shell's reading); a `$_` expansion, unquoted or inside double quotes, in the normalized command text or in any modelled Posix payload at any depth, when that text or payload has more than one record at its own top depth (shell state carried across `;`, `&&`, `||`, `|`, or newline; `bash -c 'echo pytest; env $_'` is classified through its payload; a `$_` in the only top-depth record of its text, as in FP-16, stays modelled, and a PowerShell payload's `$_` is judged by the PowerShell allowlist); a record whose first token or command word is a reserved word (`if`, `then`, `else`, `elif`, `fi`, `case`, `esac`, `for`, `select`, `while`, `until`, `do`, `done`, `function`, `!`, `[[`, `]]`, `coproc`), `eval`, `source`, `.`, or a shell-state builtin (`alias`, `unalias`, `hash`, `enable`, `builtin`, `exec`, `trap`, `set`, `shopt`, `export`, `declare`, `typeset`, `readonly`, `local`, `unset`, and `printf` with a `-v` option, separate or attached as `-vNAME`); an `env` option token before the command word that is `-S...`, a short-option bundle containing `S`, or a prefix of `--split-string` from `--s` on (env split-string); an assignment word `NAME=value` anywhere, including after `env`; a wrapper word after its payload; every Opaque or Unbalanced record.

**Mention-host executing options.** `Test-OrchestrationGateMentionHostRecord` also treats a long option as executing when its nonempty name (the text after `--` and before any `=`) is a prefix of the name of an executing long option of that host (GNU long-option abbreviation, for example `sort --compress`), and, for `git`, treats a single-dash token (not `--`) whose option letters contain the uppercase `O` (ordinal) as the executing `-O` option, so `git grep -iOpytest pytest` is classified. `Get-OrchestrationGateMentionHostTable` changes in exactly one entry: `ExecutingOption.rg` becomes `--pre`, `--hostname-bin` (`rg --hostname-bin pytest x` is classified); every other group, set, and entry is unchanged.

**PowerShell allowlist** (AST from `[System.Management.Automation.Language.Parser]::ParseInput`, which never executes): `ScriptBlockAst` with only an unnamed end block (no param, begin, process, or dynamicparam block, no using statement), `NamedBlockAst`, `PipelineAst` statements, `CommandAst` with a constant name, no `&` or `.` operator, and no redirection, `CommandParameterAst`, `StringConstantExpressionAst`, `ConstantExpressionAst`, `ExpandableStringExpressionAst`, `VariableExpressionAst`, non-static `MemberExpressionAst` with a constant member, `UnaryExpressionAst`, `BinaryExpressionAst`, `CommandExpressionAst`, and `ScriptBlockExpressionAst` only as an element of a mention-host `CommandAst` (its body judged by the same list). A `CommandExpressionAst` outside such a scriptblock must not carry a governed word. Every other node type is unmodelled.

**Placement.** Four new functions in `enforce-orchestration-preimplementation-gate-commands.ps1`: `Test-OrchestrationGatePosixTextModelled`, `Test-OrchestrationGatePowerShellPayloadModelled`, `Test-OrchestrationGateCommandModelled` (record-level conditions 1 and 2), and `Test-OrchestrationGateAcceptedConsumer`, shared by the forward D16 walk and a new backward walk. `Test-OrchestrationGateInvocationConfirmed` evaluates D17 only where it would otherwise return `$false`, so rules 1 to 5 keep their order and their coverage. `Test-OrchestrationGateMentionHostRecord` gains the abbreviation check and the `git` bundle check; `Get-OrchestrationGateMentionHostTable` gains only the `--hostname-bin` entry of `ExecutingOption.rg`.

**Bound, cost, N1.** Stage 1 is unchanged and D17 and the abbreviation check only add confirmations, so the classified set lies between the head set and the merge-base set (AC-3); every row on which head and merge base agree keeps its value. Cost: a mention with a redirection (`2>&1`), comment, background job, assignment word, compound command, or PowerShell assignment or method call stays classified, as at the merge base. N1: a redirection hand-off (`echo pytest > f; xargs env < f`) is now classified; a hand-off through a host's own file option across statements (`grep -o pytest x | sort -o f; xargs -a f env`), or through state left by an earlier call, stays outside the model. **FP rows:** none contains an unmodelled construct; the stages before the carrier in FP-01 and FP-02 are `ps`, in FP-16 `Get-Process`, and FP-16's scriptblock is the argument of the host `Where-Object` and holds only a variable, a member access, a constant, and `-match`, and its `$_` sits in its only depth-0 record; FP-07's `--grep` is no prefix of `--open-files-in-pager`, and no FP row carries a `git` token with an uppercase `O` bundle or an `rg` long option; all 17 stay unclassified. **AC reading:** AC-2's table includes ED-51 to ED-96; AC-4's fallbacks include the D17 classes; AC-5's "D2 table" is the D2 table as amended by D16 and D17. No AC text changes.

**Non-goal (decision D18, OD-1).** Deliberately obfuscated commands are out of scope for stage 2, because the gate is a policy-level control and not a security boundary (owner directive OD-1, 2026-11-14). A later finding that is only a further obfuscation variant is dispositioned out of scope rather than remediated; an ordinary, non-obfuscated invocation that stage 2 misclassifies is still a defect. The sentence added to the commands sibling header and to the brief's #1160 bullet is: "Deliberately obfuscated commands are out of scope (decision D18): a later finding that is only a further obfuscation variant is dispositioned out of scope, while a misclassified ordinary invocation remains a defect."
