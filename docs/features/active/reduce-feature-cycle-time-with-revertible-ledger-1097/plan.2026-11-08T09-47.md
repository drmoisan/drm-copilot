## Design Summary

- **Placement.** New directory `.claude/lib/review-verdict/`: the pure module `ReviewVerdictEligibility.psm1` and the thin entry point `Invoke-ReviewVerdictStatus.ps1`, following the `parallel-drift` pair (`Invoke-ParallelDriftCli`, dot-source guard). `.claude/lib` is in `config/poshqc-coverage.json` roots, the Claude bundle carries `.claude/lib`, and the Claude and Codex orchestrate skills already call `.claude/lib/ci-gate/Invoke-CiGateParser.ps1` with an absent-file rule, so both can call this entry point; the parallel and epic orchestrators can call it by the same path. Bundle copies under `extensions/drm-copilot/resources/claude-customizations/.claude/lib/review-verdict/` and two `core.json` entries satisfy the resource, completeness, and dependency-closure contracts (the entry point imports the module through `$PSScriptRoot`).
- **Seams.** The entry point owns the only I/O: `Invoke-ReviewVerdictGhExe -GhArgs`, `Invoke-ReviewVerdictGitExe -GitArgs` (each returns `ExitCode` and `Output`), and `Read-ReviewVerdictCheckpointText -Path`. Tests mock these wrappers, never `gh` or `git`, and create no file. The entry point writes no file, so no verdict file can be committed.
- **Post.** One call: `gh api --method POST repos/{owner}/{repo}/statuses/<head> -f state=success -f context=review/verdict -f description=<text>`, built by the pure `Get-ReviewVerdictStatusArgument`; a description above 140 characters throws. Exit codes: 0 posted (stdout `REVIEW_VERDICT_POSTED:`), 3 not eligible (stderr `REVIEW_VERDICT_NOT_ELIGIBLE: <code>: <detail>`, no POST), 1 read, git, or gh failure, 2 usage.
- **Mode `Review` (feature PR; posting and the records-only re-post).** Inputs: checkpoint (`remediation_loop.review_outcomes` last entry, `feature-folder`, `pr_gate.pr_number`), `gh pr view <PR> --json headRefOid,state`, and `-ReviewArtifact`. In order: last entry verdict exactly `PASS`, else `REVIEW_VERDICT_NOT_PASS`; its `head_sha` a lowercase 40 or 64 character id, else `REVIEW_VERDICT_HEAD_ABSENT`; `pr_gate.pr_number` equal to `-PrNumber` and state `OPEN`, else `REVIEW_VERDICT_PR_MISMATCH`; `feature-folder` under `docs/features/` with no blank, `.`, or `..` segment, no backslash, no trailing slash, else `REVIEW_VERDICT_FEATURE_FOLDER_INVALID`; `-ReviewArtifact` equal to `<feature-folder>/policy-audit.<yyyy-MM-ddTHH-mm>.md`, else `REVIEW_VERDICT_ARTIFACT_INVALID`, and present in the live head (`git cat-file -e`), else `REVIEW_VERDICT_ARTIFACT_NOT_COMMITTED`. Then: live head equal to `head_sha` posts; otherwise `git merge-base --is-ancestor` exit 1 gives `REVIEW_VERDICT_HEAD_NOT_CURRENT`, and the listing `git diff --name-only -z --no-renames <reviewed> <live>` must hold only paths under `<feature-folder>/` (an empty listing included), else `REVIEW_VERDICT_NOT_RECORDS_ONLY` naming the first outside path. Any other git exit gives `REVIEW_VERDICT_GIT_FAILED`. Description: `feature-review PASS: <artifact file name>`.
- **Records-only decision.** Records-only means paths under the checkpoint `feature-folder` only, the rule the merge guard and the join already apply (D4), so the status and the guard never disagree. Ledger `Merge commit:` back-fills are excluded: K8 and step 3 of the concurrent sequence land them before the review starts, and including them would post a status on a head the merge guard reports stale. The artifact-committed check makes "records before posting" mechanical: posting on the reviewed head fails until the review records are committed, and the records commit is then re-posted by this rule.
- **Mode `MainSync` (main sync into an integration branch).** Head ref matches `^epic/[A-Za-z0-9][A-Za-z0-9._-]*-integration$` and base is `main`, else `REVIEW_VERDICT_BRANCH_MISMATCH`. The live head has exactly two parents, R then M; R carries a `review/verdict` status with state `success` (read through `gh api repos/{owner}/{repo}/commits/<R>/statuses`, newest entry for the context), else `REVIEW_VERDICT_PARENT_UNVERIFIED`; M is an ancestor of `origin/main`. With B the merge base of R and M, the branch set diff(B,R) and the main set diff(B,M) are disjoint, diff(R,H) is a subset of the main set, and diff(M,H) is a subset of the branch set, else `REVIEW_VERDICT_NOT_MAIN_SYNC` naming the path. Description: `main sync: no change beyond main and the reviewed head`.
- **Mode `RecordsPr` (records-only PR).** Head ref exactly `documentationandmemories` (the only records-only branch the repository opens, `cleanup-merged-worktrees`) and base `main`; the listing from the merge base of `origin/main` and the head is non-empty and every path is under `docs/features/` but not under `docs/features/templates/` and not `docs/features/potential/template.md`, or under `.claude/agent-memory/`, else `REVIEW_VERDICT_NOT_RECORDS_ONLY`. Description: `records-only pull request`.
- **Mode `PromotionPr` (promotion-record PR).** Head ref matches `^(feature|bug)/[a-z0-9][a-z0-9-]*-([0-9]+)$` (the `${promotion-type}/${short-name}-${issue-num}` shape) and base `main`. Every `--name-status -z --no-renames` entry from the merge base is either under `docs/features/potential/` (not `template.md`) or an `A` entry under exactly one folder `docs/features/active/<name>/` whose name ends with `-<the branch number>`; at least one folder entry exists; and `git ls-tree -d --name-only <base> -- <folder>` is empty, so the folder is new. Else `REVIEW_VERDICT_NOT_PROMOTION_RECORD`. Description: `promotion-record pull request`.
- **Skill wiring.** A new section `## Review Verdict Status (review/verdict)` follows `## PR Creation Gate` and precedes `## Step 6 Delegation — Prohibited Prompt Language` in the four orchestrate copies. It states: post after every PASS once the PR exists and records are committed and pushed (after `## Post-Review Outcome Evaluation` advances a PASS, after R5 exits on PASS, and at the concurrent join), recording `head_sha` on every review outcome; that a new push leaves the new head without the status, so review must pass again; the records-only re-post; that immediately before the merge (S9 steps 6 and 7, the join, or `## CI Green Gate` on Codex) the entry point runs against the live head, and a refusal means no merge and a new review; the three non-feature modes; the absent-file rule (no post, merge unchanged); that the parallel parent posts nothing, because each item is an orchestrate run that posts after its own PASS and a head the parent changes is stale and re-reviewed by the item; that epic children post as orchestrate runs, while epic-orchestrator wiring of the integration PR is out of scope because `PINNED_FROZEN_SURFACE_HASHES` freezes the epic surfaces and the context is not yet required (D15), with `-Mode MainSync` available; that the status adds no CI run, no CI job, no workflow file, no committed verdict file, and no GitHub ruleset change; and the limit.
