## Scope

Exactly 3 npm workspaces are in scope: the repo root (`.`), `extensions/drm-copilot/`, and `packages/mcp-server/`. In each, the fix is a `package-lock.json` update via `npm audit fix` (non-force), plus a `package.json` dependency/devDependency/`overrides` range-widening edit only if `npm audit fix` itself performs one as a side effect of resolving an advisory. No production source file (`.ts`, `.py`, `.ps1`, `.cs`) may change. No `--force`/breaking major-version bump is applied; if a residual advisory can only be resolved that way, this plan requires it to be documented as a separate finding rather than silently applied.

**Context note (observed, not assumed):** A repository-state check performed while authoring this plan found that all three workspaces' `package.json` files already carry `overrides` entries for `fast-uri` (`^3.1.4`) and `qs` (`^6.15.2`) (root and `extensions/drm-copilot/` also override several other packages; `browserslist` and `@humanfs/node` carry no override in any manifest), and that the three `package-lock.json` files currently resolve `fast-uri` to `3.1.5`, `qs` to `6.15.2`, `browserslist` (root and `extensions/drm-copilot/` only) to `4.28.2`, and `@humanfs/node` to `0.16.7` in the root lockfile; `@humanfs/node` is also present in `extensions/drm-copilot/package-lock.json` (resolved to `0.16.8`, a version `npm audit --audit-level=moderate` does not currently flag in that workspace) and is genuinely absent from `packages/mcp-server/package-lock.json`. These version numbers were read directly from the lockfiles, not from a live `npm audit` run, so they do not establish whether the four advisories named in `issue.md` are already resolved on this branch (the issue's audit output was captured from CI runs on PR #624/#626, and the repository's `main` branch has since merged a dependabot dependency bump, commit `c2bbfb36`, that may have already touched some of these packages). Phase 0 below runs the real `npm audit --audit-level=moderate` command in each workspace to establish current, authoritative ground truth; nothing in this plan assumes the outcome in advance. If baseline capture in a given workspace already reports zero moderate-or-higher vulnerabilities, Phase 1's fix-application task for that workspace still runs (idempotently) and Phase 2 confirms the zero-vulnerability state with real command output, rather than skipping the workspace.
