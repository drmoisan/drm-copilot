## Scope

In scope: the VS Code extension bundling warning described in `issue.md` Expected Behavior item 2. `extensions/drm-copilot/package.json`'s `compile`/`build` scripts run `tsc -p ./`, emitting one `.js` file per `.ts` file (128 files) into `out/` with no bundling. This plan adds a new `extensions/drm-copilot/esbuild-extension.cjs` script that bundles `src/extension.ts` into a single `out/extension.js`, and updates `compile`/`build` to type-check via `tsc -p ./ --noEmit` and then bundle via esbuild.

Out of scope: the npm `E404` publish failure (Expected Behavior item 1). That defect is resolved via the human-exception runbook at `docs/features/active/2026-07-03-npm-publish-404-and-vsce-bundling-warning-283/runbooks/npm-token-rotation.runbook.md` and requires no code change. This plan does not touch `.github/workflows/publish-mcp-npm.yml` or any workflow file.

AC source: `docs/features/active/2026-07-03-npm-publish-404-and-vsce-bundling-warning-283/issue.md`, section `## Acceptance Criteria` (added during planning per the `acceptance-criteria-tracking` skill's rule that AC items are authored by planning/scoping agents; the section was missing at planning time, which is a `feature-promotion-lifecycle` step-4a integrity gap corrected here rather than inferred silently in this plan document). `spec.md` and `user-story.md` are absent by design for `minor-audit` and are not required.

Module rigor tier: T4 (scaffolding — build scripts / dev tooling) per `.claude/rules/quality-tiers.md`.
