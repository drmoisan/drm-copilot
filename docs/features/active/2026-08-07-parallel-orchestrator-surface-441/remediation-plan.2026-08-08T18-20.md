## R-01 Option Analysis and Selected Fix

Two options were evaluated against the persona's least-privilege grants.

**Option A (SELECTED) — reassign the write to the item's child chain.** The parent detects the conflicted `gh pr merge --merge`, records the conflict signal, and re-delegates the item's child orchestration; the child's `atomic-executor` performs the conflict capture inside the item's own worktree and writes `remediation-inputs.<timestamp>.md` into the item's own active feature folder, which the child then processes through its unmodified R1-R5 loop.

Reasoning:

1. It requires no new grant. The persona's `Write`/`Edit` scopes stay at `docs/features/parallel/**` and `artifacts/orchestration/**`, which is the narrowest set that still supports the run manifest projection and the checkpoint.
2. It restores parity with the frozen epic precedent. `.claude/skills/epic-orchestrate/SKILL.md:187-194` assigns both the conflict capture and the finding write to the child's `atomic-executor`, writing into the child feature's own active folder rather than the run-level folder. The parallel adaptation reassigned the actor without adding the corresponding grant; reverting the actor removes the divergence at its origin.
3. The capture moves with the write for a mechanical reason: `git merge --no-commit origin/main` and `git diff --name-only --diff-filter=U` require a working tree holding the item's branch. That is the item's worktree, not the parent's main checkout, and the parent must not mutate the main checkout to produce a conflicted-file list. Assigning the capture to the child therefore also removes a working-tree side effect from the parent.

**Option B (REJECTED) — widen the parent's grants.** Adding `Write(docs/features/active/**)` and `Edit(docs/features/active/**)` would grant the parent write access to every active feature folder in the repository — including folders belonging to features that are not items of the run — in order to author one synthetic finding file. That is the widest blast radius available on this surface, it would require the persona body to document that radius explicitly, and it would keep the actor divergence from the epic precedent in place. It is rejected on least-privilege grounds.

## R-03 Test Design (producer/consumer seam)

The test is a seam test in the style already established in this module: the persona allowlist is the **producer** of permissions and the skill procedure is the **consumer**. Both sides are parsed from the delivered files at run time. No test restates the grant set and no test restates the prescribed-target set, so a one-sided narrowing of the allowlist or a one-sided addition to the procedure fails.

Producer parsers (persona side), reading `.claude/agents/parallel-orchestrator.md` frontmatter `tools`:

- `persona_write_grants()` — every entry of the form `Write(<glob>)`, returning the glob bodies.
- `persona_bash_grants()` — every entry of the form `Bash(<pattern>)`, returning the pattern bodies.
- `write_grant_covers(grant, target)` — a `**`-terminated grant covers any target beginning with its literal prefix; a grant without a wildcard must equal the target.
- `bash_grant_covers(grant, invocation)` — a `*`-terminated grant covers any invocation beginning with its literal prefix; a grant without a wildcard must equal the invocation.

Consumer parsers (skill side), reading `.claude/skills/parallel-orchestrate/SKILL.md` body:

- `prescribed_parent_write_targets()` — split the whitespace-collapsed body into sentences at a terminator (`.`, `!`, `?`) that is followed by whitespace or end of text and is not inside a backticked span, treating a leading ordered-list marker (`<digits>.`) as a boundary rather than a terminator, so tokens such as `remediation-inputs.<timestamp>.md` and `scripts.dev_tools.validate_orchestration_artifacts` are never split. For each sentence, retain a backticked repo-relative path token (a token containing `/` and no whitespace) only when all three conditions hold: (a) the sentence contains a verb from `WRITE_VERBS`; (b) the sentence contains no marker from `NON_PARENT_ACTOR_MARKERS`; and (c) the word immediately preceding the token is either a member of `WRITE_VERBS` (direct-object form, for example `regenerate <path>`) or a member of `WRITE_DESTINATION_PREPOSITIONS` (destination form, for example `writes to <path>`, `under <path>`). The skill is addressed to `parallel-orchestrator`, so an unattributed write sentence that satisfies all three conditions is a parent write; a sentence that names another actor is that actor's write and is excluded.

  Condition (c) — the immediately-preceding-word adjacency test — is a required part of the rule and not an optimization. A sentence-scoped rule that omits it captures three specific false positives in the current body, none of which Phase 2 or Phase 3 repairs, which would make P3-T5 and P6-T4 unachievable:

  - `.claude/skills/parallel-orchestrate/SKILL.md:180` — `docs/features/active/<basename>`. This is prompt-text describing how the path is *written literally* into the delegation prompt; it is not a filesystem write destination. It cannot be reworded to evade a weaker parser, because `KICKOFF_IDENTITY_FRAGMENTS` in `tests/scripts/dev_tools/parallel_orchestrator_surface_expectations.py:117` pins the literal phrase "written literally as `docs/features/active/<basename>`" and the existing 36-test suite asserts it. Under condition (c) the preceding word is `as`, which is absent from `WRITE_DESTINATION_PREPOSITIONS`, so the token is excluded. The line-180 sentence must not be edited to satisfy the parser.
  - `.claude/skills/parallel-orchestrate/SKILL.md:191` — `origin/main`. This is the spawn branch base inside the sentence that states these parameters are "never written into the prompt text"; the preceding word is `base`, which is in neither closed set, so the token is excluded.
  - `.claude/skills/parallel-orchestrate/SKILL.md:373` — `config/orchestration-routing.json`. This is a read source ("populated with the `parallel` route's required names from …"); the preceding word is `from`, which is deliberately absent from `WRITE_DESTINATION_PREPOSITIONS`, so the token is excluded while the same sentence's genuine destination `artifacts/orchestration/parallel-orchestrator-state.json` (preceded by `to`) is retained.

  The sentence-boundary rule above is stated explicitly because a naive split on `.` fragments `remediation-inputs.<timestamp>.md` and `scripts.dev_tools.validate_orchestration_artifacts`, which would drop the intended target from the result set entirely.
- `prescribed_command_invocations()` — candidate spans are every inline backticked span plus every non-empty line inside a fenced code block. A candidate is a command invocation when it contains at least one space and its first whitespace-separated token matches `^[a-z][a-z0-9-]*$` in full. That shape admits `git …`, `gh …`, and `poetry run …` while rejecting field names, enum members, `key: value` markers, bracketed structures, and path tokens.

Pinned test data added to `tests/scripts/dev_tools/parallel_orchestrator_surface_expectations.py`:

- `WRITE_VERBS = ("write", "writes", "written", "rewrite", "rewritten", "record", "records", "recorded", "regenerate", "regenerates", "regenerated")` — deliberately excludes "generate"/"generated", which the skill uses for read-from-template and projection-description sentences.
- `NON_PARENT_ACTOR_MARKERS = ("child", "atomic-executor", "parallel-planner", "item's own `orchestrator`", "hook", "F6", "F7", "F8")` — the closed set of non-parent actors named on this surface, drawn from the surface's own actor model.
- `WRITE_DESTINATION_PREPOSITIONS = ("to", "into", "under")` — the closed set of prepositions that place a path token in a write-destination position on this surface. `from`, `of`, `as`, `at`, `in`, and `per` are deliberately absent because on this surface each of them introduces a read source or a textual-appearance description rather than a write destination.

3. The section that names `validate_parallel_manifest_text` also prescribes at least one command invocation covered by a `persona_bash_grants()` pattern, which regression-locks R-02 specifically.
