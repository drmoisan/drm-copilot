## Executive Summary

The branch adds a fourth context-free token-shape rejection to the blast-radius path classifier in both runtimes: a token containing any member of the five-marker placeholder set `<`, `>`, `${`, `$(`, `%` is rejected wherever the marker sits, because it documents a command or artifact shape rather than naming a file. The guard is placed after the root-surface equality test and before the separator guard in both `classify_path_token` (Python) and `Get-PathTokenKind` (PowerShell), and the ordering rationale is recorded inline in both runtimes in matching prose.

Because the two extraction modules stood at 497 and 498 lines against the hard 500-line limit, the guard could not be added in place. Two new leaf modules were created to hold it, and the pre-existing `spans_multiple_feature_folders` / `Test-MultipleFeatureFolderSpan` predicate was relocated into them with its two module-scoped constants. Both leaf modules import no sibling blast-radius module, so no import cycle is possible; the relocated PowerShell function is re-exported from the extraction module so every pre-existing call site and test stays source-compatible. Post-change file sizes are 475, 472, 144, and 187 lines — every file below the limit, and both extraction modules with more headroom than they started with.

All ten policy sections audited below are PASS. Every toolchain stage was re-executed by the reviewer with check-only commands and passed in a single pass: Black `--check` (442 files unchanged), Ruff `--no-fix` (all checks passed), Pyright (0 errors / 0 warnings / 0 informations), Pytest (4112 passed / 5 skipped / 0 failed), PSScriptAnalyzer (0 diagnostics across the five changed PowerShell files), `Invoke-Formatter` under the repository PoshQC settings (all five files already formatted), and the blast-radius Pester scope (409 tests, 0 failures). Coverage is above threshold repo-wide in both coverage languages, and every production file in the diff is at 100% line coverage.

Two recorded dispositions were examined on the caller's request; one is upheld and one is upgraded. **AC-8's** literal clause requires a conflict fixture that cannot be both satisfiable and discriminating; the reviewer confirmed the seam independently (`classify_path_token` has exactly two callers, at `compute_blast_radius.py:344` and `_blast_radius_extraction.py:372`, and the conflict-fixture harness at `test_blast_radius_parity.py:417-465` constructs `BlastRadius` objects from fixture literals and calls `conflicts` directly, never the classifier).
