## Executive Summary

The conversion is consistent across the four validators. Each pure entry point now has the same shape: read the envelope through the E1 helper (honoring the `-InputText` seam), produce an anomaly block when `IsValid` is false, otherwise delegate to a new `Get-*OutputBlockDecision` function that keeps the original checks in their original order and tags every block result with `Repairable`, then apply the re-entry decision in one place. Each entry tail runs the inline S1 dependency tail first and calls `Exit-SubagentStopBlock` exactly once. The CR-3 resolver guard, the CR-1 case-insensitive membership checks, the CR-7 comment, and the #786 import cleanup are correct and tested. The routing split is a pure relocation.

Test quality is good: stdin and stderr are replaced in memory and restored in `finally`, no row writes files or sleeps, every non-S1 re-entry row is exercised in both states, and AST rows pin the seam and exit placement so a later edit cannot silently reintroduce the legacy transport.

The findings below are maintainability observations. None changes runtime behavior or blocks merge. The most material is CR-2: a planner structure rule was loosened under operator Amendment B, and the corresponding spec amendment has not yet been written.

## Correctness Review Notes

- **Envelope handling.** All four entries use `$PSBoundParameters.ContainsKey('InputText')` to choose between `Read-SubagentStopEnvelope -InputText $InputText` and the stdin read, which is the E1 consumer policy 3 seam. Assistant text comes only from `AssistantText`; the re-entry flag only from `StopHookActive`. The AC-8 and AC-22 searches (re-run by this review) return no match for `.last_assistant_message`, `.stop_hook_active`, `$payload.output`, or `stop_hook_active`.
- **Exit paths.** Each tail: guard-load failure (inline `exit 2`), dependency decision (inline `exit $dependencyDecision.ExitCode`), then the pure entry and a single `Exit-SubagentStopBlock`. The required-artifact missing-argument path reads the envelope, exits 0 on `StopHookActive`, otherwise writes the message plus the halt line through `[Console]::Error.WriteLine` and exits 2, exactly as spec "Required-artifact exits" describes. No `exit 1` or `Write-Error` remains.
- **Guard placement.** Every guarded load precedes `$ErrorActionPreference = 'Stop'` (orchestrator 51-64, executor 35-39, planner 37-41, required-artifact 36-40), so a failed load is recorded rather than terminating with exit 1.
- **Re-entry classification.** Spot-checked against the spec table: `resolutionRepairable` is true only for `NoTarget`/`Ambiguous` on `epic-orchestrator-state` or `parallel-orchestrator-state` (O-5), and false for unsupported types (O-3), `Rejected` (O-4), and `orchestrator-state` (O-6); `halt` is the only non-repairable `human_interaction` result (O-11); every wave-barrier result is non-repairable (O-14, O-15); executor `BLOCKED` outside preflight (X-7) and an empty plan (X-8) are non-repairable; a malformed `-RequiredArtifact` spec (R-4) is non-repairable. All match.
- **CR-3.** The `catch` returns `Repairable = $false` with `ORCHESTRATOR_CHECKPOINT_UNRESOLVED: <type>: NoTarget (RESOLVER_FAILED): <message>`; the wrapper appends the halt line. Tested at the pure entry (S2-14) and the tail (E-ORC-6).
- **CR-1.** Both membership checks in `Find-OrchestratorOutputRunSignalValue` use `-contains`; the route value comparison keeps `-cne`. Tested by S2-13 with `Route_Id` / `Integration_Branch`.
- **Split.** `validate-orchestrator-output-routing.ps1` contains the two relocated functions with their help text; the main file loads it through a guarded dot-source that records `Add-HookDependencyFailure`. The default invoker path resolution is unchanged because the sibling is in the same directory.
- **`[AllowEmptyString()]` on `$Lines`.** Without it, a mandatory `[string[]]` parameter rejects any plan containing a blank line at binding time, so under the converted transport the executor and planner hooks would have thrown on almost every real plan (164 and 115 corpus false positives respectively). The fix changes no decision rule.
