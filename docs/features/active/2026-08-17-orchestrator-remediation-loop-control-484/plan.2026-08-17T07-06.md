## Non-negotiable invariants

- New remediation state uses remediation_loop.schema_version 2 and makes attempts and cycles canonical.
- Active remediation requires remediation_loop.cycles, including an empty array before the first completed cycle; no ad hoc pass field may replace it.
- REVIEW_VERDICT is independent from REMEDIATION_ACTION, and the documented verdict/action/path matrix is fail closed.
- An attempt begins only when R3 execution is delegated after clear preflight. A completed cycle exists only after candidate application, commit, and completed R4 re-audit.
- Attempt and cycle identifiers are one-based, gap-free, unique, strictly increasing integers. Counts equal array lengths.
- BLOCKED/NO_CANDIDATE, BLOCKED/EXTERNAL_RUNTIME, BLOCKED/AWAITING_CI, and BLOCKED/HUMAN_DECISION stop or wait before R1 without creating an attempt or consuming a cycle.
- An R3 terminal result with candidate_applied false records one attempt but performs no staging, commit, R4 review, or cycle increment.
- Blocker fingerprints aggregate all known blocking findings using the canonical JSON/SHA-256 algorithm and exclude volatile values.
- An unchanged post-cycle fingerprint stops for stagnation before another plan, attempt, or cycle only when no exact unused valid exception exists; an exact exception is consumed once and reuse is rejected.
- One-time exceptions require exact issue, blocker fingerprint, routing-policy digest, transition, and consuming-attempt bindings and cannot be reused.
- The single canonical three-cycle terminal enum is blocked_remediation_loop_limit, matching AC-11 and the transition table; blocked_cycle_limit is rejected as a conflicting schema alias and must not appear in updated runtime writers or generated documentation.
- Legacy, Codex-model, and Codex-topology routing gates remain independent, selected gates execute once, and diagnostics de-duplicate only by the documented identity tuple.
- The same caller-selected validator flags are applied at every pre-mutation, post-mutation, CLI, TypeScript, MCP, and service boundary.
- Strict remediation performs MCP capability/version/schema/flag/artifact/package/bundle/routing-digest compatibility checks before R1 or R3.
- Evidence is written only below docs/features/active/2026-08-17-orchestrator-remediation-loop-control-484/evidence/<kind>/.
- Research outputs use the feature-local research directory or docs/research; artifacts/research is retired.
- Publication, release tags, registry calls, and consumer package-pin changes are outside this implementation. Local build, pack, and offline smoke verification are required.
- No test may use a temporary file, no new dependency is authorized, and no production, test, or reusable script file may exceed 500 lines.
