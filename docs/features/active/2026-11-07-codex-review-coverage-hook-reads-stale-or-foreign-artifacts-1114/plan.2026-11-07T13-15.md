## Fixed Design (names the plan fixes)

New file `.codex/hooks/feature-review-coverage-target.ps1` (functions only, Codex header, no top-level statement other than function definitions, no dot-source):

- `Get-CodexReviewPolicyAuditPath -Message` returns the distinct policy-audit paths in the reviewer message matching `docs/features/active/<folder>/[<version>/]policy-audit.<timestamp>.md` or `docs/features/active/<folder>/audit/<timestamp>/policy-audit.md`, relative or absolute, with `/` or `\` separators, with or without a `policy-audit-path:` label. A `$null` or non-string message yields no paths; a path with a `..` segment is rejected with reason code `AUDIT_PATH_TRAVERSAL`.
- `Select-CodexReviewPolicyAudit -RelativePath` returns one relative audit path: the single distinct audit, or the lexicographically greatest timestamp among audits of one folder; audits of different folders yield reason code `AUDIT_AMBIGUOUS` naming the folders; none yields `AUDIT_NOT_NAMED` (D2).
- `Resolve-CodexReviewCoverageTarget -Message -SessionRoot` returns `ItemRoot`, `Source`, `AuditRelativePath`, `ReasonCode`, and `Reason`. Absolute paths go to `Resolve-HookTargetWorktree -SessionRoot -FilePath -WorktreeListInvoker` (the invoker calls `Get-CodexReviewCoverageWorktreeList`) and are made relative with `Get-HookTargetWorktreeRelativePath`; a `TARGET_WORKTREE_AMBIGUOUS` resolver result is returned with a reason naming the worktrees; relative paths use the session root with `Source` `SessionRoot`. The selected audit must exist beneath the item root (`Test-Path -LiteralPath`), otherwise reason code `AUDIT_NOT_FOUND` names the path and the item root.
- `Invoke-CodexReviewCoverageGitExe -GitArgs <string[]>` is the wrapper seam of `.claude/rules/powershell.md` (`## Design Seams (Minimal DI)`, option 1) and the only place the file invokes `git`: it splats `-GitArgs` into `git` with stderr discarded (the stream handling of the twin's default `GitInvoker`) and returns `[pscustomobject]@{ ExitCode; Output }`, where `Output` is the output lines joined with a line feed. Its body is one statement line, which no test executes because tests run no real git; it is the only uncovered line expected in the file.
- `Invoke-CodexReviewCoverageGitLog -Root -Pathspec` calls `Invoke-CodexReviewCoverageGitExe` with the argument list `-C`, the root, `log`, `-1`, `--format=%ct`, `HEAD`, `--`, and the pathspecs, and returns the seam's `ExitCode` and `Output` unchanged (the shape of the twin's `-GitInvoker`); a throw from the seam propagates, and the twin's freshness decision fails closed on it.
- `Get-CodexReviewCoverageWorktreeList -SessionRoot` calls `Invoke-CodexReviewCoverageGitExe` with `-C`, the session root, `worktree`, `list`, and `--porcelain`, and returns the seam's `Output` when `ExitCode` is 0, or an empty string on a non-zero exit or a throw.

External-process sites: the hook and the new target file invoke `git` only through `Invoke-CodexReviewCoverageGitExe`. The twin's default `GitInvoker` and the default `WorktreeListInvoker` of `.codex/hooks/hook-target-worktree.ps1` also hold inline `git`, but their text is pinned (to the Claude file and to the Claude module respectively), the hook always passes the wrapper blocks so neither default runs in production, and no test invokes either default; the twin's default `GitInvoker` line is therefore the only uncovered line expected in the twin.

New file `.codex/hooks/validate-feature-review-coverage-freshness.ps1`: a Codex header comment plus the four functions `Get-FeatureReviewCoverageReportPath`, `Get-FeatureReviewCoveragePathspec`, `Get-FeatureReviewReportLastWriteUtc`, and `Get-FeatureReviewCoverageFreshnessDecision`, each with extent text identical to `.claude/hooks/validate-feature-review-coverage-freshness.ps1`.

Changed hook `.codex/hooks/validate-feature-review-coverage.ps1`: entry order is payload validation, `Resolve-CodexReviewCoverageTarget` with `last_assistant_message`, audit read beneath the item root, `Get-ChangedLanguageSet -RepoRoot <item root>`, `Get-FeatureReviewCoverageFreshnessDecision -WorktreeRoot <item root> -SessionRoot <session root> -Source <source> -ChangedLanguage <set> -GitInvoker { param($Root, $Pathspec) Invoke-CodexReviewCoverageGitLog -Root $Root -Pathspec $Pathspec }`, thresholds from the root `CLAUDE.md` beneath the item root, and the unchanged row rule with `Get-LanguageRepoCoverage -RepoRoot <item root>`. Every target reason code and a non-null freshness decision emit one `Get-FeatureReviewCoverageContinuation` (its `Reasons` joined). `Get-LatestPolicyAudit` and the `docs/features/active` enumeration are removed.
