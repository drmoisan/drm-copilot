## Recorded Decisions

- **RD-1 — A1 behavior: policy deny in preparation mode, allow when dormant, exit 2 reserved for git failure.** A `git push` under a detached HEAD is NOT a transport error: a detached HEAD is a legitimate repository state (CI checks out `refs/pull/N/merge`), and git succeeds when interrogated. The deliberate behavior is: (a) `git branch --show-current` FAILS (`$LASTEXITCODE -ne 0`) → keep the existing `throw` → exit 2 (genuine inability to interrogate git; fail closed); (b) git SUCCEEDS with empty output (detached HEAD) → `$currentBranch = ''` → the decision layer governs: in preparation mode `Test-EpicPlanningBashAllowed` already withholds the push allowance for an empty `CurrentBranch` (line 150), producing the existing deny envelope with exit 0; outside preparation mode the decision returns `$null` and the push is allowed, matching the hook's dormant no-op contract. No decision-function line changes; the intended policy (push only to the resolved current branch during preparation) is unchanged and now transport-correct.
- **RD-2 — Committed regression strategy.** Committed tests may not create worktrees or temporary files, so the detached-HEAD state itself is exercised by: (a) deterministic dot-sourced unit tests that mock the git wrapper seam to return an empty pipeline with `$LASTEXITCODE = 0` — the exact CI condition — against the new resolver functions; (b) in-process entrypoint cases (C5) that run the real entrypoint and are exercised on the detached merge ref by CI itself; and (c) the existing config-driven integration test, which runs on every CI detached checkout and is the permanent net. Fail-before/pass-after proof in an actual detached worktree is captured by non-committed probes at the C4 probe root per the established #415 fail-before convention.
- **RD-3 — Seam design.** C1 extracts `Get-CodexChildGuardLiveBranch -RepositoryRoot <string>` (calls the existing `Invoke-CodexChildGuardGit` wrapper; returns `''` when `$LASTEXITCODE -ne 0` OR output is null/whitespace; otherwise the trimmed branch). A1 adds wrapper `Invoke-EpicPlanningGit -GitArgs <string[]>` (splats `& git @GitArgs 2>$null`) and `Get-EpicPlanningCurrentBranch -RepositoryRoot <string>` (throws the existing `EPIC_PLANNING_ONLY_BLOCKED` transport message when `$LASTEXITCODE -ne 0`; returns `''` on empty successful output; otherwise the trimmed branch). Both are defined above the dot-source guard so they are dot-source-testable per the repo wrapper-seam rules; mocks use signature parity `param([string[]]$GitArgs)` and set `$global:LASTEXITCODE` explicitly.
- **RD-4 — Honest-failure branch.** If after both gap-closure batches any measured changed file is below its C6-adjudicated threshold, record the numbers honestly, mark the verification task FAILED, and mark the plan outcome remediation-required. No measurement rollback.
- **RD-5 — Stale MCP measured set.** See C2. The MCP loop remains mandatory at every loop task; coverage claims cite only the local `Invoke-PoshQCTest` XML.
