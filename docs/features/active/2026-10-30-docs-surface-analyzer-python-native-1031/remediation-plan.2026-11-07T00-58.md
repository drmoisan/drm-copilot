## Remediation Design

### F6 — the helper runs with the repository root as its working directory

- Cause: `Context.TestFile` resolves under `RepositoryRoot`, while the `$invokeProcess` member of `New-DocsCommandContext` passes no root, so `Invoke-DocsProcess` defaults `WorkingDirectory` to the current location and the interpreter opens the relative helper path there.
- Design premise correction: the inputs suggest passing the root from the member to `Invoke-DocsProcess -WorkingDirectory`. The member is a bound non-closure scriptblock, because a closure resolves no script command by name, so it cannot capture `$root` as it stands. Three constraints fix the shape. A closure must call a script function through a scriptblock, which is the pattern of the five other members. The guard `enforcement-hooks-no-python-invocation.Tests.ps1` accepts `&` on a variable only when the name is a `[scriptblock]` parameter (carve-out (a) in `EnforcementHooksNoPythonInvocation.Helpers.ps1`), and the allowlist must not widen. `PSReviewUnusedParameter` does not count a parameter used only inside a nested scriptblock, which rules out a factory function holding the closure.
- Change, all in `LIB/Invoke-DocsCommand.ps1`:
  - New private function `Invoke-DocsContextProcess` with parameters `$Root`, `$FilePath`, `$ArgumentList`, `$StdinText` and `$TimeoutSeconds`, placed with the other `*-DocsContext*` helpers. It calls `Invoke-DocsProcess` with the four arguments and `-WorkingDirectory $Root`. The four arguments stay untyped, so `ConvertTo-DocsProcessRequest` still validates the values it received.
  - In `New-DocsCommandContext`, `$invokeProcess` becomes a closure in the form of the other members: `$FilePath`, `$ArgumentList`, `$StdinText`, `$TimeoutSeconds`, then `[scriptblock] $Operation` defaulting to `${function:Invoke-DocsContextProcess}`. Callers still pass four positional arguments, and the seam shape `@{ ExitCode; Stdout; Stderr; TimedOut }` and the `DOCS_PROCESS_START_FAILED` message are unchanged, so `Invoke-DocsPythonNativeInterpreter` and `Get-DocsPythonNativeResult` need no edit.
  - `Invoke-DocsProcess` keeps its signature and its default. Its `.DESCRIPTION` states that the default applies only to a direct caller and that the real command context always passes its repository root. The script header `.DESCRIPTION` and the `New-DocsCommandContext` `.DESCRIPTION` drop the "forwards unchanged" wording and state that the four arguments are forwarded with the root as the working directory. The comment "Bound (non-closure) member" is removed, and the comment above the closures covers the new member.
- Not changed: `LIB/DocsAnalyzerPythonNative.psm1`. `$script:DocsPythonNativeHelperPath` stays repository-relative, as `spec.md` `### Interpreter discovery and invocation` requires. The fallback, `-AnalysisMethod` semantics, the guard allowlist and every criterion are unchanged.
