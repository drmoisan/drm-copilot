### 3. `.claude/rules/general-unit-test.md` — [P0-T3]

- **Uniform coverage thresholds.** Line coverage must remain >= 85% across all tiers (T1–T4). Branch coverage must remain >= 75% across all tiers for languages whose coverage tooling measures branch coverage. PowerShell (Pester) and bash (kcov) are exempt from the branch threshold only. Code changes must not reduce coverage for the lines that were changed. Tier-specific lower thresholds are not used in this repository.
- **Coverage exclusion policy.** No production file may be excluded from coverage measurement. Permitted `exclude` entries cover build output (`dist/**`, `lib/**`, `lib-amd/**`), test files and test infrastructure (`**/*.test.ts`, `tests/**`, `src/test-support/**`), non-production config files (`jest.config.cjs`, `eslint.config.mjs`, `.dependency-cruiser.cjs`, `webpack.config.js`), and `node_modules/**`. Any `exclude` entry matching a production source path under `src/` is a Blocking finding.
- **Test-file-location rule.** Test files must live in a `tests/` directory tree mirroring the production source structure. Colocation inside the production source tree is not permitted. This governs the placement of `extensions/drm-copilot/test/lib/new-active-feature-folder/flow.promoted-disposition.test.ts`, `extensions/drm-copilot/test/lib/promotion-lifecycle-sequence.test.ts`, and `tests/scripts/dev_tools/test_new_active_feature_folder_part5.py`.
- **Prohibition on temporary files in tests.** Creation and use of temporary files in tests is strictly prohibited. Unit tests must not depend on external services (databases, networks, remote APIs, external processes) and must not rely on mutable global state. This is INV-8 of this plan.
- Additional constraints noted: the five core principles (independence, isolation, fast execution, determinism, readability); Arrange–Act–Assert structure; scenario completeness including negative flows and error handling; determinism infrastructure (controllable clock, seeded RNG, banned wall-clock APIs, fake timers).

### 4. `.claude/rules/typescript.md` — [P0-T4]

- **Toolchain commands.** (1) Formatting — Prettier, `npm run format`. (2) Linting — ESLint, `npm run lint`. (3) Type checking — TSC, `npm run typecheck`. (4) Testing — Jest, `npm run test:unit`; coverage command `npm run test:unit:coverage` (root `package.json` runs `node run-jest.cjs --coverage`). Run in order format → lint → type-check → test; restart from step 1 if any step fails or changes files.
- **Coding standards.** Strong typing on public functions, methods, and exported APIs; avoid `any`, prefer `unknown` plus narrowing; avoid type assertions (`as X`) unless justified. ES modules only — no `require` / `module.exports`. Domain types encode invariants; prefer discriminated unions for state machines. Naming: `PascalCase` for classes, interfaces, enums, type aliases (no `I` prefix); `camelCase` for functions, methods, variables, object properties. Kebab-case filenames. Separation of concerns: keep pure logic separate from host-bound APIs, filesystem/network I/O, and UI wiring. Error handling: fail fast with clear errors; avoid catch-all `catch (e)` without rethrowing or adding context. No new runtime dependencies without approval.
- **Testing standards.** Jest; test files named `*.test.ts`; Arrange–Act–Assert; one behavior per test; `jest.spyOn` / `jest.mock` for targeted mocking with `jest.resetAllMocks()` in `afterEach`; no network, filesystem temp files, or external processes; avoid snapshot tests unless stable and intentional. Coverage thresholds follow `.claude/rules/quality-tiers.md` (line >= 85%, branch >= 75%). Coverage regression on changed lines is a blocking finding.
- **Architecture boundaries.** Enforcement tool is `dependency-cruiser` with configuration file `.dependency-cruiser.cjs`. See P0-T11 for the verified absence of that configuration file in this repository.

### 5. `.claude/rules/python.md` — [P0-T5]

- **Toolchain commands.** (1) Formatting — Black (default settings), `poetry run black .`. (2) Linting — Ruff, `poetry run ruff check .`; suppressions require pre-authorization. (3) Type checking — Pyright, `poetry run pyright`; full type annotation required, avoid `Any`. (4) Testing — Pytest, `poetry run pytest --cov --cov-branch --cov-report=term-missing`. Run in order format → lint → type-check → test; restart from step 1 if any step fails or changes files; do not stop the loop until all four steps complete without errors in a single pass.
- **Coding standards.** PEP 8 naming (`snake_case` functions/variables, `PascalCase` classes, `CONSTANT_CASE` constants). Full type hints on all public functions and methods. Prefer `@dataclass` for value objects, `frozen=True` where appropriate, invariants enforced in `__post_init__`. `typing.Protocol` or `abc.ABC` only when multiple implementations are expected. Absolute imports; no circular dependencies. Fail fast with specific exceptions; avoid broad `except:` / `except Exception:` without context. `assert` only for internal sanity checks. Standard `logging` module; no ad-hoc `print` for permanent behavior.
- **Design rules.** Small cohesive modules with one clear purpose; small public surface with `_prefixed` internal helpers; class-vs-function selection criteria; Pyright-clean strong typing with line-specific `# type: ignore[...]` only when justified; smallest dependency seam for testability (constructor injection preferred; optional callables with sensible defaults for time/randomness); no service-locator or heavy DI frameworks.
- **Pytest rules.** One behavior per test; Arrange–Act–Assert; descriptive `test_...` names; `pytest.mark.parametrize` for boundary matrices; narrow function-scope fixtures; patch at the import location used by the unit under test; no sleeps, retries, or timing hacks; tests mirror code structure; no network, databases, external processes, or runtime filesystem temp files. Line coverage >= 85%, branch coverage >= 75%; coverage regression on changed lines is a blocking finding.
- **Prohibited behaviors.** Broad refactors outside approved scope; adding dependencies without instruction; reducing typing strictness to make Pyright pass; weakening tests to make them pass; runtime temp files or external services in unit tests; claiming success without running the toolchain.
