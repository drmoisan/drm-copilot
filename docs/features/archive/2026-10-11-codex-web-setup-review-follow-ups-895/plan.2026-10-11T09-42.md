### Design decisions (from research, confirmed against the tree)

- CR-1: `log` is defined after the top-level `SOLUTION_FILE=` selection, so logging is added as a new function `log_solution_selection` placed after `warn` and called from `main()` directly after the "Bootstrapping" log. The function prints nothing for an empty listing, which keeps test C824-61 ordering assertions intact (that test sets `REPO_ROOT` to `tests/shell`, which holds no `*.sln`).
- AC-1 two-solution case: the bats case passes a two-name listing as arguments to `log_solution_selection`. No second `.sln` fixture is needed. Only `Alpha.sln` is committed as a fixture (AC-2).
- Fixture location follows AC-2 and AC-6 text and `.claude/rules/shell.md`: `tests/fixtures/codex_web_setup/`.
- CR-10: the shared helper `tests/shell/helpers/codex_web_setup_common.bash` is loaded by bats `load` from the installers, dotnet, and verify suites. It lives in a subdirectory because the runner (`bats "$test_dir"` without `-r`) executes only top-level `*.bats` files. `teardown` stays in each suite. The copy suite is not changed except for new cases.
- CR-14: the research concludes lines 207, 210, and 302 are bare subshell delimiter lines that bash xtrace never emits, so no bats case can cover them. The plan records an attribution-limit document in the feature folder; CI kcov evidence is appended by the orchestrator at S9.
