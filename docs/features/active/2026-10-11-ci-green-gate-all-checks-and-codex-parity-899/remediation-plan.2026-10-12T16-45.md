## Planner decisions (recorded for audit)

- PD1 - Baseline comparison method. The baseline Python figure is established against `origin/main` without a second full-suite run on the base tree. P0-T3 proves CHANGED-TEST is the only `.py` path that differs from `origin/main`, so the production denominator under `scripts/dev_tools/` is identical at base and head. P0-T4 proves that CHANGED-TEST imports only `__future__`, `pathlib`, `pytest`, and SUPPORT-MODULE, and that SUPPORT-MODULE imports only `__future__`, `hashlib`, `re`, `pathlib`, `typing`, and `yaml` and is identical at base and head. No import path reaches a `scripts` or `src` module, so CHANGED-TEST executes no production line and cannot change the production numerator; its own lines are omitted from measurement by `omit = ["tests/*"]`. Therefore the base-tree production coverage equals the head-tree production coverage measured in P1-T1, and P1-T3 records that equality as the baseline comparison. A second run on the base tree is not required, and none is attempted because it would need a second checkout of the repository (a worktree or stash), which this plan does not create. The CI `CI` run on the pull request is the independent cross-check and is not a task dependency.
- PD2 - Local feasibility and fallback. The precedent run of the identical command completed the full `tests/` population on this Windows host (6956 passed, 6 skipped, 1 minute 14 seconds). The only known local failure mode is KL-510 (PD3). No reduced test subset is substituted for the full run, because a subset yields a figure that is not repo-wide and would not satisfy R-1. If the run cannot complete (exit code other than 0 or 1, a missing `TOTAL` row, or a hook denial), the plan stops and the executor reports the exact failure text; R-1 then remains open and the reaudit verdict cannot be PASS.
- PD3 - Test-failure recording. A KL-510 failure, when it is the only failed node, is recorded with `ExpectedExitCode: 1` and does not affect the disposition. Any other failed node yields `Disposition: FAIL`, the failed node IDs and assertion messages are recorded verbatim, Phase 2 still commits and pushes the evidence, and the executor reports `REMEDIATION-REQUIRED: python test failure` to the orchestrator.
- PD4 - Threshold-failure recording. If P1-T2 reports TOTAL_LINE below 85.00 or TOTAL_BRANCH below 75.00, the executor does not edit code, configuration, or thresholds. P1-T3 records `Disposition: FAIL` with the figures and records under `Baseline comparison:` that the shortfall is pre-existing on `origin/main` by PD1, so it is not attributable to this branch. Phase 2 still commits and pushes the evidence, and the executor reports `REMEDIATION-REQUIRED: python repo-wide coverage below threshold (pre-existing on base)`. The figure is not suppressed or relabelled N/A.
- PD5 - Final QA loop. Phase 2 re-runs the check-only format, lint, and type-check stages on CHANGED-TEST (P2-T1 to P2-T3) before committing; COVERAGE-RUN (P1-T1) is the test stage of the loop.
