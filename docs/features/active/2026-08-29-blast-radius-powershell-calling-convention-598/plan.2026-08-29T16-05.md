## Sequencing constraints the executor must not reorder

1. **Batch cap.** `.claude/rules/powershell.md:40` caps a batch at 3 production files and 3 test files unless an explicit override has been approved. No override has been approved for this feature, and the mirror exemption recorded in `spec.md` under "Requested but not granted" is **not** granted. Both the repository module and its bundle mirror are production files, so this plan uses **27 batches of one module pair (2 production files) each**. A 3-file batch would necessarily split a mirror pair and leave `test_bundled_claude_payload_contains_all_repo_runtime_contracts` failing at the batch boundary, which contradicts the per-batch parity gate the spec's risk mitigation 1 requires. 27 pair-batches is within the unoverridden cap; 2 is not greater than 3.
2. **The batch counter is a file that must be cleared between batches.** `.claude/hooks/enforce-powershell-batch-budget.ps1` persists distinct edited paths in `.claude/state/powershell-batch-budget.<session_id>.json` (documented at lines 14-15, written at lines 188-193) and denies the next `Write` or `Edit` once 3 production paths are recorded. A batch does not end until that file is removed.
3. **`.claude/state/**` is a parity hazard and must be cleared before every parity run.** `list_scoped_files` in `tests/scripts/dev_tools/test_push_down_claude_resource_contracts.py:34-43` walks the filesystem with `rglob` and does not consult git, so a gitignored file under `.claude/state/` is enumerated as a repository `.claude` file and demanded in the bundle. `.gitignore:68` ignores `.claude/state/`, and the bundle tree has no `.claude/state/` directory. Everything under `.claude/state/` is regenerable hook state — `current-session-id` written by `persist-session-id.ps1:150`, and the `powershell-batch-budget.<session>.json` and `python-batch-budget.<session>.json` counters. All of it must be removed before every parity run, not only the batch counters. Directories alone are not enumerated because line 41 of the parity test filters on `path.is_file()`, so an empty `.claude/state/` directory is harmless. Removing `current-session-id` is safe: `.claude/skills/identify-session-id/SKILL.md:27-30` treats it as the secondary source only, behind `env:CLAUDE_SESSION_ID` and ahead of the transcript-scan fallback, the SessionStart hook rewrites it, and no PowerShell or Python file in the repository reads it. Ordering inside every batch gate is therefore: format, analyze, Pester, **then remove everything under `.claude/state/`**, then the parity test.
4. **The convention test cannot be authored before all 27 modules carry the guard.** `tests/scripts/claude-lib/ClaudeLibModuleConvention.Tests.ps1` asserts over every module discovered on disk, so it fails for as long as one module is unedited. It is authored in Phase 8, after Phase 7 completes.
5. **The item-2 help test cannot be authored before the item-2 help edit.** The `Get-OrchestratorStateCheckpoint` contract statement lands in Phase 2; its test lands in Phase 8.
6. **The Phase 0 formatter run is write-mode and may repair pre-existing drift.** The Phase 0 baseline artifact must list every path the formatter reports on a `Formatted: ` line so a reviewer can separate pre-existing repository drift from drift introduced by this feature. Recording only the exit code would turn the baseline into a blanket waiver.
7. **Guard-induced test repairs are performed inside the batch that caused them.** If a batch gate's Pester step reports a non-zero `Failed: ` count, the executor repairs the failing test files within that same batch, inside the 3-test-file cap of `.claude/rules/powershell.md:40`, then re-clears `.claude/state/` and restarts the gate from the formatter. A repair needing more than 3 test files is split across consecutive repair batches, each with its own gate run and its own artifact at `evidence/qa-gates/batch-<Bnn>-repair-<n>.<timestamp>.md`. Every repaired test file is an additional expected entry in the `[P10-T10]` change set and is named in the repair artifact. This is a repair provision, not authorization to weaken an assertion: `.claude/rules/powershell.md:95` prohibits weakening assertions merely to make tests pass, and `spec.md` states that a module depending on a non-terminating error is made explicit in the module rather than by removing the guard.

## Observation source for the format and analyze steps

The MCP result object carries only `ok`, `tool`, `workspace_root`, and `summary` (`extensions/drm-copilot/src/mcp-tools.ts:90-113`); it carries no formatter or analyzer output line and no exit code. The self-hosted invocation is the observation source for every acceptance condition in this plan that names such a line, on the same basis already recorded for the Pester step in `[P0-T7]`. `Invoke-PoshQCFormat` prints one `Already formatted: <path>` line per unchanged file and one `Formatted: <path>` line per rewritten file (`PoshQC.Analyzer.psm1:62` and `:64`). `Invoke-PoshQCAnalyze` prints `PSScriptAnalyzer passed: no findings under <root>` only when it found nothing, and otherwise throws `PSScriptAnalyzer reported N issue(s).` (`PoshQC.Analyzer.psm1:183` and `:185`), which makes `pwsh` exit non-zero. Running the self-hosted formatter after the MCP formatter is not redundant: on a clean tree it prints only `Already formatted: ` lines, which is the required clean-pass observation, and if the two disagree it prints `Formatted: ` lines and fails the gate, which surfaces the disagreement.

Every format step in this plan is therefore the following two commands in this order:

1. `mcp__drm-copilot__run_poshqc_format` against the workspace root.
2. `pwsh -NoProfile -Command "Import-Module ./scripts/powershell/PoshQC/PoshQC.psd1 -Force; Invoke-PoshQCFormat -Root (Get-Location).Path"`

Every analyze step in this plan is the following two commands in this order:

1. `mcp__drm-copilot__run_poshqc_analyze` against the workspace root.
2. `pwsh -NoProfile -Command "Import-Module ./scripts/powershell/PoshQC/PoshQC.psd1 -Force; Invoke-PoshQCAnalyze -Root (Get-Location).Path"`

The MCP command in each pair is the policy-named toolchain call required by `.claude/rules/powershell.md:15-16` and is retained for that reason. Every recorded count, literal, and `EXIT_CODE:` is taken from the **second** command of each pair. `Invoke-PoshQCFormat` and `Invoke-PoshQCAnalyze` are exported by `scripts/powershell/PoshQC/PoshQC.psd1` at lines 15 and 16 and both accept `-Root` (`PoshQC.Analyzer.psm1:15-18` and `:83-86`).

## Batch verification contract

Each batch edit task is accepted by these four checks against its own concrete pair. `MODULE` below stands for the batch's repo-relative module path and `MIRROR` for `extensions/drm-copilot/resources/claude-customizations/` prefixed to that same path. Each batch task states its own instantiated paths.

1. **Guard position.** `Select-String -LiteralPath MODULE -SimpleMatch -Pattern 'Set-StrictMode -Version Latest' -Context 0,1` and read the single post-context line. It must print `$ErrorActionPreference = 'Stop'`.
2. **Import guard.** Count the column-0 `Import-Module` lines that do not contain `-ErrorAction Stop`. It must print `0`.
3. **Convention sentence.** Count occurrences of the token `imports its siblings with -ErrorAction Stop` in the module. It must print `1`.
4. **Mirror identity.** `git diff --no-index --quiet -- MODULE MIRROR` must exit 0.
