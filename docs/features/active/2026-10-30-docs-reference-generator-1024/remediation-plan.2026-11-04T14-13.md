## Design Summary

R1. `ConvertTo-DiscoveryCanonicalFragment` in `.claude/lib/discovery-validation/DiscoveryEncoding.psm1` (reached through `ConvertTo-DocsCanonicalJson` in `.claude/lib/docs/DocsJson.psm1`) signals a rejected number with a plain string `throw` whose prefix, `AUTHORIZATION_INPUT_INVALID`, it also uses for an unsupported value type. Because no exception type or error id separates the two cases, the fallback is selected by a pre-check of the value, not by catching and matching the message:

- A new private function `Test-DocsReferenceCanonicalNumberRejected` in `.claude/lib/docs/DocsReferenceFrontMatter.psm1` returns `$true` when the value, walked recursively through `IDictionary` values, `PSCustomObject` property values, and non-string `IEnumerable` items, contains a `[double]`, `[single]`, or `[decimal]` that `ConvertTo-DiscoveryCanonicalFragment` rejects: the value is non-integral, or its magnitude exceeds the safe-integer bound that function applies. Otherwise it returns `$false`. It is pure and is not exported.
- `ConvertTo-DocsReferenceFrontMatterText` drops the `try`/`catch`. For the key `extensions` with `Test-DocsReferenceCanonicalNumberRejected` true, it calls `ConvertTo-DocsJsonText`. In every other case it calls `ConvertTo-DocsCanonicalJson` with no handler, so any exception from that call propagates unchanged. The function's `.DESCRIPTION` states the routing and the propagation.
- The bundle mirror `extensions/drm-copilot/resources/claude-customizations/.claude/lib/docs/DocsReferenceFrontMatter.psm1` stays byte-identical.

R2. Re-verification only: the docs Pester suites, the push-down contract pytest modules, the analyzer and formatter, mirror byte-identity, and seeded shuffled file-order runs are re-run on the merged head. The R2 files are `.claude/lib/docs/Invoke-DocsCommand.ps1`, its mirror, and `extensions/drm-copilot/resources/claude-customizations/pack-manifests/core.json`. None of them is edited unless a gate fails.

Existing tests asserting the changed behavior, found by searching `tests/` for `ConvertTo-DocsReferenceFrontMatterText`, `DocsReferenceFrontMatter`, fractional literals, and `extensions` fixtures, with their dispositions:

- `tests/scripts/claude-lib/docs/DocsReferenceFrontMatter.Tests.ps1`, `Describe 'ConvertTo-DocsReferenceFrontMatterText'`, `It 'writes a non-integral extension number with the JSON writer'`: unchanged. The pre-check routes the same value to `ConvertTo-DocsJsonText`, so the asserted text is identical.
- Same `Describe`, `It 'renders --- delimiters around one key and JSON value line per field in the fixed order'` and `It 're-escapes U+0085, U+2028 and U+2029 so the value stays on one line and parses back'`: unchanged. They use strings and arrays only, so canonical JSON still serves them.
- `tests/scripts/claude-lib/docs/DocsReferenceFrontMatter.Properties.Tests.ps1`, `Describe 'ConvertTo-DocsReferenceFrontMatterText'` and `Describe 'ConvertFrom-DocsReferencePageText'`: unchanged. `Get-TestDrawnValue` draws only strings and `[long]` extension values, which canonical JSON accepts.
