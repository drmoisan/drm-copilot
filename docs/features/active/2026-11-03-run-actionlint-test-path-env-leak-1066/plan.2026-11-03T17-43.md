A non-empty residual fails the task.

## Design Decisions Fixed by This Plan

- DD1 Fix: a single `BeforeEach` and `AfterEach` pair directly in `Describe "run-actionlint.ps1"` saves and restores `$env:PATH` (value and existence) and `$global:LASTEXITCODE` (existence and value; restore removes the global variable when it did not exist). The `Context "Add-DirectoryToPath"` `BeforeEach`/`AfterEach` pair that uses `$script:originalPath` is removed, because the Describe-level pair runs outside it on every `It` and restores the same value, so behavior is unchanged. The Describe-level `AfterEach` runs while the `Install-Actionlint` Context mocks (`Test-Path`, `Join-Path`, `Remove-Item`, `New-Item`, `Write-Information`) are still active, so the pair uses only `$env:PATH` assignment, variable assignment, and `Remove-Variable`, and calls none of those mocked commands.
- DD2 Guard form (b): `GUARD` runs `TARGET` through a nested in-process `Invoke-Pester` with a configuration of `Run.PassThru` true, `Run.Exit` false, `Output.Verbosity` `None`, `TestResult.Enabled` false, and `CodeCoverage.Enabled` false, and compares `[Environment]::GetEnvironmentVariables()` before and after in an `OrdinalIgnoreCase` dictionary (added, removed, or ordinally changed values). `$global:LASTEXITCODE` is compared against a control nested run of an in-memory `New-PesterContainer -ScriptBlock` container, so a value set by Pester itself is not attributed to `TARGET`. The guard's own `BeforeEach`/`AfterEach` snapshot and restore the full environment and `$global:LASTEXITCODE`, so the guard leaks nothing even when it fails.
- DD3 Guard form (c), fallback: `GUARD` parses `TARGET` with `[System.Management.Automation.Language.Parser]::ParseFile` and fails when an assignment to `$env:PATH` (case-insensitive) inside an `It` block has no enclosing `Describe` or `Context` block that directly contains a `BeforeEach` or `BeforeAll` reading `$env:PATH` and an `AfterEach` or `AfterAll` assigning `$env:PATH`. Limited to PATH, per spec option (c).
- DD4 Guard scope: `GUARD` covers `TARGET` only. This is the smallest guard the spec allows; the other test files that assign `$env:` variables are out of scope (spec `## Scope & Non-Goals`).
- DD5 Feasibility decision rule (applied in P1-T5, pre-fix tree, so each probe compares against a Phase 0 run of an otherwise identical tree). Shapes: S0 `GUARD` alone (P1-T2); S1 single-process `DEVLIST` forward including `GUARD` (P1-T3); S2 `Invoke-PoshQCTest` over `tests/scripts/dev-tools` with coverage enabled (P1-T4). Rules: R1 the control testcase passes; R2 the environment testcase fails and its failure message names exactly one differing key, `PATH` compared case-insensitively; R3 (S1, S2) every non-`GUARD` key has the same outcome as in the matching baseline (P0-T4 for S1, P0-T9 for S2) and the testcase total equals the baseline total plus 3; R4 (S2) the coverage report lists the same files with the same per-file line totals as P0-T9, and no file's covered-line count is lower. GuardForm is `b` when every applicable rule holds in every shape; otherwise GuardForm is `c` and the failed rules with their observed differences are recorded.
