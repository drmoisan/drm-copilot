## Design

**Constants.** In `scripts/dev_tools/plan_gate_document.py` and `extensions/drm-copilot/src/lib/validate/plan-gate-document.ts`: `PLAN_TASK_GUIDELINE` becomes 20 and `PLAN_LINE_GUIDELINE` becomes 250; new `LEGACY_PLAN_TASK_GUIDELINE` (40), `LEGACY_PLAN_LINE_GUIDELINE` (400); `PLAN_STAMP_ZONES`, the read-only table from stamp shape to zone (`plan` to `America/New_York`; `plan-remediation-cycle`, `remediation-plan`, and `remediation-folder` to `UTC`); and `PLAN_GUIDELINE_CUTOFF`, a read-only mapping with exactly the keys `America/New_York` and `UTC`, each a `yyyy-MM-ddTHH-mm` stamp, both derived from one clock reading. The validators compare strings only and convert no time, so neither adds a time-zone dependency. No new production module and no new `coverageThreshold` entry is needed; the existing per-file entries for `plan-gate-document.ts`, `plan-gate-discrimination.ts`, and `orchestration-artifacts.ts` in `extensions/drm-copilot/jest.config.cjs` gate the changed files.

**Cutoff value (D2, corrected, zone-aware).** The cutoff is one instant: the UTC clock reading taken once in the helper run that makes the reduction commit, whose author and committer dates are set to that reading. Stamps are written in two zones, so one stamp string cannot represent the instant: `plan.<stamp>.md` is stamped in America/New_York by the feature-folder tooling (`scripts/dev_tools/new_active_feature_folder_models.py` and `extensions/drm-copilot/src/lib/new-active-feature-folder/models.ts`), and remediation plans carry review stamps, which `## ISO-8601 Timestamp Format` of `evidence-and-timestamp-conventions` makes UTC. A New York cutoff compared with a UTC stamp misreads plans written up to five hours before the rule existed, which D2 forbids. Each stamp is therefore compared with the `PLAN_GUIDELINE_CUTOFF` entry for its shape's zone: a stamp that sorts strictly before that entry keeps 40 and 400, and one equal to it or after it uses 20 and 250. Derivation: a helper script under `SCRATCH` reads the host clock once in UTC, formats that reading as the `UTC` entry, converts the same reading to America/New_York through the system time-zone database for the `America/New_York` entry, and never composes either by hand. Both entries are written at labelled positions (the two mapping entries in each module, the two values of the rule-file token, and the entry's cutoff line), and the helper fails when a labelled position is not found exactly once. [P1-T2] writes a provisional pair; [P2-T4] derives a check pair and runs the result check under it; [P2-T5] derives the final pair in the run that commits. A later cutoff never moves a plan from the legacy pair to the new pair, so every file that keeps its result under the check pair keeps it under the final pair; the helper asserts the final reading is at or after the check reading.

**Stamp reading (K4).** `plan_file_stamp` and `planFileStamp` split a path on both `/` and `\` and return the stamp with its shape's zone from `PLAN_STAMP_ZONES`. With `STAMP` the pattern `[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}-[0-9]{2}`, the file name fully matches `plan.STAMP.md` (shape `plan`), `plan.remediation-cycle-N.STAMP.md` with `N` digits (`plan-remediation-cycle`), or `remediation-plan.STAMP.md` (`remediation-plan`); or the name is `remediation-plan.md`, its parent segment fully matches `STAMP`, and the segment above it is `remediation` (`remediation-folder`). Any other name, an empty path, and no path yield no stamp. Matching is case-sensitive. Zone of `plan-remediation-cycle`: no tooling writes this shape, and `docs/features/` holds one instance, `plan.remediation-cycle-1.2026-10-31T21-30.md` in the #1048 folder, whose stamp lies between the UTC review stamps `2026-10-31T21-02` and `2026-10-31T21-45` of its cycle; read as New York time it would follow the review that cites it, so the shape is UTC.

**Guideline selection.** `plan_size_guideline(stamped, *, cutoff=PLAN_GUIDELINE_CUTOFF)` and `planSizeGuideline(stamped, cutoff = PLAN_GUIDELINE_CUTOFF)` take the result of the stamp reader and return the legacy pair when a stamp exists and sorts strictly before `cutoff[zone]`, and the new pair otherwise. The `cutoff` parameter is the test seam: tests inject a fixed pair, and only the doc-parity test of [P2-T1] reads the committed pair.

**Path parameter (K5).** Python `evaluate_document_gates(report, text, *, plan_path=None)`, `evaluate_plan_gates(text, *, context=None, plan_path=None)`, `validate_plan_text_with_warnings(text, *, context=None, plan_path=None)`, and `_plan_channels` passing `args.path`; TypeScript `evaluateDocumentGates(report, text, planPath?)`, `evaluatePlanGates(text, context?, planPath?)`, and `validateArtifactWithWarnings` passing `input.artifactPath` beside `buildPlanGateContext(input)`, which still returns `undefined` when any wiring field is absent. `validate_plan_text` keeps its signature and uses the new pair.

**Message.** `plan_size_message(tasks, lines, *, guideline=(PLAN_TASK_GUIDELINE, PLAN_LINE_GUIDELINE))` and `planSizeMessage(tasks, lines, guideline = [PLAN_TASK_GUIDELINE, PLAN_LINE_GUIDELINE])` render the pair that applied in the existing format, so the legacy message is byte-identical to today's and the new one reads `exceeds the guideline of 20 tasks or 250 lines`.

**D9 for G13.** The installed MCP validator applies 40 and 400 until a release carrying this change is installed, so the planner's MCP self-check does not report a plan between the two pairs; the contract tells the planner to hold a new plan to 20 and 250 itself, and preflight applies the new pair through the Python CLI route of `## Validator Gate`.

**Result check.** Name rule: a file directly in a feature folder whose name starts with `plan` or `remediation-plan` and ends with `.md`, plus each `remediation/<stamp>/remediation-plan.md`; files under `evidence/` and `research/` are not plan files. In scope: every plan file under `docs/features/active/` at `HEAD`; every plan path listed by the Epic #1019 kickoff (the folder under `docs/features/epics/` whose `epic.md` names `#1019`, read at the `refs/remotes/origin/epic/*` ref that holds it); and, for each child folder that holds a kickoff-listed plan path, every file under the name rule in that folder on every `refs/remotes/origin/*` ref that holds the folder, which reaches the in-flight #1019 remediation plans. One entry is one distinct path and content; it records every source ref that holds that content. Each entry is evaluated against the zone table: its stamp, its shape's zone, and the `PLAN_GUIDELINE_CUTOFF` entry of that zone. A file's G13 outcome is whether the Python CLI output for it carries a `plan size` finding. A file keeps its result when its outcome at its own path under the check pair equals its outcome under the legacy pair (an identical copy under `SCRATCH` named `plan.2000-01-01T00-00.md`) and, for entries recorded at [P0-T5], the recorded outcome. Ref copies sit under `SCRATCH/refs/<ref name>/` with their repository-relative path, which the stamp reader resolves as at `HEAD`. If any file does not keep its result: stop and report each path with its stamp, counts, and outcomes; no plan is changed, nothing is committed, and the uncommitted work stays in the worktree for the coordinator.

**Ledger entry and revert order.** `0008` carries `## Stored Patch`: `git diff --cached --binary --no-renames HEAD` over the paths of `## Files Changed` other than the ledger folder, generated in [P2-T5] after the final cutoff pair is written, so its hunks hold the final pair and its two create hunks hold the new test files. Under README `## Revert Order`, `0008` is the highest number, so `Invoke-ProcessReductionChain` reverts it first, against the live tree, and then `0007` to `0001`. `0008` changes text in recorded regions of two older entries: the `**Size guideline.**` bullet of the six contract copies is a context line of hunks in `patches/0001-parallel-only-test-gates.patch`, and the planner clause `a plan above 40 tasks or 400 lines` of `.claude/agents/atomic-planner.md` and its bundle is a context line of hunks in both `patches/0001-parallel-only-test-gates.patch` and `patches/0006-test-suite-baseline-restored.patch`. No `Current` fence of `0001` to `0007` holds either line (the adjacent `0004` `**Task target.**` fence and the `0005` planner fence end before them and are left byte-identical). Those hunks stay valid without regeneration: reverting `0008` first restores both lines byte-for-byte before the `0006` and `0001` turns, so each hunk's context matches again. Regenerating them to carry `0008` text would instead fail after `0008` is reverted, which is why the README rule on edits inside a recorded region applies to an edit with no entry of its own, not to a newer entry that records the edit. Step 1 of `0008` states this, and the [P2-T5] replay proves it with the full chain and with the stop-before replays of `0006` and `0001`.
