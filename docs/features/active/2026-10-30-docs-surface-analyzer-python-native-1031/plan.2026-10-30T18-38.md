## Deviations from spec.md

The epic and the delivered 1020 and 1022 contracts govern; `spec.md` is not edited by this plan.

1. Registry: four `native` rows in the 1020 row form (`Id`, `Version`, `AnalysisMethod`, `ElementKinds`, `Module`, `Function`) under `# --- 1031: Python-native analyzers ---`, not one row with `Language` and `AnalyzerIds` under a 900011 anchor (S13, U13). One analyzer function per identifier (`Invoke-DocsAnalyzerPythonNativeCli`, `...Http`, `...Api`, `...Architecture`), because `Invoke-DocsAnalyzer` passes no identifier.
2. Process access: no `ResolveApplication` member exists; each candidate is started through `Context.InvokeProcess`, and a start failure (`SEAM_FAILURE_CODE`) means "not found". The spec's single `Invoke-DocsAnalyzerPythonNative -Context -InvokeInterpreter` is replaced by `Get-DocsPythonNativeResult` and `Invoke-DocsPythonNativeInventory` plus the four pure analyzer functions.
3. Digest: no digest function is called; every element is built by 1020 `New-DocsSurfaceElement -SourceText -LineRange` (S12, U12), not by a 1022 digest function. `architecture-component` elements carry `line_range` `null` (whole-file digest, 1020 OQ-7), so the helper reports `null` line bounds for that kind.
4. Unavailability diagnostic: the snapshot diagnostic uses code `python-native-unavailable` (docs `diagnostic.code` grammar is lower-case), severity `information`, `analyzer_id` `docs-inventory`, path `null`, message naming the reason token; the exit-3 finding under `-AnalysisMethod native` uses `DOCS_PYTHON_NATIVE_UNAVAILABLE` (S4, S6). Helper exit 4 maps to `version-below-floor`, other non-zero exits to `exit-nonzero`; `pack-absent` is the reason token under `native`.
5. Protocol: `parent` is `{kind, declaration, path}` (a parent may sit in another file, such as a console-script root in `pyproject.toml`); the response file set must equal the request file set.
6. Inventory integration: neither 1020 nor 1022 calls the native provider or offers `-AnalysisMethod` (U-5), so this plan edits one 1022 row (`inventory` `Option` gains `AnalysisMethod`) and `LIB/DocsInventory.psm1`, contrary to the 1020 rule "never edit another anchor or row" and the 1022 statement that 1031 edits no 1022 file. Coordinator item 1 in `## Open Questions / Notes`.
7. Guard (Q11): the allowlist entry must match a detected finding, but `Context.InvokeProcess` is not detected by the four existing classes. This plan adds detection class 5 (`SeamInterpreterTarget`: an `&` call of a `[scriptblock]` parameter whose target argument is a constant interpreter name) to `GUARD/EnforcementHooksNoPythonInvocation.Helpers.ps1`; the single interpreter-start function makes three such calls. The helper file is added to the classification.
8. Fixture: 1031 adds `FIXTURES/python-native-corpus.json` and reads the 1022 corpus without editing it (1022 `### Shared fixtures`).
9. Helper modules: `source.py`, `cli_argparse.py`, `cli_click.py` and `cli_typer.py` are added to the spec module list to keep each file below 500 lines.
10. Evidence: S9 names `<FEATURE>/evidence/coverage/`, which is not a canonical kind. `EVIDENCE_LOCATION_OVERRIDE_REJECTED: <FEATURE>/evidence/coverage/ replaced with <FEATURE>/evidence/qa-gates/`.
11. Real-process test: none. The research proposed one integration test against a real interpreter; the binding process rule forbids it. Cross-language agreement is proven by the shared corpus on both sides.
