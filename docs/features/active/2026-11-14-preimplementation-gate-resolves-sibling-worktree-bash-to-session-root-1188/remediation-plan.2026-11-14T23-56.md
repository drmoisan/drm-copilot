### Classify sibling design (`Get-OrchestrationGateSupplementalPatternIndex -CommandText <string>`)

- Pure string function (no file, process, clock, or environment access; no dot-source of its own); returns `[int[]]`, a subset of `2` (npm scripts) and `3` (npx tools), the stage-1 pattern indexes of `Test-ImplementationCommand`.
- Form 1 (joined word): over the `Read-CommandLineSegment` records, a run starts at a record whose `Delimiter` opens a substitution (`$(`, a backtick, or `{` when its `RawText` ends with `$`) and continues through the record that follows the matching closer (nesting counted), extending while that record again ends with an opener. The joined text is the members' `ScanText` concatenated with their delimiters. Index 2 is returned when the joined text matches the unchanged npm stage-1 pattern and the run's first record carries `npm` as a whole word (`Test-CommandLineWordPresent`); index 3 likewise for the npx form below with `npx` in the first record.
- Form 2 (npx options): index 3 is returned when a record's `ScanText` or a joined text matches `npx` followed by one or more of `--prefix <v>`, `--prefix=<v>`, `-C <v>`, `--yes`, `-y`, `--no`, `-q`, `--quiet`, then the tool word `prettier`, `eslint`, `tsc`, or `jest`. Any other option (for example `-p`, `-c`, `--package`) is not accepted, so the command keeps its current classification.
- Each returned index still passes stage 2 (`Test-OrchestrationGateInvocationConfirmed`) and the index-0 bookkeeping rule exactly as a scan hit does; no command other than these two forms is newly classified, and none is newly unclassified.
- Header comment names issue #1188, the two forms, and the narrowed spec non-goal; under 200 lines.
