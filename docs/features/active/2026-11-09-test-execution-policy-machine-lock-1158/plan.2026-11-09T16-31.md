## Execution Constraints (owner brief)

- Pushed-down logic is PowerShell or bash. No new Python file and no TypeScript change: Python edits are in place in `scripts/dev_tools/fix_all_branches.py`, `scripts/dev_tools/fix_all_branches_extra.py`, `scripts/dev_tools/atomic_executor/qc_runner.py`, and `pyproject.toml`. Codex publication of `.agents/skills/test-execution-policy/scripts/` follows pack-manifest paths under `ROOT_FOLDERS` in `extensions/drm-copilot/src/lib/push-down/codex-agents-customizations.ts`, so D17 needs no TypeScript edit.
- Pure logic lives in host-neutral helpers with scriptblock seams for clock, sleep, filesystem, environment, and process; tests create no temporary file, perform no real wait, and set no environment variable without a paired restore.
- Gates are parallel only: one `Invoke-PoshQCParallelTest` run, one `pytest -n auto` run, Jest through its normal workers, bats through `scripts/bash/shell-qc.sh`; each is re-run only after a fix. A focused run of one file is debugging only, never a gate. Test order dependence is fixed on both sides.
- Evidence is append-only: never back-date, rewrite, or delete evidence or receipts; a re-run writes a new stamped file.
- Defaults: the new test-execution knobs change behavior by design (lanes excluded, one suite per machine, launcher required); the PoshQC `-ExcludeTag` and `-ExcludeTestFileSuffix` parameters and the MCP template lock branch keep today's behavior when omitted or when the helper is absent.
- The hook is a standalone PreToolUse hook registered the usual way (#1159 absorbs it after merge). Policy documents under `.claude/rules/` and `.github/instructions/` are not modified.
- SCRATCH is `<session scratchpad>/issue-1158/`; scratch file names start with `issue-1158-`; evidence records the token `SCRATCH`, never a host path, a worktree root, or a host name.
- `<FEATURE>` in evidence paths is `docs/features/active/2026-11-09-test-execution-policy-machine-lock-1158`.
- Ordering: Phase 0 runs on the current routes before the launcher exists. P3-T3 (live two-process proof) runs before P4-T3 (hook registration). From P4-T3 on, every test run, including a focused debugging run, goes through the launcher. No acceptance condition depends on a live hook denial; hook behavior is proven by Pester (brief `## Hook Execution Context`).
- Batch budget: no task edits more than three distinct non-test PowerShell or Python production files through Write or Edit. Twins, mirrors, and bundle copies are produced by the copy script `SCRATCH/issue-1158-copy-mirrors.sh` and proven by hash equality and the mirror contract tests. The plan writes more than three PowerShell production files in total (Python totals exactly three), so execution needs a worktree checkpoint on the large, remediation, or preparation route, or successive executor sessions; a `POWERSHELL_LARGE_PATH_REQUIRED` denial stops the run and is reported, never worked around.
- Lane effect on comparisons: Phase 0 runs include the integration-named test files; final gates through the launcher exclude them. The comparison in P7-T8 subtracts their tests and records a non-blocking deviation citing the CI jobs `poshqc / PowerShell QC`, `poshqc / PowerShell hook suites (Linux)` (for `tests/scripts/codex-hooks/codex-pretooluse-integration.Tests.ps1`), `quality-checks7 / Code Quality & Tests (3.13)`, and `drm-copilot-extension-tests / drm-copilot Extension Tests (windows-latest)`.
