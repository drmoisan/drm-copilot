## Size Justification

The plan exceeds 40 tasks because the caller requires one regression-test task per fail-closed case in the spec (AC-03 to AC-16, fourteen tasks) in addition to the allow cases, the regression suite, the three deny-text pins, and the Python fragment pin; and because the change spans one hook, one new hook, four prose surfaces, six bundle mirrors, one pack manifest, and a full PowerShell and Python verification loop with isolation runs. Splitting the item would separate the hook from the deny-text pins and the prose that the pinned documentation tests assert together, which leaves either half failing its own contract tests.

## Pre-Mortem

- Review checklists: a reviewer could find that the green branch fires for a parallel child, that `epic_mode` accepts a truthy string, that a deny-text pin is stale, or that a prose surface claims the parallel exclusion is closed. Prevention: one task per fail-closed case (P1-T5 to P1-T18) including the string-typed `epic_mode` row, exact-case rows, and three paired parallel-decline rows; P5-T11 confirms the three pins changed together; P3-T1 to P3-T8 state the residual window with the token `best-effort`; the self-review task P5-T14 walks the three templates.
- Coverage: the live-head wrapper is I/O-thin and the gate is an entry-point file, so per-file line coverage of `.claude/hooks/enforce-epic-merge-gate-green-ci.ps1` or `.claude/hooks/enforce-epic-merge-gate.ps1` could fall below 85 percent. Prevention: the wrapper body is exercised through six mocked `Invoke-DocsOnlyGhExe` outcomes (P1-T13); every stage has parameter-driven rows; P0-T4 records the baseline per-file figure for `.claude/hooks/enforce-epic-merge-gate.ps1` and P5-T7 reads both files from `artifacts/pester/powershell-coverage.xml` after a full single-process run and records the comparison. No production Python file changes, so no Python coverage gate applies (the touched Python file is test support).
- Mirror parity: six edited or new Claude files need byte-identical copies under `BUNDLE/.claude/`, and the new hook needs a `BUNDLE/pack-manifests/core.json` entry, or the push-down contract, manifest-completeness, and dependency-closure tests fail. Prevention: P4-T1 copies all six with a hash comparison per pair, P4-T2 adds the manifest entry, P4-T3 runs the three contract tests, P4-T4 runs the Codex generator `--check`. The execution-environment brief is not edited, because this change alters no fact the brief states (no CI job, required context, tool route, or batch-budget rule changes), so no brief-update task is needed and its six copies stay byte-identical; P5-T10 confirms the brief has no diff against `MERGE_BASE`. The Codex hooks and Codex bundle are unchanged (decision D7).
- File size: `.claude/hooks/enforce-epic-merge-gate.ps1` is 460 physical lines and `session-root-reads-850.Constraints.Tests.ps1` caps it at 500; `hook-docs-only-diff.ps1` is 497 lines; `enforce-epic-merge-gate.Tests.ps1` is 471 lines. Prevention: all new logic goes into `.claude/hooks/enforce-epic-merge-gate-green-ci.ps1`; `.claude/hooks/enforce-epic-merge-gate.ps1` receives only the guarded dot-source, the branch call, the suffix append, the deny text, and header prose; no test is added to `enforce-epic-merge-gate.Tests.ps1`; new rows go into three new suites; P0-T3 and P5-T9 record physical counts with `wc -l` before and after.
- Test isolation: a new suite that omits a checkpoint-seam mock could read a live checkpoint or start `gh`, and leaked mocks could change shuffled results. Prevention: each new suite follows the baseline isolation form of `enforce-epic-merge-gate.DocsOnly.Tests.ps1` and calls `Invoke-EpicStateInterceptionProbe` from inside an `It`, which `enforce-gate-suites.EpicStateIsolation.Discovery.Tests.ps1` verifies for every discovered suite; `Get-EpicMergeGateLivePrHeadSha` and `Invoke-DocsOnlyGhExe` are mocked by name and `gh` is never mocked or started; no test creates files. Isolation runs: P5-T8 runs a seeded shuffled file-order run of the touched Pester suites with three seeds (each seed and file order recorded) and a reversed-order run of the touched Python test module; P5-T7 is the fresh single-process run over `tests/scripts`. No Jest code is touched, so no Jest shuffle run applies.
- CI-only behavior: the Linux hook-suite job runs `tests/scripts/claude-hooks` on a case-sensitive file system with coverage disabled, and shard runs expose module-scope leaks. Prevention: fixtures use `/synthetic-worktrees/<name>` roots built with `Join-Path`, forward-slash relative paths, exact file-name case, no drive letters and no backslash literals; no test reads gitignored `artifacts/` state; P5-T7 runs the single-process shape. The Pester criterion relies on `poshqc / PowerShell QC` for coverage on `windows-latest` and on `poshqc / PowerShell hook suites (Linux)` for the `ubuntu-latest` hook-suite run; both are pending-CI under AC-31.
- Evidence: the live scenario (a standalone run merging its own PR, a parallel child not doing so) cannot be proven before merge because isolated subagents run `main`'s hooks, and PoshQC MCP results carry no output. Prevention: AC-31 is listed pending-CI and AC-32 is recorded as a deferred live verification in P5-T13, counts come only from the JUnit and coverage files, and all evidence is written under `FEATURE/evidence/<kind>/`.
