## Conventions Used in This Plan

- `FEATURE` means `docs/features/active/2026-08-23-parallel-parent-routes-on-a-band-nothing-produces-532`. Every evidence artifact is written under `FEATURE/evidence/<kind>/` (`baseline`, `regression-testing`, `qa-gates`, `other`, `remediation-baseline`). No evidence is written under `artifacts/`.
- `<ts>` in an evidence file name is the execution timestamp in `yyyy-MM-ddTHH-mm` form, taken when the artifact is written.
- Every command-step artifact carries `Timestamp:`, `Command:`, `EXIT_CODE:`, and `Output Summary:`. An artifact under `evidence/qa-gates/`, `evidence/regression-testing/`, or `evidence/other/` carries exactly one line whose text before the first colon, trimmed, is `EXIT_CODE`, because the Python collector keeps the last such line and the TypeScript collector keeps the first. A second command in the same artifact is recorded inside `Output Summary:` as a list item of the form `- <command> exited <n>` with no colon before the exit status. An artifact for a command whose expected exit code is non-zero also carries `ExpectedExitCode: <int>`.
- The single-line rule also applies to `Timestamp:` and `Command:`, because both collectors key on all three required fields (`REQUIRED_FIELDS` in `scripts/dev_tools/pr_context/verification_evidence.py` and `extensions/drm-copilot/src/lib/pr-context/verification-evidence.ts`). For uniformity it applies to multi-command artifacts under `evidence/baseline/` as well. In a multi-command artifact, the `Command:` and `EXIT_CODE:` lines belong to the command the task names as primary; each other command is a `- <command> exited <n>` list item in `Output Summary:`, followed by its output lines. A gate that needs its own pass/fail row is written to its own artifact rather than appended as a list item.
- Superseded attempts: when a gate task is re-run after a failure (a Phase 7 loop restart, or a re-run of any Phase 1 to Phase 6 gate task after a fix), the failed attempt's artifact must not remain under `evidence/qa-gates/`, `evidence/regression-testing/`, or `evidence/other/`, because both collectors render every parseable artifact in those folders as a row (`CANONICAL_GLOBS` in `scripts/dev_tools/pr_context/verification_evidence.py` and `extensions/drm-copilot/src/lib/pr-context/verification-evidence.ts` lists exactly those three folders, recursively, and does not list `evidence/remediation-baseline/`). Before the re-run, move each superseded artifact, keeping its file name, to `FEATURE/evidence/remediation-baseline/superseded/`. Before the first move, create that folder by writing `FEATURE/evidence/remediation-baseline/superseded/README.md` with the Write tool, stating that the folder holds superseded gate attempts outside the collector globs. Move one file per Bash command with `mv <artifact> FEATURE/evidence/remediation-baseline/superseded/`. If `mv` is denied, Write identical content to the destination, then `rm -f` the source. The P1-T6 or P2-T6 `[expect-fail]` artifact that satisfies every condition on its task's Acceptance line is never moved. An earlier P1-T6 or P2-T6 attempt that did not satisfy that acceptance is superseded and moved like any other failed attempt. An `issue-510-first-run-p5-t23.<ts>.md`, `issue-510-first-run-p7-t5.<ts>.md`, or `issue-510-first-run-p7-t10.<ts>.md` artifact is moved only when the gate run it precedes is itself superseded.
- Python commands run from the worktree root. TypeScript commands use `npm --prefix extensions/drm-copilot run <script>`, which runs the package script with `extensions/drm-copilot` as its working directory. Prettier is invoked as `node extensions/drm-copilot/node_modules/prettier/bin/prettier.cjs` from the worktree root (the package has no Prettier config file, so the defaults used by the package `format` script apply).
- Environment constraints: the Bash tool denies commands containing the words for the POSIX shell, PowerShell 7 executable, or the Linux subsystem, and denies heredocs. Every command in this plan uses `poetry`, `npm`, `node`, `git`, `grep`, `wc`, `cmp`, `cp`, `mv`, `rm`, `ls`, or `sh`. The `atomic-executor` frontmatter lists no `npm` pattern; preflight round 1 observed `npm --prefix extensions/drm-copilot run lint` execute and exit 2 on a missing package rather than on a permission denial, so `npm` is invoked directly. Pester runs use the scratchpad wrapper defined in P0-T19 (`<session scratchpad>` is the executor's session scratchpad directory; no absolute path is recorded in any artifact). PoshQC MCP results carry no output text; no task asserts a count from a PoshQC MCP result.
- Python batch budget: if the Python batch-budget hook denies a Write/Edit, repeat the P5-T21 procedure and write a new `FEATURE/evidence/other/python-batch-budget-reset.<ts>.md` before retrying.
- The plan commits nothing. Files created by this plan are untracked until the orchestrator commits, so every search against a created file uses plain `grep`, never `git grep`.
- Known environment condition (issue #510): `tests/scripts/dev_tools/test_push_down_claude_resource_contracts.py::test_bundled_claude_payload_contains_all_repo_runtime_contracts` enumerates the filesystem, so gitignored `.claude/state/*.json` hook counters produce `Repo file missing from bundle: .claude/state/...` failures locally.
