## Pre-Mortem

- Review checklists: A reviewer could read the merge resolution or the fence updates as an unrecorded reduction change. P1-T3 is the one token-bearing commit, P0-T2 records both sides of every conflict, and P3-T6 checks the token rule and the scan-text rule; P3-T7 adds one row per input finding.
- Coverage: Removing duplicates can lower coverage if a branch case covered a path no main case reaches; P1-T2 keeps any such case, and P3-T5 compares each changed file with its pre-change figure. `read-error` adds one branch to `Invoke-PoshQCLeakScan`, covered by `LI-14`.
- Mirror parity: P2-T3 copies `PoshQC.LeakAllowlist.psm1` and `README.md` to the bundle under the PoshQC mirror rule, and `test_poshqc_bundled_module_files_match_repo_root_sources` checks both. - File size: The merge takes `test_qc_runner.py` and `test_cli_part3.py` above 700 lines; P1-T3 and P2-T1 move cases into existing files, and P2-T1 measures every test file in the diff. `test_prompt_builder.py` was 768 lines on `origin/main` and is reported, not split.
- Test isolation: The gates are one `Invoke-PoshQCParallelTest` run, one `pytest -n auto` run, and Jest through its normal parallel workers, each re-run only after a fix. Moved tests keep their bodies and fixtures, `LI-14` uses the in-memory seam, and no temporary file is created. The leak scan of P1-T1 and P3-T1 covers main's Pester files after the merge.
- CI-only behavior: Main's #1106 tests key `_PYTEST_STEP` by exact argv, so a missed `-n auto` fails on every runner; P1-T3 updates it and P3-T3 names the dependent test. The leak scan runs in `poshqc-static` over the merged tree, so P0-T3 and P1-T1 surface any new finding before CI does. More than three production files change across the branch, so the worktree checkpoint must select the remediation route; a batch-budget denial stops the executor for the orchestrator.
- Evidence: Conflict sides, duplicate decisions, fence replay, and file sizes each have a named artifact. Gate figures come from JUnit and coverage files, runner output stays under `SCRATCH`, and P3-T6 scans `<FEATURE>/evidence/` for host paths and excluded run citations.
