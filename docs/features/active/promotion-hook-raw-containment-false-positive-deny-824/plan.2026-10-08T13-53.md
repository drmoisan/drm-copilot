## 1. Rules binding on every task

1. **Evidence location and schema.** Every artifact is written under `FEATURE/evidence/<kind>/` with `<kind>` one of `baseline`, `regression-testing`, `qa-gates`, `issue-updates`, `other`. Every command-step artifact carries `Timestamp:`, `Command:`, `EXIT_CODE:`, and `Output Summary:`. An artifact whose command is expected to exit non-zero also carries `ExpectedExitCode: <n>`. `EXIT_CODE: SKIPPED` is never a passing outcome; no task in this plan authorizes a skip.
2. **Evidence location override (recorded once in [P0-T7]).** The spec names `evidence/regression/`, `evidence/qa/`, and `evidence/coverage/`. Those are not canonical kinds. They are replaced as follows and every AC that names them is satisfied by the canonical location:
   - `EVIDENCE_LOCATION_OVERRIDE_REJECTED: FEATURE/evidence/regression/ replaced with FEATURE/evidence/regression-testing/`
   - `EVIDENCE_LOCATION_OVERRIDE_REJECTED: FEATURE/evidence/qa/ replaced with FEATURE/evidence/qa-gates/`
   - `EVIDENCE_LOCATION_OVERRIDE_REJECTED: FEATURE/evidence/coverage/ replaced with FEATURE/evidence/qa-gates/`
3. **No host data.** No artifact or test contains an absolute host path, drive-letter user path, or account name. Script output that contains the worktree root is recorded with the root replaced by `<WORKSPACE_ROOT>`.
4. **PowerShell route (environment constraint).** The worktree isolation guard refuses Bash command text containing `pwsh`, `bash`, `wsl`, or a heredoc. Therefore:
   - The PoshQC MCP tools `mcp__drm-copilot__run_poshqc_format`, `mcp__drm-copilot__run_poshqc_analyze`, and `mcp__drm-copilot__run_poshqc_test` are the toolchain route in Phase 10. Their results carry no command output, so only their call disposition (`MCP_CALL: returned`, `MCP_CALL: error <message>`, or `MCP_CALL: unavailable <reason>`) is recorded. No count, percentage, or finding is read from an MCP result.
   - Every count, percentage, test name, and finding that an acceptance condition reads comes from an observation script of section 6. Each script is written with the Write tool to `SCRATCHPAD/<name>.ps1` together with a launcher `SCRATCHPAD/<name>.sh` whose only line is `exec pwsh -NoProfile -File "$(dirname "$0")/<name>.ps1" "$@"`, and is launched with the Bash command `sh SCRATCHPAD/<name>.sh <args>`. Each script obtains the repository root with `$root = (Get-Location).Path` (the Bash tool's working directory is the worktree root).
   - Exception, S-FULL-RUN only. The full Pester run exceeds the 600-second Bash foreground limit (a recorded run in this repository reported 571.662 s of test time alone, before discovery and coverage processing). Its launcher `SCRATCHPAD/s-full-run.sh` has exactly four lines: `pwsh -NoProfile -File "$(dirname "$0")/s-full-run.ps1"`, `code=$?`, `echo "FULL_RUN_EXIT_CODE: $code"`, `exit $code`. It is launched with the Bash tool parameter `run_in_background: true`, and the executor waits for the background-task completion notification before reading its output. The artifact's `EXIT_CODE:` is the integer printed on the `FULL_RUN_EXIT_CODE:` line; a run whose output lacks that line is recorded as incomplete and stops execution as BLOCKED.
   - If a launcher is refused, the executor records the refusal text in the task artifact and stops as BLOCKED.
5. **Plain commands.** `git`, `poetry`, `npm`, and `gh` commands run directly in the Bash tool, one command per call: no `&&`, no `;`, no `cd`, no heredoc.
6. **Mirrors are byte copies.** Every `.codex/hooks/` copy of a shared module and every file under `extensions/drm-copilot/resources/` other than the two `pack-manifests/core.json` files edited by [P7-T3] and [P7-T4] is written only by script S-MIRROR (`Copy-Item -LiteralPath <source> -Destination <target> -Force`), never with Write or Edit. Each copy appends source, target, and both SHA256 values to `FEATURE/evidence/other/mirror-log.md`. The `.claude/hooks/` shared modules are `hook-command-scanner.ps1`, `hook-command-heredoc.ps1`, `hook-command-payload.ps1`, `hook-command-payload-powershell.ps1`, `hook-command-invocation.ps1`, and `hook-command-invocation-operands.ps1`; the S-MIRROR groups that contain them are `codex-scanner`, `codex-payload`, and `codex-invocation` (section 6). In Phases 2-6, when a `.claude/hooks/` shared module is edited and no later S-MIRROR run in the same phase copies it (in Phases 2-4 the planned S-MIRROR task copies only its own group, so an edit to a module outside that group, or any edit made after that task, is not copied), the executor re-runs each S-MIRROR group containing that module before that phase's Pester gate. This includes a fix made to pass that gate; each such re-run records `FEATURE/evidence/other/mirror-<group>-phase<N>.STAMP.md`, the phase gates are [P2-T5], [P3-T6], [P4-T8], [P5-T18], and [P6-T7], and a gate is re-run if a mirror ran after it. ## 2. Design contract (planner decisions binding on implementation)

Each item is a decision the spec left open or stated ambiguously. Items marked **PD** deviate from or tighten the spec text and are flagged for orchestrator review.

- **DC-1 Module layout (PD-24).** New shared modules, each with a Claude copy, a byte-identical Codex copy, and bundled mirrors:
  - `hook-command-heredoc.ps1`: `Read-CommandLineHeredocHeader` and `Read-CommandLineHeredocBody`, moved verbatim from `hook-command-scanner.ps1:198-301`; the scanner dot-sources it. The move is unconditional because the scanner (483 lines) cannot absorb `Delimiter` and `TokenText` under the 500-line cap.
  - `hook-command-payload.ps1`: `Read-CommandLineInvocationSegment`, `Test-CommandLineWordPresent`, POSIX/`eval`/`xargs` payload extraction, transparent-wrapper skipping, substitution-body extraction, backslash-newline normalization, command-word leaf normalization, and the inert proof.
  - `hook-command-payload-powershell.ps1` (**PD-24**, not in the spec file table): `pwsh`/`powershell` flag parsing, base64 UTF-16LE decode, and the `[System.Management.Automation.Language.Parser]::ParseInput` adapter. Split out so `hook-command-payload.ps1` stays under 500 lines; AC-23 and AC-24 obligations apply to it exactly as to the spec-named modules.
  - `hook-command-invocation-operands.ps1`: `Get-CommandLineOperand`, `Get-CommandLineFlagValue`, `Test-CommandLineFlag` (moved), and `Resolve-CommandLineInvocationTarget`.
  - `hook-command-invocation.ps1` dot-sources, in order: scanner, payload, payload-powershell, operands. No consumer hook adds a dot-source line.
- **DC-2 Scanner record.** `Read-CommandLineSegment` keeps its parameter list (`CommandText` only, pinned at `tests/scripts/claude-hooks/hook-command-scanner.Tests.ps1:380-385`) and gains two record properties: `Delimiter` (`;`, `&&`, `||`, `|`, `&`, newline, `(`, `)`, `{`, `}`, `$(`, backtick, or `''` at end of text; `&&` and `||` consume both characters, which removes the empty segment the second character produced before) and `TokenText` (the already-computed text with heredoc bodies blanked and quoted spans intact). No other scanner behavior changes; backslash-newline is NOT normalized in the scanner (DC-6).
- **DC-3 Iterator record.** `Read-CommandLineInvocationSegment -CommandText <string> [-MaxDepth <int> = 4]` returns records carrying every spec property (`Index`, `RootIndex`, `Depth`, `Origin`, `Wrapper`, `Dialect`, `RawText`, `RootRawText`, `Tokens`, `CommandWord`, `Literal`, `Unbalanced`, `Opaque`, `OpaqueReason`, `Delimiter`) plus one additive property `PresenceText` (DC-9). `Index` is pre-order source order; `RootIndex` is the `Index` of the depth-0 record the record descends from (itself at depth 0). `OpaqueReason` is one of `''`, `NoPayload`, `DecodeFailure`, `DepthLimit`. A PowerShell parse error sets `Unbalanced = $true` on one record carrying the payload text.
- **DC-4 Wrapper detection and payload extraction.** The wrapper word is the leaf-normalized (DC-5) command word after `VAR=value` prefixes and after skipped transparent wrappers (`env` with its `-x`/`VAR=v` tokens; `timeout` with its `-x` tokens and one duration token; `time -p`; `command -p|-v|-V`; `nohup`).
  - POSIX (`sh`, `bash`, `zsh`, `dash`, `ksh`): the first token matching `^-[A-Za-z]*c[A-Za-z]*$` (for example `-c`, `-lc`); the next token is the payload; later tokens are positional arguments and stay in `RootRawText`.
  - `pwsh`, `powershell`: command forms `-c`, `-cwa`, `-commandwithargs`, and any case-insensitive prefix of `-command` with length at least 4; the payload is the remaining tokens joined by single spaces (`-cwa`/`-commandwithargs`: the next token only). Encoded forms `-e`, `-ec`, and any prefix of `-encodedcommand` with length at least 3: decode the next token as base64 UTF-16LE and recurse; a decode failure yields `Opaque`/`DecodeFailure`. Before the command or encoded form, flags are consumed case-insensitively: the standalone flags `-NoProfile`/`-nop`, `-NoLogo`/`-nol`, `-NonInteractive`/`-noni`, `-NoExit`/`-noe`, `-Login`/`-l`, `-MTA`, `-STA` are skipped; the flags `-ExecutionPolicy`/`-ep`/`-ex`, `-WorkingDirectory`/`-wd`, `-WindowStyle`/`-w`, `-InputFormat`/`-if`, `-OutputFormat`/`-of`, `-ConfigurationName` are skipped together with exactly one following value token. Any other token beginning with `-` before the command or encoded form is an unrecognized flag and yields `Opaque`/`NoPayload` per the no-payload bullet below.
  - `eval`: the remaining tokens joined by single spaces (POSIX dialect).
  - `xargs`: skip tokens beginning with `-` (the options `-n`, `-I`, `-L`, `-d`, `-P`, `-s`, `-E`, `-a` also consume the next token when no value is attached); the remaining tokens form a record with `Origin = ArgumentInjector`.
  - A wrapper word from the set `sh, bash, zsh, dash, ksh, pwsh, powershell, eval, xargs` with no extractable payload (script-file form, stdin heredoc, `-File`, `-f`, unrecognized flag) yields `Opaque = $true`, `OpaqueReason = NoPayload` on that record.
  - Depth: payload records are `Depth + 1`. A wrapper record at `Depth = MaxDepth` whose payload would exceed `MaxDepth` yields `Opaque`/`DepthLimit` and no payload records.
- **DC-5 Leaf normalization.** At every depth the command word is the text after the last `/` or `\` with a trailing `.exe` removed case-insensitively; case is otherwise preserved and comparison is case-insensitive.
- **DC-6 Backslash-newline (PD-9).** `Read-CommandLineInvocationSegment` replaces every backslash followed by an optional carriage return and a line feed with one space before calling `Read-CommandLineSegment` for the top level and for every POSIX payload. The scanner itself is unchanged, so no other scanner consumer changes behavior.
- **DC-7 PowerShell adapter.** One record per `CommandAst` found anywhere in the payload AST (nested script blocks and subexpressions included), in `Extent.StartOffset` order. `Tokens` are the element values (`StringConstantExpressionAst.Value`, `CommandParameterAst` text, otherwise `Extent.Text`). `Literal = $false` when any element is not a constant or parameter-without-argument or when the command name is not a constant. Additionally, one non-command record (`CommandWord = ''`, `Literal = $false`) is emitted for each top-level statement that is not a pipeline made only of `CommandAst` elements, and for each `CommandExpressionAst` pipeline element. A `CommandAst` with redirections sets that record's `Literal = $false`. A `CommandAst` whose name is itself a wrapper recurses per DC-4.
- **DC-8 Substitution bodies.** For a record whose scanner segment has `HasLiveSubstitution`, the content of each double-quoted span containing `$(` or a backtick is re-segmented with `Read-CommandLineSegment` (after DC-6); each resulting segment becomes a record with `Origin = Substitution`, `Depth + 1`.
- **DC-9 Presence text (PD-6).** `PresenceText` per origin: `TopLevel` = its own `RawText`; `WrapperPayload` = `RootRawText`; `Substitution` = the concatenated `TokenText` of the re-segmented body (heredoc bodies blanked, so a `$(cat <<'EOF' ... EOF)` commit body is inert); `ArgumentInjector` = the whole normalized command text.
- **DC-10 Classification (`Get-CommandLineInvocation`).** For each record, in order, the first applicable rule wins:
  1. `Unbalanced` -> Indeterminate, `Reason = Unbalanced` (unconditional, parity with today's R1; **PD-7**).
  2. `Opaque` with `DecodeFailure` -> Indeterminate `Opaque`; with `DepthLimit` -> Indeterminate `DepthLimit` (unconditional; **PD-7**).
  3. Structural walk over `Tokens` (skip `VAR=value` and transparent wrappers per DC-4, leaf-compare the command word, absorb modeled global options while recording ordered `{Name, Value}` pairs): a `Terminal` option (DC-11) ends the record as no match; an unmodeled dash token before the subcommand -> Indeterminate `Opaque` (**PD-5**, preserves `tests/scripts/claude-hooks/hook-command-invocation.Tests.ps1:44-47`); a full subcommand-path match -> Structural with `OperandIndex`, `Operands`, `OperandsComplete` (DC-12).
  4. Not matched and `Opaque`/`NoPayload`, or a transparent-wrapper-led record whose walk failed (**PD-3**): Indeterminate `Opaque` when the command word and every subcommand element are present (DC-13) in the record's own `RawText` (heredoc body included).
  5. Not matched and the command-word token is non-literal, or the command word matched and the first token at a subcommand position is non-literal (**PD-2**): Indeterminate `DynamicPosition` when all words are present in the whole normalized command text.
  6. Not matched, `Origin` in `WrapperPayload`, `Substitution`, `ArgumentInjector`: Indeterminate `NotProvenInert` when all words are present in `PresenceText` and the root's payload is not proven inert (DC-14). At most one such match per `RootIndex`.
  7. Otherwise no match.
  `Indeterminate` records carry `OperandIndex = -1`, empty `Operands`, `OperandsComplete = $false`.
- **DC-11 Terminal options and `--exec-path`.** `Get-CommandLineGlobalOption` returns `{WithArgument, Standalone, Terminal}`. git: `WithArgument = -C, -c, --git-dir, --work-tree, --namespace`; `Standalone` gains `--exec-path` (so `--exec-path=<value>` is absorbed as one token); `Terminal = --version, -v, --help, -h, --html-path, --man-path, --info-path, --exec-path`. gh: `Terminal = --version, --help`. npx: `Terminal` empty. `Skip-CommandLineOption` tests the bare token (no `=`) against `Terminal` before any other list and returns a `Terminal` flag.
- **DC-12 Operands.** Collection follows the current `Get-CommandLineOperand` loop (`hook-command-invocation.ps1:319-355`). `OperandsComplete = $false` when: the record or an ancestor has `Origin = ArgumentInjector`; any operand is non-literal (contains `$` or a backtick, or begins with `(`, `@`, or `{`); a token beginning with `<` or `>` or matching `^\d*>|^&>` appears after the subcommand (a bare operator also consumes the next token as its target; neither is an operand); or an unmodeled dash token is followed by another token.
- **DC-13 Presence predicate.** `Test-CommandLineWordPresent -RawText <string> -Word <string>` is `(?<![\w-])<escaped word>(?![\w-])` with `IgnoreCase, CultureInvariant`. `Get-CommandLineInvocation` evaluates every whole-token presence test of DC-10 rules 4-6, and any whole-token test performed while evaluating DC-14, by calling `Test-CommandLineWordPresent`; no other presence implementation exists in any module. This is what lets the IV-16 mock of `Test-CommandLineWordPresent` reach every presence decision.
- **DC-14 Inert proof (PD-4).** A root's payload is proven inert only when every record with that `RootIndex` and `Depth >= 1` is `Literal`, is neither `Unbalanced` nor `Opaque`, has a leaf-normalized `CommandWord` in `SINKS`, and has no token containing `<` or `>`. This applies the spec sentence "any other command ... is not inert" to every command in the payload, and adds the redirection exclusion (fail-closed).

- **DC-20 Allowlist hook (PD-13).** New `.claude/hooks/enforce-pr-author-command-allowlist.ps1`, following the import and entry-point pattern of `.claude/hooks/enforce-epic-worktree-removal-gate.ps1:406-457` (HookPayload import, `Read-ClaudeHookRawPayload`, compact JSON, `exit 0`).
