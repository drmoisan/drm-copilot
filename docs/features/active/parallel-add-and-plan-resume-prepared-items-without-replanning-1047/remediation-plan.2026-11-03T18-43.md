## Design Summary

- **File-size headroom.** `Invoke-ParallelAdmission.ps1` is one logical line below the 700-line advisory tier, and the code review asks that further subcommands not grow it. The four pure JSON helpers (`ConvertFrom-ParallelAdmissionJsonElement`, `ConvertFrom-ParallelAdmissionJson`, `Write-ParallelAdmissionJsonValue`, `ConvertTo-ParallelAdmissionJson`) and the integer type-name list they use move unchanged in name and behavior into the new sibling module `.claude/lib/parallel-admission/ParallelAdmissionJson.psm1`, which the script imports like its other two siblings. The seams stay in the script, so mocks are unchanged.
- **M3 (git stderr).** `Invoke-ParallelAdmissionGit` returns `ExitCode`, `Output` (stdout lines only), and a new `Stderr` (stderr lines only). `Invoke-ParallelAdmissionGitChecked` throws `git <args> exited <N>: <first non-blank stderr line, trimmed>` when stderr is non-empty and keeps the current `git <args> exited <N>.` otherwise. A result object without a `Stderr` property (every existing mock) is read as empty, so strict mode does not throw on it.
- **M1 (`reuse-edges`).** New subcommand `reuse-edges -Slug <slug> -IssueNum <n> -PlanHash <hex> [-Ref <ref>]` calls `Get-ParallelAdmissionRecordedEdge` and prints one JSON object with keys `action`, `edges`, and `reason` (exit 0 for both `reuse` and `recompute`). Usage errors exit 2. A record that is not a JSON object exits 1 with the failure prefix. It runs no fetch. `.claude/skills/parallel-plan/SKILL.md` `### Seeding procedure` step 7 calls it instead of a manual `git show` and hash comparison.
- **M2 (fetch wording).** The script header, the seam synopsis, and the `assess` help state that `assess` runs `git fetch --quiet origin`, which updates remote-tracking refs and the object store and needs network access; every other git call reads by ref; the helper writes no file. Behavior is unchanged.
- **Consistency edits caused by M1.** The subcommand list in `.claude/rules/parallel-orchestration.md` `## Prepared-Item Admission (issue #1047)` and the `## API / CLI Surface` table in `spec.md` gain `reuse-edges`. The acceptance-criteria text is unchanged.
- **R1 and R2.** Both coverage artifacts are produced in the final phase after every edit: a fresh full Pester run over `tests/scripts` with module-default settings, which is the last Pester run of the plan, and a full `-n auto` pytest run with coverage.
