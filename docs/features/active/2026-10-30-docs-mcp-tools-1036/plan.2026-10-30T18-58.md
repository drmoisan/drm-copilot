## Design Decisions Recorded by the Planner

- D-1 (`limit`): confirmations `### F1a` is binding and supersedes the spec table's "positive integer": `limit` is a string with the docs `identifier` grammar and the `diagnostic-` prefix, permitted only for `set-disposition` and `remove-entry`, as the exclusive alternative to `element`. The `-Limit` versus non-`deferred` disposition rule is left to PowerShell (exit 2 `DOCS_CLI_ARGUMENTS`).
- D-2 (resolver rejection code): input rejections throw a `DocsInputError` whose message is prefixed `DOCS_INPUT_INVALID`; a missing or non-string `workspace_root` throws `DOCS_WORKSPACE_ROOT_INVALID` from the resolver, and the executor raises the same code for a non-absolute root.
- D-3 (parity strings): each TypeScript grammar constant is the exact `pattern` string of PARITY-SOURCE, including its terminating `(?![\s\S])` lookahead. The element-id and page-reference grammars are pinned by literal unit tests when PARITY-SOURCE carries no definition for them ([P0-T4] records which).
- D-4 (extra test file): `test/mcp-tool-inputs-docs.ledger.test.ts` is added beyond the spec table to keep each test file below 500 logical lines (spec AC "below 500"); class test, rule E2.
- D-5 (default seams): `createDefaultPwshResolver` and `createDefaultDocsDependencies` live in `src/repo-automation-execute-docs.ts`, take PATH, PATHEXT, platform and an existence predicate as parameters, and are tested without launching a process; `DefaultRepoAutomationService` only wires them.
- EVIDENCE_LOCATION_OVERRIDE_REJECTED: `<FEATURE>/evidence/coverage/` (spec and user-story coverage criteria) replaced with `<FEATURE>/evidence/qa-gates/`.
