## Parity Notes (binding design decisions)

These notes capture the exact observable behavior of the bundled Python that the port MUST reproduce. The Python `potential_to_issue.py` does NOT import `markdown_label_formatter`; the F1 `markdown-label-formatter.ts` is NOT a dependency of this port and MUST NOT be wired in.

### Filesystem seam (do NOT widen the F1 `FileSystem` interface)

The bundled Python `FileSystem` protocol exposes `resolve_path`, `exists`, `read_text`, `write_text`, `write_lines`, `ensure_dir`, and `move`. The F1 `src/lib/file-system.ts` `FileSystem` interface exposes only `glob`, `isFile`, `readTextFile`, `writeTextFile`, `ensureDir` — it has NO `exists`, `move`, `writeLines`, or `resolvePath`. To avoid widening the shared F1 surface (mirroring the F6 decision), the port MUST define a port-local interface `PotentialFileSystem` in `promotion.ts` (or `promotion-filesystem.ts`) with the methods the workflow needs:

- `resolvePath(pathStr: string): string` — port of `resolve_path`; production default expands `~` and resolves to an absolute path using `node:path`/`node:os`, returning a path string (the port uses path strings, not a `Path` object).
- `exists(path: string): boolean` — port of `exists`.
- `readText(path: string): string` — port of `read_text`.
- `writeLines(path: string, lines: readonly string[]): void` — port of `write_lines`; joins with `"\n"` and writes (matches Python `"\n".join(lines)` then `write_text`).
- `ensureDir(path: string): void` — port of `ensure_dir`.
- `move(src: string, dest: string): void` — port of `move`; ensures the destination parent directory exists, then moves the file.

Provide `RealPotentialFileSystem implements PotentialFileSystem` backed by `node:fs`/`node:path`/`node:os` for production. Tests inject a `Map`-backed fake mirroring the Python `FakeFileSystem` in `tests/scripts/dev_tools/test_potential_to_issue_missing_label_regression.py` (tracks `files`, `dirs`, `moves`; `move` throws when the source is absent; `read_text` throws/raises for an absent path). Do NOT add any of these methods to the shared F1 `FileSystem` interface.

### `gh` client seam (use the injected F1 `CommandRunner` for all `gh` calls)

Port `GhClient` and `RealGhClient`:

- `GhResult` = `{ output: string[]; exitCode: number }` (port of the dataclass; `output` is the combined stdout+stderr split into lines).
- `isAuthenticated(): boolean` — port of `is_authenticated`: run `gh auth status`; return `true` iff exit code is `0`.
- `issueCreate(title, body, promotionType): GhResult` — port of `issue_create`: invoke `gh issue create --title <title> --body-file - --label <promotionType>` with `<body>` supplied on stdin. Preserve the exact arg ordering: `["issue", "create", "--title", title, "--body-file", "-", "--label", promotionType]`.
- `ensureLabel(label): GhResult` — port of `ensure_label`: invoke `gh label create <label> --color 0e8a16 --description "Feature work"`. Constants `FEATURE_LABEL_COLOR = "0e8a16"` and `FEATURE_LABEL_DESCRIPTION = "Feature work"` MUST be byte-identical.
- `issueView(issueNumber): GhResult` — port of `issue_view`: invoke `gh issue view <issueNumber> --json number,title,url,author,updatedAt`. The `--json` field list MUST be byte-identical: `number,title,url,author,updatedAt`.

`RealGhClient` MUST run all `gh` invocations through the F1 `CommandRunner` with `allowError: true` (the Python uses `check=False` and inspects the return code itself; the workflow recovers from non-zero exits, so the runner MUST NOT throw). The combined output is `(stdout + stderr)` split into lines via a `splitlines()`-equivalent. The `gh` body for `issueCreate` is passed on stdin: because the F1 `CommandRunner.run` signature does not accept stdin input, the port MUST either (a) extend `RealGhClient` to invoke a stdin-capable runner method, or (b) since `--body-file -` reads the body from stdin, define a narrow `GhCommandRunner` seam in `gh-client.ts` that adds an optional `input?: string` parameter and wraps the F1 `SubprocessRunner` (the production default), keeping the F1 interface unchanged. Choose (b) to avoid widening the shared `CommandRunner` interface; document the choice. The `gh` executable resolution mirrors Python `shutil.which("gh")`; a missing `gh` MUST raise the byte-identical message `gh CLI not found on PATH. Install gh and authenticate first.` Resolution MUST be injectable so tests never touch the real PATH.

### Promotion workflow (`promotePotential`) — exact behavior

Port `promote_potential` into `promotePotential(options)` preserving this control flow and every emitted line:

1. Validate `promotionType` against `PROMOTION_TYPES = ("epic", "feature", "refactor", "bug")`; on miss, throw `PromotionError` with `Invalid promotion type: ${promotionType}` (byte-identical).
2. Validate `workMode` against `ACCEPTED_WORK_MODES` (reuse F1 `ACCEPTED_WORK_MODES`); on miss, throw `PromotionError` with `Invalid work mode: ${workMode}` (byte-identical).
3. Resolve the filesystem, gh client, and workspace from injected options (production defaults: `RealPotentialFileSystem`, `RealGhClient`, workspace = current working directory).
4. If `!gh.isAuthenticated()`, throw `PromotionError` `GitHub CLI is not authenticated. Run 'gh auth login' first.` (byte-identical).
5. `resolved = fs.resolvePath(potentialPath)`; if `!fs.exists(resolved)`, throw `PromotionError` `Potential file not found: ${potentialPath}` (uses the ORIGINAL `potentialPath` arg, not the resolved path — byte-identical to Python).
6. `content = fs.readText(resolved)`; if `content.trim()` is empty, throw `PromotionError` `Potential file is empty: ${resolved}` (uses the RESOLVED path — byte-identical to Python).
7. `featureName = getFeatureName(content, resolved)`; `featurePath = getFeaturePath(featureName)`; `prefix = TITLE_PREFIXES[promotionType] ?? "Feature"`; `issueTitle = normalizeSmartPunctuation(`${prefix}: ${featureName}`)`. `TITLE_PREFIXES = { epic: "Epic", feature: "Feature", refactor: "Refactor", bug: "Bug" }`.
8. Compute `relativePath` as the POSIX form of the path relative to the workspace (port of `os.path.relpath` then `Path(...).as_posix()`); on a relpath error (e.g. different drive), fall back to the resolved path string, matching the Python `ValueError` fallback.
9. `selectedMode = normalizeRequestedWorkMode(workMode, promotionType)` (reuse F1); on the thrown error, re-wrap as `PromotionError` with the SAME message string (Python catches `ValueError` and re-raises as `PromotionError(str(exc))`).
10. Body construction routing (decision order MUST match Python exactly):
    - if `selectedMode === "minor-audit"`: extract sections `Problem / Why`, `Proposed Behavior`, `Acceptance Criteria (early draft)`, `Constraints & Risks`, `Test Conditions to Consider` (each `|| PLACEHOLDER`), and `Evidence Checklist` (when empty, default to the literal three-line checklist `- [ ] Baseline\n- [ ] End-state\n- [ ] Targeted verification`), then `body = buildMinorAuditBody(selectedMode, problem, implementationIntent, acceptanceCriteria, dependenciesRisks, verificationSteps, evidenceChecklist, relativePath)`.
    - else if `promotionType === "bug"`: build `bugSections` = `{ heading: getSection(content, heading) || PLACEHOLDER }` for each heading in `BUG_SECTION_HEADINGS`, then `body = buildBugBody(selectedMode, bugSections, relativePath)`.
    - else: extract `Problem / Why`, `Proposed Behavior`, `Acceptance Criteria (early draft)`, `Constraints & Risks`, `Test Conditions to Consider` (each `|| PLACEHOLDER`), then `body = buildBody(selectedMode, problem, behavior, criteria, constraints, tests, relativePath)`.
11. `body = normalizeSmartPunctuation(body)`.
12. Emit (collect into `messages` AND forward to the injected `emit` sink, exactly as Python `_emit`): `Selected mode: ${selectedMode}`; then if a `fallbackReason` is set, `Fallback reason: ${fallbackReason}` (the Python initializes `fallback_reason = ""` and never sets it on this path, so this line is NOT emitted — preserve that; keep the variable for parity but do not emit when empty); then `Creating issue: ${issueTitle} (label: ${promotionType})`.
13. `createResult = gh.issueCreate(issueTitle, body, promotionType)`.
14. Missing-label recovery (the regression scenario): if `isMissingLabelFailure(createResult.output, promotionType)` — i.e. any output line lowercased contains ``could not add label: '${label}' not found`` — emit `Missing promotion label detected; ensuring label exists and retrying.`; call `gh.ensureLabel(promotionType)`; emit each line of the ensure-label output; if the ensure-label exit code is `0`, retry `gh.issueCreate(issueTitle, body, promotionType)` and replace `createResult`. Only recover from THIS specific missing-label failure; all other gh errors fall through to the failure path unchanged.
15. If `createResult.exitCode !== 0`: the output lines are `createResult.output` or, when empty, the single line `gh CLI exited with code ${createResult.exitCode}`; emit each line; return `PromotionOutcome(exitCode = createResult.exitCode, messages)` (no destination).
16. On success, emit each line of `createResult.output`.
17. `[issueUrl, issueNumber] = parseIssueReference(createResult.output)`.
18. `lastUpdated = null`; if `issueNumber` is set, call `gh.issueView(issueNumber)`; if its exit code is `0` and it has output, `lastUpdated = extractLastUpdated(viewResult.output.join("\n"))`.
19. If both `issueNumber` and `issueUrl` are set: split `content` into lines, `updatedLines = updateMetadataLines(lines, featureName, issueNumber, issueUrl, lastUpdated, featurePath)`, `fs.writeLines(resolved, updatedLines)`, emit `Updated potential file with issue metadata: ${resolved}`.
20. `promotedDir = <workspace>/docs/features/potential/promoted`; `fs.ensureDir(promotedDir)`; `destPath = promotedDir/<basename(resolved)>`; `fs.move(resolved, destPath)`; emit `Moved potential file to promoted folder: ${destPath}`.
21. Return `PromotionOutcome(exitCode = 0, messages, destination = destPath)`.

The `emit` seam defaults to a no-op-print equivalent; in the service path, `emit` forwards lines to the output channel via the injected `log`. The `messages` array preserves every emitted line in order for the service summary/return.

### `content.ts` parity (port of `potential_to_issue_content.py`)

Port each function with byte-identical regexes, formats, and constants:

- `PLACEHOLDER = "(not provided in potential file)"`.
- `ISSUE_URL_PATTERN = /https?:\/\/\S+\/issues\/(\d+)/`.
- `BUG_SECTION_HEADINGS` = the seven headings in order: `Summary`, `Environment`, `Steps to Reproduce`, `Expected Behavior`, `Actual Behavior`, `Logs / Screenshots`, `Impact / Severity`.
- `SMART_PUNCTUATION_MAP` = the seven char mappings (curly double/single quotes -> ASCII, en/em dash -> `-`, NBSP -> space). `normalizeSmartPunctuation` MUST replace ALL occurrences of each mapped char (Python `str.translate`); use a global-regex or per-char replace-all, NOT a first-occurrence `String.replace`.
- `stripPotentialMarker(value)`: strip a trailing `(Potential...)` marker (case-insensitive `/\s*\(Potential[^)]*\)/i`), `.trim()`; fall back to the trimmed original when the result is empty.
- `getFeatureName(content, filePath)`: first markdown H1 (`/^\s*#\s+(.+)$/m`) -> `stripPotentialMarker`; else the basename with a trailing `.md` removed (case-insensitive).
- `getFeaturePath(featureName)`: replace runs of whitespace with `_`, then drop any char not in `[A-Za-z0-9_-]`.
- `getSection(content, heading)`: extract the body under a `## <heading>` block up to the next `##` or end-of-string; regex `^##\s+<escaped-heading>\s*\r?\n(.*?)(?=^##\s+|\Z)` with multiline+dotall semantics; return the trimmed group or `""`.
- `buildBody`, `buildBugBody`, `buildMinorAuditBody`: reproduce the section ordering, headings, `- Work Mode: <mode>` first line, the `## Source\nFrom: <relativePath>` footer, and the exact blank-line spacing (`buildBody`/`buildMinorAuditBody` use `\n\n` between sections and a single trailing `\n`; `buildBugBody` joins parts with `\n\n` and appends a trailing `\n`).
- `parseIssueReference(output)`: join lines with `\n`, search `ISSUE_URL_PATTERN`; return `[match[0], match[1]]` (full URL, number) or `[null, null]`.
- `extractLastUpdated(issueJson)`: `JSON.parse`; on parse error return `null`; read `updatedAt`; if not a string return `null`; parse the ISO timestamp (replace trailing `Z` with `+00:00`); return the date portion (`YYYY-MM-DD`) or `null` on parse failure. Use a deterministic date extraction (do NOT use wall-clock `Date.now`; parse the provided timestamp string).
- `findMetaEnd(lines)`: first index whose left-trimmed line starts with `## `, else `lines.length`.
- `setLineValue(lines, label, value, metaEnd)`: if a line matches `^- <escaped-label>:`, replace it in place and return `metaEnd`; else insert `- <label>: <value>` at `metaEnd` and return `metaEnd + 1`.
- `updateMetadataLines(lines, featureName, issueNumber, issueUrl, lastUpdated, featurePath)`: set `lines[0] = `# ${featureName} (Issue #${issueNumber})`` when non-empty; then `Issue` -> `#<n>`, `Issue URL` -> `<url>`, optional `Last Updated` -> `<lastUpdated>`, and `Status` -> ``Promoted -> docs/features/active/${featurePath}/ (Issue #${issueNumber})`` (byte-identical, including the `->` arrow and trailing slash).
- `evaluateMinorAuditEligibility(content)`: port the deterministic eligibility heuristic returning `[boolean, string]` with byte-identical reason strings, even though `promotePotential` does not call it on the MCP path (it is part of the content module's public surface and is covered by `test_potential_to_issue_content.py`).
