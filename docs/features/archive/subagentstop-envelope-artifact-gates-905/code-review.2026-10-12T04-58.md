## Executive Summary

The change is narrowly scoped and follows the E1 helper contract. Each pure entry function takes `-InputText`, forwards it to `Read-SubagentStopEnvelope` only when bound, maps an invalid envelope to `<PREFIX> payload anomaly - <clause>`, and each script tail ends in `Exit-SubagentStopBlock -Message` or `exit 0`. The four rule changes match the normative text in `spec.md` character for character. Mirrors are byte-identical. All targeted suites pass on a reviewer rerun, PSScriptAnalyzer reports zero findings, and changed-line coverage is 100.00%.

The reviewer found no Blocking finding. Eleven Non-blocking findings are recorded below; the most relevant are test-depth gaps on the negative boundary of R3 and R4 (NB-1, NB-3), the documented residual breadth of R3 (NB-2), and a pre-existing fail-open path for uncaught exceptions that the exit-2 switch does not address (NB-6).

Mandatory evaluations: R3 is correct, narrowly scoped, and does not weaken a check that previously caught a real defect. R4 is correct, narrowly scoped, and does not weaken a check. The per-validator corpus gate is satisfied for all four validators: a zero after-change false-positive count was committed in each conversion commit before the corresponding switch commit.

## Rule Change R3 Evaluation (exhaustive-search-scope wording)

**Correctness: PASS.** Both sites now evaluate `(?i)\b(entire|whole|all|complete)\b.*\b(repository|repo|worktree|source tree|tree)\b`, identical to the normative pattern (`validate-prd-feature-output.ps1:51`, `validate-task-researcher-output.ps1:202`). The `-notmatch` operator, the trimmed value, the position in `Test-NumericDerivationEvidence`, and the rejection message are unchanged. Unit tests pass for `entire worktree.`, `the whole worktree, all directories.`, `entire repository` (accepted) and `the hooks folder` (rejected with the unchanged message) in both suites (reviewer rerun). The pattern is a strict superset of the old one: every alternation member of the old pattern remains.

**Narrow scoping: PASS.** The three-dot diff of each function shows exactly one changed line (the regex). `evidence/qa-gates/r3-verification.2026-10-11T23-22.md` independently records `BASE-OLD-PATTERN-COUNT: 1`, `CURRENT-NEW-PATTERN-COUNT: 1`, `CURRENT-OLD-PATTERN-COUNT: 0`, `R3-ONLY-CHANGE: YES` for both hooks. Mirrors are byte-identical (reviewer `sha256sum`).

**Weakening of a check that previously caught a real defect: NO.** Evidence:

- Prior tests and fixtures: on the base, the only scope fixtures are `entire repository source tree` (positive) and `focused directory` (negative), in `validate-prd-feature-output.Tests.ps1:19`, `:128` and `validate-task-researcher-output.Tests.ps1:28`, `:406`. Neither contains `whole` or `worktree`, and the negative still rejects (suites pass). The originating commit `29b42cc87` (#593) added no fixture in which a whole-worktree or entire-worktree scope was a rejected case.
- Corpus: before R3, 20 scope-message failures were recorded in the prd-feature corpus; 8 were classified CHECKER-DEFECT (all whole-worktree or entire-worktree values) and 12 ARTIFACT-DEFECT. All 12 ARTIFACT-DEFECT scope values still fail the scope check after R3, including the two values closest to the new tokens (`those four files on the current worktree.`, `the whole file, lines 1-335.`) (`corpus-prd-feature.2026-10-11T15-03.md:1945-2036` before, `:2470-2561` after). The 8 CHECKER-DEFECT paths pass the scope check after R3 (`SCOPE-RECHECK-FAILED: 0`) and each still fails a different, unchanged rule, so R3 did not convert any corpus failure into a pass (EVIDENCE-FAILURES 56 before and 56 after, `AFTER-FAIL-NOT-IN-BEFORE-COUNT 0`).
- Runtime: before this branch the hooks never received input and exited 1, so the old pattern never blocked a completion at runtime.
- Residual breadth: R3 admits values that pair `whole`/`entire` with `worktree` but then narrow the covered set (NB-2). This matches the breadth of the old pattern for `entire repository excluding ...` and is recorded in spec Risk 5a.

## Rule Change R4 Evaluation (empty-token guard in the discovery gate)

**Correctness: PASS.** Line 190 reads `if ($trimmed -and (Get-DiscoveryArtifactType -Path $trimmed)) {`, identical to the normative text. In PowerShell any non-empty string is truthy (including `"0"`), so for every non-empty token the original call is made with the same argument and the result is unchanged. For an empty token, the old code raised a parameter-binding exception and never returned a reference, so no reference can be lost. The unit case (`""` plus `discovery/coverage-ledger/coverage-ledger.json`) returns exactly that reference without error (reviewer rerun).

**Narrow scoping: PASS.** The function diff contains one changed line. Tokenization, trim set, de-duplication, return type and `Get-DiscoveryArtifactType` (including its mandatory `-Path`) are unchanged. Mirror is byte-identical.

**Weakening of a check that previously caught a real defect: NO.** The base has no test of `Find-DiscoveryArtifactReference` and no test that expects the binding exception. The exception was not a check; it terminated validation. Under the old transport the termination produced exit 1 (non-blocking); under the new transport it would also exit 1 and fail open (NB-6), or, in the corpus harness, be recorded as a block of a message that has no failing artifact. The discovery corpus shows 12 such `EXCEPTION:` blocks before R4 and 0 blocks after, with all 17 source files producing identical token classifications (`corpus-discovery.2026-10-11T15-04.md:6`, `:1165`).

## Additional Review Notes

- Transport: each entry function distinguishes "parameter not bound" (stdin) from "bound to empty" (`$PSBoundParameters.ContainsKey('InputText')`), so in-process tests cannot accidentally read the test runner's stdin. This is the correct use of the E1 seam.
- Allow semantics: discovery allows a blank message, no references, or an absent declaration; pr-author, prd-feature and task-researcher block a blank message with their existing empty-output reasons (`PR_AUTHOR_OUTPUT_EMPTY`, `last assistant message is empty`, `agent output is empty`). Matches spec data-flow section.
- R1 (`validate-task-researcher-output.ps1:104`) and R2 (`validate-prd-feature-output.ps1:74-90`) match the normative patterns; R2 evaluates checkbox lines one at a time, applies `IgnoreCase`, and normalizes `\` to `/` before the policy-marker check.
- Read failures: `Get-Content` calls in prd-feature and task-researcher are wrapped and return block results naming the path; covered by dedicated cases.
- Task-researcher guard: bootstrap after `param()`, guarded helper edge before `Set-StrictMode`, dependency tail before the pure call, and a guard-shape test using the shared E1 helpers without modifying them.
- Help text: all `CLAUDE_HOOK_INPUT` and exit-1 references are removed from comment-based help; help now documents stdin and exit 2.
