## Governing Rules

**Fail-closed evidence rule:** Every baseline, regression, targeted-verification, final-QA, and coverage-comparison step has its own artifact under `docs/features/active/subagentstop-artifact-gates-review-notes-929/evidence/<kind>/`. If any required artifact is missing or lacks a required field, the audit verdict is BLOCKED or INCOMPLETE, never PASS.

**Evidence accounting rule:** Each evidence-producing task names its artifact. A task is not checked off until that artifact exists. Every command artifact carries `Timestamp:`, `Command:`, `EXIT_CODE:`, and `Output Summary:`. An artifact whose gate exits non-zero by expectation carries `ExpectedExitCode: <int>` and records exactly one gate (one command); a task that needs such a gate and other gates writes separate artifacts. Probes whose two outcomes are both legitimate (for example "does the branch contain `origin/main`") are written as hash comparisons that exit 0 in both cases, never as `git merge-base --is-ancestor`.

**Evidence filenames:** Artifacts are named `<name>.<timestamp>.md`. The stamp is the UTC write time read from the host clock immediately before the write (`date -u +%Y-%m-%dT%H-%M`). A task that consumes an artifact selects the lexicographically greatest file matching `<name>.*.md` in the named folder. Evidence locations are limited to `evidence/baseline/`, `evidence/regression-testing/`, `evidence/qa-gates/`, and `evidence/other/` under the feature folder. No evidence is written under `artifacts/`. Tool output that PoshQC writes under `artifacts/pester/` (gitignored by the `/artifacts` entry of `.gitignore`) is tool output, not evidence.

**No host paths:** Artifacts never record a host absolute path. The executor worktree root is recorded as the literal token `WORKTREE_ROOT`. Coverage XML package names (which carry absolute paths) are never copied into evidence; only `counter` and `line` elements are copied.

**Scratch location:** The orchestrator for this session uses the untracked worktree-root directory `SCRATCH/` as its scratchpad; this child's issue-unique directory is `SCRATCH/929/`, which already exists in the worktree. Every scratch file this plan names lives directly under `SCRATCH/929/`: the PowerShell scripts and shell wrappers of the script route, the commit-message files, and `SCRATCH/929/powershell-coverage.baseline.xml` and `SCRATCH/929/powershell-coverage.final.xml`. Nothing under `SCRATCH/` is staged or committed: every `git add` names explicit paths, `git add -A` and `git add .` are never used, and every clean-tree check excludes it with the pathspec `":(exclude)SCRATCH"`. Artifacts record scratch paths in the literal form `SCRATCH/929/<file>`, never a host path.

**Script route (every PowerShell command):** The executor has no PowerShell tool, and in an agent-isolated worktree the Bash tool refuses command text containing `pwsh`, `bash`, `wsl`, or a heredoc. Every PowerShell command in this plan therefore runs as follows. For the script named `SCRATCH/929/<ID>-<n>.ps1` in a task, the executor (1) writes that file with the Write tool, containing exactly the script body quoted in the task; (2) writes `SCRATCH/929/<ID>-<n>.sh` with the Write tool, containing exactly two lines: `cd "$(dirname "$0")/../.." || exit 97` and `pwsh -NoProfile -NonInteractive -File SCRATCH/929/<ID>-<n>.ps1` (with `<ID>-<n>` replaced by the same concrete name); (3) runs `sh SCRATCH/929/<ID>-<n>.sh` with the Bash tool. The wrapper's exit status is the exit status of the `pwsh` process, unchanged. The first wrapper line makes the worktree root the working directory, so the route works the same in a non-isolated worktree. The artifact's `Command:` field records the `sh` command and a `Script:` field quotes the script body verbatim. Every task below states its concrete script name; no task uses a placeholder name. PoshQC MCP tools (`mcp__drm-copilot__run_poshqc_format`, `mcp__drm-copilot__run_poshqc_analyze`, `mcp__drm-copilot__run_poshqc_test`) remain direct tool calls. `git`, `poetry`, and `sh` commands run directly in the Bash tool from the worktree root.

**Pester runner exit code:** Every Pester runner script below ends with `exit [int]$r.FailedCount`, so its exit code equals its failed-test count and `EXIT_CODE: 0` means no failure.

**Commit and push:** Every phase ends with a commit and `git push origin bug/subagentstop-artifact-gates-review-notes-929`. Each commit message is written with the Write tool to the file named in the task (`SCRATCH/929/<ID>-commit-msg.txt`) and contains exactly: line 1, the subject quoted in the task; line 2, empty; line 3, `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; nothing after line 3. The commit runs as `git commit -F SCRATCH/929/<ID>-commit-msg.txt` with the concrete file name; `-m` and heredocs are not used. Never force-push, never rebase pushed history, never delete a repository file. Every clean-tree acceptance uses `git status --porcelain -- . ":(exclude)SCRATCH"`, which lists nothing, or only this plan file when the executor has updated its checkboxes after the commit. If a repository hook denies a staging, commit, or push command, record the denial text verbatim beside the affected task, leave the task unchecked, do not bypass the hook, and continue with the next task.

**Verification policy (Option A):** Local verification uses the PoshQC MCP tools plus CI evidence. A PoshQC MCP result carries no per-test output, count, percentage, or finding, so no acceptance condition in this plan reads any of those from an MCP result; only the call disposition (`EXIT_CODE: 0` when the call returned, non-zero when it raised) is recorded. Counts, named-test results, analyzer findings, and coverage come from (a) the Pester runner scripts, which print `<Result> | <name>` lines and `FAILED=`/`PASSED=` totals, (b) direct `Invoke-ScriptAnalyzer` per file, and (c) the self-hosted PoshQC module's `artifacts/pester/powershell-coverage.xml` and `artifacts/pester/pester-junit.xml`.
