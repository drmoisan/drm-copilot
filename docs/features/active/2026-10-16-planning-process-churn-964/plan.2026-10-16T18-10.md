## Conventions for This Plan

- `FEATURE` abbreviates `docs/features/active/2026-10-16-planning-process-churn-964`. Every evidence artifact is written under `FEATURE/evidence/<kind>/` as `<name>.<timestamp>.md`, with the stamp read from the UTC clock at write time; a consuming task selects the lexicographically greatest `<name>.*.md`. Command-step artifacts carry `Timestamp:`, `Command:`, `EXIT_CODE:` and `Output Summary:`. No artifact records an absolute path or host name.
- `SCRATCH` resolves to `<session scratchpad>/issue-964/`. Every scratch script, staged copy and helper this plan names lives under it, and its file names start with `issue-964-`. Artifacts record the token `SCRATCH`, never a host path.
- This plan is design-level. Each task names files, symbols or headings, behavior, the tests that prove it, and its acceptance. Tool routes, launchers and per-command recipes are owned by the executor's environment knowledge (and, once written, by the `execution-environment` skill this item creates); they are not restated here. Literals are quoted only where they are the asserted value.
- Execution runs in the item worktree under a non-terminal checkpoint whose route is `large`, `preparation` or `remediation` (batch budget). Bundle and mirror copies are made only by the copy script of [P5-T1], never by Write or Edit. PowerShell scratch files are never written with Write or Edit.
- Hook changes on this branch are proven by Pester only; isolated subagents run `main`'s hook copies. Enforcement hooks stay PowerShell (no Python invocation).
- In-item plan validation uses `poetry run python -m scripts.dev_tools.validate_orchestration_artifacts plan <path>`; the installed MCP validator does not carry G11 to G13 until release.
- No task diffs against `origin/main` inside a test. Scope comparisons in evidence anchor on the merge base of `origin/main` and `HEAD`.
- Files listed under spec `### Files deliberately not touched` are not edited. In particular `scripts/dev_tools/validate_orchestration_artifacts.py`, `tests/scripts/dev_tools/test_claude_rules_frontmatter.py`, `tests/scripts/dev_tools/test_plan_gate_parity.py`, `extensions/drm-copilot/src/lib/validate/plan-gate-observability.ts`, `scripts/dev_tools/plan_gate_observability.py`, `extensions/drm-copilot/src/lib/validate/plan-gate-commands.ts`, `.claude/skills/epic-orchestrate/SKILL.md`, `.claude/agents/epic-orchestrator.md`, `.claude/settings.json` and `quality-tiers.yml` must show no change at the end of the plan.

- Evidence: baselines, QA gates, isolation runs, the G11 to G13 corpus measurement, the self-review and the #962 re-plan summary are written under `FEATURE/evidence/<kind>/` with clock-read UTC stamps.
- Batch budget: about eight production PowerShell files (four hooks plus bundle copies) exceed the direct-mode cap; the large-route checkpoint and the copy script keep execution inside the budget.
- Hooks-run-main's-copy: no acceptance condition relies on a live subagent exercising a branch hook; hook behavior is proven by Pester, and the #962 re-plan is delegated non-isolated by the orchestrator.

## Size Justification

The spec's File Inventory spans about 140 written paths across three runtime surfaces, two validator runtimes and four PowerShell hooks, and 32 of its 34 acceptance criteria are executor-owned. Mirror copies are collapsed into one copy-script task and the 44 generated Codex files into one generator task, but each canonical surface edit, each new test file and each QA gate remains one binary task so that a failure names one file. Splitting the item would separate the contract text from the hooks and validators that enforce it, which the spec treats as one change.
