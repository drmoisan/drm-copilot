**Shared conventions for every new or changed test row:** in-memory seams only (worktree porcelain through `WorktreeListInvoker`, transcripts through `ReadTranscriptHead`, files through the existing probe seams); POSIX roots `/repo`, `/repo/.claude/worktrees/item`, `/sibling/item-b`, `/host-a/repo`, and `/host-b/repo`; forward slashes and exact file-name case; no temporary files, no sleeps or wall-clock waits, no gitignored `artifacts/` state; modules imported in `BeforeAll` are removed in `AfterAll`. A regression row that needs a seam parameter the plan adds passes it through a suite-local argument builder that includes a parameter only when `Get-Command` reports that the command under test declares it, so the identical row runs against the unmodified code (fail-before) and the changed code (pass-after); the suite header states this. Rows added to an existing suite keep that suite's own synthetic root form (for example `/synthetic-worktrees/main`) and add `/host-a/repo` as the prior host. A D9 resolver seam is a suite-local script block `param($Branch)` that returns `[pscustomobject]` with `WorktreeRoot` and `ReasonCode`: a mapped branch gives its root and no reason code, a `<ReasonCode>` case gives a null root and `TARGET_WORKTREE_NOT_DERIVABLE` or `TARGET_WORKTREE_AMBIGUOUS`, and every invocation is appended to a list the row owns, so a row can assert the invocation count.
