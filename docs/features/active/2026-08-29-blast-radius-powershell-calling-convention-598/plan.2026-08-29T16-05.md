1. ## Observation source for the format and analyze steps

The MCP result object carries only `ok`, `tool`, `workspace_root`, and `summary` (`extensions/drm-copilot/src/mcp-tools.ts:90-113`); it carries no formatter or analyzer output line and no exit code. The self-hosted invocation is the observation source for every acceptance condition in this plan that names such a line, on the same basis already recorded for the Pester step in `[P0-T7]`. `Invoke-PoshQCFormat` prints one `Already formatted: <path>` line per unchanged file and one `Formatted: <path>` line per rewritten file (`PoshQC.Analyzer.psm1:62` and `:64`). `Invoke-PoshQCAnalyze` prints `PSScriptAnalyzer passed: no findings under <root>` only when it found nothing, and otherwise throws `PSScriptAnalyzer reported N issue(s).` (`PoshQC.Analyzer.psm1:183` and `:185`), which makes `pwsh` exit non-zero. Running the self-hosted formatter after the MCP formatter is not redundant: on a clean tree it prints only `Already formatted: ` lines, which is the required clean-pass observation, and if the two disagree it prints `Formatted: ` lines and fails the gate, which surfaces the disagreement.

Every format step in this plan is therefore the following two commands in this order:

1. `mcp__drm-copilot__run_poshqc_format` against the workspace root.
2. `pwsh -NoProfile -Command "Import-Module ./scripts/powershell/PoshQC/PoshQC.psd1 -Force; Invoke-PoshQCFormat -Root (Get-Location).Path"`

Every analyze step in this plan is the following two commands in this order:

1. `mcp__drm-copilot__run_poshqc_analyze` against the workspace root.

## Change-set attribution contract

`[P0-T2]` recorded `BaseRef: main`. Before the merge, `git diff --name-only main...HEAD` reported this feature's own changes plus a small set of Markdown documents inherited from the integration branch, and the `[P0-T2]` base-ref note recorded that those documents cannot affect any acceptance condition because every assertion is either pathspec-scoped away from them or counted by the `.psm1`, `.py`, and `.Tests.ps1` extensions.

The merge invalidates that reasoning. `main` is an ancestor of the merged-in branch, so `main...HEAD` now also reports every file the merge brought in, including `.psm1`, `.py`, and `.Tests.ps1` files. An assertion over that span can no longer distinguish this feature's files from merged-in files, so it verifies nothing about this feature. `[P10-T10]`'s requirement that the change set contain zero `.py` files is not merely inaccurate over that span, it is unsatisfiable.

The following definitions replace it. `[P0-T11]` records the three refs; every later task names them rather than re-deriving them.

- `BaseRef` — the value recorded in `[P0-T2]`, which is `main`.
- `MergeRef` — the SHA of the merge commit that brought `origin/epic/claude-runtime-portability-integration` into this branch.
- `PreMergeRef` — the merge commit's first parent, that is this feature branch's tip immediately before the merge.
- `MergedBranchRef` — the merge commit's second parent, that is the tip of the merged-in branch.

Two derived path sets:

- **`FAS`, the feature-attributable change set** — the de-duplicated union of three path lists:
  1. `git diff --name-only <BaseRef>...<PreMergeRef>` — every path that differs between `main` and this feature branch's pre-merge tip. Re-derived against this repository, that span reports 54 paths: the 14 `.psm1` paths of batches B01 through B07, 21 of this feature's own documents and evidence artifacts, and 19 Markdown documents belonging to sibling features and to the epic, which the branch inherited from the integration branch at creation. The 19 inherited documents are not this feature's work. They affect no acceptance condition in Phases 9 and 10, because every one of those conditions is either pathspec-scoped away from them or counted by the `.psm1`, `.py`, and `.Tests.ps1` extensions, none of which they carry.
  2. `git diff --name-only <MergeRef>..HEAD` — this feature's commits made after the merge.
  3. the path column of `git status --porcelain` — uncommitted and untracked paths.

  The third list is required because the first two enumerate tracked committed changes only and cannot report a file the executor has created but not yet committed. The first two are required because the third goes empty once the work is committed. Every span carries an explicit ref operand; none compares the worktree against the index.
- **`MAS`, the merge-attributable set** — `git diff --name-only <PreMergeRef> <MergeRef>`, that is the files the merge itself changed relative to the pre-merge feature tip.

Rule. Every change-set and exclusion assertion in Phases 9 and 10 is evaluated against `FAS`. A path present in `MAS` and absent from `FAS` is a merged-in file and is not part of this feature's change set. A path present in both is a file this feature edits that the merge also touched; each such path is named explicitly in the artifact of the task that reports it.

Identification check. `MAS` must contain `.claude/lib/requirements/GeneratedDocumentCounters.psm1`. That module reached this branch through the merge and through nothing else, so a `MergeRef` whose `MAS` omits it is the wrong commit and the executor stops and reports rather than proceeding on a misidentified ref.
